# 文档、原型与数据库业务支持审查

日期：2026-09-26；阶段1内审查小阶段，基线`7691970`。本轮按用户要求检查当前业务设计与双端HTML原型的一致性，以及数据库设计能否承接业务。只新增审查记录与索引，不修改业务规格、原型、正式代码、迁移或运行实例；下列问题均保持待修复，审查完成不等于缺陷关闭。

## 1. 结论与证据范围

**主要业务已有持久化设计，但目前不能认定为完整无缺口，更不能认定已经实现。** 本轮确认6项数据库设计问题、3项原型流程/状态覆盖差异和1项现行文档冲突。数据库问题集中于约束、冻结引用及成品元数据，宜优先扩展既有结构，不据此重建整套模型或直接增加大量表。

- [目标关系清单](../../architecture/database-relations.md)实际统计为142个不重复表名，含1张条件启用的邮件交付表；未启用该条件时为141张。[Redis设计](../../architecture/redis-design.md)登记R01～R19共19类键，不是19张表。
- [生成数据库字典](../../../contracts/database-schema.json)登记B0的12张业务表，迁移基线仍为`0001_b0_identity`；这不是142张目标表已建成的证据。本轮未连接数据库查询现场结构。
- [原型说明](../../../prototype/README.md)最新交互为DESIGN22；DESIGN23/24明确只改文档。因此近期NLP/语言准入设计尚未完整体现在原型中，不能把原型当作正式流程的完整验收依据。
- 审查覆盖材料与考试、查询与收藏、NLP/AI/TTS/缓存、身份设置与权限，以及任务/用量/容量/通知的相关设计。对业务关键路径逐项核对字段和约束，未声称对所有未来SQL、供应商行为或运行负载作了验证。

## 2. 数据库设计问题

以下6项均为P2设计缺陷或持久化映射缺口，应在对应业务切片建表前解决；本轮没有确认P1。位置以审查基线为准。

### DB-01 根级教材Lesson无法表达

证据：[教材规格](../../modules/textbooks.md)§2明确无显式Unit时允许Lesson/节直接位于书下；[材料字典](../../architecture/database-materials.md)§3.2（第222行）却要求`textbook_lessons.unit_id`非空，唯一键只有`(S,unit_id,ordinal)`。

只有“Lesson 1、Lesson 2”而无Unit的合法教材，会被迫拒绝或补造不存在的Unit。建议允许真实根级Lesson，补齐同一材料版本内根级排序/唯一约束及父节点归属校验；已有表可承接，关系清单应同步。

### DB-02 直接收藏题目的来源与去重约束未同步

证据：[收藏字典](../../architecture/database-learning.md)§2.1（第34、36、44行）仍规定exercise只来自已校验卡片，只有`card_id/card_revision`分支及对应唯一键；[题目直接收藏](../../modules/vocabulary-practice.md#题目直接收藏)要求`question_ref`与卡片分支互斥，并按本人、题目版本及作答上下文去重。

教材题、AI习题或交卷后题目无需先生成查询卡片。不同设备使用不同幂等键收藏同一题面时，现有卡片唯一键不覆盖该请求；只按题目ID去重又会混淆作答前与不同场次的快照。建议在`collection_items`登记受控来源联合、冻结题目/作答上下文及可索引的规范身份，增加与题目分支相符的唯一约束；不能仅把必要身份隐含在任意JSON中。

### DB-03 共享词音等待请求缺少冻结配置引用

证据：[语音请求字典](../../architecture/database-learning.md)§6.5～6.6（第343、355～359行）中，等待他人生成时本人`job_id`为空，音频尚未就绪，`speech_requests`主要依赖可变的`global_word_lookup_id`；该lookup的profile版本及活动slot会更新。收藏行也只保留当前词音选择。

用户等待声音配置v1后改选v2时，旧请求缺少恢复原配置/执行代次所需的冻结身份，无法仅凭最新lookup证明迟到音频仍对应旧请求。[缓存发布规则](../../architecture/learning-cache.md)§6要求播放请求绑定自身配置与代次。建议请求保留词条、profile版本、严格键及等待代次，明确request_generation与个人selection_generation的对应关系；不得通过读取其他用户私人Job补足这些信息。

### DB-04 共享音频格式派生缺少明确持久化映射

证据：[TTS适配器](../../architecture/tts-adapters.md)§4要求按原资产摘要和转码版本缓存确定性格式派生；[共享音频字典](../../architecture/database-learning.md)§6.5（第342、346行）只登记一组对象/格式字段，并以严格键和模型生成代次唯一。[FileObject](../../architecture/database-materials.md)§2.2全部为本人私有，不能作为公共派生对象的共享读取根。

当已有共享成品需要为另一设备派生可播放格式时，当前设计未明确原音频、派生规格/转码版本、对象校验与GC引用保存在哪里。建议在公共音频范围补充有界派生登记，或明确既有表扩展映射；转码不应变成新的模型合成代次或新供应商attempt。

### DB-05 共享成品缺少实际合成出处

证据：[TTS适配器](../../architecture/tts-adapters.md)第36行要求供应商返回的实际路由/模型修订可得时写入成品；[共享音频字典](../../architecture/database-learning.md)第332～342行只有调用前已冻结的profile及音频对象属性，没有响应后实际路由/修订等合成出处的位置。

这些信息不能只留在贡献者私人attempt，也不能事后修改不可变profile来代表所有历史音频。建议公共成品保存不含贡献者/Key的实际合成规格与出处，明确未知值及适配器/API版本；私有`audio_assets.synthesis_config`已有载荷位置，本项不将其列为缺列。

### DB-06 听力准备问题代码不一致

证据：[材料字典](../../architecture/database-materials.md)第291行列出`script_missing/audio_missing`，而[试卷结构契约](../../contracts/material-structures.md)第110行要求`listening_script_missing/listening_audio_missing`。

按两份正文分别实现写入枚举与就绪校验，会出现缺稿/缺音频待办写入被拒或阻断项识别不一致。建议使用同一受控代码注册集合，统一到权威契约，并纳入已确认的`language_confirmation_required`分支；无需新增审批表。

## 4. 已有设计能够承接的关键业务

| 业务 | 已有映射与本轮结论 |
| --- | --- |
| 身份、资料与设置 | `users`与`user_extensions`合并扩展，profile/study/settings三组revision隔离更新；多语言/Key/会话保持一对多，容量单独计数。未发现本轮可确认的P1/P2缺陷 |
| 查询前后文 | `query_context_budget_tokens`默认10000、1000～64000范围与设置/API一致；上下文快照、配置及严格生成键有对应契约，查询缓存不只按单词字符串匹配 |
| 材料提取与原书ruby | 不可变FileObject、材料版本和canonical内容、JobStage/OCR结果及原书ruby映射分别保存；原注音不混入canonical_text，NLP不能冒充原书读法 |
| 全应用基础NLP | `text_analysis_versions/units/sentences`保存来源版本、pipeline、输入快照、句子跨度、单元内有界token JSONB和状态；所有内容不需每个词建一行，也不需每页新建分析表 |
| AI完整成品 | `explanations/cards`等业务结果与source_result_bindings、查阅/生成状态承担成品和版本引用；AI正文仍属业务结果，NLP是其派生标注，失败不必重调AI |
| 持久缓存 | PG/对象存储为成果权威，Redis/本机为可淘汰副本；miss先查持久结果，有效引用期间不按TTL/LRU删成品。共享词音的DB-03～05需补齐 |
| TTS模型适配 | 模型目录已有adapter ID/version及版本化能力契约，私人声音配置、冻结规格、真实attempt用量均有映射；模型真实兼容性仍待工程验证 |
| 小说逐句与章节准备 | 逐句解析/音频、章节Job/阶段、分别准备及本机就绪、阅读位置/书签已有映射，不需把整章拼成单个不可恢复的大缓存 |
| 试卷与学习证据 | 冻结卷、场次/答案、评分历史、听力脚本确认/冻结音频、在线播放次数及错题/掌握证据均有对应结构；DB-02/06仍待修复 |
| 权限、任务与运维 | 持久撤销/授权版本、作用域服务事务与父锁、Job/Outbox、供应商attempt、私有/共享容量和站内通知有对应设计；Redis不是唯一安全或任务事实来源 |

两项建议不计入确定缺陷：

1. 教材词表/表格非习题字段需进一步明确怎样映射NLP原文范围。现有`source_locator`与三张分析表可承载，但[SourceAdapter清单](../../architecture/text-analysis.md)对结构晚于原文发布时的字段/冻结时点解释不足；应明确复用原文跨度还是注册独立结构来源，不先断言缺表。
2. 词本创建/添加收藏仍提供中文目标语，而学习语言设置只展示日英。DESIGN24直接限制的是材料上传和正式NLP，中文辅助学习内容仍允许保存；应统一这些入口的能力说明，不能仅据材料白名单推断中文收藏超出范围并删除入口。
