# 查询上下文、TTS适配器与系统缓存

日期：2026-09-26，阶段1内原型/文档小阶段DESIGN22，基线eddba5b。用户要求手动查询携带足够上下文，预算在设置中可配置、默认一万，并完善查询缓存、全部朗读缓存及每模型TTS适配。范围为设计文档和HTML原型，正式Flutter/Python/ORM/迁移未修改。

## 行为与设计

新增[查询上下文契约](../../contracts/query-context.md)，默认10000 tokens表示补充前后文合计，完整父句/目标另计。区分稳定ContextPlan和真实模型窗口约束下的ContextSnapshot，明确同章/同单元/当前有权题面等边界、显式上下文不静默截断、图片独立计量及运行冻结。预算数值本身不改变缓存身份，实际上下文改变才区分语境。

完善[统一缓存](../../architecture/learning-cache.md)：内存、本机副本、Redis和PG/MinIO四层；完整成功解释与音频自动持久保存，收藏仅归类。清本机/Redis、换Key和播放倍速不重新调用模型；声音/读音/合成输入变化区分资产。补充各入口、并发占用、失败恢复、容量/GC、账号隔离、标准词音共享及限次试卷听力例外。

新增[逐模型TTS适配器](../../architecture/tts-adapters.md)，按精确模型、API家族及契约修订注册能力和测试，分别处理Gemini及OpenRouter不同协议。请求展开、音频解码与完整性校验、未知结果及用量进入统一运行层。官方协议依据链接保留在正文，不把示例模型当正式允许清单。

数据库设计仅扩充现有用户设置/模型目录及既有JSON快照映射，保持142张目标表；Redis目录、API、模块、覆盖索引、导航及路线图同步。DB定义检索skill的本机目录没有已注册索引，本轮以仓库现有设计书为字段依据，未创建外部数据库或执行迁移。

原型增加独立“查询与上下文”设置、快捷/自定义预算、查询补充输入及可展开的前后文。朗读设置按模型更新声音/能力，缓存页区分本机与已保存成果；章节准备和各处喇叭计入示例缓存。模型能力、字符估算和两层保存计数均为内存模拟，不执行真实模型/音频/持久化。

## 独立审查

非作者Agent `sentence_speech_review`完成两轮局部审查。第一轮集中发现4项P2：图文查询误命中文字卡；格式重绘回默认项；切实例未重置本机容量；相同单词从小说查询与独立查询朗读重复建缓存键。分别纳入附件身份、固定格式value、重置实例设置，以及让非正文词汇回统一音频键。

第二轮在手机390px和电脑1440px通过真实UI定点复核：带PNG显示尚未识别且无伪卡，回纯文字仍命中；WAV保存/离页后保持；切实例回100/500MB和Gemini且缓存归零；两入口朗读同一个“そっと”始终只有一段音频。4项全部关闭，两端无脚本异常，未调用供应商。

作者同时修正完整父句提取、按冻结声音区分章节准备记录及汇总章节缓存；阅读/解析模式取文均排除ruby，原型不伪造未加载的长上下文。
