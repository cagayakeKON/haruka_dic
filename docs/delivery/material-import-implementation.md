# M1实现方案：材料导入、材料库与通知

状态：实施中。依次完成下面三个单元，每个单元通过必要局部验证与非作者review后独立本地提交，再进入下一单元。前后端在同一单元内按共同接口并行，不提前开展后续单元的业务实现。

## 1. 交付范围

沿[路线图M1](roadmap.md#阶段-2三类材料与可靠源数据)，交付真实三步导入、本人不可变源文件与初始版本、三类类型分派、材料列表/搜索/筛选/分页/详情/改标题/确认删除、有权任务进度，以及持久站内消息的列表、未读、已读与跳转。保留既有B1小说来源及收藏出处兼容。

小说、课本先支持MD/EPUB；试卷支持MD/EPUB、PDF及图片源文件。目标语言只允许日语/英语。上传与格式验证完成不代表正文可读、教材可学习或试卷ready；三类结构解析与阅读页面分别在M2～M4实施。扫描/图片不使用传统OCR，也不在本轮追加真实模型、NLP或TTS调用。

流程与状态以[材料模块](../modules/materials-reading.md)为准，格式与语言以[三类契约](../contracts/material-types.md)为准；不可变发布遵守[数据与任务](../architecture/data-jobs.md)。本方案只安排实施顺序，不复制这些状态机。

## 2. 单元一：协议、兼容迁移与数据访问边界

后端先实现具体DTO、模型与增量迁移，前端同步类型和真实数据访问接口。

- `material-imports`创建、读取及未受理取消；上传内容写入与`uploads/{id}/complete`；服务端能力目录；材料metadata列表/详情/改标题/删除；消息列表/标读/快照全部已读沿[API目录](../contracts/api.md)发布具体契约。
- 临时上传采用同API实例的相对URL与短期能力请求头，客户端仅能写本人staging对象；Android与Web使用各自已配置的同一服务实例。final对象只由服务端生成，不向客户端签发写能力。
- 扩展现有上传意图/文件对象、材料/版本、Job及Outbox；新增当期材料导入、容量预留和消息持久结构。头像原专用路径保持。无模型材料Job合法使用空凭据/运行引用，行内CHECK按操作类型约束，模型任务仍要求有效引用。
- 消息采用库根锁内分配的提交序列；新增消息和序列递增同事务。列表签发绑定本人、实例、受众的快照，后续全部已读仅作用于已提交的序列范围，不以旧时间戳上界误读晚提交消息。
- 既有B1材料列表的版本/第一章有值语义保持；新材料metadata允许尚无已发布正文引用，旧阅读和出处接口继续执行原保护。历史迁移原字节不改，不新增物理外键或隐式级联。

完成条件：DTO/契约导出、行内约束及受控增量迁移验证通过，旧头像、B1来源/收藏与模型任务形状兼容，前后端使用同一协议；非作者检查该单元后提交。

## 3. 单元二：真实导入与材料库

前端亲自操作当前已确认Flutter mock的手机和电脑导入、列表及dialog，然后在同一页面、外壳和导航接线。后端实现受控对象存储、领域服务及任务分派。

- 三步表单实际选择文件、计算有界大小/摘要、申请意图、上传临时对象并确认完成；未知提交结果通过原意图查询/幂等重放恢复，不创建重复材料。
- 服务端并发预留容量，领取完成代次/租约，复制到独占final对象并验证实际字节、完整摘要和真实格式；在当前权限、归属、期限及代次有效的事务中受理材料、Job与Outbox。过期、取消、覆盖、撤权和发布失败有确定结果。
- 复用既有Worker/Inbox生命周期处理无模型源验证与类型分派，不建立第二套任务系统。语言不确定时按既有语言Issue/Job检查点阻断；未确定语言或扫描内容不标可读，进一步模型处理保持未请求状态。请求中尚未实现的OCR/AI阶段明确拒绝，不接受后静默丢弃。
- 材料库实现本人类型/语言筛选、标题搜索与稳定分页；详情、改标题CAS、确认删除及删除代次栅栏接真实服务。未有可靠正文时不进入空白阅读器，也不展示虚构目录或学习结果。
- 任务REST与WebSocket复用当前协议，订阅和重连重新授权；已提交源层状态与后续领域准备状态分别展示。材料库卡片不另设任务百分比/进度面板入口，遵守已确认界面。
- dialog/菜单取消、失焦、切回应用不重拉已有业务数据；成功保存只更新相关数据，切筛选、换账号及迟到响应按现有作用域处理。

完成条件：真实PG/对象存储证明上传覆盖、并发容量、取消/到期、重放、撤权、删除迟到及A/B隔离；Web与Android完成对应真实导入、列表、详情/删除和进度路径。非作者集中review，修复后定点复核并提交。

## 4. 单元三：持久本人通知

源事件和安全边界遵守[通知契约](../contracts/notifications.md)，消息与任务进度分别授权。

- 只消费已提交的完成/失败/待校对白名单事件，与Inbox幂等事务写本人消息；重复事件不增发，Redis丢失不影响消息和已读事实。
- 实现稳定分页、未读筛选/计数、单条幂等已读和服务端快照全部已读；首个read_at保持，多端重试及旧时间戳晚提交不误标新消息。
- 摘要使用安全message_code/引用，不写原文、题答或秘密；来源不可用时通用降级，打开资源重新检查当前权限、归属、版本及业务状态。管理员不能读取他人私有消息。
- 接现有手机“我的→消息”、Android通用通知栏摘要和电脑header入口，保持原消息页面及缓存作用域；换账号清理旧摘要，系统通知被拒绝仍有页面入口。

完成条件：PG幂等/并发快照与权限隔离定点验证，Web/Android真实消息列表、标读、全部已读、跳转、失败重试及返回操作通过，正常/失败事件进入统一日志；非作者review后提交。

## 5. 分工与M1完成

主Agent负责共享协议协调、本人通知后端及单元衔接；后端Agent负责材料领域、对象存储、迁移和Worker；前端Agent负责已确认Flutter UI、数据访问及必要Web/Android实操；独立reviewer检查每个单元及直接影响。共享模型/迁移、接口注册与生成源由后端Agent统一编辑，避免并发覆盖。

本轮只运行证明各单元所必需的模块、契约和真实集成路径。三个单元完成并联调后声明M1完成，随后列出M2～M4及阶段3～6的剩余开发范围；M1通过不代表三类阅读、朗读、练习、考试或完整版本已实现。
