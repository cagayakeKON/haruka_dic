# 多单词本与每日学习

状态：2026-09-22，VB1设计，业务未实现。用户已确认可以创建多个单词本，掌握状态由练习结果自动判定，不能手动选“已掌握/未掌握”。本篇定义单词本的完整使用流程；四类收藏、照片与普通练习保持在 [收藏与练习](vocabulary-practice.md)，算法/证据在 [词汇学习状态](../architecture/vocabulary-learning.md)。

## 1. 范围、入口与权限

单词本是本人单词的多对多组织方式，不等于私有Library，也不是一本原书。每个账号可创建多本，例如“教材A”“旅行”“考试词汇”；P0不设只能一本的限制，容量上限按部署配额明确显示。每本固定一个目标语，空本可修改目标语，有条目时不得通过改语言使成员语种不匹配。

| P0核心能力 | 范围 |
| --- | --- |
| 多本管理 | 创建、命名/简介、列表/详情、删除本；一个单词条目加入多本，加入/移出/移动不复制条目和学习进度 |
| 单词管理 | 手动录入、阅读/卡片收藏时选本、CSV/照片导入后归本；释义/词形/读音、词性说明、原句/出处、笔记/标签与标准发音 |
| 查找与批量操作 | 按本/语言/标签/来源、掌握度、到期/常错/暂停筛选；文本搜索、稳定排序/分页；批量归本、移出、暂停/恢复及明确删除条目 |
| 每日学习 | 到期复习、重学、新词额度；按单本、多本或全库生成去重队列；学习预览与真正测验分开 |
| 自动掌握 | 新词/学习中/已掌握/需重学的只读结果、判定证据、下次复习；用户只能控制是否参与计划，不能修改掌握结论 |
| 结果与历史 | 本次完成/待评/待复核、错词回练、题目/评分依据、掌握变动原因、日历式历史列表和简单趋势；不是完整学习日历计划产品 |
| 数据迁移 | 全部/筛选单词CSV，包含词本归属；导入不伪造练习或恢复可信掌握度，规则见[CSV](../contracts/vocabulary-csv.md) |

本次将基础到期复习/间隔调度纳入单词本P0，替代旧“SRS全部P1”的安排。公开词本市场、用户间共享词本、录音发音打分、完整离线作答同步、复杂智能词本规则和个性化算法训练不在本次范围。

入口沿用户端“收藏/单词本”模块组织，不强制新增底部导航项。使用client.vocabulary_notebook.read/create/update/delete，条目读取和修改仍检查collection权限，学习需practice.read/start/answer，明确新生成/AI评分才另验相应权限、Key与预算；依赖只在 [权限目录](../contracts/permissions.md) 定义。每本、成员、聚合计数及批量选择都按owner/library隔离。

## 2. 流程、状态与异常

### 2.1 多本、成员和删除

单词本首页先显示“今日待复习/可学新词”，随后是本人各单词本。系统视图提供全部单词、未分组、未掌握、已掌握、常错、已暂停；这些是筛选视图，不能删除，也不算额外用户单词本。“未分组”表示没有任何有效自定义词本成员关系，移出最后一本后自动进入该视图。

创建本填写名称、目标语和可选简介；名称规范化只用于本人同语种去重，显示值保留。加入已有词时选择本人同语种条目；“加入另一本”新增关系，“移动”原子新增目标关系并移除指定来源关系，词同时属于其他本的关系不受影响。重复加入幂等；任何外来ID、跨语言或并发版本冲突整批拒绝，不静默跳过。

删除本需预览名称/成员数并确认，只删词本及成员关系，不删单词、音频、掌握证据或历史Attempt。“删除单词”是独立collection.delete动作，明确从全部词本移除并停止未来选题；保留历史答题快照，迟到评分不复活已删条目。正在学习时删本：已经冻结且仍有collection.read的条目可继续，结果仍归单词；删除单词/撤销其读权则停止新的答题并给出原因。服务端计划依据具体条目授权，不因旧本ID获得额外权利。

同一CollectionItem在多本共用一套学习状态；不同释义/读音或未确认同义的收藏仍是独立条目，不仅凭lemma合并。列表可聚合同拼写并展开义项/出处，但聚合行只有所有子条目满足标准才显示全已掌握，否则显示已掌握数量，不能把某个义项的成绩推广到所有义项。

### 2.2 录入与单词详情

所有来源复用CollectionItem：手动、阅读划词、AI卡片、CSV、照片确认。创建时可明确选择一个或多个本人词本；无选择进入未分组，不强迫每次新建一本。创建词与所选成员关系在有界事务内一起校验/提交；CSV大批仍按其分批规则。

详情分为词形/读音与标准发音、目标义项/释义、原句/出处、笔记标签、所属词本、学习记录；词条摘要用collection.read，所属本另验notebook.read，历史/证据明细另验practice.read及来源权限，不能借详情绕过撤权。释义缺失、读音歧义或可用题不足显示待补全，不伪造答案或静默调用AI补词。全局标准词音遵循 [缓存规则](../architecture/learning-cache.md#51-收藏库标准单词发音的全局缓存)，点击发音不产生掌握证据；例句和私人解释保持各自作用域。

编辑词形、语言、目标义项或读音的实质变化创建新的learning_revision；旧证据保留为历史，新版本重新评估。存在有效词本成员时拒绝改成与任一本不匹配的语言，提示先明确移出相关本，不静默删关系；语言修改、加入/移动成员与词本语言修改使用相同父锁顺序重验。笔记、标签、归本调整不重置进度。修改页不能出现手动掌握开关；API也拒绝写mastery_state、due_at、计数或调度参数等服务端派生字段。

已建立的收藏kind不通过编辑在word/其他类型间转换；需要改变类型时明确新建目标类型条目并保留原历史，不能让词本成员指向句子或把单词学习证据转给其他类型。

### 2.3 检索、批量与统计

每本展示总条目数、已掌握/未掌握、到期、暂停、资料待补全及最近学习时间。已掌握+未掌握等于去重后的有效条目总数；到期/暂停是独立维度，不能把这些数量全部相加当总数。多本汇总与队列按CollectionItem去重，不能把同词在两本中的关系算成学了两次。

排序至少支持加入本时间、词形、下次复习、最近练习和错误次数，均加稳定ID作为并列游标。批量选择区分当前勾选和全部筛选结果；后者冻结服务端选择快照/版本，明确条数，不能只处理当前页或操作后来加入的条目。受控上限内原子执行，过大分批任务必须预告部分提交及逐批重验权限，保持幂等和真实完成数。

用户可暂停/恢复一个词的复习，影响它在所有词本中的计划，界面明确说明。暂停不改变掌握度，恢复不清空证据或把已经逾期的due_at改成未来；“只从本中移出”仅改变归类。P0没有“批量标记已掌握”或“导入即已掌握”。

### 2.4 今日队列与一次学习

1. 选择单本、多本或全部单词、目标语、每日新词/复习目标及已有题型。队列先重学和到期，再补新词；顺序稳定，按词去重。推荐每日新词20/复习100作为可调初值，待样本验证；创建计划时原子预留本人学习日的新词额度，跨本/设备不能超领，取消/跨日处理见学习状态专题。达到本轮目标仍显示剩余到期数，不显示全部清零；加学新词须明确调整每日目标。暂停/已删除/无权限条目排除，缺资料或缺可用题数量单列。
2. “学习预览”可以看释义、原句和听发音，但不据此判掌握。开始测验冻结PracticePlan、条目学习版本、题目版本和证据目标，复用PracticeSession/Attempt，禁止前端传入“本题已掌握”。
3. P0提供可靠已有题的词义识别、释义/原句提示下填词等主动回忆；开放同义回答按冻结答案规则或显式AI评分处理。不靠随机拼凑相近释义制造错误选择题。无Key仍可做有可靠答案的现成/确定性题；资料或题目不足时显示补齐信息/显式生成入口。
4. 作答先服务端保存，再展示规则结果或待评；答案、辅助记录和评分贡献均由后端维护。答案揭示前可选“不会”，这会提交明确的未回忆成功；普通跳过/结束不自动判错。用过答案提示的正确答案不能当无提示成功；查看答案必须通过记录揭示状态的受控接口。
5. 结束页显示本轮实际作答、已评/待评/争议、有效掌握变化及下一次复习。错词可以立即再练，但同次机会反复答对不累加掌握证据。音频失败、网络中断、Key缺失或AI待评均不能记成词汇错误。
6. 跨设备继续读取同一服务端会话；同一词在两端重叠复习共享后端判定的学习机会，重复提交不重复延长间隔。只读离线缓存不扩展成离线作答，重联先恢复身份与已提交进度。

每日学习时区由已保存的本人偏好确定，计划冻结其值。跨午夜、夏令时及修改时区不重新计算旧记录的学习日、不重复发放当天新词额度。所有时间点仍用UTC存储，精确规则见学习状态专题。

### 2.5 按本自选条件出题

除今日队列外，可从本详情或练习页选择单本/多本，按收藏/入本/最近有效练习/到期时间以及新词、学习中、已掌握、需重学组合生成题目，例如“考试本最近7天加入且未掌握的词”。筛选、快照、空结果、数量不足及付费确认统一见[普通练习生成](vocabulary-practice.md#按单词本时间和记忆情况生成)，不维护第二套时间/记忆规则。生成前可预览命中数，不因生成题目增加掌握或消耗新词额度；开始作答再绑定机会与日账本。

## 3. 前端职责

Flutter共用NotebookRepository、队列/状态DTO与业务controller，独立紧凑/宽屏视图。Android采用词本列表→词列表→详情/测验，批量操作使用选择模式、底部操作区和系统返回保护；生成条件用专用配置页/筛选面板及固定预览/确认区。Windows/Web可用词本侧栏、词列表及详情分栏，生成条件与候选预览并列；键盘选择/提交须避免输入法未完成时误提交。切布局保留条件和selection_id，不重复预览/生成、不新建学习会话或丢答案；更改条件使旧预览不可提交，迟到响应按请求/账号代次丢弃。

学习状态只读展示“为什么达到/未达到标准”、最近证据和下次复习，后台重算时明确更新中，不能先乐观勾为掌握。题目出现/揭示/提交、成员操作、跨本筛选、暂停与删除各有稳定Test ID和无障碍名称，沿既有注册表单源维护，不在文档造生产测试旁路。词本离线变更/离线答题不落写队列。

## 4. 后端职责

NotebookService负责词本/成员/批量事务；CollectionService继续拥有词内容、来源和学习版本；PracticeService拥有冻结题、作答/辅助及有效评分；VocabularyLearningService消费可追溯学习证据，更新掌握和调度投影。复用现有Python包、PG/Outbox/Worker、Flutter功能模块，不新增独立服务。

Notebook与NotebookItem均有owner/library、created_at/updated_at，成员唯一键包含本人/词本/条目；跨表逻辑关联按ScopeContext及共同父锁校验，无物理外键。目录计数、选题、批量快照及CSV不得把无权限词或其他账号本名计入结果。索引覆盖owner/library、notebook/member、mastery/due与稳定分页，实际DDL/查询计划在实现阶段验证。

## 5. 公共契约与依赖

[学习状态](../architecture/vocabulary-learning.md) 是判定/调度/重评唯一正文；[API](../contracts/api.md)、[权限](../contracts/permissions.md)、[CSV](../contracts/vocabulary-csv.md)、[数据与任务](../architecture/data-jobs.md) 分别维护公开入口、动作、迁移格式与持久事务规则。

记录notebook.created/updated/deleted、notebook.members.changed、vocabulary.review.plan_created、vocabulary.learning.updated/rebuild_failed等白名单事件，仅包含数量、状态、策略版本和受控引用，不记本名、词、释义/答案或个人成绩明细。服务端提交为业务事实，前端打开词卡/播放埋点不作为学习贡献。

## 7. 待决与后续

自动掌握和多本是已确认要求；掌握阈值、日额度、FSRS参数与公共词表覆盖属于推荐工程基线，需用真实样本及验收锁定，不宣称已有学习效果。P1可扩展智能筛选本、听写/拼写专项、更多统计和调度优化；P2录音评价和完整离线同步需另行方案。用户要求重新测试时创建新练习，不通过“我已掌握”按钮跳过评估；争议只能沿有效评分的复核/重评流程纠正。
