# 手动查询上下文与预算

状态：2026-09-25，DESIGN22用户确认带上下文查询、设置可配置及默认一万预算；其余范围/算法/实现上限为本轮设计，正式业务未实现。操作见[查询](../modules/query.md)，源范围见[出处](content-locator.md)，命中与并发唯一维护于[学习结果缓存](../architecture/learning-cache.md)。

## 1. 预算设置

设置“查询与上下文”提供`query_context_budget_tokens`，默认 **10000 tokens**，表示当前目标之外的前后文合计预算，不是字符数、固定句数或必须填满的额度。原型及推荐首版接受1000～64000的整数，提供5000/10000/20000快捷值及自定义输入；最终服务硬上限由版本化配置发布。该字段属于本人Settings投影/settings_revision；保存不调用模型、不重算旧结果、不改变在途任务。

当前完整父句、所有选中目标及明确提交的必要输入另计；系统指令、工具schema、图片、输出预留和安全余量不占这项用户前后文预算，但全部计入模型总窗口。设置页解释Token单位，显示请求预算与当前模型可用上限；实际取文不足时按实际显示，不用重复文字补满。无法确定供应商窗口时不宣称预算可用，生成前要求选择已验证模型。

独立查询保留原输入框，另有可折叠的“补充上下文”文本框。只取本次输入及显式补充，不自动把此前所有查询、收藏库或整本书当作聊天历史；补充字段允许空，没有上下文时明确标注。显式补充不可静默截断，超限须精简；图片成本由视觉适配器另计，不能用字符数充当图片Token。选区本身的长度上限不因扩大上下文预算而扩大。

## 2. 来源与取文顺序

| 来源 | 必需中心 | 可补充的前后文及边界 |
| --- | --- | --- |
| 小说选词/选句 | 当前完整父句、按原文顺序的目标范围 | 同一不可变章节中相邻完整句/段，默认不跨章，不附全书摘要 |
| 课本正文 | 当前句与所在内容角色 | 当前Lesson内连续课文/同角色块，停止于单元或角色边界；不混入答案区 |
| 普通题/交卷后试卷题 | 本题有权题干、选项和必要共享材料 | 同一题组的合法公共材料、当前已发布反馈；不扩到其他题答案、隐藏听力稿、rubric或未发布评分；试卷提交前仍拒绝学习查询 |
| AI解析/词句卡/收藏 | 当前可见字段及完整父句 | 当前已提交卡片中的相关释义/例句或同一字段连续文字；保留生成资源身份，不递归抓取上游原书/别的查询 |
| 独立文字/图文查询 | 当前输入、显式附件和补充上下文 | 没有绑定来源则不推测材料身份，不把相同单词的历史释义当上下文；图片只引用本人已发布资产 |

服务器重取源内容及当前可见字段，不相信客户端的prefix/suffix、DOM文本、身份、Token数或hash。ruby注音不混入canonical_text。章节或单元即使尚未在客户端加载，也可在当前权限允许下由服务端有界取文；这不是客户端无限滚动预加载。

补充默认前后各分一半，按距目标由近到远选完整句，某一侧触边时把未用预算让给另一侧；输出保持原文先后顺序，不按距离乱序拼接。超长外围句可省略并注明裁剪原因，中心父句及目标不可被截掉。多词选择共用去重后的上下文并一次计预算，不给每个词各分10000；非连续目标仍按出处契约分别输出卡片。

## 3. 稳定计划与实际发送

ContextBuilder先用版本化、与默认模型无关的应用分词/Token估算器生成`ContextPlan`，以避免模型切换仅因分词器不同而令旧缓存消失。该估算只用于稳定取文和预览，不能冒充供应商用量。输入相同且应用计划版本不变时范围应确定；算法升级保留旧计划并明确历史差异，不偷偷重生成。

查阅先按该计划找已有结果，命中不创建AiRun/Job/供应商attempt，也无需为命中结果调用模型计数。只有显式新生成时才用对应模型tokenizer/count接口或经验证的保守估算校验窗口：

~~~text
可用补充 = max(0, min(用户前后文预算, 运行补充硬上限,
                      模型总窗口 - 系统与工具 - 必需中心输入 - 图片成本
                                 - 输出预留 - 安全余量))
~~~

只能继续裁掉最远补充，保留原顺序和完整句边界，形成冻结的`ContextSnapshot`。预算不足以放下中心/显式输入时拒绝生成并提示缩小目标或换模型；不得静默删除中心、图片或用户明确补充。结果显示“请求预算 / 实际前后文估算 / 受限原因”，并可展开查看本次有权发送的前后文。内容只出现在业务界面，不进日志。模型默认变更时已有结果仍按其实际上下文可读，提供明确重新解析动作。

## 4. 类型化契约与缓存身份

| 类型/字段 | 含义 |
| --- | --- |
| QueryInput | `source_ref/target_ranges`或`manual_input`可辨识分支；`explicit_context`、有序`image_refs`、说明语言/详细度、请求模式；手动查询任务保持auto，不新增用户类型选择 |
| ContextPlan | `schema_version`、`builder_version`、`estimator_version`、`settings_revision`、`requested_budget_tokens`、中心引用、去重有序`planned_spans`、显式输入/附件版本摘要、`context_plan_digest` |
| ContextSnapshot | `plan_digest`、实际有序`sent_spans`/有权文字快照、`sent_context_digest`、`estimated_context_tokens`、`token_count_method`、模型窗口/输出预留、`truncation_reason`、不可变依赖版本 |
| 查询响应 | `context_summary`（预算、实际数量、前/后句数、边界/模型缩减原因）、`match_kind`、`result_id/version`、真实生成配置；完整上下文只通过本人有权结果详情读取 |

预算数值与settings_revision是来源记录，不直接当结果身份。预算改为20000但同章只有800 tokens、实际计划完全相同时命中原结果；计划因扩大预算包含更多原文时作为新的语境查阅，旧结果仅作明确标注的历史选项。计划摘要含目标身份、依赖版本、上下文范围及内容、显式输入/附件，不含临时签名URL、Key、播放速度或页面入口。

严格生成身份还包含实际发送快照和模型/Prompt/schema/有效参数。模型受限而少发前后文时仍保留其计划与实际差异；下一次同计划查阅显示该既有结果及差异，不自动尝试“补齐”。用户明确重生成才发布新的查阅代次。不同语境不以相似度/同lemma合并，详情见[缓存匹配](../architecture/learning-cache.md#4-命中规则与版本)。

## 5. 授权、冻结与验收

受理、每个新模型阶段、结果读取和上下文详情都检查当前账号/来源权限与可见性；仅扩大设置不扩大权限。模型不得把原文当工具指令。运行冻结settings、计划、模型与实际发送快照；设置保存不修改在途输入，旧run迟到按lookup_generation/fence发布。查询上下文预算只控制解释，**不自动传入TTS**；TTS使用独立适配器的最小必要发音上下文。

| ID | 正式必需验证 |
| --- | --- |
| QCTX-01 | 默认10000、快捷/自定义、非法值/越界/版本冲突，保存不调用；在途输入不随设置改变 |
| QCTX-02 | 小说近邻顺序/章节边界、课本角色、本题共享材料、生成卡字段、无来源输入和图片；目标/注音/多词去重正确 |
| QCTX-03 | 模型容量缩减、超长父句/显式输入拒绝、Token估计与真实用量分开；无旧两句/2000预算硬编码 |
| QCTX-04 | 同计划重复输入命中；预算变化同计划命中、不同计划隔离；模型/Key变化不隐式重生成；重生成乱序不覆盖 |
| QCTX-05 | 跨账号/失权/交卷前/隐藏稿拒绝，缓存与上下文详情不能绕过；日志不含全文或可反推文本的完整摘要 |
