# 小说章节准备契约

状态：2026-09-25，DESIGN20用户确认，正式业务尚未实现。入口和解析模式见[小说模块](../modules/novels.md)；本篇唯一维护章节准备请求、范围、分项状态与恢复规则。[学习结果缓存](../architecture/learning-cache.md)继续维护逐句成品的匹配、持久保存和复用，不新建整章解释或整章音频资产。

DESIGN22章节AI解析沿[查询上下文契约](query-context.md)逐句构造计划，批次冻结受理时的预算/设置与builder版本；用户后来修改预算不静默扩张已授权批次。已完成句按实际语境复用，重新解析不同计划需明确新批次。TTS冻结[模型适配契约](../architecture/tts-adapters.md)和声音，不把整章或查询预算直接发送成朗读输入。

## 1. 两类处理与显式授权

导入小说后必须异步遍历全部已发布正文，完成分句/分词、词形/词性/活用、可得读音及源范围的基础NLP处理。逐章报告完整性；正文可以先阅读，未完成标注的章节不能显示“语言标注完成”。未知词/人名/特殊读法记录不确定状态，允许校正；原书ruby优先，显示用注音不能进入canonical_text或选区偏移。NLP不等于已生成整句译文、语法详解或音频。

章节目录和阅读器提供同一个“准备章节”入口。先选一章，再用两个独立checkbox选择`analysis`（AI解析）和`audio`（朗读），默认两项勾选；允许任一单项或两项，不能用radio/互斥枚举实现。空集合在前端禁用提交、服务端拒绝且不创建Job或调用模型。选择/取消、打开模式或点击已有句子均不自动提交准备任务；点击“开始准备”才授权该章所选内容的新生成与本机缓存。

解析和朗读独立准备。只选解析不合成/下载音频；只选朗读不为生成音频顺带生成AI详解。两项选择时不能因某项成功就标整次就绪，某项失败也不丢弃另一项成品。读音基础标注属于NLP阶段，不能把它计作用户未选的AI详解。

## 2. 请求及冻结范围

以下是业务载荷设计，不是现有接口或DDL。当前用户从认证上下文取得，不接受客户端owner或正文作为权威来源。

| 字段 | 要求 |
| --- | --- |
| schema_version | 初始版本1，未知版本拒绝 |
| material_id / material_revision_id / chapter_id | 同一本人小说的不可变章节版本；服务端校验类型、存在、归属、发布状态及删除代次 |
| analysis_version_id | 已发布的语言标注版本，覆盖该章全部合法句子；版本变更不静默改变在途任务 |
| components | 去重集合，非空且仅包含`analysis`、`audio`；不得以枚举`both`替代多选语义 |
| explanation_options | components包含analysis时需要，未选则不提交：说明语言、详细程度、解释目的及本人模型配置引用；冻结实际版本 |
| speech_options | components包含audio时需要，未选则不提交：语言、声音/模型/profile及有效合成参数；冻结实际版本；播放倍速不属于合成参数 |
| idempotency_key | 本人作用域请求幂等；同键不同载荷冲突，同配置实际句子生成沿用GenerationSlot合并 |
| expected_revision | 暂停/继续/重试等操作的任务控制版本，阻止陈旧页面覆盖后续操作 |

服务端从冻结章版本展开有序句子，不信任客户端total或句子列表；保存章与标注版本、确定性遍历游标及范围摘要，不在一个Job载荷塞入整章正文/全部模型输出。AI上下文可包含获权相邻句，但输出逐句关联原范围，不能把单句无上下文翻译当成章节精读质量保证。音频沿用同一逐句合成上下文规则，句子面板与连续朗读可以匹配同一成品。

## 3. 分项进度与完成条件

analysis/audio各自返回`selected`、`total_sentences`、`ready_sentences`、`failed_sentences`、状态与可重试原因。未选项显示“未选择”或其已有缓存数量，不进入本次分母，也不被当作成功完成。进度来自持久提交及校验结果；流式半句、仅提交供应商、未知结果和音频下载片段不算ready。

每个所选项支持queued/running/paused/partial_failed/ready/cancelled；任务整体由所选项派生。全部所选项的所有目标句子成品ready，才能称“服务端准备完成”。客户端单独维护本机完整副本数量及下载状态，只有完整下载与校验后才称“本机就绪”。服务端完成但磁盘满/断网时明确显示等待下载或下载失败，不误报本机可用；重试下载不能重调AI/TTS。

准备页面分别显示“AI解析 x/n句”和“朗读 y/n句”，并区分服务端准备与本机就绪。关闭面板/离开章节不取消已明确授权的服务端准备；用户可继续阅读已发布正文、查看已完成句子。进入解析模式只查已有结果，未完成句子显示准备状态及同一章准备入口，不偷偷发起另一套逐句生成。

## 4. 暂停、继续与重试

暂停停止该章节批次未开始的句子调用/本机下载，保留已经提交结果和检查点。已发给供应商的调用不承诺立即取消，也不承诺无用量；合法在途结果可落盘，但不得继续扩张新工作或恢复播放。运行中的components固定；要调整选择，先暂停，再显式提交新的所选范围，未选项不继续调度。

继续/重试先逐句只读resolve，再补未完成或失败部分；成功句不重新生成。同配置重复章节准备、单句读取与连续朗读命中既有成品，无零Token模型调用。默认模型、Key或界面模式变化不隐式重生成；用户显式换配置沿现有查阅键/严格生成键与generation规则建立版本。

章节批量准备与播放器预取是不同授权范围：本批次可覆盖用户选择的整个章，但Worker并发/单次调用/技术限额仍有界。普通连续播放仍仅当前与有限后续片段；暂停播放不会取消独立提交的章节准备，暂停章节准备也不会删除可播放成品。任务只覆盖该章，不自动扩展相邻章节或全书。

## 5. 权限、持久化与本机副本

准备需要当前来源read与本人任务操作资格；analysis另验ai.explain及实际Agent调用权限，audio另验speech.generate/play。仅选单项时不能要求或消费另一项的生成权限。每个新供应商阶段重查当前权限、Key、技术限额、源删除代次；缺Key/失权暂停相应新工作，不借用其他用户配置；已有成品仍按现行读取权限处理。取消/暂停采用本人job.cancel，继续/重试沿本人job.retry控制范围并在接口明确分派，不建立无权限检查的通用执行入口。

复用PG持久Job/Outbox及已有任务checkpoint编排章节批次，解析复用Explanation/Card/SourceResultBinding，音频复用AudioAsset/Segment/Manifest；NLP复用text_analysis_versions/text_analysis_units/text_analysis_sentences及unit内token数组，见[统一文本分析](../architecture/text-analysis.md)。章节准备是任务和结果的聚合投影，不新增chapter_cache、chapter_audio或每个checkbox一张物理表；最终实现按现有数据库规范校验并发与引用。Redis只加速已有任务/结果投影，清空Redis后从PG/MinIO恢复，不把Redis计数或短TTL当作准备事实。

所选章节的解析和普通音频在当前设备按账号/实例分区提前下载，遵守容量、完整校验及离线权限租期；跨设备登录先查服务端成品，再下载缺失副本，不因新设备重新生成。退出/切实例/账号立即停止旧设备下载与播放、隔离迟到响应；章节准备不能成为考试听力下载或隐藏答案旁路。客户端清理只删副本，不删有有效引用的服务端成品。更广泛的下载中心、固定保留和全库离线包仍是后续范围。

## 6. 验收

| ID | 必需行为 |
| --- | --- |
| NPREP-01 | 两个checkbox，默认全选；仅解析、仅朗读、两项与空集合分别正确；未选项零新增调用/下载，空集合零Job |
| NPREP-02 | 冻结章/源/标注/配置，跨用户/错误类型/跨章引用拒绝；切模式、展开面板、重复点击不扩展授权或重复调用 |
| NPREP-03 | 分项进度基于已提交完整句子；部分失败/unknown不算完成，某项成功不掩盖另一项失败 |
| NPREP-04 | 暂停不启动新句；继续/重试只补缺失；重启/重复投递/多端请求不重复发布，在途未知按调用记录恢复 |
| NPREP-05 | 服务端ready与本机ready分离；断网/磁盘满/截断下载重试不重生成，退出和租期约束有效 |
| NPREP-06 | 解析模式ruby不污染文本/偏移；点句读取成品，面板喇叭与连续播放复用同句音频，未完成句不伪造结果/收藏 |

正式验收按阶段2建立NLP与出处、阶段3实现章节任务/解析/TTS/本机缓存；原型仅给出内置节选和计时演示，不能替代真实模型、存储、Worker恢复和三端证据。
