# 单词掌握度、学习证据与间隔复习

状态：2026-09-22，VB1设计，未实现。已确认掌握由练习结果计算；多本操作见 [单词本](../modules/vocabulary-notebooks.md)。本篇替代旧的用户手选new/learning/mastered/paused方案，不替代 [普通评分](../modules/vocabulary-practice.md) 或 [考试有效成绩发布](data-jobs.md)。

## 1. 学习身份与分离状态

P0以本人CollectionItem(kind=word)+learning_revision作为一个具体词形/义项/读音的学习目标；一个条目加入多本仍共用目标。不同义项、读音或未确认同义的独立条目不因拼写相同共用掌握状态；同一词音可以共享，但学习证据不能跨用户或义项共享。

| 字段 | 权威含义 |
| --- | --- |
| mastery_state | 服务端计算new/learning/mastered/relearning；未掌握视图含new、learning和relearning，不提供写接口 |
| study_control | 用户可设active/suspended，仅控制以后是否入默认队列；不删除证据、不改变掌握结论 |
| due_at / schedule_state | 按词/学习版本/能力的调度结果；到期与掌握独立，mastered仍可到期复习，单纯逾期不能宣称已证明遗忘 |
| assessment_status | ready/pending/rebuilding/needs_content等投影可用性，不把待评/缺题显示为零分或已学会 |
| learning_revision | 词形/语言/目标义项/读音发生实质变化时递增；笔记、标签、归本不递增 |

首次收藏/导入为new；浏览释义、朗读、收藏次数、阅读高亮和前端埋点不是掌握证据。暂停词在各本仍显示真实掌握状态和暂停标记。内容版本变化保留旧记录供解释，但不把旧版掌握转移到新学习目标。合并收藏只有经服务验证学习内容等价时才合并引用；证据按原Attempt身份去重并重算，不能相加两个缓存计数或保留最大掌握值。

## 2. 什么可以成为学习证据

题目发布时冻结assessment_targets：本人条目ID/learning_revision、能力类别、实际评分项、答案/rubric版本及可用辅助策略。P0能力为meaning_recognition（识别词义）与active_recall（依据释义/有效语境主动回忆词形）；听力、发音与真实自由运用未测试就显示未评估。

| 结果/动作 | 对学习的处理 |
| --- | --- |
| 已提交且发布effective的可靠规则/合格AI评分 | 生成或替换该Attempt/评分项/学习目标的唯一证据，保留评分来源 |
| 无提示的完整正确 | 可作为成功候选；仍需学习机会与间隔规则，不能刷相同题制造多个成功 |
| 可靠错误、按规则提交空答或明确“不会” | 失败证据；与技术失败/普通跳过区分 |
| 部分正确、提示后正确、已揭答案后的抄写 | 不能作为无提示成功，按有辅助/不完整回忆处理；不据此增加掌握成功次数 |
| 未请求评分、pending/needs_review/failed/unknown、未发布的整卷部分结果 | 不进入正式掌握/调度；保留既有有效证据，显示待评/复核 |
| 跳过、退出、传输/音频失败、仅看卡片/播放 | 不判词汇错误，不产生正向证据 |

普通练习以该Attempt的完整effective评分为边界，考试以整次有效评分发布为边界。普通题/考试仅在冻结的目标映射与分项评分足够确定时回流词汇；一篇作文总分或试卷总分不能自动映射到每个出现的词，AI在事后猜“考了某词”不是权威。映射不明的成绩仍进入普通学习历史，不影响词条掌握。

辅助/揭答案由服务端接口记录，绑定session_item及目标的ReviewOpportunity，并在共同目标/机会锁下与提交按接受序列排序。同一机会内A端揭答案但不提交，B端后来作答仍算已辅助；换session/本/设备不能恢复无提示资格。普通学习预览不生成成绩；若揭示了仍在待测机会的答案，同样记录曝光。只影响曝光之后的提交，不倒改之前已接受答案的资格；提交后正常反馈及其后的同机会订正仅作训练，不因系统展示反馈制造新的失败或正向证据。不会按钮提交明确响应类型，普通skip单独记录。响应速度仅用于体验统计，不据此使用Easy或提高掌握。

## 3. 自动掌握规则v1

以下为可解释的推荐产品阈值，须在阶段4用样本校准，不是科学上的永久掌握证明，也不是AI自由判断：

- new：当前learning_revision尚无有效测验证据；有有效证据后进入learning。
- mastered：最近3个有效学习日的证据组均为无提示完整成功（同一目标每天最多贡献1组），其中至少2组包含active_recall，且最新一次active_recall距上一次该skill的有效机会至少7×24小时。同日有效机会先归并，真实失败或未独立回忆不能被当天刷对覆盖；使用的义项/读音、题型及证据必须匹配本目标。
- relearning：曾达到mastered后出现更新的可靠失败或辅助/不完整回忆；完成新的上述成功窗口后才恢复mastered。
- 同一机会只贡献一次，短期重复、相同题的订正只用于训练；不能靠新session_id、跨本或两台设备绕过。无数据/单次答对/连续当场答对均不足以达到mastered。

已达标后不因额外正向练习、最近窗口排列变化或单纯逾期而降级；新的真实负面证据、有效重评纠正旧证据、学习版本变化或显式版本化策略重算才可改变该结论。训练性重复不作为负面证据，正常测验机会内的真实失败仍有效。

每次返回mastery_state同时返回policy_version、已满足/尚缺条件和截至版本；例如“2次有效成功，还需间隔复习验证”。证据引用/练习历史明细另验practice.read及实际来源权限，只有collection.read时只给词条学习摘要，不泄露题目、答案、成绩明细或可探测的Attempt ID。同拼写聚合视图按各义项计算，不生成无来源的综合百分比。过期复习单独标“待复习/逾期”，不把时间流逝当作新的失败练习。

用户提出成绩异议仍按现有review_status处理，不自动抹除有效分数。只有新的有效重评结果、经过审核的题目作废规则或新的真实测验改变掌握；首版不提供用户/管理员直接改mastery字段的入口。策略升级保存版本和重算原因，不伪造新作答。

## 4. 复习调度与去重机会

推荐在Python后端用 [py-fsrs](https://github.com/open-spaced-repetition/py-fsrs) 作为间隔调度适配器。FSRS接收Rating并计算复习时间；其记忆概率估计不直接等于本产品“已掌握”。[Anki FSRS说明](https://docs.ankiweb.net/deck-options.html#fsrs) 仅为算法使用参考，本应用不照搬用户手点难度作为测验成绩。

调度记录按owner/library/item/learning_revision/skill唯一，保存状态、稳定性/难度、due_at、算法/参数版本和revision。推荐初始desired_retention=0.9、关闭随机fuzz以便确定性重算，采用验证后的默认权重，不凭空训练个人模型；依赖版本、步长、最大间隔与参数须在实现时锁定。本次不安装依赖，也不把推荐配置当已验证。

评分适配固定为：可靠无提示成功→Good，可靠失败/“不会”→Again；提示/揭示或部分正确不按成功增加间隔，作为未独立回忆处理→Again，并保留原因。不根据响应时间使用Easy；不把“忘记”映射成Hard。普通跳过和技术/待评状态不调用调度器。

### 一次机会与临时加练

服务端为到期或新目标的skill创建ReviewOpportunity，绑定item/learning_revision/skill、当时schedule_revision、opened_at和机会ID；同一目标/版本/能力同一待处理代次最多一个机会。一个词在多个词本/设备/练习计划出现时复用该机会。purpose=review的PracticePlan冻结机会引用，不接受客户端自造ID；归本或换设备不重新计数。

机会内所有已接受且具备测验资格的有效作答由规则归并：存在可靠失败或辅助/不完整回忆时该机会不算无提示成功；重评纠正后可重算。正常提交后反馈引出的订正已标为training_only，不进入此次归并或Again映射。多个正确答案只算一个机会，事件重复按Attempt/评分项唯一键替换。首个有效结果可更新投影，随后迟到的同机会结果只替换该机会结论，不追加新间隔；用户显示实际修订原因。机会关闭后在下一次due_at前的普通重做是加练，正确不推进掌握/间隔；若出现真实可靠失败仍生成去重的负面观察，使掌握回退并提前复习，不能因“尚未到期”忽略遗忘。

普通练习若冻结实际学习计划时该目标已到期，可取得同一机会；未到期的正向结果仅存练习历史。未持有合法冻结目标映射的原材料/考试题不创建任意词的机会。初学/重学短间隔机会可以调度，但mastery按不同学习日与长期间隔过滤；同一机会的多个skill结果也不能计成多个独立学习日。

计划/机会只冻结候选，不预填成功。待评机会不重复发放；用户仍可做不记正向间隔的加练，正式重评和任务恢复沿原run。旧内容版本/删除目标的迟到结果仅留历史，不能恢复新版本状态。

按词本/时间/记忆条件的[出题筛选](../modules/vocabulary-practice.md#按单词本时间和记忆情况生成)只读有效投影，PracticeSelectionSnapshot及purpose=generate的PracticePlan不创建学习机会/日额度预留。purpose=review的实际学习计划才按开始时当前状态冻结机会、预留额度；未到期词自选加练仍受本节限制。出题时的as_of/掌握快照只解释选词原因，不覆盖作答时事实；同词多题依然归并机会，未发布的待评分数不能改变筛选状态。

## 5. 有效评分、重放与事务

| 逻辑记录 | 用途 |
| --- | --- |
| VocabularyNotebook / NotebookItem | 用户多本及多对多归属；不持有第二套掌握数据 |
| EffectiveLearningEvidence | Attempt/评分项/目标/机会、effective_grade版本、skill、结果/辅助原因、学习版本和服务端accepted_at；唯一来源证据 |
| ReviewOpportunity | 当前调度代次对应的有界学习机会和状态，防跨本/跨端刷次数 |
| DailyLearningBudget / NewWordReservation | owner/学习日账本和item/learning_revision唯一额度预留；计划领取原子占额，跨本/设备共用 |
| VocabularyLearningState / ReviewSchedule | 每词当前掌握、证据版本/原因与每skill调度投影，可重算，不由客户端直接修改 |

有效评分发布事务同时替换LearnerContribution并写Outbox；词汇消费者按原业务唯一键upsert当前有效证据，不在消息到达时简单加计数。它在目标父行/投影锁下校验归属、learning_revision、未删除、有效评分和证据版本，再重算该目标的掌握及相关schedule，提交后发状态事件。投影保留source_evidence_revision/applied_revision，前端能区分待更新和已同步。

迟到成绩或重评会改变过去的有效证据，按服务端记录的作答接受时间、稳定Attempt/评分项ID排序从受影响检查点重放，不能按消息抵达时间追加。机会归并/负面观察、算法/参数/策略和学习日版本全部参与重放；同日、同机会的重复不会增加间隔。重放使用事件原时间，不把历史失败当“现在又答错一次”；结果due_at已经过去则显示到期，不静默延后。新重评失败仍保留旧effective证据；新正确重评替换旧失败一次并重算后续调度，不删除真实Attempt。

每个用户词条的学习日由服务端accepted_at按当时已生效的study_timezone解析并冻结；同一机会跨午夜只取其首个已接受作答的学习日。时区变更从下一个已持久化日边界生效，已有日桶和当日已领取新词额度不重置，不用设备时钟/本数/重复会话计数。

创建计划/领取新目标时锁定owner+学习日日账本，按owner+学习日+item+learning_revision唯一键原子预留额度，并绑定各消费计划；同词跨本/设备共用一次预留，不同词的并发领取不能越过“已消费+未释放预留”的上限。首次答案被服务器接受即标额度已消费，评分pending/失败不释放重领；正式有效后更新学习完成数，配额已用和已学会不是一个计数。只有没有已接受作答且没有其他有效计划引用的取消/过期预留可以释放。未开始答题的预留在日边界失效，跨日继续必须在新日原子重领并重新授权，额度不足明确暂停新词而保留计划，不偷偷计旧日；已接受作答继续按原日计一次。调整每日目标保留已消费/预留，不能靠切时区/降低再提高目标清账。

所有业务表执行TimestampMixin、无物理外键、ScopeContext、父锁和幂等规则。改目标内容/删词推进学习代次，正在执行的投影写入必须比较代次；删本不修改学习代次。暂停只停止新的计划领取，已合法接受的作答可以继续发布，恢复沿原证据重新计算到期。投影作业按既有系统派生职责只处理已授权提交事实和封存/删除规则，不开启新模型调用。

## 6. CSV、接口和日志边界

Collection写模型只有内容和study_control等可编辑字段，mastery/schedule只出现在响应。词本成员操作不能修改LearningState。CSV v2导出掌握快照供查看，导入保留为非权威来源快照，不能把任意mastered字符串写成服务端掌握；既有条目合并不覆盖真实证据，新条目从new开始。CSV不增加题目/作答/调度历史备份，详见 [CSV契约](../contracts/vocabulary-csv.md)。

只读状态/队列预览不创建付费任务；创建复习计划检查practice.start/collection.read/本读取权限，提交和AI评分使用已有独立权限。源事件、调度用量和更新失败进统一日志，仅记录类型/计数/策略与受控引用，不记录词、答案或逐人掌握明细。管理员只能在已有运维范围看状态/非付费修复元数据，不能直接编辑个人掌握结论。
