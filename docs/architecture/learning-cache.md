# 查询、解释与 TTS 的统一持久缓存方案

状态：2026-09-23，设计方案，缓存业务尚未实现。用户要求一本书中查过的单词、AI解析过的内容、句子及TTS都缓存；已确认的试卷文字听力稿TTS同样适用。本篇维护结果保存、匹配、并发与生命周期；操作入口见 [AI与朗读](../modules/ai-speech.md)，试卷冻结关系见[解析数据结构](../contracts/material-structures.md)，本机管理见 [设置](../modules/settings.md)，范围/权限遵循 [三类材料](../contracts/material-types.md) 和 [RBAC](authorization.md)。

DESIGN16/17将普通学习及交卷后复盘文字统一为选区朗读/查询，包含已提交AI解释、中文说明和例句；受控资源字段选区身份遵循[出处协议](../contracts/content-locator.md#11-非材料学习文字的选区)，加入原有来源/版本与严格生成键。试卷在交卷成功后对有权复盘文字提供通用选区工具条，提交前禁用；历史结果存储与专用复盘/听力授权不因此删除或放宽。

DESIGN20新增用户显式按章多选准备AI解析、朗读或两项；批次授权、分项进度、暂停/重试与本机下载见[章节准备契约](../contracts/novel-preparation.md)。服务端成品仍逐句持久保存并共用原有查阅键/生成键，不因章节任务另造音频或解释缓存库；切解析模式和点句只读已有成品。

## 1. 保存承诺与范围

DESIGN22补齐[手动查询上下文预算](../contracts/query-context.md)与[逐模型TTS适配器](tts-adapters.md)。默认10000 tokens的设置只影响下一次查询取文，不批量刷新已有结果；查询词音、词条喇叭、例句、AI解释、小说单句/连续及章节准备、交卷后有权文字朗读全部通过同一SpeechService。考试限次听力仍使用专用播放授权。

成功且完整的单词/短语解释、句子翻译/语法解析、摘录解释、结构化卡片及生成音频，自动写入服务端持久存储，不以点“收藏”为条件。默认归当前用户；收藏库标准单词独立发音按第5.1节进入同一Haruka实例的跨用户共享目录，不共享个人解释、出处或收藏关系。收藏表达学习意图，保存结果避免丢失和重复模型调用，两者独立。保留有效引用的结果不设按天过期或LRU删除；清理Redis、本机缓存、换设备、退出、轮换/删除供应商Key，均不删除这些已提交结果。

这不要求预先解析或朗读整本书。只保存实际查过、已生成和明确授权预取的结果；页面预加载只读已有结果，不能顺带调用模型生成。用户明确删除材料/相关业务记录后的保留与回收仍受公共规则约束，不作无限容量或灾难永不丢失的保证。用户备份仍仅单词CSV，不新增音频或整书打包导出。

小说以章节/段落选区绑定，课本以Lesson/角色块绑定，普通试卷解释以合法题面/交卷后复盘版本绑定；考试听力音频另绑定已确认的ScriptVersion、ExamListeningBinding、SynthesisSpec与冻结AudioBinding。考试中禁用的解释、隐藏脚本或答案提示即使命中缓存也不可提供。OCR转写与材料分析已经按各自不可变产物保存，本篇不把它们变成解释缓存，也不缓存评分结果来跳过新答卷评分。

## 2. 四层职责

| 层 | 位置与内容 | 保留和丢失后的行为 |
| --- | --- | --- |
| Flutter内存 | 当前账号/页面的词句结果、可见区索引、播放缓冲 | 有界LRU；页面释放/换账号清理，再从本机或服务端取 |
| Flutter本机 | Drift保存索引及解释副本；平台私有文件/经验证的Web存储保存完整音频段 | 文本/音频分别限额和LRU；已显示结果/播放下载自动尝试落盘，失败提示未缓存到本机，不影响服务端结果 |
| Redis | 热门结果/索引副本、短期缺失提示与协调信号 | 有界TTL和容量；丢失回查PG，不直接视为需要再调用模型；不存唯一结果或承担唯一并发约束 |
| 服务端持久层 | PG保存Explanation/Card、源绑定、版本/索引、生成占用和AudioAsset元数据；MinIO保存完整音频字节 | 有效业务引用期间保留，跨端复用；发布以PG事务及已验证对象为准，纳入运维保护 |

Redis允许按内存策略淘汰键，因此必须是持久数据的副本，不能承载唯一的模型结果。[Redis淘汰说明](https://redis.io/docs/latest/develop/reference/eviction/)。Web存储可能因配额或浏览器回收而丢失，本机“已缓存”只表示当前已验证副本存在；服务端保存才是跨设备保证。[浏览器存储配额与回收](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)。不因本方案调整共享MyHome Redis全局淘汰策略。

私有结果以及所有本机副本、请求和使用记录以服务实例/用户/受众分区；仅global_word服务端目录/热副本和生成占用使用实例级公共命名空间。两类通过独立类型与仓储访问，不能把私有记录的owner设空变成通配查询。服务端播放仍限获权的client作用域，不因admin会话同属一个人就开放私有内容。登录和在线授权仍需要现有PG/Redis认证条件；结果可回查PG不代表Redis认证材料失效时可以绕过重新登录。

## 3. 一本书的已查索引与语境结果

分开维护“这个词在本书查过”和“这次原文位置的完整解释”。书内索引按词/词形/语种组织，但具体结果按源版本、选区和上下文区分。首版不使用向量相似度、仅lemma或相同单词字符串决定语境解释命中。

例如同书出现 `river bank` 和 `bank account`：书内索引可以共同归到bank，两个位置分别保存解析。再次选择同一位置并查询显示原结果；查询另一位置可查看注明出处的历史释义，但不能把“河岸”当成金融语境的当前解释。已有卡片里的简短词义也不能冒充完整的本句解析。

| 逻辑记录 | 必要信息与用途 |
| --- | --- |
| MaterialLearningIndex（source_result_bindings与当前lookup的查询投影，不另建物理表） | owner/library/material、词句类别、语言、表层词/可选lemma、源位置与已有结果引用；支持按书/章/Lesson分页查询 |
| SourceResultBinding | 带类型的来源身份、不可变版本/locator或手工输入摘要、结果ID及派生依赖；提交时把解释关联到持久来源，不由只读resolve补写学习记录 |
| Explanation/Card | 不可变完整输出、说明语言/详细程度/任务种类、实际上下文摘要与必要快照、模型/参数/提示/协议版本、来源和质量标记 |
| LearningLookupState | owner、查阅键、revision/lookup_generation、当前选择的严格生成键/active_run_id、effective_result_id；跨模型/Prompt配置维持本次查阅的权威结果指针 |
| GenerationSlot | owner、严格生成键、active_run_id、执行租约/fence；只合并同配置调用，不决定本书某处应显示哪个配置结果 |
| AudioAsset/Segment/Manifest | 真实音频格式/校验和/字节数/时长、合成键、句子/脚本源范围及播放顺序；试卷以ExamListeningAudioBinding引用同一私有音频库，不建立第二套TTS库 |
| GlobalWordAudio/GlobalWordGenerationSlot | 受控词条/读音与标准声音profile版本、全局合成键、不可变音频对象/校验信息、ready指针/发布代次；公共资产无收藏/材料/贡献者字段，生产Job关联仅内部占用记录可见 |

以上是逻辑职责，按现有Explanation/Card/Audio表扩展或增加必要关联，不要求每行新建一张表。所有业务表遵循 [数据库规范](../engineering/database.md)：created_at/updated_at、ScopeContext、业务唯一约束、无物理外键和共同父行锁。源绑定不是浏览埋点；成功解释提交时就建立，不能等待前端补发日志才出现“已查”。普通只读resolve不写学习进度或伪造新查询成功次数。

同一句从阅读器、其收藏来源或完整句子卡进入，只有服务器确认来源版本、选区和任务语义一致时才共用解析；卡片改写句、例句、译文、词条摘要各自标来源，不能当作原句。各AI功能的Agent结果照常持久保存，任务或上下文不同不按最后一个词句直接复用整个结果；只有已提交、来源/目的完整的结构化结果才可纳入对应索引。

## 4. 命中规则与版本

区分两个键，防止升级模型或Prompt后把已有结果当作丢失：

- **查阅键**：实例/owner/client作用域 + 带类型的来源身份 + 任务种类/手动查询auto模式 + 原文语言/说明语言 + 详细程度/用户明确的解释目的 + ContextPlan的实际语境身份。用于找“这里、这个上下文以前已解析的结果”，不包含Key、访问Token或当前默认模型。auto请求不能用事后推断类型充当前置查找条件；类型随已提交结果返回。
- **严格生成键**：上述语义输入及其规范化协议 + 实际选区/上下文/其他依赖摘要 + provider/model或可用修订标识 + 全部有效生成参数 + Prompt/上下文构造/输出schema版本。用于生成请求合并、精确匹配和可复现的配置记录；程序统一序列化/摘要，不能相信客户端自报hash。

来源身份是带标签联合，不能以空material_id/spans代替所有无材料输入：材料使用library/material_id/不可变版本/精确spans；收藏、生成卡片等使用各自受控资源ID、不可变内容版本及选区；手工输入使用服务器计算的全文、用户显式上下文与规范化协议版本摘要，并保留“无材料出处”标记。规范化保留语义差异，不折叠大小写、标点或有意义空白。只有经服务器验证与原句完全等价的资源才可映射到同一材料身份；否则各自查询与授权。无材料来源不写书内索引，也不由模型编造原书绑定；同样完整保存并支持重新输入相同内容时复用。

ContextPlan按应用稳定估算器确定有序依赖范围，与实际模型发送的ContextSnapshot分别记录，详见[上下文契约](../contracts/query-context.md#4-类型化契约与缓存身份)。预算数值增加但取到的原文完全相同仍命中；原文范围/显式上下文/附件版本变化则建立不同查阅键。严格生成键包含真正发给模型的上下文、全部目标及适配后的参数；查阅命中保留原结果的实际裁剪信息，不因默认模型容量或tokenizer变化重新调用。旧键schema结果以历史身份展示，只有显式验证全部输入等价才映射，不能简单删除旧缓存重做。

查阅已有结果时显示其实际模型、配置与生成时间。当前默认模型/Prompt更新不触发重新调用供应商；返回已有可渲染结果，并明确配置差异，用户选择“用当前配置重新解析”才开始新run。用户改说明语言/详细程度/解释目的属于不同查阅请求，旧结果可作为标明差异的历史选项，不能宣称满足新要求。原文版本/上下文不同也不自动冒充当前结果。

重新解析在不含模型/Prompt的LearningLookupState上分配新lookup_generation并记录所选严格生成键与run。旧有效结果在新结果完整提交前继续可读，新run失败保留旧结果。发布当前结果须同时匹配lookup_generation、所选严格键、active_run_id及执行fence；仅自己GenerationSlot有效不足以更新书内当前绑定。模型A先开始、后来用户选B、B先完成时，A迟到只保存其历史/封存结果，不能覆盖B；即使B失败，也保留此前已提交有效版，不自动把仍在途的A设为新选择。

同配置的普通重复点击合并到当前run；显式重新生成则用expected_lookup_revision取得新代次，旧同键run在退出有效占用前不能启动第二个有效生成，先取消/等待并明确在途模型用量。不同严格键可有在途调用，最终查阅指针仍只由同一LookupState控制。每次成功新版保留自己的结果，不覆盖旧内容。运行SDK升级不影响历史结构化结果读取；schema兼容转换由确定性代码完成，不能为显示旧结果再调模型，无法转换时明确为历史格式而非缓存未命中。

材料/OCR重解析按出处协议生成新版本，旧解析继续绑定旧来源。只有源映射唯一、选区/上下文及相关内容角色等全部依赖等价时，程序才可显式建立新版本绑定并复用结果；仅同文/同lemma或同书名不足。语言标注升级不改旧句子ID含义；以span/真实文本依赖检查，而不是把新sentence_id套到旧解析。

## 5. TTS保存与复用

所有入口先由[模型适配器](tts-adapters.md)展开`ResolvedSynthesisSpec`再算键。键schema加入精确模型/API家族、adapter输入契约版本及真正影响音频的默认参数；适配器不能在算键后改变文本/声音。播放器所需派生容器按原资产摘要+转码版本另存对象引用，确定性转码不重新合成；若用户明确改变的是供应商输出/采样配置，则属于新合成输入，不能当成本机格式偏好。

每个成功合成的完整片段必须保存原始可播放音频及manifest，不能只存会过期的供应商URL、音频URL签名或文字。服务端先持久化/校验对象，再发布ready；客户端完整下载并校验长度/校验和后才标为本机可用，Range片段或断开的临时文件不算完整缓存。

私有合成键由owner/library + 精确合成文本/文本协议 + 语言/读音控制 + provider/model/声音 + 实际传入的上下文、风格/合成语速等参数 + Prompt/分段/输出格式与采样配置组成；试卷听力还固定ScriptVersion、segment顺序/说话人及SynthesisSpec版本。**播放器倍速、页面入口、Key版本和媒体签名URL不进入合成键。** 同一内容从阅读器、收藏或卡片朗读，在全部合成输入等价且来源获权时复用本人音频；标准收藏词音走下述全局键，其他私有音频或结果索引仍不跨用户共享。

声音、语言或供应商合成参数改变时查找对应版本；缺失则显示生成动作，不能把旧声音当新声音。旧音频仍可明确选择播放；配置变化不自动销毁/重合成历史版本。Key轮换/删除不失效已有音频，供应商调用阶段才检查当前Key；URL过期只重新鉴权签发，下载失败只重试传输。

按稳定句子/有界短段组成播放清单，不把整章作为唯一缓存单位。每段保存准确文本范围和分段方案；只有独立音频或经过验证的真实时间映射才能切出其中一句复用，不能凭字数估时把多句音频算作每句均已缓存。供应商需要相邻句维持语调时，相邻上下文必须进键；相同句子置于不同合成上下文可能需要不同音频，界面准确展示可复用范围。

DESIGN18：小说单句与连续朗读共用稳定句子范围和同一合成配置展开方式，连续入口/临时词气泡/选择颜色/本机播放偏移不形成新缓存键。相邻上下文若参与合成，两个入口按同一规则取得上下文并进键；不为“连续”另造整章音频。

用户显式章节准备可生成该章所选音频，受[章节批次](../contracts/novel-preparation.md)的冻结范围与有限并发约束，独立于播放器的2句预取窗口；没有提交章节准备时，当前/有限后续片段预取遵守已有TTS授权与上限。连续队列绑定已确认当前章范围；推荐首版最多提前2句（运行上限可收紧），只有明确生成并连续朗读才允许窗口内新合成。长按查词、播放短音频或手动暂停均停止扩张窗口，未发出的预取意图不继续启动；已发出的有权结果可正常保存，但不能自动恢复播放。仅播放缓存遇缺失时停下提示，不靠预取绕过生成授权。停止播放/关闭页面只停止消费者和未开始的预取意图，不等于删除已生成音频；显式取消共享Job按本人job.cancel规则执行，并提示影响其他正在等待该Job的客户端。断网只能播完整本机片段，不补发模型请求。

试卷听力只对人工确认的脚本/题目绑定生成，生成成功后以ExamListeningAudioBinding固定私有AudioAsset/Manifest和segment映射。相同本人、ScriptVersion与SynthesisSpec命中服务端持久结果时不再调用供应商；改稿、换声音/模型或改变合成参数建立新绑定，旧场次仍使用原冻结资产。该音频绝不进入global_word；开考、刷新、倍速、清本机/Redis或签名URL过期都先回查持久成品，不能隐式重合成。有限播放次数只允许通过场次PlayAttempt领取媒体，不能把这份持久合成缓存暴露为通用speech下载或完整本机离线缓存；active/终态和续播以考试契约为准。未确认脚本、答案/rubric来源或旧generation即使命中相同文本也不得绑定到当前试卷。

### 5.1 收藏库标准单词发音的全局缓存

**已确认：标准单词独立发音跨用户共享，不按书或用户重复生成。** 这里的“相同”指同语种、同词形和读音变体，以及相同实际声音/合成配置；不同释义如果读音相同可以共用。拼写相同不一定读音相同，例如read的现在时与过去时读音不同，参见 [Oxford词条](https://www.oxfordlearnersdictionaries.com/us/definition/english/read_1)。TTS的声音、口音和语速也影响音频，能力以 [Gemini官方说明](https://ai.google.dev/gemini-api/docs/speech-generation) 及所选适配器实测为准。

| 维度 | 全局词音约定 |
| --- | --- |

DBDESIGN4补齐[共享成品与请求字段](database-learning.md#65-global_word_audiosglobal_word_lookup_statesglobal_word_generation_slots)：GlobalWordAudio同表内以synthesized/derived区分合成根与确定性格式派生，一根多派生，各自保存完整对象/校验信息。个人选用及目录当前指针只绑定合成根，派生格式不推进合成generation；媒体读取额外验证派生属于该根。派生键取源字节摘要、转码版本及有效输出spec，唯一成品/活动容量预留合并并发，损坏按确定性恢复处理，不新增供应商调用。共享容量登记源及派生字节，GC保护根、派生、在途预留与个人引用；原音频仍有合法引用时，不因本机清理或格式闲置按TTL删服务端成果。

合成根保存发布时的实际合成出处，包含请求规格、适配器/API版本及可得的实际供应商路由/模型修订；未知明确unknown/NULL，不用目录假定值填充，白名单排除个人身份/凭据/Job和原始供应商响应。派生追溯根出处与自己的转码spec；公共成品独立于贡献者私人attempt或账号生命周期，profile升级不改写旧成品。

操作与模型用量：先检查本人collection.read、speech.play、条目版本及业务状态，服务器确定标准词条/读音/profile，再只读查全局ready结果。命中直接播放，无需本人的生成权限或Key；命中的是共享产物，不是他人凭据。歧义读音无可靠选择时先选读音，不随机选首条。词形/读音变更推进本人条目/播放代次，迟到的旧选择不能应用。只读resolve不写学习事实；个人选用引用按既有授权写操作保存，不修改公共资产。

已有填充在途时，resolve可返回绑定本人scope的等待引用，无需Key即可等候现成产物；只返回共享可用状态，不能订阅生产者的私人SSE。新生成实际要占用slot时才校验当前Key/上限。标准profile指定的供应商与本人配置不兼容时明确配置Key或选择另一个已发布profile，不能静默换供应商/声音。

resolve的等待描述是只读投影，不因此插入个人请求；持久speech_requests由既有有权写动作建立。请求冻结词条、profile版本、strict键、源learning_revision/选择代次及等待slot/generation；global_word分支的request_generation等于本次个人selection_generation，重复点击复用。直接ready命中冻结根audio的generation；missing不自动订阅未来任意生成。改选或明确等候新执行代次创建新请求，不能改旧请求身份。回调只绑定冻结执行的成品，更新当前收藏还须匹配当前学习版本及选择代次；旧声音迟到最多完成有权历史请求，不覆盖新选择。取消/失权不复活，笔记修改不使相同词音选择失效。

全局缺失时用户明确选择生成，说明使用本人Key、实际配置和模型用量，并将纯标准词音留作共享。服务端检查speech.generate、当前本人Key/上限和共享存储配额，以PG全局严格键的唯一约束/租约/fence占用一个生产者；其Job/Outbox/AiRun/ExternalCall、取消和模型用量记录始终属于实际发起人，工作阶段继续检查该用户与来源权限，不设借任意Key的系统生产者。其他用户取得各自的等待/播放引用，仅观察共享结果状态，不接收生产者job_id/owner、Key、模型用量或私人错误。关闭一个等待者只结束其等待，不能调用他人的job.cancel。

生产者取消、撤权、失败或unknown时，已有就绪版本保留，等待者收到不含私人细节的未就绪状态；不得自动换用等候者或生产者的Key续跑。后续生成必须由有Key/权限的用户重新明确发起，确认原执行已退出有效占用或按unknown处置后才取得新代次，不将超时直接当安全重试。公共目录的有效指针按共同查阅身份分配代次，跨profile修订的旧结果只留历史，不能覆盖新选用版本。同一严格键的ready不由普通用户强制替换；明确选择已发布新profile修订可生成对应新资产，个人选择仍独立于目录指针。

发布由受控Worker校验输入来自公共目录、音频格式/范围、有效租约/代次及发起人的当前资格，保存完整对象后事务发布。可解码不能证明发音正确，标准profile与多读音必须有真实音频样本验收；发现问题由固定目录维护流程隔离错误版本/修复指针，普通用户反馈不直接改所有人的音频。维护仅处理公共目录和不发起供应商调用恢复，不读取个人内容或用个人Key重新生成。

ready后的公共目录引用独立于贡献者账号或原收藏。删除某人的账号/收藏只清其请求、引用和使用记录，不删除公共词音；共享字节计实例目录容量一次，不对每位使用者重复计算音频容量，最初模型用量仍只记实际发起人。有效公共目录引用期间不按TTL/LRU回收；撤下/损坏的资产通过同一目录父锁、私有选用引用和在途发布检查后处理。目录配额不足在新模型调用前阻断，不清掉成功词音腾空间。

全局共享不新增匿名媒体库：沿既有speech接口返回明确asset_kind，读媒体/签名时同时携带并验证当前本人收藏来源、版本、已选读音/profile和共享资产匹配关系；只知道公共asset_id/hash不能借此查别人的收藏、使用者列表或任务。API不返回贡献者/首次用户生成时间/引用人数，公网CDN仍不缓存带会话响应。本机副本、离线许可、下载和埋点继续按账号隔离，换账号不得沿用前账号的播放授权。

## 6. 读取、并发与故障流程

1. 客户端先校验账号作用域。在线先取得当前会话/动作/源状态授权，再按artifact版本使用内存或本机副本；不能用长时间有效的旧权限快照直接显示新受限内容。离线按第7节的有限租期。
2. 只读resolve在当前权限/来源/业务状态下查索引及Redis/PG，返回ready结果/运行中引用/缺失原因与历史配置差异。批量查当前可见范围设置条目上限，每项检查作用域，不能用书级接口枚举无权考试解析。GET和只读POST resolve绝不创建模型任务。
3. 用户选择解释/生成或明确重解析后，服务端计算查阅键/严格生成键，在PG事务内按固定顺序取得LookupState/GenerationSlot并创建AiRun/Job/Outbox，登记查阅代次与选用run。相同严格键当前执行代次只保留一个活动生成，多幂等键/设备普通点击也合并；不同配置的迟到结果由LookupState再次拦截。Redis锁只作加速，过期/重启不能放行第二个有效发布者。不能在数据库事务内等待供应商。
4. 完整结果通过schema/来源/业务校验后，先保存必要对象，再事务写结果/历史源绑定与阶段结果；仅通过查阅代次/选用run校验才更新书内当前索引和有效指针，过期结果只进入有权限的历史。提交后才广播对应状态，流式半句、失败、拒绝及unknown都不能作为完整解释命中。TTS播放请求/manifest也绑定自身的配置与请求代次，不把迟到的另一声音结果覆盖当前播放选择。
5. 数据库/对象写入失败时保留已返回产物的受控恢复记录/临时对象并只重试落盘；界面显示未完成保存，不能显示缓存成功后马上丢失。进程崩溃造成响应不可恢复按unknown规则处理，不能保证供应商恰好只执行一次，也不能把存储失败变成无提示新调用。
6. Redis miss、清理本机、浏览器回收、换设备都先回查服务端持久结果。服务端确认音频对象丢失/损坏时标broken，保留记录与诊断，修复/恢复优先；任何重新模型调用必须明确发起，禁止“缓存未命中”直接无限合成。

失败状态只做有界抑制重复请求，不作为长期语义缓存；短期负缓存不得掩盖新提交结果，发布时更新/失效并携带结果版本。身份/权限拒绝与网络不可达区分，明确拒绝不能退回本机旧结果。每个读取、提交、绑定、签名和Worker仍执行 [数据与任务](data-jobs.md) 的归属/删除代次检查。

## 7. 本机、容量与删除

本机自动保存已读取的完整解释/已下载音频，解释与音频独立配额。内存、本机及Redis可以按容量淘汰副本；PG/MinIO中仍有合法业务引用的成功结果不按LRU或短TTL删除。具体本机容量随三端样本与设备约束定版，不把某个Web配额当所有设备保证。当前正在使用/写入的文件按本机协调规则处理，临时文件原子发布，磁盘满明确显示仅服务端已保存。

已有解释作为只读学习内容纳入现有离线租期：离线展示同时需要来源read与ai.explain快照许可，音频需要来源read与speech.play；期限取会话、动作与源租期的最短值。离线不能生成新解释/音频、写收藏/笔记/学习记录或看受限考试答案；管理端保持在线。上线、重连先鉴权，换账号/受众/实例清掉旧副本和迟到响应。本期包含DESIGN20显式所选章节的提前下载与缺失重试；不扩展固定保留、全书离线包或离线写入同步。

| 操作/变化 | 已保存结果如何处理 |
| --- | --- |
| 清除此账号本机缓存 | 只删除设备副本，后续从服务器取回，不产生新模型费；按书/类别清理等细分入口仍按设置模块留在P1 |
| Redis过期、应用重启、退出或换设备 | 结果与源绑定仍在持久层，当前授权成立后读取 |
| Key删除、默认模型/Prompt升级 | 旧结果保留并显示实际来源配置；不批量刷新/重生成 |
| 改声音/说明语言/用途 | 独立匹配对应配置，旧版可作为有差异的历史结果，不谎报新配置命中 |
| 原书删除 | 先tombstone阻止读取/新增绑定/迟到发布；移除仅属于原书的引用，按公共宽限和父行锁复核回收；独立收藏/历史版本确需的合法引用按其权限保留，仅返回其获准快照，不借缓存恢复已失权原书全文/上下文 |
| 某个查询记录/内部Agent会话删除 | 不级联删除已经作为书内解释/独立收藏持久保存的结果；仅查询/运行上下文自身内容按其生命周期处理 |

服务端配额在模型调用前按受控输出/音频上限预留，并按实际落盘调整或释放；超容量暂停新生成，提示原因，不能先模型调用后因为普通LRU删掉旧解释。已返回结果的存储失败执行第6节恢复，不谎报保存成功。服务端按真实对象/引用核算容量；跨书复用一个同用户音频对象不能重复算物理字节，删除一处引用不能删除另一处正在使用的对象。GC把结果版本、来源绑定、有效业务引用及在途提交全部纳入权威检查，不仅看过期引用计数。

## 8. 接口、可观测性与验收

API目录见 [公共契约](../contracts/api.md)：解释增加只读resolve和按材料分页的已查索引，保留既有生成/读取结果接口；普通音频沿用speech/resolve、requests、assets/manifest/media，试卷听力通过exam专用生成/绑定入口调用同一SpeechService并按题面/隐藏稿投影返回。前端用artifact_id/version、match_kind、storage_state等类型化信息区分同配置命中、历史版本、生成中、服务端已保存、本机已下载和不可用；字段在业务schema落地，不把缓存细节暴露成必须理解的技术流程。

## 9. 统一读写流程与配置矩阵

~~~mermaid
flowchart TD
    A[查询或朗读动作] --> B[验证账号 来源及当前动作]
    B --> C[构造语境查阅键或展开合成规格]
    C --> D{内存或本机完整副本}
    D -->|有效权限租期及匹配版本| E[展示或播放]
    D -->|缺失或需在线确认| F[服务端授权及当前PG指针]
    F --> G{Redis副本或PG成品}
    G -->|有完整成品| H[下载校验并补本机副本]
    H --> E
    G -->|无成品| I[返回缺失或在途状态]
    I --> J[显式生成动作]
    J --> K[PG占用及Job Outbox 容量预留]
    K --> L[模型适配器及真实attempt]
    L --> M[完整校验与持久发布]
    M --> H
~~~

步骤C的查阅不持有解密Key。普通“查询”点击可以同时表达resolve及未命中时生成的意图，服务仍先resolve；进入页面、点已准备句、刷新/重新下载仅表达读取。朗读已有音频直接播放，缺失显示生成按钮或沿已有明确连续/章节授权执行。旧结果存在时“用当前配置重新解析/生成”单独明确，不因设置保存、恢复连接或负缓存过期自动发起。

| 对象/入口 | 权威保存与共享范围 | 命中身份重点 |
| --- | --- | --- |
| 手动文字/图文查询 | 本人完整卡片/Explanation及来源绑定，未收藏也保存 | 原输入、附件版本、上下文计划、目标语/说明语/详细度；图像OCR结果不是另一次相似图片的替代 |
| 小说/教材/生成卡解释 | 本人不可变成品，章准备共用逐句记录 | 受控来源版本/字段/目标、实际上下文与任务目的；相同词不同语境不误用 |
| 收藏标准单词喇叭 | 合资格时global_word；个人关系独立 | 公共词条/读音变体/语种/标准声音profile，绝不带私人上下文 |
| 查询单词发音、自定义词、短语 | 默认本人私有音频 | 实际词形/读音/语言/完整声音规格；未收藏不能凭“像常用词”绕过共享目录资格 |
| 例句、译文、AI解释、普通题与已提交复盘朗读 | 本人私有音频，同输入跨合法入口复用 | 只读所选文本，必要发音上下文和适配参数入键；来源授权逐次验证 |
| 小说单句、连续与章准备 | 本人逐句/有界短段资产及manifest | 三种入口采用同一合成上下文规则；队列位置、预取窗口及章节批次ID不进合成键 |
| 试卷听力 | 本人冻结脚本音频，场次专属交付 | ScriptVersion/SynthesisSpec/说话人/分段；限次播放账本在线执行，不进入通用离线音频 |

同用户等价TTS输入可跨入口复用资产，但来源绑定各自存在且新绑定服务事务验证；不能让已失权来源借另一缓存ID读取其上下文。多音词必须记录已确认读音/规范发音输入，相同拼写不是充分条件。查询解释的前后文用于消歧不意味着所有这些文字都必须发送给TTS或朗读出来。

| 变化/故障 | 必须行为 |
| --- | --- |
| 预算增大、实际上下文不变 | 命中同一结果，展示原生成记录与当前请求预算；不记录新模型用量 |
| 上下文范围/内容、说明语言、目的改变 | 形成不同语境查阅；旧结果明确标差异，不冒充当前匹配 |
| 默认模型/Prompt/Key更新 | 历史结果可读，不隐式重生成；新生成按严格键区分 |
| 声音/读音/有效合成参数改变 | 匹配新规格，旧版保留；无新资产时明确生成 |
| 播放倍速、签名过期、本机格式转换 | 不调用TTS，分别改变播放、重签传输、生成确定性派生对象 |
| Redis/local miss或下载损坏 | 回源PG/对象存储或重传；不能跳过持久层直接调模型 |
| 输出中断、空音频、格式错误 | 不发布ready，不进入成功缓存；完整响应在手时只修复发布，unknown先对账 |
| 并发点击/Worker重投/Redis锁丢失 | PG唯一键、lookup代次和slot fence决定有效执行/发布；不同业务幂等键也须合并同严格输入 |
| 撤权、换账号、原文删除 | 当前授权优先，清本机范围与迟到响应；可保留获权独立收藏快照，不能恢复原材料全文 |

TTL唯一值见[Redis目录](redis-design.md#2-键目录与-ttl)：结果副本30分钟、查阅指针10分钟、短缺失3秒、协调15秒均为推荐运行初值，非结果保留期。上下文正文随不可变结果/运行快照持久保存，不为每次取文增设一套Redis长文库。缓存payload超上限直接绕过Redis回源；可变指针按PG版本读取，Outbox只加速失效。

本机文本/音频分开设置容量，推荐原型初值100MB/500MB；它们只限制可淘汰副本，按实例/账号/设备存储，不写user_extensions。完整下载校验后才计入已缓存，读取更新本机last_access，淘汰时保护当前播放/打开资源；空间不足可只在线使用并标明未下载。清本机不删除PG/MinIO，用户端不提供“清服务器成果”通用按钮。退出/租期失效不能凭本机命中继续读私人材料。

供应商Prompt缓存是另一项可选传输优化：仅供应商文档及本人配置支持时使用，不作为应用结果命中依据。缓存句柄按owner/credential/provider/model及内容协议分区，过期重新发送合法输入，不丢业务结果；仍创建真实attempt并按供应商报告记录cache_read/write。首版不承诺主动创建供应商缓存资源或节省比例。

新增验收LC-12：遍历上表全部朗读入口及手动查询，清本机/Redis、换Key/倍速/URL后供应商计数不增加；语境/声音变化正确隔离，未知结果不命中。与QCTX-01～05、TTSA-01～05及既有LC-01～11按来源分期验收：B2a完成设置、阶段2完成源取文；阶段3验证独立图文查询、材料选区、全部四类卡片/解释、收藏词音、章节与听力准备；阶段4补习题/诊断、阶段5补交卷复盘绑定与权限。LC-13随各阶段的新文字成品增量验证；所有已确认入口覆盖后才可关闭完整缓存验收，HTML计数只是演示。

## 10. 源提取、NLP与AI成品的完整链路

DESIGN23把[文件提取/原书ruby](../contracts/source-extraction.md)及[全应用NLP](text-analysis.md)纳入上述四层方案。以下都是已提交业务成品或其副本，不能仅因页面离开、Redis过期或用户未收藏而丢失。

| 成品 | 持久位置 | 缺失/失败时的恢复 |
| --- | --- | --- |
| 原文件、受控页图 | FileObject/MinIO及来源资产引用 | 重新下载既有对象；不能无授权重新取外链或改源 |
| 完整视觉OCR候选 | 私有FileObject JSON对象 + JobStage.result_refs | 业务发布失败复用已保存识别稿/原书ruby候选；仅未成功阶段按原授权/unknown规则恢复 |
| 已发布正文与原书ruby | MaterialRevision/ContentBlock及presentation_payload | 按源版本读取；原书注音校正建新源版本，不靠NLP覆盖 |
| 基础NLP单元/句子/token/ruby | text_analysis_versions/units/sentences，词序列为unit JSONB | 本机/Redis miss回PG；真正未完成仅恢复确定性NLP任务，不重识别或重调AI |
| AI解释及卡片 | Explanation/Card完整结构化载荷、上下文/配置及source bindings | 保留成功结果；其内部文本NLP失败只修复标注 |
| 完整音频 | AudioAsset/Manifest及MinIO | 只修复下载/发布；换模型或有效读音时明确匹配新规格 |

NLP单元随文字按需下载，计入现有本机文本容量，不再增加用户必须理解的一套缓存开关。R19仅为有界热点副本，所有可见范围与来源动作都在返回前验证；考试隐藏答案/稿件的标注与统计也不能下发。本机没有相应完整标注时提供准备状态/手动范围，不能因为要做到长按即时而偷偷调用视觉/文本模型。

NLP版本升级不直接改变AI/TTS键：以确定的原文目标/ContextPlan和实际ResolvedSynthesisSpec判断语义是否变化。单纯token边界变化而目标、上下文、读音均相同，可复用既有解释/音频；读音变化可能只影响TTS，目标范围变化可能影响查询。原书注音与NLP读音均保留各自来源，实际用作发音提示时才加入合成语义输入。

GC从业务根、独立收藏快照、冻结考试版本和在途Job追踪到标注/候选/音频；仍有合法引用不按TTL/LRU删服务端成果，无引用旧分析允许受控回收。原书删除不能借NLP快照继续读取原书，独立收藏使用自己的有限文本和权限。LC-13与NLP-04～07联动验证：清本机/Redis只回源、NLP失败不重复AI、格式/OCR/ruby/NLP多版本依赖准确、隐藏内容与跨账号隔离。
