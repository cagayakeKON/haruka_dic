# 现有客户端缓存缺陷修复

后续说明：本页对应原13项故障；共享存储代次引出的文本清理、音频收尾及正文补存问题另见[后续修复记录](2026-09-27-cache-audio-text-recovery.md)，不把前一轮局部通过扩展为未审路径的保证。

范围：阶段1现有缓存基础的小阶段修复，承接[完整审查与故障复现](2026-09-27-cache-comprehensive-review.md)。用户明确要求“修完现有缓存全部缺陷，正式业务另做”；不新增正式 validate/grant 服务、正文与音频业务页面，也不将普通超时或5xx当作已证明断网。GPT-6-Sol负责实现，主Agent负责独立review和串行运行验证。按用户要求不提交、不推送。

## 改动与审查

- 不可用或许可撤销先建立资源/精确版本拒绝标记；磁盘撤销失败不能重新恢复旧许可。明确的新许可成功落盘才能解除对应版本的拒绝，重复撤销会清除此前重新授权的例外。旧账号请求的迟到401/403不能封锁新账号。
- 清理pending及普通存储写失败保留服务端已确认的在线正文，并标记本机未就绪；账号、存储、依赖、发布和同版本正文冲突仍拒绝。native损坏索引保留原文件并使用内存；未来schema经Drift remote包装后仍要求更新应用。
- 精确条目读取核对版本与键；head和snapshot使用相同的完整依赖集合。广播将资源标签归为公开类别，不传播资源ID；内存正文退出后回收相应空闲元数据，安全拒绝信息不得按普通LRU丢弃。
- 音频逐块复核授权，并在授权事件发生时取消暂停中的消费者；删除失败保留deleting记录和字节占用，恢复发现的孤儿重新记账。native字节锁增加同进程互斥并保留稳定锁文件；浏览器实际配额错误允许一次有界淘汰和重试，淘汰在发布锁外执行。
- 查询卡快速离开再返回会排队新复验，旧可见周期不能发布或重新取得展示pin。设置只在可见前台周期复验，返页/恢复时立即复验；慢请求不会被定时器不断取消，表单草稿保持挂载。PreviewApp释放自己创建的查询仓储。

主Agent第一轮集中审查后，定点修订了撤销后重新授权例外、pending与真实CAS冲突的顺序、音频等待者计数和锁内淘汰、授权流取消、查询可见周期及设置慢请求。第二轮只复核这些差异和运行失败，不重新审查未改动的整个项目。

## 最终13项核对

| 项 | 当前结论 | 修复边界 |
| --- | --- | --- |
| 1 撤销后离线恢复旧内容 | 原复现路径已修复 | 正常写入删除磁盘许可；写失败时本运行先拒绝逻辑资源/精确版本，不能由旧磁盘许可恢复。没有把内存拒绝标记称为持久tombstone；重启没有可信时间锚时仍拒绝离线读取。 |
| 2 旧账号401/403封锁新账号 | 已修复 | 拒绝响应先核对捕获的账号、存储和读取代次及取消状态。 |
| 3 授权撤销不停音频流 | 已修复 | 分块复核与授权事件取消同时生效，暂停消费者也释放读锁。 |
| 4 保存失败连在线正文也丢失 | 已修复普通存储故障 | 清理pending、配额及普通写库失败返回在线正文和`localReady=false`；真实代次、版本、同版本正文冲突仍拒绝。 |
| 5 删除失败丢配额账 | 已修复 | 保留deleting操作、实际字节占用及待清理状态，孤儿恢复重新记账。 |
| 6 远程包装的未来schema降内存 | 已修复 | 有界解包Drift远程异常并要求升级，不修改原索引。 |
| 7 精确键和版本不一致命中 | 已修复 | 读取核对版本派生精确键，不一致按损坏处理。 |
| 8 损坏原生索引阻断在线读取 | 已修复 | 保留原文件并使用内存后端；writer冲突与未来schema不走此降级。 |
| 9 同进程音频读删不互斥 | 实现及低层测试已修复 | 原生文件锁外增加进程内读写锁；没有Android真机运行结论。 |
| 10 浏览器真实配额异常不淘汰 | 实现及故障注入已修复 | 识别`QuotaExceededError`，发布锁外有界淘汰并仅重试一次；未实测填满物理磁盘。 |
| 11 设置周期、查询快速返页漏复验 | 已修复 | 设置前台30秒复验，慢请求不被反复取消；查询可见周期和排队复验分开。 |
| 12 预览壳不释放自建仓储 | 已修复 | 仅释放自己创建的仓储，外部注入仍由其所有者管理。 |
| 13 空闲元数据随历史增长 | 已修复 | 正文退出、读取结束、pin释放时回收闲置元数据；安全拒绝集合有界且溢出关闭离线，活跃读取/pin所需状态保留。 |

正式业务离线闭环、发布环境的跨标签升级/部署配置和Android原生音频运行不在本次完成声明内；Windows宿主不作原生实测。
