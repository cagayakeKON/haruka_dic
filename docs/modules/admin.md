# 管理后台操作流程

PLAN2范围补充：本页closed/open、默认关闭和“不提供审批/人工恢复”的限制描述B1最小管理合同，保持不变；B2b补齐原型审批注册与人工恢复策略的真实管理操作、用户端流程及安全交付，见[账号分界](accounts.md)。分别冻结操作权限/授予边界、expected_revision/策略快照、审批决定/身份核验/一次性挑战交付/撤销/审计及失败用例，不允许一个策略开关伪装整个能力完成，不自动改变当前部署策略。

状态：设计基线 v0.1。身份治理的管理操作已有实现和切片复核，2026-09-30 正式 Web/Android 实操、集中修复与独立定点复核已完成，B2b当期范围验收通过，见[实现记录](../delivery/reviews/2026-09-29-identity-governance-implementation.md)。任务、用量和诊断查询仍未开放。管理端为 Flutter Web，权限规则由 [RBAC](../architecture/authorization.md) 与 [权限目录](../contracts/permissions.md) 定义；本篇负责页面操作与失败处理。

## 1. 范围、入口与权限

/admin/login独立登录后取得admin快照，再渲染有权菜单；默认首页是有权的运维概览，否则首个可访问页或空状态。导航建议：概览、用户、角色权限、菜单、注册策略、运行限制与模型、资源任务、审计诊断。列表统一服务端分页/筛选/排序，详情与操作都独立鉴权。

| 模块 | 首版能力 | 边界 |
| --- | --- | --- |
| 运维概览 | 用户/存储/任务/AI 用量与失败摘要，受权限控制的管理首页 | 只呈现授权的聚合或运维字段 |
| 用户管理 | 查询账号、创建/启停账号、分配角色、查看登录状态、撤销指定/全部会话 | 当前审批模式支持批准/拒绝；创建/改角色/禁用/撤销分别授权；不能读取密码、个人Key、出生年份/性别、语言档案、头像原图或私人偏好 |
| 角色与权限 | 自定义角色、多角色分配、角色继承、授权/拒绝矩阵、影响预览、有效权限查询 | 权限代码由后端注册；编辑角色权限不等于可新增任意可执行接口 |
| 两端菜单 | 分别维护用户端/管理端的菜单分组、标题、顺序、显示开关及所需权限 | 路由/组件键来自发布版本允许清单，不能配置任意代码或外部脚本 |
| 登录与注册策略 | 开放/关闭注册；账号与会话治理；后续完整后台管理受限的注册默认角色 | B1默认关闭，仅有权管理者可切换；邮箱验证/邮件找回已确认，配置缺失不能开启；关闭不影响已有账号登录/验证/找回；B2b提供审批与人工恢复完整流程 |
| 运行限制与模型目录 | 配置可用功能、供应商/模型能力目录、用户/全局技术上限 | 不新增共享模型调用 Key，不读取或替用户填写个人 Key；上限不是商业套餐 |
| 资料/试卷与任务运维 | 查看所有者引用、格式、容量、解析/批改状态、失败类别；取消任务和恢复明确不触发外部模型调用的阶段 | 默认不提供他人原文、答卷、成绩正文；重试供应商调用步骤仍需原用户当前权限与授权 |
| 审计与日志 | 查询权限/账号/管理操作审计；查询经授权裁剪的 Haruka 诊断摘要 | Grafana 保持独立运维认证，不能凭菜单权限获得共享 Loki 全量访问 |

个人资料、学习语言档案、材料、答案和模型Key的既有隔离继续生效。管理角色可以获得平台运维所需的邮箱、显示名、账号状态和安全元数据范围，但不能默认读取出生年份/性别、自定义说明、头像原图、母语/目标语/水平或私人偏好，也不能通过普通用户接口指定其他user_id变成他人；管理端操作必须走单独授权的管理服务/DTO。原始私有内容查看、代登录和代用户供应商调用不作为后台默认能力。

## 2. 流程、状态与异常

### 2.1 用户与会话

| 操作 | 正常步骤 | 并发/异常与结果 |
| --- | --- | --- |
| 查询 | 有admin.user.read →允许字段筛选→分页结果→详情 | 只返回邮箱、显示名、账号/验证/锁定状态、角色/会话等管理必要摘要；不返回密码/Key、人口属性、语言档案、头像原图或材料正文 |
| 创建 | 输入邮箱/可选显示名→有role.assign时选择可授予角色→预览→提交 | 仅user.create可建无业务角色pending账号并显示待授权；带角色需额外role.assign；同事务建User/Library/一个空UserExtension（分组版本）/绑定/审计，无永久默认密码 |
| 启用/禁用 | 预览受影响登录端/任务→近期重验→提交 | 禁用事务增加epoch并审计，新请求失效；后续Job停止受限步骤，已保存数据保留 |
| 分配角色 | 查询可授予角色→查看继承/deny有效差异→提交expected_revision | 不接受前端自报可授予范围；影响自身/受保护目标/越界拒绝；两管理员修改冲突不静默覆盖 |
| 查看/撤销会话 | 只读设备/受众/时间摘要→指定会话或某端/全部撤销→确认 | 以PG撤销/epoch提交为成功点，缓存删除延迟不影响生效；操作幂等 |

管理员不在本期直接删除账号或彻底删除他人学习资料。审批/封禁/恢复不会自动获得查看其答卷、使用其Key或代登录的能力；新增此类产品需求需单独设计。

### 2.2 角色、权限与授予边界

创建角色输入唯一code、名称、描述与启用状态；编辑界面按client/admin和业务域分组，区分allow/deny/未配置，显示直接与继承来源、scope、依赖和供应商调用步骤。code建立后不随标题改名，删除/停用引用中的角色必须先预览影响并迁移或拒绝。

role.create只允许空角色；同时设置初始allow/deny/继承需要role.permission.assign与完整授予边界检查。update的标题/描述可单独授权；启停、继承、删除或移除deny如果改变有效权限，同样附加role.permission.assign，不因换了CRUD方法就跳过授权。涉及用户解绑/迁移还需user.role.assign，受保护目标检查贯穿所有路径。

编辑继承时显示方向、有效闭包、环/深度错误；disabled父角色不会继续贡献上级权限。提交前后端计算差异、受影响用户数量、登录资格改变和授予上限，客户端预览不作为授权凭据；真正提交在同事务重新验证当前操作者权限、revision及最后管理员。

受保护授权页仅对拥有admin.grant_boundary.update/admin.protected_role.manage且满足目标约束的管理员开放；委派管理员不能通过改自己已持有角色、默认注册角色、父角色或目标上限来升权。初始超级管理员由部署命令创建，角色权限种子不覆写后台人工配置。

保存冲突显示安全差异和“重新加载后再提交”，不自动合并权限增减；提交失败不更新本地“已保存”状态。成功返回新revision、audit_id和affected_count；随后刷新快照，当前管理员若失去页面权限则跳出。

### 2.3 两端菜单与显示

分别编辑用户端与管理端菜单；route_key/component_key只能从已发布清单选取，支持分组、标题、顺序、图标、显示开关和附加权限条件。拖动排序/批量修改保存为一个revision事务，防止并发覆盖。

预览按某个允许查询的目标账号计算，但不创建其会话、不展示其学习数据。页面最低权限来自代码目录，菜单只能收紧可见条件；隐藏导航仍可通过授权深链访问，关闭功能访问应使用对应服务端feature flag/权限撤销。界面用“隐藏菜单”和“停用功能访问”两个明确操作。

未知路由/旧组件版本禁止发布，空父菜单不显示；为当前用户隐藏所有入口时仍提供本人安全/退出入口。管理界面自身恢复入口不能通过一次普通菜单编辑永久锁死。

### 2.4 登录策略、运行限制、模型与功能开关

- 注册策略先显示当前/目标开关及生效对象，初始closed；B1只允许closed/open并校验通知依赖，不允许关闭邮箱验证或改成人工恢复。提交带expected_revision，记录审计并同步策略版本。关注册不影响已有账号登录、继续验证和找回；pending不因切开关激活。公共默认角色只能使用经过继承闭包验证的可公开client角色，B1开关接口不能修改默认角色。
- 可用功能使用已发布的 feature flag/能力项配置，不允许后台临时创造未知组件或接口；停用功能必须同时影响服务端执行与两端显示，不能只隐藏菜单。
- `admin.quota.*` 为兼容既有权限代码保留名称，只管理账号/全局并发、调用次数、存储和任务类别等技术上限，不代表套餐或可购买额度。不允许使用负数/溢出或高于部署硬上限；降低上限不删除已存资料，只限制后续新增；未知外部调用保留占用并提供核对状态。
- 模型目录维护provider/model与text/vision/tools/structured_output/tts能力、启停和验证记录。不能把聊天支持等同TTS支持，也不能填入共享模型调用Key。
- 配置更新使用expected_revision，后端schema/范围检查，预览影响后提交并审计。供应商实际能力不是后台表单宣称即可成立，依赖受限验证记录。

### 2.5 资料/试卷、任务与运行概览

资源页只显示owner引用、格式、容量、创建时间、准备/失败状态等允许元数据，不返回文件名中的私人文本或原始下载链接。任务页显示类型/阶段/次数/状态/安全错误码/关联ID，操作需独立admin.job.cancel/retry。

取消是发送取消意图并在执行边界生效；已经发出的供应商请求可能仍会完成。重试只允许系统标记为可重试且不触发外部模型调用的阶段，状态/租约冲突返回409；不能用管理重试重新执行已完成或结果unknown的供应商attempt。需要所有者确认时显示“等待所有者处理”，不提供模拟用户确认按钮。

运行概览显示授权的用户数量、存储、任务、AI 用量和失败摘要，由后端限定聚合计算或读取授权诊断摘要。模型用量按时间桶、供应商、模型、能力、状态聚合，至少分开input/output/cache read/cache write；缺数据显示未知/采集异常，不当作0或健康。字段聚合不包含个人身份、Key、Prompt、回复、成绩或原文，口径见[模型用量统计](../contracts/model-usage.md)。

### 2.6 审计与诊断

审计可按时间/动作/操作者/目标/结果分页查询，详情展示 revision、原因分类、request/operation ID，以及清洗后的短标量变更摘要。权限标识列表不进入该摘要。应用无编辑/删除审计按钮；首版不提供批量导出审计文件，保持用户导出范围为单词CSV。

诊断接口只允许服务端固定Haruka查询模板和时间/条数上限，DTO脱敏，不接收任意LogQL或其他项目名。Grafana入口仅在运维另行授权时可用，Haruka角色不映射成Grafana管理员。日志接收和管理前端埋点与同一个 [观测规范](../operations/observability.md) 对齐。

## 3. 前端职责

页面状态 loading/ready/empty/forbidden/error，提交状态 editing/previewing/submitting/succeeded/conflict。按钮只因动作权限显示，业务前置条件不足时禁用并给明确原因。被撤权立即清除受限页面状态，无法通过浏览器返回恢复敏感行数据。

Flutter Web 管理布局独立于学习端，复用模型/认证/权限组件，浏览器刷新、深链接、前进后退和新标签都经过守卫。管理端必须在线，不使用离线快照进行授权配置或诊断查询。

界面展示直接/继承权限、allow/deny 来源、有效范围和变化预览，表格只接收当前有权字段；读写权限分别控制筛选、详情、批量操作和提交。敏感操作展示目标、影响和近期重验，不在客户端按角色名称判断是否能提交。失败/冲突保留可恢复表单并要求重载安全差异，不自动合并授权变化。

## 4. 后端职责

管理服务独立校验当前 admin 身份、动作、目标范围、授予上限、受保护角色及业务状态。账号/角色/继承/deny/默认注册角色等会改变有效权限的路径采用统一授权事务，不能因换一个 CRUD 入口漏检；并发最后管理员保护及版本/审计规则以授权设计为准。

资源和任务服务只返回获准运维字段，不能通过 metadata 权限读取原文、答卷、成绩正文或用户 Key。任务取消由原执行边界处理；后台恢复仅限已标记可重试且不触发外部模型调用的阶段，不模拟原用户授权，也不重新执行结果unknown或已经完成的模型请求。

配额与功能配置受部署硬上限限制，模型能力需要受控验证证据；诊断服务只能运行固定 Haruka 查询模板并裁剪结果。审计与业务变更同事务，提交失败不产生半状态；Outbox 将安全摘要送统一日志平台，日志平台故障不回滚已提交授权。

## 5. 公共契约与依赖

[授权设计](../architecture/authorization.md) 是角色模板、继承、显式拒绝、授予边界、权限版本和审计事务的唯一机制说明；[权限目录](../contracts/permissions.md) 是稳定代码与动作依赖的唯一目录。[API 契约](../contracts/api.md) 维护 `/api/v1/admin` 的管理 DTO、幂等与 expected_revision，不与普通用户私有内容接口混用。

两端登录/近期重验见 [认证设计](../architecture/authentication.md) 与 [账号模块](accounts.md)，任务取消/安全恢复见 [数据与任务](../architecture/data-jobs.md)。资源、模型能力、用量和注册策略的配置约束与初始化依 [配置与运行](../operations/configuration.md)。

管理查询、登录拒绝、账号/会话/角色/菜单/策略变更、初始化及越权拒绝接入 [日志与埋点](../operations/observability.md)。记录安全状态差异、操作者/目标引用、revision、原因类别及 operation/request ID，不记录私有内容或秘密。审计本身在业务数据库持久化，Grafana 使用独立运维授权。

## 7. 待决与后续

管理端 Flutter Web 与 PyCasbin 是当前推荐实现，具体依赖和容量需要工程验证；已确认的是管理后台和完整 RBAC 的产品能力。邮箱/人工恢复等账号附加能力依 [待决清单](../decisions/pending.md)。

原始私有内容查看、代登录、代用户发起供应商调用、直接删除他人学习资料、批量审计导出均不作为本期管理默认能力。后续增加需要独立产品范围与契约，不得把“超级管理员”解释为任意旁路。

私有内容查看、代登录、代用户供应商调用、删除他人学习资料和批量审计导出没有实现。身份治理的页面和接口见实现记录；2026-09-30 正式 Web/Android 实操、集中修复与独立定点复核已完成，B2b当期范围验收通过。部署与账号恢复的实际操作验收另见交付规范。
