# 查询图片与拍照入口

日期：2026-09-24，阶段1内独立原型与文档小阶段 DESIGN10，基线 7e688da。用户确认查询图片输入、Web粘贴、Android相册添加与直接拍照。本次交付为HTML原型和设计/验收文档，正式Flutter/Python、真实上传、视觉模型和Android原生相机尚未实现。

## 交付内容

- 两端查询支持本机选图、缩略图放大/移除、纯图片或图文发送；手机输入区同时显示相册和拍照，动作至少44px且间隔8px。图片消息与当轮文字关联，后续草稿不改变旧消息。
- Web粘贴仅处理输入区的用户事件，混合内容保留文字，纯文字输入不受影响。取消/图片损坏/不支持格式或超限保留已有草稿，不静默丢弃后发送；本轮图片全部准备完成后才能发送。
- 手机拍照入口使用HTML capture请求系统采集，桌面可能打开文件选择；真实Android权限、取消/恢复和相机行为需后续实体设备证据。临时图片URL在移除/退出时释放，退出清空查询内存，过期异步回调不能带回图片。
- 原型限制4张PNG/JPEG/WebP、单张10MB/2400万像素，仅本机预览、不上传；含图消息明确未分析，不用内置纯文字答案冒充图片回答。正式私有附件、受控解码/去元数据、本人视觉模型、权限/幂等/删除/日志和QRY-06～09已写入相应正文，未冒充工程完成。

## 独立 review

作者root，独立reviewer `mobile_design_review`。第1轮代码与截图复核发现两项P2：添加按钮解码期间被禁用导致选图后失焦；退出后迟到文件头读取仍可短暂创建Blob并解码。修复为记录本次文件选择器来源，在原输入区/账号代次仍有效且焦点未移向其他控件时回焦输入；文件头await返回后、创建URL前检查账号/请求代次。

第2轮确认迟到读取保护和不抢新焦点通过，另定位选图返回有时停在原添加按钮，使“统一回到输入框”的严格断言不稳定。本轮内调整为点击选图时记录来源，文件准备后下一帧同时处理背景、原添加按钮或原文件控件的返回焦点。两端6组修订回归通过；16份文档及API用途发布/路线图同步审查无新增缺陷。最终焦点分支独立确认两端均回到输入框，两项P2关闭，无遗留缺陷；证据为 `artifacts/design10/review-round2-focus-final.json` 和 `artifacts/design10/review-round2-async-results.json`，不增加第三轮全面审查。
