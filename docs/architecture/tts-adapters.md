# 按模型注册的 TTS 适配器

状态：2026-09-25，DESIGN22设计，正式供应商调用未实现。每个允许使用的TTS模型必须有明确适配器注册与独立契约测试，不能只按Gemini/OpenRouter分成两个万能客户端。共用[Agent任务及用量入口](agent-runtime.md)、[音频缓存](learning-cache.md#5-tts保存与复用)，不通过文本Agent自由生成并猜测音频。

## 1. 注册与职责

注册身份为`provider + exact_model_id + api_family + model_contract_revision`，映射不可变`adapter_id/adapter_version`和能力清单。每个模型都要显式登记；已证明协议一致的模型可以复用传输/解码实现，但仍分别验证声音、参数、限制和输出，不能使用通配符“所有audio模型”。未适配显示不可选，下线仅停止新生成，旧音频仍可播放。

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| SpeechService | 当前权限/来源、词音共享资格、resolve、预算、Job/Outbox、生成占用、发布与媒体授权 | 不拼供应商请求或猜测音频编码 |
| ModelTtsAdapter | 能力校验、展开实际默认参数、准备读音输入、构造请求、解码流/响应、完整性判定、错误与用量映射 | 不选他人Key、不持久化业务资产、不自行循环重试或换模型 |
| ProviderTransport | 身份注入、HTTP/SDK连接、超时、受控下载/流读取 | 不把不同模型/协议当作语义等价 |
| AudioPublisher | 受限转码/封装、校验和/时长、完整对象及manifest、原子ready与派生格式 | 不因本机不支持容器再次调用TTS |

## 2. 每个模型必须声明

能力manifest包括：精确模型与API家族、语种/声音目录版本、单/多说话人、逐字朗读保证及已验证限制、读音控制、非朗读上下文支持、风格/合成语速允许值、输入字符/Token/字节上限、流式/一次性/异步方式、容器/编码/采样率/位宽/声道、真实时间戳能力、取消及供应商幂等支持、用量口径、窗口与超时上限。缺失能力是unknown或unsupported，不猜成支持。

统一输入`SynthesisInput`持有canonical_text、source refs、语言/读音提示、必要且不会读出的上下文、逐句/短段或已确认说话人映射。`resolve_spec()`将模型/声音profile/有效参数与默认值展开成冻结的`ResolvedSynthesisSpec`，含adapter/API/输入协议/分段/输出版本，随后计算严格合成键；不能先算键再由适配器悄悄补默认值。

运行接口按职责提供`validate`、`resolve_spec`、`build_request`、`decode_response_or_stream`、`validate_complete`、`map_usage`、`map_error`；不要求实现为七个独立类。返回类型区分AudioChunk、完整ValidatedAudio与不确定失败，包含实际MIME、编码、校验和、已知时长/时间映射、供应商请求ID和规范化用量。未经可靠验证的字/词时间戳为空，不按字数估算成事实。

## 3. 必须分开的调用方式

2026-09-25查阅官方文档得到以下协议区别；这只是设计依据，不是已完成接入或永久模型目录：

| 适配路径 | 需处理的区别 |
| --- | --- |
| Gemini TTS | 官方TTS与Live API用途不同；模型/接口版本决定语音配置、风格放置和音频响应结构。必须按对应版本解码并验证MIME，不能一律把返回字节当作无头PCM后再加WAV头。[Gemini官方](https://ai.google.dev/gemini-api/docs/speech-generation) |
| OpenRouter专用speech | `/api/v1/audio/speech`接收`input`文本、`model`、声音及模型支持的参数，返回原始音频字节流；声音、默认值和有效参数因模型不同。不能调用后再把JSON字段当音频。[官方TTS](https://openrouter.ai/docs/guides/overview/multimodal/tts) |
| OpenRouter聊天音频输出 | `/api/v1/chat/completions`使用modalities/audio，文档所述输出经流式`delta.audio`交付；必须分别处理音频块与文本，不能和speech字节流共用响应解析。只有经验证能按原文朗读的具体模型才进入本应用TTS允许目录。[官方音频](https://openrouter.ai/docs/guides/overview/multimodal/audio) |

请求中的不支持参数必须在调用前拒绝，不能让供应商静默忽略后界面仍宣称已生效。风格/读音指令不拼到会被逐字读出的正文中。若模型不能把前后文与朗读文本分开，则不传任意上下文，只用其已验证的读音控制；缺少必要读音能力时要求改配置。禁止为生成某一句而请求朗读整章、再用估算时间裁切。

OpenRouter也须冻结实际模型及已允许的路由约束，不启用语义不同模型/声音的自动fallback；需要新配置时由用户明确选择。供应商返回实际路由/修订可得则记入成品，未知标记unknown，不伪造固定版本。供应商升级导致契约变化时发布新适配修订并补测试；仅兼容解码修复可声明输入语义不变，保留旧资产可读。

## 4. 流式保存、失败与复用

所有路径统一为“持久attempt → 模型调用 → 受控临时对象/缓冲 → 完整校验 → 不可变音频与manifest → PG发布”。流式首包可在线临时试听，结束标志、格式、长度/帧完整性及模型特有结束条件满足后才标ready；无法验证的截断音频不能作为成功缓存。缓存对象保留完整可播放字节，不只保存易过期供应商URL。

raw PCM必须由适配器提供真实采样参数再确定性封装，已有WAV/MP3不能重复包头；格式派生按原始资产摘要+转码版本缓存，无需新供应商attempt。完整音频已收到但落盘失败只恢复发布/下载；超时且供应商结果未知进入unknown，统一恢复流程先对账，不由SDK和Worker各自重试。每次真实重试单独记录attempt与用量，未知用量为null，缓存命中无attempt。

任何私有材料TTS、查询词音、例句、AI解释与小说逐句朗读都进入同一服务。收藏中的受控标准独立单词才可进入global_word，私人上下文与读音不能泄露进公共目录；考试听力仍走冻结脚本和场次授权。10k查询上下文预算不转为10k合成输入，TTS只发送适配器声明的必要内容。

## 5. 接入门禁

| ID | 每个注册模型的必需证据 |
| --- | --- |
| TTSA-01 | 输入/有效参数和默认值快照、声音/语种/长度拒绝、不支持参数拒绝；换模型不沿用旧声音 |
| TTSA-02 | 对应协议一次性/流式/异步夹具、多块边界、base64/原始PCM/已有容器、空响应/坏帧/截断/MIME不符 |
| TTSA-03 | 单词多音、句子原文、说话人映射、指令不被朗读、真实时间戳为空/存在的正确处理 |
| TTSA-04 | 输入语义相同键稳定；声音/合成参数/上下文/适配协议变化隔离；倍速、Key、URL、派生格式不重复合成 |
| TTSA-05 | 限流/超时/unknown/取消/迟到/fence、账号隔离、用量映射与无秘密日志；重复点击只有一个有效生产者 |

常规检查用Fake传输及脱敏固定响应验证协议与缓存；允许目录的真实质量/音频跨端兼容在正式接入时按授权样本验收。原型只展示模型能力与配置联动，不持有Key或运行这些适配器。
