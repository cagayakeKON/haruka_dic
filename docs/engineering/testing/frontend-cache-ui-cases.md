# 前端缓存与界面测试用例

状态：2026-09-27，前端独立实现阶段的用例清单。范围为 Flutter `test/` 中的 unit/widget 测试及人工原型对照；本轮不编写自动 E2E。用例通过只表示该层已运行的断言成立，不表示服务端权限、Android 系统行为或跨设备同步已经验收。缓存行为依据[前端缓存机制](../../architecture/frontend-cache.md)与[校验契约](../../contracts/client-cache.md)，界面范围依据[原型清单](../../delivery/prototype-scope.md)。

## 统一夹具与执行规则

- 固定两账号 A/B、同 UUID 但不同 API 服务地址与 instance、client/admin 两受众、两次 session_ref、security_epoch 与 authz_version。测试不能通过传入 user_id 模拟已授权。
- 缓存文本包含日文、中文和 emoji，用 UTF-8 字节数检查容量；版本向量分别改变 resource、representation、artifact、NLP、binding。数据层使用真实 Drift/SQLite 内存库，网络层用可控 `Future` 和 `CancelToken` 排列响应，不调用真实供应商。
- 每个异步用例明确 `pending → mutation/clear/switch → late completion` 顺序；测试超时视为失败。成功检查显示值、来源、`serverSaved`、`localReady` 和持久副本；失败检查不展示旧私有数据、不落盘、不自动重放写入。
- widget 用例分别设置 390×844 和 1440×900 逻辑视口，并在 759/760 断点补边界检查。领域接口可用 Mockito 替身构造合法初态；仓储联动则以虚构来源适配器或 Mockito 远端替身穿过真实 `CacheCoordinator`。目标动作必须由 widget 点击/输入触发。测试中不调用服务端或系统文件选择器，系统行为另记未验证。
- 界面断言至少同时检查可见内容、可操作状态与状态变化；不能只检查某个标题存在。对话框需覆盖确认和取消；列表需覆盖有数据、无数据、无匹配、返回后状态。动画用受控时钟检查开始/结束与减少动态选项，不用无限 `pumpAndSettle`。
- `已运行` 只在本仓库对应测试实际通过后标注。尚未实现的前端或服务端协作保持 `待实现`，不能将设计用例计为通过。
