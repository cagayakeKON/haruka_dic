# 管理后台操作流程

状态：设计基线 v0.1，2026-09-22，未实现。管理端推荐 Flutter Web，权限规则由 [RBAC](../architecture/authorization.md) 与 [权限目录](../contracts/permissions.md) 定义；本篇负责页面操作与失败处理。

## 1. 管理布局与访问

/admin/login独立登录后取得admin快照，再渲染有权菜单；默认首页是有权的运维概览，否则首个可访问页或空状态。导航建议：概览、用户、角色权限、菜单、注册策略、配额模型、资源任务、审计诊断。列表统一服务端分页/筛选/排序，详情与操作都独立鉴权。

页面状态 loading/ready/empty/forbidden/error，提交状态 editing/previewing/submitting/succeeded/conflict。按钮只因动作权限显示，业务前置条件不足时禁用并给明确原因。被撤权立即清除受限页面状态，无法通过浏览器返回恢复敏感行数据。

## 2. 用户与会话

| 操作 | 正常步骤 | 并发/异常与结果 |
| --- | --- | --- |
| 查询 | 有admin.user.read →允许字段筛选→分页结果→详情 | 只返回账号管理必要字段、状态与角色摘要，不返回密码/Key/材料正文 |
| 创建 | 输入邮箱/显示名→有role.assign时选择可授予角色→预览→提交 | 仅user.create可建无业务角色pending账号并显示待授权；带角色需额外role.assign；同事务建User/Library/绑定/审计，无永久默认密码 |
| 审批 | 查看pending及前置条件→批准/拒绝并确认理由分类 | 批准不绕过邮箱条件；状态revision冲突要求重载，不能批错已禁用账号 |
| 启用/禁用 | 预览受影响登录端/任务→近期重验→提交 | 禁用事务增加epoch并审计，新请求失效；后续Job停止受限步骤，已保存数据保留 |
| 分配角色 | 查询可授予角色→查看继承/deny有效差异→提交expected_revision | 不接受前端自报可授予范围；影响自身/受保护目标/越界拒绝；两管理员修改冲突不静默覆盖 |
| 查看/撤销会话 | 只读设备/受众/时间摘要→指定会话或某端/全部撤销→确认 | 以PG撤销/epoch提交为成功点，缓存删除延迟不影响生效；操作幂等 |

管理员不在本期直接删除账号或彻底删除他人学习资料。审批/封禁/恢复不会自动获得查看其答卷、使用其Key或代登录的能力；新增此类产品需求需单独设计。

## 3. 角色、权限与授权边界

创建角色输入唯一code、名称、描述与启用状态；编辑界面按client/admin和业务域分组，区分allow/deny/未配置，显示直接与继承来源、scope、依赖和付费步骤。code建立后不随标题改名，删除/停用引用中的角色必须先预览影响并迁移或拒绝。

role.create只允许空角色；同时设置初始allow/deny/继承需要role.permission.assign与完整授予边界检查。update的标题/描述可单独授权；启停、继承、删除或移除deny如果改变有效权限，同样附加role.permission.assign，不因换了CRUD方法就跳过授权。涉及用户解绑/迁移还需user.role.assign，受保护目标检查贯穿所有路径。

编辑继承时显示方向、有效闭包、环/深度错误；disabled父角色不会继续贡献上级权限。提交前后端计算差异、受影响用户数量、登录资格改变和授予上限，客户端预览不作为授权凭据；真正提交在同事务重新验证当前操作者权限、revision及最后管理员。

受保护授权页仅对拥有admin.grant_boundary.update/admin.protected_role.manage且满足目标约束的管理员开放；委派管理员不能通过改自己已持有角色、默认注册角色、父角色或目标上限来升权。初始超级管理员由部署命令创建，角色权限种子不覆写后台人工配置。

保存冲突显示安全差异和“重新加载后再提交”，不自动合并权限增减；提交失败不更新本地“已保存”状态。成功返回新revision、audit_id和affected_count；随后刷新快照，当前管理员若失去页面权限则跳出。

## 4. 两端菜单与功能显示

分别编辑用户端与管理端菜单；route_key/component_key只能从已发布清单选取，支持分组、标题、顺序、图标、显示开关和附加权限条件。拖动排序/批量修改保存为一个revision事务，防止并发覆盖。

预览按某个允许查询的目标账号计算，但不创建其会话、不展示其学习数据。页面最低权限来自代码目录，菜单只能收紧可见条件；隐藏导航仍可通过授权深链访问，关闭功能访问应使用对应服务端feature flag/权限撤销。界面用“隐藏菜单”和“停用功能访问”两个明确操作。

未知路由/旧组件版本禁止发布，空父菜单不显示；为当前用户隐藏所有入口时仍提供本人安全/退出入口。管理界面自身恢复入口不能通过一次普通菜单编辑永久锁死。

## 5. 登录策略、配额与模型目录

- 注册策略先显示当前/目标配置及生效对象；公共默认角色只能使用经过继承闭包验证的可公开client角色。关注册不影响已有账号；改变审批/验证要求默认只作用新注册，已有pending需显式管理。
- 配额区分账号/全局并发、调用次数、存储和任务类别，不允许使用负数/溢出或高于部署硬上限。降低配额不删除已存资料或倒扣历史调用，限制后续新增；未知外部调用保留预算占用并提供核对状态。
- 模型目录维护provider/model与text/vision/tools/structured_output/tts能力、启停和验证记录。不能把聊天支持等同TTS支持，也不能填入共享付费Key。
- 配置更新使用expected_revision，后端schema/范围检查，预览影响后提交并审计。供应商实际能力/价格不是后台表单宣称即可成立，依赖受限验证记录。

## 6. 资源与任务运维

资源页只显示owner引用、格式、容量、创建时间、准备/失败状态等允许元数据，不返回文件名中的私人文本或原始下载链接。任务页显示类型/阶段/次数/状态/安全错误码/关联ID，操作需独立admin.job.cancel/retry。

取消是发送取消意图并在执行边界生效；在途外部调用可能已收费。重试只允许系统标记为可重试的非付费阶段，状态/租约冲突返回409；不能用管理重试重新触发用户已消费或unknown的收费调用。需要所有者确认时显示“等待所有者处理”，不提供模拟用户确认按钮。

运行概览由后端限定聚合计算或读取授权诊断摘要，图表缺数据需显示未知/采集异常，不当作0或健康。字段聚合不包含个人成绩/原文。

## 7. 审计与诊断

审计可按时间/动作/操作者/目标/结果分页查询，详情展示安全权限差异、revision、原因分类与request/operation ID。应用无编辑/删除审计按钮；首版不提供批量导出审计文件，保持用户导出范围为单词CSV。

诊断接口只允许服务端固定Haruka查询模板和时间/条数上限，DTO脱敏，不接收任意LogQL或其他项目名。Grafana入口仅在运维另行授权时可用，Haruka角色不映射成Grafana管理员。日志接收和管理前端埋点与同一个 [观测规范](../operations/observability.md) 对齐。

## 8. 管理验收

| ID | 期望 |
| --- | --- |
| ADM-01 | 每模块read与write可分离；按钮/字段/深链/直接API权限矩阵一致 |
| ADM-02 | 账号创建/审批/禁用/启用/角色/会话操作有独立权限、成功点和审计，失败不产生半状态 |
| ADM-03 | 越权授予、继承环、改默认角色升权、自升权及并发移除最后管理员被拒 |
| ADM-08 | 只有user.create/role.create/update不能夹带初始角色/权限/继承；启停/删除deny角色需附加assign，纯元数据修改仍可独立执行 |
| ADM-04 | 菜单预览无私人数据；配置不能降低页面权限或引入任意组件代码 |
| ADM-05 | 配额和模型更新有范围/版本检查，管理员无全局Key回退或代用户收费路径 |
| ADM-06 | 取消/安全重试状态可见，旧租约与未知付费请求不能被后台强制重跑 |
