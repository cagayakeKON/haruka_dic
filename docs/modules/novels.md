# 小说导入与阅读

状态：2026-09-25，DESIGN20确认解析模式、全书基础NLP及按章多选准备，沿用分词浮层与连续朗读；正式业务待实现设计。小说是独立业务模块；类型/格式、重新处理和版本边界见 [三类材料契约](../contracts/material-types.md)，共用上传/书库/进度写入规则见 [材料模块](materials-reading.md)，NovelManifest/Chapter/Block与独立语言分析版本见[解析数据结构](../contracts/material-structures.md#41-小说)。

## 1. 范围、入口与权限

导入时选择小说；书库小说卡打开章节阅读器。首版覆盖连续横排阅读、目录、字体/主题、选区、书签/进度和有权使用的解释/收藏/朗读；不把小说自动转成课程或试卷。P0 文件基础为 MD/EPUB，PDF/TXT/OCR 仍按产品优先级后续接入。

内容读取使用 `client.material.read`，上传/重解析/AI分析及选区动作分别采用 [权限目录](../contracts/permissions.md) 的独立动作；类型本身不增加一套角色。没有 Key 可读原文、使用本地确定性语言标注；不能借用公共或其他用户 Key。

## 2. 流程、状态与异常

导入 → 格式提取 → 小说结构与质量检查 → 发布可读版本 → 异步遍历全书逐句语言标注 → 用户选择章节及解析/朗读准备 → 就绪句子直接查看/播放。结构基线优先原目录与正文顺序；没有目录时可生成明确标记的“未分章正文”，不捏造原书章名。长文可按有界技术分片加载，技术分片不作为原书章节显示。

小说预处理专门处理段落、引号对话、章节边界、ruby/脚注和断行。保留作者段落及全半角、标点等原文；软换行与跨页断词修复必须可追溯到源范围，不能全局删空格/换行或让模型润色。目录、版权页、页眉页脚只在可验证规则下标为非正文/附属内容，不从原文件销毁；不确定片段保留并在质量页说明。PDF 获准后，缺页/阅读顺序问题另设阻断或降级，OCR 置信度不能冒充内容完整性。

章节加载失败可单章重试，解析失败不能显示整本已可读；保留可访问片段时明确 `degraded`、缺失范围与重试入口。语言标注未就绪或失败时仍能手动划选已发布原文，未准备的词形/整句快捷操作显示状态；AI 分析失败也不撤销确定性正文。无声替换正文、自动改类型或启动供应商调用步骤均禁止。

阅读中长按选句（键盘选区后显式唤出）→ 调整选区 → 工具栏按权限朗读或查询 → 完整查询结果可收藏。保存进度使用公共 revision/多端冲突规则；重解析与文字重排分别处理，文字重排不改变出处。单句朗读仅处理浮层范围；用户明确选择连续朗读时从当前句到本章末尾，逐句缓存和有限预取，章末停止。该能力不等于书库“继续阅读/最近在读”入口。

### 2.1 阅读与解析模式

阅读器只设“阅读 / 解析”开关。阅读模式保留原文及原书ruby；解析模式显示基础NLP补充的有效读音，汉字词优先标假名，纯假名和标点不重复注音；不确定项不伪装为已确认读法。逐句点击直接读取已有详细释义，不要求再长按或点查询；未准备句显示状态与同一章准备入口。全局长按分词浮层仍保留，拖选不打开面板，长按结束不能同时触发句子点击。

手机用带动效的底部句子面板，电脑用右侧解析面板；同一面板用上一句/下一句切换，不叠加相同句子弹窗；关闭后回到当前查看句，从句子面板进入章节准备后可返回原句面板。展示当前原句、译文、意群、词汇/活用和语法详解，完整结果可收藏；面板喇叭朗读原句，缺音频时同位置显示“准备朗读”。面板文字继续支持通用长按查询/朗读。切模式保留阅读位置，点击句子时暂停连续播放，关闭后手动继续；句子学习高亮与实际播放高亮分别表达。

### 2.2 章节多选准备

章节目录及当前章入口打开同一“准备章节”面板：选择一章，独立勾选“AI解析”“朗读”，默认全选，支持单项或两项，空集合不可开始。逐项显示准备及本机缓存数量；暂停、继续与重试只处理所选缺失内容，已完成句子可先使用。关闭面板可继续阅读，不自动取消已授权批次；全部所选成品与本机副本完成后分别显示对应就绪状态。具体字段、冻结范围、恢复/权限和NPREP验收唯一维护于[章节准备契约](../contracts/novel-preparation.md)。

## 3. 前端职责

`features/novels` 拥有独立 NovelReaderController、小说目录与阅读页面。紧凑布局侧重通栏正文、目录抽屉、底部选区操作；宽屏可常驻目录和解释侧栏。布局按 [Flutter规范](../engineering/flutter.md) 选择；同一小说的两个布局共用其 controller，不与课本/考试共用业务 controller。

以段落/文本块渲染，划选位置通过公共偏移转换找到语言标注范围；正文不为每个词创建常驻可交互 Widget，只有当前句子浮层按需构建可多选词气泡。解析模式按稳定句子范围提供点击目标和ruby，词的注音不是独立点击按钮。触控/鼠标长按默认选句并可拖动扩选；普通划选只作原生选择，不自动打开浮层或暂停朗读，键盘显式唤出遵循同一[全局选区交互](ai-speech.md#21-全局选区交互)；浮层保留整句喇叭及查询按钮，点词改变查询范围，完整结果可收藏；词边界可调整，不被分词器错误锁死。小说提供连续朗读入口和轻量播放器，长按/查询或短音频时暂停，关闭后手动继续。注音不混入正文索引；字号、横竖窗口与解释面板变化后用 locator 恢复位置。超长章节按块懒加载，避免一次构建整本书。

只缓存授权内容和本人音频，沿用有效权限租期、账号切换清理和离线不排队业务写入的约束。章节百分比表示阅读位置估计，不表示已掌握词汇。

## 4. 后端职责

NovelProcessingService负责公共SourceUnit/ContentBlock到NovelManifest、Chapter/ChapterBlock的编排和质量产物，NovelReadingService提供已发布的章节/内容与阅读状态。公共ContentBlock只作来源，不能直接当小说页面，也不能与课本ContentNode或ExamItem合成万能业务表。二者是同一Python工程内的职责划分，不要求新进程；格式适配器只提取源内容，不能决定小说课程结构或考试状态。

语言标注按块/语言执行，记录标注版本、词与句的源范围：英文处理缩写、小数、引号；日文处理句末符号、括号/对话、无空格分词和活用词形；混合语言段落允许局部语言标注。禁止只按空格分词或只用 `.!?` 切全书。跨块句子用 spans 引用，不复制成另一份不可追溯正文；切句不能把脚注文本插入主句。

句子、分词 token、模型上下文和 TTS 合成片段分别建模：模型上下文可含相邻句；连续朗读以每句独立音频为基线，超长句可拆有界短段；多句音频仅在有真实句边界时作为可逐句寻址资产，必须保存到原句/范围的映射。供应商没有词级时间戳时只能提供实际可证明的片段高亮，不伪造逐词同步。全书基础NLP必须处理每句；AI详解与音频按用户明确选择的章及多选内容提前生成，不自动扩展全书。按句保存并按本人/版本复用，章节任务与播放器有限预取分别授权，详见[章节准备契约](../contracts/novel-preparation.md)。

NLP 具体库、词典及阈值在阶段2用英/日样本验证后锁定；本规格确定接口/质量要求，不声称已有依赖选型或性能结果。原文与派生标注版本分开，规则见三类材料契约。

## 5. 公共契约与依赖

依赖 [出处](../contracts/content-locator.md)、[API](../contracts/api.md)、[数据与任务](../architecture/data-jobs.md) 及 [AI/朗读](ai-speech.md)。NovelManifest 只编排小说章节及相关源引用；元数据、上传和保留策略仍由材料模块维护。

使用材料/阅读/书签已有事件字典，在受控字段中标记 `material_type=novel` 与阶段；词句正文和划选不进入埋点。新阶段或字段先注册，再由统一 Telemetry/logging 输出到既有观测平台。

## 6. 验收

| ID | 操作与通过标准 |
| --- | --- |
| NOV-001 | MD/EPUB 小说的章序、对话段落、脚注和 ruby 与标注样本一致；无目录时回退明确，不制造原书结构 |
| NOV-002 | 英文缩写/小数、日文对话/活用、混合语言、emoji/组合字符能正确映射；语言标注失败仍可手动选区且原文不变 |
| NOV-003 | 三端进入专属阅读页，改字号/窗口/解释面板后位置和选区恢复，无整书重建或重复供应商请求；性能按登记样本举证 |
| NOV-004 | 缺章/错序/解析失败可见；重试、标注升级与重解析不覆盖旧来源/音频映射，跨账号、错误类型访问被拒绝 |
| NOV-005 | 当前句至章末的连续朗读可随时暂停/原位置继续，按真实播放句高亮；长按查词暂停且不抢用户选区，边界调整不改原文，遵循SEL-004/TTS-008 |

同时执行NPREP-01～06、当期 MAT/READ/TYPE 与适用的 FLT/TTS 验收；这里只定义未来行为，当前未运行。

## 7. 待决与后续

EPUB 竖排/复杂注音保真见 OPEN-03；PDF/TXT/OCR、分页、正文双语对照层与热力图按产品后续优先级；解析模式中的逐句译文和语法详解已经纳入本期确认范围。小说正文以外的文章/笔记导入不成为额外业务类型；新增类型需要重新确认范围和独立流程。
