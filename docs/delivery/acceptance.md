## 1. 三类完成状态

| 状态 | 完成标准 | 不代表 |
| --- | --- | --- |
| 文档交付 | 范围/契约/操作流程/异常路径/测试验收可追踪，链接/围栏检查完成，独立评审问题闭环 | 应用可以运行或部署 |
| 功能交付 | 功能实现、权限/事件/迁移同步，相关静态检查与测试通过，说明实际平台/限制 | 已公开发布或已验证所有供应商 |
| 发布交付 | 同一候选制品经过平台与部署验收，配置/恢复/回滚/制品证据齐全，按已授权范围发布 | 用户 CSV 可以恢复整库 |

**必须**按实际证据更新路线图，不能因文档已写、测试代码已创建、构建成功或 reviewer 未发现问题就勾选运行验收。**推荐**每阶段产生可独立复核的小交付。**例外**记录适用版本、责任人、期限、替代验证和残余影响；已知越权、秘密泄漏、学习数据丢失、P0 主路径失败不能例外放行。

阶段1内部按 [脚手架蓝图](../engineering/scaffold.md) 和 [脚手架验收](milestones/scaffold.md) 交付B0工程基础、B1身份/收藏参考流程、B2a资料设置、B2b完整治理与B2c单能力模型任务。它们属于限定范围的功能交付，不增加“搭好目录即可完成”的第四种完成状态，B2c的任务通过不能代替B2a/b资料/后台、真实供应商各能力或发布验收。

## 2. 功能进入开发前的就绪条件

每项功能必须明确：入口/权限、正常与异常操作、状态机、请求/响应和错误、数据归属/事务/幂等、埋点、三端差异、验收案例与迁移影响。其需求 ID/文档段落与实际测试对应，API 和数据协议以对应专题为权威正文。

涉及建表/数据库变更时，按 [数据库规范](../engineering/database.md) 同步模型/字典/迁移和受影响DB验收：零物理外键、公共时间字段、scope与逻辑关系校验及删除竞争均需对应证据。静态schema检查不能代替真实PG事务和应用越权测试，亦不要求每个小改动运行全部DB项。

尚待选择的事项用推荐值 + 影响 + 决策门禁管理。例如试卷文件格式、邮箱验证/找回路径、Windows 音频实现与目标设备范围，在相关功能开始实现或公开发布前锁定；不得将“待明确”默默当作“无需实现”。不影响该功能的未决事项不阻止独立工作。

## 3. CI 顺序与合并门禁

CI 实体尚未创建，工程初始化时按以下职责落地；CI 平台按实际仓库托管确定，不假定已有 GitHub Actions、分支保护或既定提交模板。

下表列出检查职责，执行频率与范围以根 [AGENTS.md](../../AGENTS.md) 为准。小阶段/bug修复只运行必要检查和所选必需用例；大阶段/发布大节点运行完整矩阵及全仓覆盖门禁。小阶段1～2轮review、完成后本地commit；大阶段完成后另做全盘review。不能把这张表解释为每次小改动都要运行全部检查。

| 顺序 | 检查/动作 | 门禁及证据 |
| --- | --- | --- |
| 1 | 变更范围、SDK/工具版本、清单/锁文件、配置模式检查 | 缺必要工程/测试入口明确失败；仅文档变更进入文档通道 |
| 2 | 锁定依赖安装、生成物重建与清单比较 | 不更新锁文件或产生未提交差异；缓存键含 SDK/OS/锁摘要 |
| 3 | 文档检查、Ruff/format/Pyright、Dart format/analyze | 零未登记违规；实际命令/版本/退出码归档 |
| 4 | 协议与权限/事件目录、测试收集门禁、快速单元/组件/契约测试 | 未登记路由、未知权限/组件、私有字段泄漏、必需 case_id/层级映射缺失阻断 |
| 5 | 隔离基础设施集成与安全回归、报告汇总与覆盖率门禁 | 按必需用例 × 平台/参数核对真实 passed；拒绝 skip/xfail/deselect/缺记录，核对手写源码完整分母及总体/核心组阈值 |
| 6 | 受影响平台构建、制品扫描/清单、部署样式冒烟 | 功能合并至少构建受影响平台；候选发布三平台及管理 Web 全覆盖 |
| 7 | 独立评审与已发现问题复核 | 作者以外 reviewer 或子 agent 审查；问题有逐项处理与复核 |
| 8 | 候选制品发布环境验证与推广 | 使用同一摘要的制品；生产凭据仅授权发布阶段可用，不授予普通 PR |

依赖、权限、协议、数据库、跨端共享代码变更只扩大有直接影响依据的必要检查范围；局部纯文档/格式修改无需运行不存在或无关应用测试。全量确定性回归在大阶段/发布大节点执行，慢故障/容量用例仅在其必要风险路径或对应大节点执行。报告绑定实际提交/制品/配置；修复后的未受影响证据若复用，须记录变更影响和适用性依据，不能无条件用旧报告替代新制品验证。

第五步按范围调用 [测试规范](../engineering/testing/strategy.md) 的检查器：小阶段汇总所选必需用例的真实结果，大节点另执行全仓覆盖率完整性/阈值检查。pytest/Flutter返回0、strict marker、xfail_strict或生成LCOV不能替代相应检查；所需分片全跳过会阻断，完整覆盖门禁还拒绝核心清单为空或手写模块漏报告/漏登记。检查器自身坏样本在实现/修改检查器时属于必要测试，实体在工程阶段实现。

前端工具责任、UIE项与候选制品证据按 [前端E2E](../engineering/testing/frontend-e2e.md)，场景工厂、TDS项与清理按 [测试数据](../engineering/testing/data.md)。报告关联case/variant/run/shard/attempt、场景/素材摘要及清理结果；不可只保留重试成功。浏览器trace/HAR/storageState、截图与录屏分别控制秘密采集，控制台脱敏不代表附件安全。Windows原生操作没有经验证驱动时必须保留具体人工证据，不宣称自动覆盖。

常规 CI 禁止真实供应商请求和生产服务连接。安全扫描工具在初始化时锁定并登记许可证/依赖漏洞与秘密扫描能力；报告需区分可达漏洞、误报、修复与有期限的例外，不用一个未知扫描器的“零发现”代替威胁与隔离测试。

## 4. 变更说明与独立评审

变更说明至少包含：

1. 用户触发场景及修改后的行为；功能/需求引用和范围。
2. 权限/数据/协议/日志/配置/迁移变化，兼容性与回滚影响。
3. 实际执行检查的命令、版本、结果和证据；未执行项说明原因。
4. UI/操作变化的真实截图或操作记录，包含空/错误/无权状态；不使用概念图冒充运行结果。
5. 已知限制、后续决策和交付产物位置，不放真实 Key、账号密码或私有材料。

独立评审按AGENTS规定分层：小阶段第1轮检查本次改动及直接影响，有修订时第2轮定点复核，不自动扩成全盘审查；大阶段完成后必须整体审查产品流程、前后端联调、授权隔离、并发/失败恢复、测试有效性和文档一致性。文档改动也按规模执行，修复由非作者reviewer复核，不能以轮数上限为由忽略未关闭缺陷。

问题记录包含编号、级别、位置、触发条件、影响、修复、验证/复核结果。P0 为安全/数据灾难或无法交付，P1 为核心错误或高风险缺口，P2 为明确的功能/契约/测试缺陷，P3 为改进建议。发布不得有未关闭的 P0/P1；本次若目标是“问题全部修复”，还须关闭 P2，P3 明确采纳或说明不构成缺陷。不能把真实未解决缺陷改称已知限制以满足零问题。

## 5. 版本、配置与制品

应用推荐使用 MAJOR.MINOR.PATCH，预发布标识与递增 build 单独记录；文档 Draft 版本、API v1、CSV协议版本（当前草案v2兼容v1）、数据库迁移 revision、权限目录和事件 schema 版本相互独立。Flutter 三端同一功能发布共享 release 标识，平台 build 信息保留各自差异。

| 交付物 | 必须包含 |
| --- | --- |
| Python | API/Worker/Outbox 使用的镜像/包摘要、源提交、Python/依赖锁摘要、入口、许可证清单 |
| Web 用户/管理端 | 静态制品摘要、版本配置、同源 API/路由回退策略；私有 source maps 单独归档 |
| Android | 签名 release 安装包及目标 ABI/API 范围；发布到商店时再提供符合渠道要求的 AAB |
| Windows | 可安装/升级的 release 包及全部运行依赖、架构/OS 范围、签名与安装卸载记录；包格式在平台原型后固定 |
| 数据与协议 | Alembic 迁移/起止 revision、权限/菜单种子版本、OpenAPI/事件协议和兼容性说明 |
| 运维 | 脱敏配置模板、服务/端口与依赖清单、健康检查、日志采集/看板版本、恢复/回滚说明 |
| 验证 | 静态检查/测试/平台报告、覆盖率、独立评审结论、扫描结果和已知限制 |

所有制品写入机器可读发布清单，至少包括 release/build、commit、构建时间、工具/依赖版本、SHA-256/镜像 digest、配置 schema 与迁移 revision。制品不可覆盖同名版本；推广复用候选摘要，不在生产重新解析依赖或临时重新构建。

配置证据包含 schema/版本、目标隔离和必需配置校验结果；配置值与秘密输入的规则以 [运行配置](../operations/configuration.md) 为准。发布清单不得含秘密，需证明客户端/镜像/日志没有夹带服务端 Secret 或共享 AI Key，缺必需配置时按安全错误分类拒绝启动。

平台构建能力依据 [Flutter Windows 发布](https://docs.flutter.dev/deployment/windows)、[Android 发布](https://docs.flutter.dev/deployment/android)、[Web 发布](https://docs.flutter.dev/deployment/web)。签名秘密只供受限发布环境，source maps/符号文件须与 release 精确对应并有访问控制。

## 6. 部署、迁移与恢复证据

有序操作及故障分支统一以 [部署与恢复](../operations/deployment-recovery.md) 为准，本节只规定交付必须出示的证据。本文和运行说明都不自行授权修改 MyHome 或生产服务；本地源码调查不能代替实际部署环境核验。

| 门禁 | 所需证据 |
| --- | --- |
| 目标与配置 | 本次授权范围、环境/资源指纹、Haruka 独立凭据与命名空间、容量/依赖版本；OPS-01 配置拒绝样本与健康结果 |
| 首次部署与种子 | OPS-02 干净环境结果、迁移与目录版本、独立首管理员初始化及 learner/admin 探针；无默认密码、重复创建或人工授权覆盖 |
| 迁移 | 起止/实际 revision、制品资源摘要、同连接持锁与 DDL 执行结果、争锁/断连故障证据；每项迁移的可逆性、锁/耗时、数据损失风险和恢复前提 |
| 发布兼容 | 同一候选摘要的后端/Worker/Outbox 与三端发布记录；新旧客户端/schema、会话/权限种子、未完成 Job/Outbox 兼容及分批推广结果 |
| 故障与观测 | OPS-03 实际故障/恢复、任务 fence/unknown 处理、全部采集来源及成功/info/审计关联；缺口和降级范围如实记录 |
| 回滚与前向修复 | OPS-04 对应上一制品/配置/schema 的演练；不兼容时的前向修复或恢复证据，不以破坏性 downgrade 冒充通用回滚 |
| 数据与密钥恢复 | OPS-05 配对数据库/对象/加密版本、旧会话失效、权限/审计/幂等/学习贡献核对；实际恢复窗口和耗时、负责人、保留、RPO/RTO，以及历史备份依赖密钥的可恢复证据 |
| 共享服务共存 | OPS-06 MyHome 原有运行/查询、资源余量及限额证据，确认 Haruka 操作没有停止或清空共享服务 |

迁移、回滚或恢复未演练、目标未固定时不能签署相应发布验收。失败记录须给实际状态与处置结果，不能仅凭维护命令退出成功；在途供应商调用与恢复点外结果按运行协议核对。平台运维恢复与用户单词 CSV 是不同交付范围。

- [ ] 迁移、应用回滚、运维恢复演练和剩余任务处理有报告；平台 RPO/RTO 与审计留存不借用 Loki 七天默认值。
- [ ] 交付制品/摘要、配置/迁移/协议版本、签名和调试符号归档齐全；独立评审及问题复核完成。

性能阈值先在阶段 1/相关平台原型建立基线，在候选发布前固定并量测；测试报告必须给设备、负载、样本、百分位/错误率和观测区间，不能写“性能良好”。现有日志正常到达 15 秒等数值属于待验证初始目标，最终值以实际验收记录为准。

## 8. 交付记录与关闭条件

未来每次发布的验收记录使用以下信息结构，文件位置按实际仓库流程确定：

| 字段 | 内容 |
| --- | --- |
| release / build / commit | 被验收的唯一版本 |
| scope | 本次需求与变更，支持的平台/文件格式/供应商 |
| evidence | 每项门禁的命令、环境、结果和报告/制品引用 |
| review | reviewer、问题编号、修复与复核结果 |
| migration / rollback / recovery | 起止 revision、执行结果、恢复点与演练记录 |
| limits / exceptions | 限制或例外、影响、负责人和到期条件 |
| decision | 通过、失败或待验证；不能把未执行项标记通过 |

发布后的观测和事故处理按 [部署与恢复](../operations/deployment-recovery.md) 执行，并将事件、处置与后续验证关联到交付记录。最终汇报只陈述实际完成和实际验证的内容。
