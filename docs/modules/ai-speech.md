## 2. 流程、状态与异常

### 2.1 全局选区交互

DESIGN17补充：普通学习及服务端确认交卷后的复盘中，所有已显示且有权读取的学习文字统一使用 **选中文字 → 朗读或查询 → 查询结果可收藏**。覆盖小说、课本正文/词表、收藏列表/详情、查询结果、AI解释（含中文说明）、例句、普通习题题干/选项/已发布反馈、错题与学习诊断；不只允许外语原文。导航、设置标签、凭据和编辑中的输入框不作为学习正文。试卷准备/作答中及提交失败/结果未知时禁用通用工具条和题目收藏；确认交卷成功后即开放，不必等待评分完成。只操作当前有权可见的题面、已提交作答和已发布解析，不从未发布评分或隐藏听力稿补充内容；听力仍使用专用流程。

1. 单词列表（含每日单词）、词表、单词卡片标题与详情的词形旁提供小喇叭，点击只播放该单词，不打开详情、不选中作答，也不自动查询。图标视觉轻量，触控区域遵循平台规范；不把整篇正文中的每个词常驻变成按钮。标准收藏单词可使用受控全局词音，其他来源先走有权私有路径，不因同文扩大共享目录范围。
2. 长按学习文字，默认选中所在句；原句在原位置高亮，附近出现带轻阴影的句子浮层，不移动正文。窄屏、放大和软键盘下保证浮层在安全可见范围，可滚动且不遮蔽当前操作。DESIGN19确认普通鼠标拖选/键盘扩选只保留原生选择，不自动弹层、不触发查询或暂停。触控/鼠标长按才主动打开句子浮层；已打开后允许调整选区。键盘用户选区后可用Alt+Enter显式唤出并聚焦同一浮层；轻点仍负责原有导航/作答，长按、拖选、滚动不误触详情或答案。
3. 浮层按当前语种自动分词，原顺序、空格和标点保留，词汇成为可切换选中的气泡。点击一个或多个词只改变选择，不调用模型；再次点击取消。没有点词时“查询”默认查整句，点词后同一个按钮查询所选内容。相邻词作为连续词组，不相邻词按各自范围分别解释并携带同一原句上下文，不能拼成虚构短语；顺序按原文而非点击顺序。超限就地提示缩小选择，不悄悄忽略末尾词。
4. 自动分词只是辅助，可用原文选区手柄/键鼠或浮层的“调整范围”修改字词边界；标注失败仍可手选。按字素调整并转为规范偏移，不截断组合字符；每个选择保留来源、版本及有序span，规则见[出处协议](../contracts/content-locator.md#12-分词气泡与多范围查询)。临时气泡与选择不持久建表，也不在长按时新调AI分词。
5. 浮层旁的小喇叭始终朗读当前浮起的完整句子/原生划选范围；点词只改变查询范围，避免选词后喇叭含义跳变。单词喇叭与句子喇叭共用SpeechService：先只读解析音频，命中一按播放；缺失同位置明确“生成并朗读”、本人配置及用量含义，点击才授权新生成，不新增确认步骤或系统TTS回退。句子外独立词的发音仍用其词条喇叭。
6. 操作冻结点击时的来源/版本/文字范围和原句上下文，工具按钮不丢选区。调整范围使旧只读匹配失效，旧响应不能影响新选择；页面/账号/权限或来源版本变化清理失效操作。长按浮层用约240ms轻微上浮/淡入，词气泡短暂依次显现；查询/收藏等dialog打开有淡入与短位移，关闭约150ms淡出。同一弹窗内部更新不重播入场，动效不推迟业务状态、不重复查询/收藏；减少动态使用直接状态切换。浮层和弹窗支持键盘、关闭及焦点隔离，返回恢复来源位置；查询结果仍在当前上下文展示，不进入聊天页。
7. 完整成功并持久提交的类型化查询结果可收藏，沿用零个或多个同语言词本的选择；多个不连续词的结果分别为完整卡片，用户自行收藏所需项。收藏保留卡片版本及来源，不把所选词存成未生成的占位卡。AI解释、中文说明及生成例句可继续长按，用同一浮层再查询/朗读；半成品、失败提示及不可校验结果不开放结果收藏。
8. 小说另有明确的“连续朗读”入口，从当前句依序播放至本章末尾，章节结束即停，不自动扩到下一章或整本。当前句优先取刚选中的句子，否则取阅读视口首个可见句；已有暂停队列时入口恢复该队列的位置。正文高亮实际正在播放的句子，和浮层中用户选词的深色气泡区分。底部轻量播放器可暂停、继续、停止及倍速；暂停保留句ID和片段内位置，继续不重头生成/播放。
9. 连续播放时长按选词、打开查询或播放单词/单句先暂停连续队列，保留原句和音频位置；关闭浮层/查询或短音频结束不自动恢复。短音频停止后返回暂停的连续队列，由用户明确继续，不能同时播放两路声音。导航离开小说、换账号、失权或换章清理旧播放代次；单纯窗口重排保留同一有效播放状态。自动跟随当前句不抢焦点，用户手动浏览时不强行拉回。

题目另有直接“收藏题目”动作，无需选择文字、查询、作答正确或先成为错题；普通教材题/AI习题作答前后均可收藏，试卷题目仅交卷成功后开放。查询习题卡片可直接整卡收藏，已有错题历史收藏入口保留，详见[题目直接收藏](vocabulary-practice.md#题目直接收藏)。这个题目级动作不增加选区工具条按钮。独立查询页保留用户直接输入/图片查询；单词本既有手动添加属于管理动作。单词喇叭和小说连续朗读已属本次确认的P0入口；P1收藏列表批量播放队列仍不提前实现。

非材料文字也必须可验证：解释、卡片、收藏、习题反馈和诊断引用各自已提交资源/版本的可见文字字段与范围，规范见[出处协议](../contracts/content-locator.md#11-非材料学习文字的选区)。原材料出处作为追溯信息保留，不能把AI生成文字的偏移写回书中原文。现有资源、解释/卡片、收藏及私有语音资产承担持久化；临时选区不新增物理表，Redis只保存可淘汰副本，完整结果仍遵循[学习结果缓存](../architecture/learning-cache.md)。

HTML原型用浏览器Intl.Segmenter展示分句/分词与边界调整，内置查询卡片/内存收藏及计时播放状态；单词/句子喇叭和连续播放器明确“无实际音频”。逐句就绪集合与预取窗口仅是内存演示，不是音频缓存；真实音频、播放器事件、高亮同步、持久匹配、语言质量及Android原生手柄仍待正式实现与验收。

### 2.2 即时解释

1. 用户从普通学习及交卷后复盘内容中选择文本，在共用工具条点击“查询”；服务端根据引用重取原文和有限前后句。手工输入明确没有材料出处，不能由模型补一个不存在的引用。
2. 请求包含 selection/source_ref、目标语、解释语言、详细程度及模型配置引用，客户端不能指定 user_id/credential_owner。服务器验证 explain、源对象读取/状态、选区版本和长度；活动考试题面不通过考试入口取得解释/答案提示，遵循 [试卷模式](exams.md)。
3. 先只读解析本人已有结果：内存/本机、Redis未命中仍查服务端持久结果；当前来源/目的的结果存在就直接显示，不因默认模型/Prompt升级自动再生成。确无可用结果且用户已明确发起解释时，才检查本人文本Key/上限，合并或创建AiRun执行Pydantic AI；预加载与resolve不发起供应商调用。
4. UI 显示来源、正在解释和停止按钮；流式文字可先显示。卡片到达且完整通过 schema、文本范围/来源校验并持久提交后才允许选区朗读/查询，以及收藏/出题等结果动作；其中单词卡标题保留直接发音喇叭，其他文字使用句子浮层。
5. 所有完整成功结果自动持久保存为Explanation/卡片，并同事务建立来源绑定；有合法材料出处时建立本书已查索引，手工输入/无材料卡片保留各自身份，不编造书内出处，不要求用户收藏。提交后才显示已保存，再填充本机/Redis副本；首包/总耗时分别统计。关闭浮层、退出或副本淘汰不删除结果；断流重开先查run/已存结果，不自动再次发起供应商调用；同一attempt的迟到用量仍可幂等补全。
6. “有用/不准”提交版本化反馈记录，可附受限长度的自愿说明；原文和反馈正文只存业务库，不进入遥测。反馈不自动修改历史解释、Prompt 版本或用于模型训练，后续优化需要独立验证。

缓存匹配、持久保留、书内词句索引与四层职责唯一维护在 [学习结果缓存](../architecture/learning-cache.md)。同词不同语境分别保存；查阅键用于找已有解析，严格生成键包含实际上下文/模型/Prompt等完整输入。旧配置结果可明确展示，语言/目的变化不能伪装命中。显式重新解析才创建新generation，成功前保留旧结果，迟到run不覆盖；网络重试同一Idempotency-Key只恢复原run。

| 输入 | 结果内容 | 校验/回退 |
| --- | --- | --- |
| 词 | 表面词/读音/词性、词典义与本句义、1–3 个例句 | 保留当前词形；lemma 可另给；有出处例句需指向本人内容，生成例明确标识 |
| 短语 | 整体义、字面义、可拆分性、使用例 | 用 WordCard phrase 子型承载，不拆成无关单词释义 |
| 句子 | 母语翻译、意群、最多 3 个主要语法点，可选自然改写 | 意群引用原句合法 span；翻译和改写不能当作原文覆盖 |
| 摘录 | 摘要、关键表达、理解难点/段落关系 | 以结构化解释结果承载，可链接词句卡；超长选区要求缩小，不能无提示截掉末尾 |

可选信息按问题和证据提供：词的搭配、近反义、词源、语体和常见错误；短语的同义表达；句子的语气/自然改写；摘录的段落逻辑。它们不要求每次生成齐全，也不允许缺少证据时编造确定结论。解释默认用母语，用户可切到目标语。

解释细节可选简短/标准/极客，但不会改变原始引用。模型无法可靠判断的内容显示不确定/需要更多上下文，不用 schema 通过宣称解释正确。目标首内容等待沿用 PRD 的正常网络下 3 秒，具体模型、网络、样本和百分位记录在验收证据，不把文档目标当已达成。

### 2.3 具体AI功能与共享运行层

#### 功能入口与运行状态

用户端不提供学习Agent页面、会话列表、新建聊天、“问Agent/问学习Agent”或通用消息输入框。AI通过语言查询、阅读/教材的词句解释、习题批改与出题、学习诊断等具体入口使用；结果在当前卡片、面板、题目或报告页显示，不跳入聊天。查询保留统一图文输入和学习结果，受查询模块的语言任务限制。后台Pydantic AI作为可复用运行层保留，由各领域服务按动作调用；AgentThread/Message是查询记录和功能运行上下文的内部存储，不要求用户先创建会话。创建内部上下文不调用模型；新run检查本人Key、上限及实际动作权限，读取已提交结果仍按对应read权限。

同一运行上下文首版同时只运行一轮。具体功能请求包含当前资源/上下文版本、目标语、受控source_ref、该动作的业务输入和Idempotency-Key；查询允许本轮图文输入。服务端占用本轮并记录输入/AiRun，跨端并发冲突返回活动run，不互相覆盖。成功后提交完整类型化结果与卡片；中断标记interrupted，未校验结果不可操作。内部SDK消息仍可持久保存用于审计、上下文和恢复，不形成用户聊天产品。

短即时运行状态依照公共 AiRun 协议；UI 视图为等待、生成、工具处理中、已完成、用户停止、中断、失败和结果未知。重连先用 run_id 查询状态/结果，已完成不重跑；无法续接的中断轮次需明确重试，同一已提交工具业务动作仍幂等。删除查询记录/内部会话仍需agent.delete；有活动运行先停止并确认结束，再按领域生命周期删除，不悄悄取消用户其他独立Job。该接口不意味着必须提供聊天管理页。

#### 上下文和动作边界

每次功能调用只装入该动作需要的已授权选区、有限前后文、当前目标语、相关收藏/错题及必要的运行记录和版本化摘要。摘要是辅助记忆，不能覆盖业务统计；早前消息中的敏感源对象失权后不得重新装载。用户切目标语时新一轮显式绑定新语言，历史保留原语言，不把英语错题合入日语诊断。

卡片上的展开语法、查看语境或生成习题等具体动作显式引用原卡片/资源及版本；不同入口可以复用同一运行层，但不能自动继承无关入口的全部历史。必要上下文超上限时先裁剪非必要记录，无法保留证据则要求缩小范围或补充资料。语言查询由AI判断任务，不显示类型选择；信息不足时仅针对当前语言任务请求补充，不转为闲聊或通用聊天。未上线的能力不能因为模型识别到意图就假装可用。

| 工具类型 | 输入和结果 | 额外权限/执行边界 |
| --- | --- | --- |
| 读取本人材料/收藏/错题 | 受限筛选、版本化引用、有限结果 | 对应 read；后端注入本人作用域，不向模型暴露可指定 owner 的参数 |
| 生成诊断 | 目标语/窗口/证据范围 → report_id/job_id | diagnosis.generate 及来源读权；统计由应用计算 |
| 创建练习 | 已授权来源/题型/数量 → plan/session/job_id | practice.generate/start 等实际动作；写幂等键绑定用户意图，不只用不稳定 tool_call_id |
| 打开原文/收藏 | 返回受控 route_key 与业务引用 | 不执行模型生成 URL/脚本；客户端再经路由与资源授权后导航 |
| 卡片收藏 / 卡片选区朗读 | 收藏按钮或共用选区工具调用独立领域服务 | collection.create 或 speech.play/generate；agent.use 不隐含这些权限 |

仅提供用户当前可用工具，每次执行、模型调用及最终提交再次检查权限。材料正文/模型工具结果都按不可信数据处理，不能改变角色、配置、系统提示或授权规则。学习 Agent 不包含用户/角色管理、任意 SQL、任意网络请求、宿主文件或 Shell 工具。

用户通过功能入口明确确认生成练习等动作后，允许在已披露上限/数量内执行；卡片或报告中的建议不能自行启动新模型任务。模型输出数量或耗时超本轮上限时由应用中止，不能靠下一个工具反复拆分绕过限制。SDK、HTTP 客户端和 Job 重试共享总上限，具体上限见运行层和部署配置。

本人运行取消使用 `client.job.cancel` 对应的本人执行控制接口，不要求仍具有 agent.use；用于停止后续调用，不授予重试/读取/新调用能力。账号或登录资格撤销时服务端自行停止后续未授权步骤，不依赖被撤权客户端成功点击停止。已经发出的供应商请求可能仍会完成；停止不删除已经提交的练习或学习数据。

### 2.4 朗读选择与播放

所有朗读入口共用同一SpeechService/播放器，不为阅读器、学习卡片、查询或试卷另建缓存。普通学习及交卷后复盘的输入来自已验证的单词/可见文字范围或小说当前章的有序句清单，包括已提交解释/卡片的可见字段；试卷听力输入为已人工确认的`ExamListeningScriptVersion`；试卷来源必须同时绑定有权的ExamVersion/Stimulus/题目范围，不能接受客户端直接传隐藏文字。语种来自受控来源，声音来自provider/model能力目录；没有支持组合时要求修改设置，不悄悄换语言声音或回退系统TTS。

收藏库标准单词的独立发音采用 [全局词音缓存](../architecture/learning-cache.md#51-收藏库标准单词发音的全局缓存)：同语言/词形/读音/标准profile跨用户复用，默认使用已发布标准声音，不携带收藏上下文。个人句子、例句、定制读音及解释仍私有；同拼写的不同读音先明确选择，不能仅按词串命中。

播放已有音频只需 speech.play 与内容范围，Key 被删除也不自动销毁已生成音频；新合成另需 speech.generate、本人有效 Key 和上限。UI 先解析缓存；未命中时明确展示生成动作，只有用户选择生成才提交供应商请求。生成请求在当前权限仍成立且命中已有完整可用缓存时可以返回该结果，不要求 Key、不消耗新模型上限；缓存失效时不能把此前命中当继续发起供应商调用的授权。GET/只读缓存查询不能触发生成。

跨句选区或小说连续朗读先构建不可变 PlaybackManifest，绑定 material_revision、顺序、sentence_id 和合成配置版本。P0 优先每句一个 AudioSegment；特别长句按可追溯短段拆分，高亮只能精确到实际片段范围。段内多句若没有可靠对齐，不宣称逐词/逐句时间戳；以真实播放 segment 的状态驱动高亮。小说连续队列必须有逐句音频或经过验证的真实句边界，不能按文字长度计时推进正式高亮；超长句拆成短段时仍高亮其原句并保存准确短段位置。

试卷听力在开考前由用户显式确认脚本/题目绑定、语言、声音映射和播放策略后生成，构建私有PlaybackManifest并发布`ExamListeningAudioBinding`；合成键包含本人、script_version、语言、模型/声音/参数/格式，不进入global_word。相同严格键可复用已有服务端持久结果，播放器倍速或媒体签名刷新不重新合成；修改脚本/声音形成新绑定和试卷版本。有限次数场次的媒体读取必须走考试PlayAttempt，不能经通用speech下载端点或完整本机离线副本绕过计次；合成缓存复用与场次播放授权是两个层次。P0不接收原始音频，不对音频转写/自动绑定，也不把普通题面朗读冒充听力材料。

考试开始前先解析全部冻结音频并检查speech.play、来源权限和实际可用性，未就绪不启动计时。考试中播放器执行冻结的次数、暂停/拖动/速度和脚本可见策略，不用通用播放器设置绕过；必要音频故障报告给考试场次协议，不能自行重生成后继续原场次或把受影响题记零。

### 2.5 播放状态、取消与故障恢复

播放器区分 `idle/resolving/buffering/playing/paused/stopped/completed/error`。开始播放需要实际播放器报告 ready/playing；首音频等待从用户点击计到可听开始，不能拿服务端合成结束替代。暂停保留当前位置，停止终止当前队列与后续预取调度；重复点击播放复用现有请求/音频。

小说连续朗读首次缺失时，同一入口明确“生成并连续朗读”，说明从当前句到本章末尾、本人声音配置及有界逐句生成；该显式动作授权仅本次队列范围，缓存播放不隐含后续生成许可。仅播放已有音频且遇到缺失时暂停并显示生成动作，不静默跳句。单句和连续模式的合成输入一致时复用同一音频。

快进到未生成句子显示等待和明确生成状态；跳章或更换声音增加本地播放代次，迟到的旧片段不能插回新队列。暂停（包括长按/查询触发）后不继续扩张预取窗口，保留当前音频偏移；停止后取消尚未调用供应商的专属预取任务，若同任务仍被本人其他活动播放请求引用则不能误取消共享工作。明确提交的选区后台生成任务通过任务中心取消，不因离开页面自动终止；连续队列只在已授权窗口内逐句处理；独立的整章多选准备沿DESIGN20章节准备契约，不将两种授权混为一项。

网络失败优先重试下载；媒体 401/403 先处理会话/权限而非无限刷新 URL；404/对象丢失报告缓存失效，经用户明确同意才重新合成。音频解码失败标记不支持/损坏，保留诊断类别，不能重复下载失败后暗中反复发起供应商调用。

退出、换账号、切服务实例、在线撤销 play 权限时停止播放并清除授权音频队列；离线仅在有效权限租期内播放本账号已完整下载音频。签发地址的到期前残余访问与离线无法即时撤权的限制见认证/RBAC，产品不承诺远程擦除用户已导出的文件。

## 3. 前端职责

### 3.1 类型化卡片与流式呈现

卡片通用字段建议为 `card_id/type/schema_version/payload/source_refs/provenance/created_at`。来源引用由应用验证；provenance 区分材料引用、用户输入、AI 生成例和推断。卡片内容、生成时版本与出处一并保存，不能仅保存一段最终 Markdown。

| 卡片 | P0 payload 要求 | 动作 |
| --- | --- | --- |
| WordCard | lexical_kind、词/短语、读音、词性、本语境义、可折叠其他义、2 个短例句、可选活用；短语子型增加整体/字面义、可拆分性与常用程度 | 词形旁喇叭、分词浮层朗读/查询、整卡收藏、加入AI习题选择、查看有权来源、反馈 |
| SentenceCard | 原句、翻译、合法意群范围（选中文字后查询）、主要语法点、可选改写 | 选区朗读/整卡收藏、展开语法卡、句译练习、来源、反馈 |
| GrammarCard | 母语/目标语规则名、当前句主例、带标签的 2 个对比例、考察点 | 收藏完整语法、打开例句、生成习题、选区朗读/查询后收藏新卡片、来源、反馈 |
| ExerciseCard | 语言题面、用户作答（缺失则明确标记）、参考答案/建议订正、逐项依据、不确定性/待补充状态、目标语、经验证的来源及schema/revision；无标准答案标AI参考，不伪造确定分数 | 收藏完整习题与订正、查看来源、补充题面；不自动写作答、成绩、掌握或错题账本，正式证据沿用Practice/Exam契约 |

每张卡显示类型标签，使用原生组件；朗读、收藏、出题、来源与有用/不准反馈均按各自权限和内容范围提供。卡片“收藏”保存完整结构化载荷：WordCard按lexical_kind成为word/phrase，SentenceCard为sentence，GrammarCard为grammar，ExerciseCard为exercise；不把组件硬塞为word。GrammarCard中的例句/摘录可通过共用选区工具条查询，再收藏新生成的完整结果卡片；原卡片与新查询卡片分别保留来源身份，不提供直接另存选区入口。收藏时保留已存在材料来源，不能因为使用Agent运行层而改成无出处查询。每轮默认最多 3 张，额外解释可折叠或提出继续，不偷偷生成大量卡片。

应用事件使用 `accepted/progress/text_delta/tool_status/card_ready/completed/failed/cancelled`，携带 run_id、单调 sequence、schema_version 与关联 ID，完整信封以 API 契约为准。最终数据库结果是权威，SSE 中间 delta 不能直接视为持久成功。断线后按 Last-Event-ID/sequence 去重；若事件保留窗口已过，查询已授权最终快照，不补跑模型来“重放”。

未知卡片类型/新 schema 在旧客户端显示“需更新才能展示”与允许的安全文字摘要，不动态执行模型 HTML/JavaScript 或任意组件。结构校验失败进行上限内有限修复；仍失败时显示失败/普通安全说明，不把半截 JSON 暴露为可点击按钮。前端使用原生卡片控件，文字渲染过滤外部资源和主动脚本。

### 3.2 三平台播放器

| 平台 | 专项行为与验证 |
| --- | --- |
| Windows | 锁定并验证 just_audio 的 Windows 平台实现与编解码；设备切换/睡眠后恢复安全状态，播放器停止后旧事件不重启 |
| Web | 浏览器用户手势/自动播放限制下显示点击播放；媒体 CORS/同源凭据、Range、刷新和多标签页取消不绕过授权 |
| Android | 音频焦点、耳机拔出/来电、后台/进程重建明确暂停或恢复；P0 不默认承诺锁屏常驻播放服务 |

所有平台都验证句间停顿、声音一致性、首音频等待与连续播放缓存，不把模拟音频测试当成真实供应商朗读效果验收。

## 4. 后端职责

后端使用 Pydantic AI 执行文本理解、上下文重取、上限控制、工具授权和类型化输出校验；保存 Explanation、AgentThread/Message、Card 与版本化出处。工具只发出受控业务动作，不能代替数据库事务或自行创建身份。模型与 Key 按当前用户依赖注入，模型内容不能改变用户权限。

解释、查询/其他AI功能与 TTS 复用各自已完成结果时不要求重新提供 Key；真正的新供应商调用阶段再检查当前 Key、动作权限与上限。缓存命中是读取已有产物，不是下一次未命中时自动发起供应商调用的授权。短即时运行和长 Job 的执行恢复采用 Agent 运行层，不承诺任意模型步骤自动续跑。

### 4.1 TTS 生成与媒体发布

1. 解析受控文本引用，验证权限、来源版本、语种、模型/声音/格式和长度。只朗读允许的文本，生成提示和输入正文分开，不允许朗读内容成为任意工具指令。
2. 先由服务器判定private或global_word，再按对应合成键查持久ready音频，相同键的并发请求经PG占用合并到一个有效生产者，Redis协调不承担唯一约束。全局词音不返回生产者私人任务/模型用量，等待者只读自身请求状态；合成键与输入/配置按学习结果缓存专题维护，不同入口/播放器倍速/Key轮换不制造新结果。
3. 创建对应AudioAsset/segments或GlobalWordAudio候选，并持久化实际发起人的Job/Outbox。章节按窗口生成，推荐首版预取当前句后2句、同用户合成并发2，另有全局上限；标准收藏词音不因列出词表就预生成。全局缺失只使用明确发起者的当前Key，取消/失败不自动借等候者Key续跑。
4. 音频适配器检查返回状态、真实媒体类型、非空、长度/解码可用性。裸 PCM 按已知采样率/声道/位深正确封装或转换；只改扩展名不算有效音频。适配路由、声音和格式随具体模型版本实测锁定。
5. 每个成功完整音频段先保存到MinIO并验证，再事务发布ready元数据、来源引用及manifest，不能仅缓存临时URL。有效引用期间不因TTL或LRU回收；崩溃孤立对象受控清理，已有结果传输/落盘失败优先恢复，不隐式重新合成。
6. 向已授权客户端签发短期媒体访问或经过鉴权的媒体代理；支持正确 Content-Type、长度和 Range。刷新过期媒体地址只重新授权/签发同一对象，不发新模型请求。

试卷听力生成在上述步骤前额外验证exam.read/edit、material.analyze阶段的人工确认结果及script/binding generation；每个外部调用前仍检查speech.generate、本人credential_version和上限。发布事务只在候选run仍是当前代次、脚本/题目绑定与播放策略未改变时写入ExamListeningAudioBinding，迟到旧声音/脚本结果只留历史，不能使ExamPaperVersion ready。

AudioAsset/Segment 的领域状态为 `queued/generating/ready/failed/cancelled/unknown_outcome`；部分已就绪的章节显示已可播句数和后续等待，不把半章当完整缓存。供应商超时但结果未知执行公共不确定结果策略，不能自动无限生成同一段。

缓存身份不包含播放器倍速：0.7–1.5 倍速只在客户端改变播放速率，不新合成。若用户修改的是供应商支持的合成语速/风格，则构成不同配置和新合成键，点击前说明会重新生成；不支持的参数禁用并解释，不默默忽略。

## 5. 公共契约与依赖

[API 契约](../contracts/api.md) 统一 `/api/v1` 的 explanations、agent/threads、runs 与 speech 资源和 SSE 信封；[权限目录](../contracts/permissions.md) 定义来源读取、各业务动作和本人取消的依赖。本篇不重复维护 API 路由表。卡片来源字段使用 [出处协议](../contracts/content-locator.md)，生成、取消、重试和不确定结果使用 [Agent 运行层](../architecture/agent-runtime.md) 与 [数据与任务](../architecture/data-jobs.md)。

| 业务操作 | 持久结果/执行 | 事件 |
| --- | --- | --- |
| 解释/反馈 | Explanation、Card、AiRun、版本化反馈 | explanation.requested/completed/failed、ai.feedback.submitted |
| 已查索引/只读解释解析 | 本人来源绑定、分页索引、完整持久结果或运行中引用，不创建模型调用任务 | learning.cache.resolved；读取不算新生成/新的业务学习提交 |
| 会话与轮次 | AgentThread/Message、Card、AiRun | agent.thread.created/deleted、agent.message.submitted、agent.run.completed/failed |
| 运行进度/取消 | 公共 AiRun SSE、本人执行控制 | accepted/progress/text_delta/tool_status/card_ready/completed/failed/cancelled |
| 只读音频解析 | 已有 manifest/缺失片段，不创建模型调用任务 | speech.cache.hit |
| 音频生成 | PlaybackManifest、AudioAsset/Segment、Job | speech.requested/generated |
| 媒体访问与播放体验 | 已授权媒体，不隐式重生成 | playback.started/failed；与服务端生成分开 |

即时解释和 Agent 的事件/取消由公共 AiRun 控制入口收口；后台 Job 控制遵循中央目录。事件只含类型、状态、耗时、计数/用量和受控资源引用，不含 Prompt、对话、原词句、工具正文、Key 或媒体签名 URL。通过 operation/request/job/ai_run/model_call 关联同一 [日志平台](../operations/observability.md)。

## 7. 待决与后续

后续卡片保留原产品内容要求；启用前须新增受版本控制的业务 schema 和实际验收，不能只把当前 Markdown 改名为组件：

| 能力 | 内容与边界 |
| --- | --- |
| P1 ContrastCard | 两个或多个形式并排，说明何时用 A/B、易错点及对比练习入口 |
| P1 PronunciationCard | 读音符号、常速/慢速 TTS、对母语者的近似发音提示；跟读评分另属 P2 |
| P1 ExerciseReviewCard | 用户答案与参考对照、错因、相关规则/词和再练入口，引用当时作答 |
| 后续独立 PhraseCard | 整体义、字面义、可拆分性、常用程度和例句；P0 已由 WordCard phrase 子型承载 |
| 后续 DiagnosisCard | 诊断报告的压缩呈现并可展开；P0 使用独立结构化报告，不因语言习题卡片而把DiagnosisCard提前纳入首版 |

P1生词减速/重复和收藏列表朗读通过已有manifest播放队列实现，默认改变播放安排；真正改变合成参数时仍需生成权限和明确模型调用意图。OPEN-12另行设计原始考试音频上传、转写/切段与自动绑定，它不能借现有TTS媒体接口提前开放。先听后显示只控制学习布局，不声称考试保密；P2跟读评分另外需要录音/识别/评价契约，TTS能播放不意味着能评口语。

2026-09-22 核对的官方资料仅用于确认接入方向：

- [Gemini TTS 官方说明](https://ai.google.dev/gemini-api/docs/speech-generation)：专门的文本转音频能力；输出格式、流式接口与声音取决于具体 TTS 模型/版本，实现时验证。
- [OpenRouter TTS 官方说明](https://openrouter.ai/docs/guides/overview/multimodal/tts)：提供独立 audio/speech 接口，返回音频字节；模型目录和声音/速度支持需按供应商能力筛选。
- [just_audio 官方包说明](https://pub.dev/packages/just_audio)：Windows 需另外选择平台实现；音频格式和服务端媒体头也影响实际播放。

这些资料不构成本项目已连接供应商、已实测平台或支持目录中全部模型的证明；具体模型 ID、声音、编码和依赖版本在技术验证后锁定。

默认 OpenRouter 统一入口或 Gemini 官方直连、具体模型/声音/格式及调用和输出上限仍见 [待决清单](../decisions/pending.md)。官方资料确认接入方向，最终能力需要工程验证。

独立查询页面、仅语言相关的图文任务、卡片收藏弹窗和QRY验收以[查询模块](query.md)为准；沿用同一Agent运行层和本人凭据，不新增模型执行框架。
