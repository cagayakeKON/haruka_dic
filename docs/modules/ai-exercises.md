# AI 习题与错题库

状态：2026-09-23，已确认产品方案，待实现。用户端不提供词汇复习、每日复习、到期队列或 SRS；P0 提供由用户显式发起的 AI 习题，并由服务端记录所有可靠错题。收藏/单词本的内容管理见[收藏与练习](vocabulary-practice.md)和[多单词本](vocabulary-notebooks.md)，评分发布见[数据与任务](../architecture/data-jobs.md)。

DESIGN17补充：已有AI习题与普通教材题均提供直接“收藏题目”，作答前后都可保存当前可见的完整题面快照，不要求查询或产生错题；查询ExerciseCard仍可直接整卡收藏。错题历史收藏保持原有入口与独立状态。统一载荷、归本、去重及试卷交卷门槛见[题目直接收藏](vocabulary-practice.md#题目直接收藏)。

## 1. 范围、入口与权限

“AI 习题”是用户端独立功能入口。用户选择一个或多个来源、筛选条件、题型和题量，预览候选范围后确认生成；Pydantic AI 生成类型化候选，应用校验后形成不可变习题集。它不是系统按时间自动推送的词汇复习，也不承诺每天有固定题量。

P0 来源包括：本人一个或多个单词本/全部单词、手选收藏、教材内容或原题、全部/当前/已收藏错题、近期错误与诊断薄弱点。不同来源可以组合，但每项都重新检查对应读取权限；隐藏或失权数据不进入候选、计数、Prompt 或结果。新生成需要 `client.practice.generate`、本人有效文本模型 Key、上限和来源读取权限；开始已有习题、保存答案、AI 批改、收藏错题分别使用独立动作，生成权限不隐含这些权限。

用户没有 Key 时仍可查看错题库、使用已有习题集以及完成可规则评分的原题；不能生成新的 AI 习题，也不能把“无 Key”静默改成其他用户/实例 Key、规则拼题或系统词汇复习。

## 2. 服务端错题账本

### 2.1 哪些结果成为错题

服务端在评分成为当前 `effective` 结果后，根据冻结题目、答案/rubric 和程序校验生成错题事实：

- 普通教材题、已有习题和 AI 习题的可靠错误或部分正确，按可评分叶子记录。
- 试卷只有整次有效评分发布后记录；共享题干/大题不重复计错，多空题按冻结计分粒度记录。
- 规则评分和合格 AI 评分都可形成错题；`pending/partial run/needs_review/failed/unknown_outcome` 不冒充错误。
- 普通跳过、技术/媒体故障、传输失败、未请求评分和无依据诊断不形成错题；明确提交的可靠空答可以按题目规则形成错误。

每次可靠错误/部分正确形成不可变 `MistakeOccurrence`，至少绑定 owner/library、来源种类、Attempt 或 ExamSession、题目/版本、评分版本、可评分叶子、用户答案快照、判定/错误标签、考察点、源引用和发生时间。唯一约束按有效评分项防止 Worker 重投重复记录。题目或材料删除后保留最小复盘快照；仍需原文权限才能回跳，不用快照旁路读取已撤销材料。

### 2.2 历史、当前状态与重评

“记录所有错题”表示每次有效错误事实有历史，不表示列表永远把已纠正题目算作当前错误。服务端在不可变 occurrence 之上维护可重算投影：

| 投影 | 含义 |
| --- | --- |
| unresolved | 当前有效结果仍错，且没有更新的合格纠正证据 |
| improved | 后续独立作答已正确，但历史错误仍保留 |
| invalidated | 原评分被有效重评纠正或题目被正式作废；历史标明原因，不再作为薄弱点 |
| pending_rebuild | 重评/题目处理已提交，投影尚未追上；不按 unresolved 选题 |

显式重评以新的 effective 版本替换贡献并重算状态，不物理删除旧 occurrence。新的正确练习可以使考察点进入 improved；在原题反馈后立即抄写的订正只作训练，不自动证明已纠正。相同题反复答错可以保留多次 occurrence，但生成权重按根题/考察点聚合并设置上限，不能靠重复记录挤掉其他薄弱点。

### 2.3 错题收藏

任何已形成的本人错题记录，包括 unresolved、improved 和 invalidated 历史，都可以收藏；用户也可取消收藏。`MistakeFavorite` 是 owner + occurrence 的本人关系，带创建/更新时间、revision 和可选私人笔记，不复制或改写评分事实。物理映射为mistake_occurrences的favorited_at/favorite_updated_at/favorite_notes/favorite_revision字段组，逻辑收藏ID复用occurrence.id；取消只清收藏组并推进版本，不删错误。多个 occurrence 的聚合只用于列表分组和生成权重，不改变每条历史可独立收藏的语义。

收藏状态与错误状态正交：后来答对不会自动取消收藏，取消收藏不会删除后台错题历史，也不会改变分数、掌握状态或诊断。重评使 occurrence invalidated 时保留收藏并显示“原判定已更正”，默认不进入针对当前薄弱点的生成；用户可显式把该历史收藏作为参考来源，但新题不得继续把已作废答案当真值。

错题库支持按当前状态、是否收藏、来源材料、题型、考察点、目标语和时间筛选；排序/分页稳定。详情读取当前用户答案、评分依据和题面快照需 `client.practice.mistake.read` 及实际来源/成绩权限；只有列表摘要权限时裁剪敏感字段。收藏写入需 `client.practice.mistake.favorite`，不能用收藏入口读取他人题面。

## 3. AI 习题生成

### 3.1 选择与预览

用户选择目标语和来源，再配置题型、方向、题量及生成重点。单词本可按收藏时间、加入本时间、最近有效作答时间和自动掌握状态筛选；错题可按发生时间、unresolved/improved、收藏、错误标签、材料和题型筛选。不存在 `due_at`、到期/逾期、新词额度、每日目标或复习计划筛选。

同一维度多选取并集，不同维度取交集。多本按 CollectionItem 去重，不同义项保持独立；错题按 occurrence 全部保留历史，但预览同时显示去重后的根题/考察点数，默认不会为同一错误重复生成多题。时间区间以本人已生效时区和服务端时间形成 UTC 半开区间，冻结 `as_of`；客户端时间不作权威。

预览是只读操作，不调用模型、不要求 Key、不创建习题或学习证据。服务端持久化短期 `ExerciseSelectionSnapshot`，保存规范化条件、稳定候选顺序、来源/权限/内容/学习投影版本、抽样结果、题型、方向、题量、同源多题策略、难度/生成重点、模型/配置引用、预计模型用量摘要及过期时间。客户端不能上传任意单词、错题 ID 或 mastery 作为真值；任何影响候选、题面或模型用量的设置变化以及重新随机抽样都生成新预览。无结果不建立 Job，数量不足明确显示，由用户重新选择范围/允许同源多题，不能自动扩大到未选择的内容。

### 3.2 生成、校验与开始

确认只提交 selection_id、expected_revision 和幂等键；生成设置从快照复制，确认接口不接受覆盖值。事务内重查账号、权限、来源版本、错题/收藏状态、Key/能力和上限，再创建ExerciseSet内不可变 `AiExercisePlan` 字段组、Job/Outbox和模型调用意图；生成设置复制，所选来源持久引用同一选择快照中的不可变候选，计划存在期间不得因预览到期清理；任何设置摘要不一致返回冲突并要求重新预览，同一幂等请求不重抽候选或重复调用供应商。Worker 每个供应商调用阶段及发布前再次检查当前权限和来源有效性，只读取计划中的冻结设置，不动态借用其他用户数据补位。

Pydantic AI 输出题目、选项/空位、答案/rubric、考察点、错误针对关系、难度提示和来源引用。程序检查题型、答案唯一性/可评分性、分值、引用归属和模型输出中的主考目标；无效候选有界重试或按部分生成报告，不把模型自报成功当发布。生成例句明确标 `generated`，教材原题标 `extracted`，针对错题的变式保留 `derived_from_mistake` 引用但不把用户旧答案写进新题题面。

生成完成只得到可开始的习题集，不算学习完成或掌握证据。用户显式开始后创建 PracticeSession，逐题提交和反馈沿用[收藏与练习](vocabulary-practice.md)的 Attempt/评分规则；可靠结果再进入掌握投影与错题账本。已生成习题不会因后来筛选/掌握变化静默换题，来源撤权时按快照可见性和业务规则裁剪/阻止读取。

### 3.3 针对性策略

针对错题生成时，程序先从有效事实计算考察点和权重，再让模型生成内容。默认优先 unresolved、近期重复错误及用户收藏的有效错题；improved 用于巩固只在用户选择时加入，invalidated 默认排除。权重考虑不同错误发生次数、最近时间、题型/能力覆盖和同源上限，不直接把模型诊断当统计真值。

用户可选择“重做原题”或“生成变式”：重做不调用生成模型，读取冻结原题版本；变式需要 AI 生成权限并明确发起供应商调用。生成结果展示所依据的错题/考察点数量和来源类别，不暴露其他用户、隐藏材料或完整 Prompt。系统不会在后台自动生成，也不会因为新错题出现就启动任务。

查询得到的ExerciseCard可按收藏来源显式选择，但其粘贴作答/AI建议不是MistakeOccurrence或有效掌握证据，不混入“当前错题”。已有正式题目的引用继续逐项验证；生成和真正作答沿用本模块快照与PracticeSession流程，不因新增卡片另设评分旁路。

## 4. 前端职责

Flutter 使用独立 `AiExercisesController` 管理条件、selection、生成 Job、习题集与开始动作；`MistakeLibraryController` 管理自动账本投影、筛选和收藏。二者不复用词汇复习/到期队列状态，也不把模型 Job 状态塞进单词本 controller。

紧凑布局使用“AI习题”入口→来源/条件分步页→预览确认→生成进度→习题集；错题库使用筛选列表和独立详情页。宽屏可将条件与预览、错题列表与详情并排。布局切换保留账号/selection/job/session和未提交答案，不重新预览、调用模型或开始新会话；Android软键盘、Windows/Web键鼠和大字模式按[Flutter规范](../engineering/flutter.md)验收。

生成表单分成“选择来源”和“设置与确认”两步：选中来源后在该项下展开词本、收藏条目、教材单元或错题范围；手选收藏必须有逐条选择控件。第二步同时展示题目设置及具体候选内容/来源，宽屏并排、紧凑布局顺序排列，允许返回修改且保留选择。只保留一次明确的生成确认，不叠加内容相同的确认弹窗。来源不足时提示减少题量或显式允许同源多题；变更来源、语言、题型或题量后重新确认同源策略。正式预览仍遵守3.1的只读快照、版本及过期约束：设置变化重建预览，加载/冲突期间不能确认旧范围，不因减少UI步骤取消权限或Key校验。DESIGN12的HTML清单只根据本页内存实时计算；最终按钮明确打开1道内置示例，不实现服务端快照、生成或学习证据。

错题卡明确显示自动记录来源、当前状态、收藏状态、题型/材料和可用动作；“已纠正”不等于删除，“原判定已更正”不能继续显示为当前错误。收藏、取消收藏、重做、生成变式分别有稳定Test ID和无障碍名称。按钮可见性不能代替 API 授权。

## 5. 后端、数据与日志

PracticeService 保存作答和评分；MistakeService在 effective 发布事务/Outbox 消费中幂等写 occurrence、重算投影并维护收藏；AiExerciseService负责选择快照、计划、生成校验和习题集。它们使用同一 Python 后端、PG、Job/Outbox/Kafka/Worker和Pydantic AI，不增加微服务或第二套Agent框架。

所有业务表使用 owner/library、UTC `created_at/updated_at`、revision及无物理外键规则。跨表引用由 ScopeContext、同一父锁顺序和版本/代次校验；删除/GC不移除被历史答题或收藏引用的必要快照。管理员只可看任务状态、数量、失败码和用量等获权运维元数据，不能浏览用户错题题面、答案、收藏笔记或借管理权限生成私人习题。

事件建议为 `mistake.recorded/status_changed/favorite_changed`、`ai_exercise.selection_previewed/generation_requested/generated/failed/session_started`。日志只记录计数、来源类型、题型、状态、Job/AiRun和受控ID，不记录单词、题目、用户答案、rubric、笔记、Prompt或模型正文；前端点击不是错题/生成成功的权威事实。
