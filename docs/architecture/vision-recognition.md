# 统一视觉模型 OCR

状态：用户已确认OCR统一使用视觉模型，三类文本/扫描PDF及试卷图片已纳入首版；下述执行合同待实现。适用于获准格式中的扫描页、图片文字识别及拍照识词，不改变[三类材料](../contracts/material-types.md)的独立处理边界，也不自动开放小说/课本独立图片或任意多图组合。

DESIGN23补齐[文件提取与原书ruby](../contracts/source-extraction.md)：扫描/图像型PDF、图片及必要的EPUB嵌图走本人视觉模型；EPUB真实文字/注音直接解析。OCR分别返回基础文字和注音候选，校验映射后发布source_ruby，不将注音串入正文。完整阶段成品先保存为私有FileObject并由JobStage引用，发布重试复用成品；后续[基础NLP](text-analysis.md)与AI详解分别执行。

## 1. 技术边界

所有 OCR 经过统一 VisionRecognitionService，由 [Pydantic AI 运行层](agent-runtime.md) 使用用户配置的视觉模型进行类型化调用。沿用允许的 OpenRouter/Gemini 供应商入口；具体模型通过图像输入、结构化输出及英/日样本验证后启用，默认型号仍由 OPEN-04 管理。统一的是调用、凭据、上限、任务和识别协议，不要求所有业务使用同一个提示词或同一个模型型号。

不建立 PaddleOCR、Tesseract 等传统 OCR 执行路径，也不在视觉模型失败时静默回退。PDF 文本层提取、页面渲染、旋转/裁切/压缩属于文件预处理，可以本地确定性执行；它们不承担 OCR。MD/EPUB/TXT 的真实文本以及可用 PDF 文本层无需先转图片调用模型。

检测到无文本层、乱码、扫描/文字混合或需识别的嵌图时，先形成待识别页/区域清单。不能仅凭“存在文本层”认定文字完整，也不能因一页需要识别而默认重识别整本；同一区域只采用一种已选定来源，防止文本层和视觉结果重复拼接。

## 2. 授权、选择与模型用量

导入页面区分“直接提取文字”“视觉识别”和后续可选“结构/学习分析”。`requested_stages` 分别保存视觉识别与后续分析意图；选择 OCR 不代表同意额外生成释义、答案、翻译或整书分析。

- 新材料 OCR 需要目标导入权限及 `client.material.analyze`，已存在材料重识别还需 `client.material.reparse` 和来源读取权限；试卷附加权限、完整原件使用资格按 [权限目录](../contracts/permissions.md) 与三类材料契约校验。
- 拍照识词继续使用 `client.vocabulary.photo.import` 及其确认写入权限，不因共用视觉服务额外要求材料导入/analyze；普通学习 Agent 的 use 权限不授予 OCR。
- 确认时展示所选模型、将发送的页/区域范围、输入规模和调用上限；模型用量事前未知时只展示范围，不估算金额。初次无法确定页数时先由后端确定性检查，展示清单后再显式发起识别；先前已明确授权的范围/上限内可继续，超出时暂停重新选择。
- 使用本人当前有效视觉 Key、能力与供应商调用限额；缺 Key 或能力不符时显示待配置，已有上传可保留，但扫描部分不能声称已可读。更新 Key 不自动开始旧模型调用任务。用户只选直接提取时，标出待识别范围，不静默切到视觉模型。
- 重试、取消、撤权与 unknown_outcome 沿用 [数据与任务](data-jobs.md)；每个新供应商请求及结果发布重新检查当前动作/归属/代次，禁止借公共 Key、其他模型或传统 OCR 自动补偿失败。

尚无已发布内容版本的待识别材料，可通过 `POST materials/{id}/analysis` 显式请求首次视觉转写，复核原导入动作、来源读取及analyze；明确已授权的初始导入Job也可执行此阶段。已有已发布版本（包括部分可读版本）时，补识别或重识别会改变规范文本，必须走 `POST materials/{id}/reparse` 并同时校验reparse/analyze，发布新内容版本。对已发布正文的结构/学习分析仍走analysis且不得改写正文。请求绑定源对象/页区域计划版本和expected_revision，过时计划冲突，不能换图后沿用旧确认；首次转写并发发布遵守同一revision/任务代次规则。

## 3. 页面准备、识别与结果发布

1. 只读取已校验的不可变源对象。应用生成页 ID、页序、尺寸/旋转与受限区域 ID；获准 PDF 先渲染受控页图，图片去除无业务用途的 EXIF 等元数据后形成新的私有派生对象，不原位覆盖原文件。
2. 大页按已验证模型限制缩放或裁切，保留坐标变换和必要重叠；页数、像素、总输入量、批量、超时及并发受部署硬上限和个人上限限制。不把无限整本图片一次塞进上下文。裁切损失信息、过小字、缺页或模型输出截断均列入质量问题。
3. JobStage 按页面/受控区域批次持久化，模型只能回传所给引用的文字与结构候选；材料/页/块的可信 ID 和页序由应用维护。图片中的指令一律作为待识别内容，不改变系统规则；固定识别调用不开放网络、文件或写业务工具。
4. 输出模型包含源页/区域引用、转写候选、阅读顺序/表格等结构候选、不可辨认区域和质量提示。程序验证引用、覆盖清单、范围、长度、顺序及 schema，并去除裁切重叠造成的重复；未覆盖/失败/截断的页不能计为完成，不能以返回合法 JSON 作为准确识别证据。
5. 将原图视为原始证据，视觉转写明确标记 `source_method=vision`，经业务质量检查后由应用生成 ID 并发布不可变规范文本；它是识别稿，不冒充原文件已有文本或经过人工校对。禁止模型润色、补写看不清的字或编造答案；不确定区段显式保留标记。已发布正文的重新识别/修正创建新 MaterialRevision，不原地覆盖已有选区、书签或考试依据。
6. 仅对通过检查的已提交页/区域复用结果，恢复只处理未完成的合法阶段。结果复用键按用户、源对象/页/区域摘要、渲染参数、模型/提示/输出协议和处理配置分区；新模型配置或显式重识别不误用旧结果。重复投递不重复发布；在途发起供应商调用结果不确定时不得声称“没有执行”或无限重试。

模型自报置信度只作诊断提示，不视为校准概率或自动通过依据。源页及应用裁切范围是可靠定位基础；模型提出的字框/精确坐标只能作为待验证候选，没有可靠映射时回跳到整页/裁切区并标明粒度，不能伪造逐字高亮。阅读器里的字符选区针对已发布转写版本，按 [出处协议](../contracts/content-locator.md) 使用 Unicode 偏移。

## 4. 各业务的独立校验

| 消费方 | 专用识别配置/候选 | 发布及使用限制 |
| --- | --- | --- |
| 小说 | 章序、段落、对话引号、ruby/脚注、跨页断行 | 核对顺序与缺段；可靠识别稿可进入小说阅读/语言标注，缺页明确降级，不能静默补全故事 |
| 课本 | 多栏、表格列、词条、例句、图文与题目/答案关联 | 保留单元/内容角色；不把列打散拼句，题目残缺只限制相应题，不阻止其他可靠单元学习 |
| 试卷 | 题号、共享材料、听力指令/脚本文字、空位、选项、题图、分值及答案区 | 保留跨页关联；已发布视觉转写可作为听力脚本候选来源，但AI仍须另行标记疑似听力题并匹配脚本—题组/小题，人工校对后才生成TTS。识别成功不等于可开考，不生成“原卷标准答案” |
| 拍照识词 | 图片中的词条/上下文，生成释义与原图已有文字分开标记 | 返回独立候选预览，用户确认才写收藏，不把单图成功当整本/整卷识别验证 |

各消费方提供自己的 Pydantic 输出约束和业务校验；视觉服务不能直接创建可开考试卷、提交作答或收藏。结构候选可复用同次结果，另一次模型调用语义分析仍需相应明确意图和上限，不强制每页重复调用两个模型。

本视觉OCR合同只处理图片/页图中的文字和版面，不接受或转写原始听力音频。P0试卷听力从用户上传文字稿或已发布试卷文本/视觉转写取得脚本候选；原始音频转写、切段和自动题目绑定由OPEN-12留到P1，不能把视觉模型接口改造成未定义的音频入口。

## 5. 存储、日志与验收

转写和页图是私有业务数据，输入/输出全文不进入日志、消息队列或前端埋点。Job/Outbox 只传引用，临时图保留/清理采用公共对象规则，仍被出处/冻结版本引用的必要对象不能提前回收。所有真实视觉请求进入统一 AiRun/ExternalCall 遥测，记录模型、阶段、页/区域计数、状态、耗时和可用用量；已提交结果命中不计作新调用，未知用量不虚构为零。

| ID | 未来必需验证 |
| --- | --- |
| OCR-01 | 原生文本不触发OCR；扫描/混合页只识别所选必要范围，不重复拼接文本层；未获准格式仍拒绝 |
| OCR-02 | 缺Key/无权限/超上限/仅直接提取时不调用模型；显式确认后只用本人视觉配置，撤权/换账号不发布失权结果，不回退传统OCR |
| OCR-03 | 三类及拍照独立样本验证漏行、跨页、旋转、多栏/表格、注音、小字和截断；schema合法但内容有误不能自动通过，模型置信度/坐标不当真值 |
| OCR-04 | 重投/重启仅复用已提交阶段，unknown调用有界恢复；重识别发布新内容版本，旧出处/冻结题目不被覆盖；双账号缓存/源引用隔离 |
| OCR-05 | 提示注入不执行工具；日志/队列无页图/base64/转写/签名URL/Key，所有视觉调用可关联且无重复用量统计 |

按各消费功能与最终批准格式分阶段落实 OCR 验收；常规测试使用模拟模型，真实视觉质量另用许可明确的人工标注样本和授权调用验证。本文没有选择具体模型版本或宣称识别准确率。
