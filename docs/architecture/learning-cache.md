# 单词、句子与 TTS 的持久保存和缓存

状态：2026-09-22，设计方案，缓存业务尚未实现。用户要求一本书中查过的单词、AI解析过的内容、句子及TTS都缓存。本篇维护结果保存、匹配、并发与生命周期；操作入口见 [AI与朗读](../modules/ai-speech.md)，本机管理见 [设置](../modules/settings.md)，范围/权限遵循 [三类材料](../contracts/material-types.md) 和 [RBAC](authorization.md)。

## 1. 保存承诺与范围

成功且完整的单词/短语解释、句子翻译/语法解析、摘录解释、结构化卡片及生成音频，自动写入当前用户的服务端持久存储，不以点“收藏”为条件。收藏表达学习意图，保存结果避免丢失和重复付费，两者独立。保留有效引用的结果不设按天过期或LRU删除；清理Redis、本机缓存、换设备、退出、轮换/删除供应商Key，均不删除这些已提交结果。

这不要求预先解析或朗读整本书。只保存实际查过、已生成和明确授权预取的结果；页面预加载只读已有结果，不能顺带付费生成。用户明确删除材料/相关业务记录后的保留与回收仍受公共规则约束，不作无限容量或灾难永不丢失的保证。用户备份仍仅单词CSV，不新增音频或整书打包导出。

小说以章节/段落选区绑定，课本以Lesson/角色块绑定，试卷以合法题面/交卷后复盘版本绑定；考试中禁用的解释或答案提示即使命中缓存也不可提供。OCR转写与材料分析已经按各自不可变产物保存，本篇不把它们变成解释缓存，也不缓存评分结果来跳过新答卷评分。

## 2. 四层职责

| 层 | 位置与内容 | 保留和丢失后的行为 |
| --- | --- | --- |
| Flutter内存 | 当前账号/页面的词句结果、可见区索引、播放缓冲 | 有界LRU；页面释放/换账号清理，再从本机或服务端取 |
| Flutter本机 | Drift保存索引及解释副本；平台私有文件/经验证的Web存储保存完整音频段 | 文本/音频分别限额和LRU；已显示结果/播放下载自动尝试落盘，失败提示未缓存到本机，不影响服务端结果 |
| Redis | 热门结果/索引副本、短期缺失提示与协调信号 | 有界TTL和容量；丢失回查PG，不直接视为需要再调用模型；不存唯一结果或承担唯一并发约束 |
| 服务端持久层 | PG保存Explanation/Card、源绑定、版本/索引、生成占用和AudioAsset元数据；MinIO保存完整音频字节 | 有效业务引用期间保留，跨端复用；发布以PG事务及已验证对象为准，纳入运维保护 |

Redis允许按内存策略淘汰键，因此必须是持久数据的副本，不能承载唯一的付费结果。[Redis淘汰说明](https://redis.io/docs/latest/develop/reference/eviction/)。Web存储可能因配额或浏览器回收而丢失，本机“已缓存”只表示当前已验证副本存在；服务端保存才是跨设备保证。[浏览器存储配额与回收](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)。不因本方案调整共享MyHome Redis全局淘汰策略。

服务实例/用户/受众是每层分区前缀；服务端业务结果仅供client作用域使用，不因admin会话同属一个人就开放私有内容。登录和在线授权仍需要现有PG/Redis认证条件；结果可回查PG不代表Redis认证材料失效时可以绕过重新登录。

## 3. 一本书的已查索引与语境结果

分开维护“这个词在本书查过”和“这次原文位置的完整解释”。书内索引按词/词形/语种组织，但具体结果按源版本、选区和上下文区分。首版不使用向量相似度、仅lemma或相同单词字符串决定语境解释命中。

例如同书出现 `river bank` 和 `bank account`：书内索引可以共同归到bank，两个位置分别保存解析。再次点同一位置直接显示原结果；点击另一位置可查看注明出处的历史释义，但不能把“河岸”当成金融语境的当前解释。已有卡片里的简短词义也不能冒充完整的本句解析。

| 逻辑记录 | 必要信息与用途 |
| --- | --- |
| MaterialLearningIndex | owner/library/material、词句类别、语言、表层词/可选lemma、源位置与已有结果引用；支持按书/章/Lesson分页查询 |
| SourceResultBinding | 带类型的来源身份、不可变版本/locator或手工输入摘要、结果ID及派生依赖；提交时把解释关联到持久来源，不由只读resolve补写学习记录 |
| Explanation/Card | 不可变完整输出、说明语言/详细程度/任务种类、实际上下文摘要与必要快照、模型/参数/提示/协议版本、来源和质量标记 |
| LearningLookupState | owner、查阅键、revision/lookup_generation、当前选择的严格生成键/active_run_id、effective_result_id；跨模型/Prompt配置维持本次查阅的权威结果指针 |
| GenerationSlot | owner、严格生成键、active_run_id、执行租约/fence；只合并同配置调用，不决定本书某处应显示哪个配置结果 |
| AudioAsset/Segment/Manifest | 真实音频格式/校验和/字节数/时长、合成键、句子/源范围及播放顺序；复用既有音频聚合，不建立第二套TTS库 |

以上是逻辑职责，按现有Explanation/Card/Audio表扩展或增加必要关联，不要求每行新建一张表。所有业务表遵循 [数据库规范](../engineering/database.md)：created_at/updated_at、ScopeContext、业务唯一约束、无物理外键和共同父行锁。源绑定不是浏览埋点；成功解释提交时就建立，不能等待前端补发日志才出现“已查”。普通只读resolve不写学习进度或伪造新查询成功次数。

同一句从阅读器、其收藏来源或完整句子卡进入，只有服务器确认来源版本、选区和任务语义一致时才共用解析；卡片改写句、例句、译文、词条摘要各自标来源，不能当作原句。多轮Agent响应照常持久保存，对话历史不同不按最后一个词句直接复用整段回答；只有已提交、来源/目的完整的结构化结果才可纳入对应索引。

## 4. 命中规则与版本

区分两个键，防止升级模型或Prompt后把已有结果当作丢失：

- **查阅键**：实例/owner/client作用域 + 带类型的来源身份 + 任务种类 + 原文语言/说明语言 + 详细程度/用户明确的解释目的。用于找“这里以前已解析的结果”，不包含Key、访问Token或当前默认模型。
- **严格生成键**：上述语义输入及其规范化协议 + 实际选区/上下文/其他依赖摘要 + provider/model或可用修订标识 + 全部有效生成参数 + Prompt/上下文构造/输出schema版本。用于生成请求合并、精确匹配和可复现的配置记录；程序统一序列化/摘要，不能相信客户端自报hash。

来源身份是带标签联合，不能以空material_id/spans代替所有无材料输入：材料使用library/material_id/不可变版本/精确spans；收藏、生成卡片等使用各自受控资源ID、不可变内容版本及选区；手工输入使用服务器计算的全文、用户显式上下文与规范化协议版本摘要，并保留“无材料出处”标记。规范化保留语义差异，不折叠大小写、标点或有意义空白。只有经服务器验证与原句完全等价的资源才可映射到同一材料身份；否则各自查询与授权。无材料来源不写书内索引，也不由模型编造原书绑定；同样完整保存并支持重新输入相同内容时复用。

查阅已有结果时显示其实际模型、配置与生成时间。当前默认模型/Prompt更新不触发重新收费；返回已有可渲染结果，并明确配置差异，用户选择“用当前配置重新解析”才开始新run。用户改说明语言/详细程度/解释目的属于不同查阅请求，旧结果可作为标明差异的历史选项，不能宣称满足新要求。原文版本/上下文不同也不自动冒充当前结果。

重新解析在不含模型/Prompt的LearningLookupState上分配新lookup_generation并记录所选严格生成键与run。旧有效结果在新结果完整提交前继续可读，新run失败保留旧结果。发布当前结果须同时匹配lookup_generation、所选严格键、active_run_id及执行fence；仅自己GenerationSlot有效不足以更新书内当前绑定。模型A先开始、后来用户选B、B先完成时，A迟到只保存其历史/封存结果，不能覆盖B；即使B失败，也保留此前已提交有效版，不自动把仍在途的A设为新选择。

同配置的普通重复点击合并到当前run；显式重新生成则用expected_lookup_revision取得新代次，旧同键run在退出有效占用前不能启动第二个有效生成，先取消/等待并明确在途费用。不同严格键可有在途调用，最终查阅指针仍只由同一LookupState控制。每次成功新版保留自己的结果，不覆盖旧内容。运行SDK升级不影响历史结构化结果读取；schema兼容转换由确定性代码完成，不能为显示旧结果再调模型，无法转换时明确为历史格式而非缓存未命中。

材料/OCR重解析按出处协议生成新版本，旧解析继续绑定旧来源。只有源映射唯一、选区/上下文及相关内容角色等全部依赖等价时，程序才可显式建立新版本绑定并复用结果；仅同文/同lemma或同书名不足。语言标注升级不改旧句子ID含义；以span/真实文本依赖检查，而不是把新sentence_id套到旧解析。

## 5. TTS保存与复用

每个成功合成的完整片段必须保存原始可播放音频及manifest，不能只存会过期的供应商URL、音频URL签名或文字。服务端先持久化/校验对象，再发布ready；客户端完整下载并校验长度/校验和后才标为本机可用，Range片段或断开的临时文件不算完整缓存。

合成键由owner/library + 精确合成文本/文本协议 + 语言/读音控制 + provider/model/声音 + 实际传入的上下文、风格/合成语速等参数 + Prompt/分段/输出格式与采样配置组成。**播放器倍速、页面入口、Key版本和媒体签名URL不进入合成键。** 同一内容从阅读器、收藏或卡片朗读，在全部合成输入等价且来源获权时复用本人音频；不同用户不共享私有音频或结果索引。

声音、语言或供应商合成参数改变时查找对应版本；缺失则显示生成动作，不能把旧声音当新声音。旧音频仍可明确选择播放；配置变化不自动销毁/重合成历史版本。Key轮换/删除不失效已有音频，付费阶段才检查当前Key；URL过期只重新鉴权签发，下载失败只重试传输。

按稳定句子/有界短段组成播放清单，不把整章作为唯一缓存单位。每段保存准确文本范围和分段方案；只有独立音频或经过验证的真实时间映射才能切出其中一句复用，不能凭字数估时把多句音频算作每句均已缓存。供应商需要相邻句维持语调时，相邻上下文必须进键；相同句子置于不同合成上下文可能需要不同音频，界面准确展示可复用范围。

当前/有限后续片段预取遵守已有TTS授权与预算。停止播放/关闭页面只停止消费者和未开始的预取意图，不等于删除已生成音频；显式取消共享Job按本人job.cancel规则执行，并提示影响其他正在等待该Job的客户端。断网只能播完整本机片段，不补发模型请求。

## 6. 读取、并发与故障流程

1. 客户端先校验账号作用域。在线先取得当前会话/动作/源状态授权，再按artifact版本使用内存或本机副本；不能用长时间有效的旧权限快照直接显示新受限内容。离线按第7节的有限租期。
2. 只读resolve在当前权限/来源/业务状态下查索引及Redis/PG，返回ready结果/运行中引用/缺失原因与历史配置差异。批量查当前可见范围设置条目上限，每项检查作用域，不能用书级接口枚举无权考试解析。GET和只读POST resolve绝不创建模型任务。
3. 用户选择解释/生成或明确重解析后，服务端计算查阅键/严格生成键，在PG事务内按固定顺序取得LookupState/GenerationSlot并创建AiRun/Job/Outbox，登记查阅代次与选用run。相同严格键当前执行代次只保留一个活动生成，多幂等键/设备普通点击也合并；不同配置的迟到结果由LookupState再次拦截。Redis锁只作加速，过期/重启不能放行第二个有效发布者。不能在数据库事务内等待供应商。
4. 完整结果通过schema/来源/业务校验后，先保存必要对象，再事务写结果/历史源绑定与阶段结果；仅通过查阅代次/选用run校验才更新书内当前索引和有效指针，过期结果只进入有权限的历史。提交后才广播对应状态，流式半句、失败、拒绝及unknown都不能作为完整解释命中。TTS播放请求/manifest也绑定自身的配置与请求代次，不把迟到的另一声音结果覆盖当前播放选择。
5. 数据库/对象写入失败时保留已返回产物的受控恢复记录/临时对象并只重试落盘；界面显示未完成保存，不能显示缓存成功后马上丢失。进程崩溃造成响应不可恢复按unknown规则处理，不能保证模型恰好收费一次或把存储失败变成无提示新调用。
6. Redis miss、清理本机、浏览器回收、换设备都先回查服务端持久结果。服务端确认音频对象丢失/损坏时标broken，保留记录与诊断，修复/恢复优先；任何重新付费必须明确发起，禁止“缓存未命中”直接无限合成。

失败状态只做有界抑制重复请求，不作为长期语义缓存；短期负缓存不得掩盖新提交结果，发布时更新/失效并携带结果版本。身份/权限拒绝与网络不可达区分，明确拒绝不能退回本机旧结果。每个读取、提交、绑定、签名和Worker仍执行 [数据与任务](data-jobs.md) 的归属/删除代次检查。

## 7. 本机、容量与删除

本机自动保存已读取的完整解释/已下载音频，解释与音频独立配额。内存、本机及Redis可以按容量淘汰副本；PG/MinIO中仍有合法业务引用的成功结果不按LRU或短TTL删除。具体本机容量随三端样本与设备约束定版，不把某个Web配额当所有设备保证。当前正在使用/写入的文件按本机协调规则处理，临时文件原子发布，磁盘满明确显示仅服务端已保存。

已有解释作为只读学习内容纳入现有离线租期：离线展示同时需要来源read与ai.explain快照许可，音频需要来源read与speech.play；期限取会话、动作与源租期的最短值。离线不能生成新解释/音频、写收藏/笔记/学习记录或看受限考试答案；管理端保持在线。上线、重连先鉴权，换账号/受众/实例清掉旧副本和迟到响应。本期不扩展固定下载、全书离线包或离线写入同步。

| 操作/变化 | 已保存结果如何处理 |
| --- | --- |
| 清除此账号本机缓存 | 只删除设备副本，后续从服务器取回，不产生新模型费；按书/类别清理等细分入口仍按设置模块留在P1 |
| Redis过期、应用重启、退出或换设备 | 结果与源绑定仍在持久层，当前授权成立后读取 |
| Key删除、默认模型/Prompt升级 | 旧结果保留并显示实际来源配置；不批量刷新/重生成 |
| 改声音/说明语言/用途 | 独立匹配对应配置，旧版可作为有差异的历史结果，不谎报新配置命中 |
| 原书删除 | 先tombstone阻止读取/新增绑定/迟到发布；移除仅属于原书的引用，按公共宽限和父行锁复核回收；独立收藏/历史版本确需的合法引用按其权限保留，仅返回其获准快照，不借缓存恢复已失权原书全文/上下文 |
| 某个Agent对话删除 | 不级联删除已经作为书内解释/独立收藏持久保存的结果；仅对话自身内容按其生命周期处理 |

服务端配额在付费前按受控输出/音频上限预留，并按实际落盘结算/释放；超容量暂停新生成，提示原因，不能先付费后因为普通LRU删掉旧解释。已返回结果的存储失败执行第6节恢复，不谎报保存成功。服务端按真实对象/引用核算容量；跨书复用一个同用户音频对象不能重复算物理字节，删除一处引用不能删除另一处正在使用的对象。GC把结果版本、来源绑定、有效业务引用及在途提交全部纳入权威检查，不仅看过期引用计数。

## 8. 接口、可观测性与验收

API目录见 [公共契约](../contracts/api.md)：解释增加只读resolve和按材料分页的已查索引，保留既有生成/读取结果接口；音频沿用speech/resolve、requests、assets/manifest/media。前端用artifact_id/version、match_kind、storage_state等类型化信息区分同配置命中、历史版本、生成中、服务端已保存、本机已下载和不可用；字段在业务schema落地，不把缓存细节暴露成必须理解的技术流程。

记录缓存层、结果类别、命中/缺失原因、等待/下载耗时、去重等待、落盘失败及受控引用，不记录词句、上下文、音频内容或可推断私有内容的完整hash。API响应、书内索引和本机副本均为私有；Web公共HTTP/CDN/Service Worker静态资源缓存不得收录带身份的解释/音频响应。按账号显式管理的本机存储才承担离线副本。
