# 账号认证与用户数据隔离

状态：Draft v0.5，2026-09-22，未实现。产品依据：[PRD](../product/overview.md)；授权依据：[管理后台与 RBAC](authorization.md)；详细操作：[账号流程](../modules/accounts.md)；部署参考：[MyHome 复用](../operations/myhome-integration.md)。

## 1. 已确认范围与推荐方式

支持多用户注册和登录，每位用户独立管理材料、收藏、学习记录、模型配置及音频。同一账号可在 Windows、Web、Android 使用自己的数据。

已确认增加管理后台及完整 RBAC。登录需有对应 client.login/admin.login 资格；登录后根据有效权限显示两端页面/菜单/按钮，并由后端逐项检查业务操作和数据范围。用户私有 Library 不因管理角色自动变成共享数据；完整策略、角色、管理功能和撤权契约以 RBAC 专题为准。

推荐首版采用邮箱 + 密码，注册时事务性创建 User、私有 Library 和 StudyProfile。登录标识规范化后具有数据库唯一约束；密码不做静默截断或改变。显示名不承担身份标识。邀请注册、邮箱验证和找回密码的交付方式尚待明确，公开上线前需要确定可用的账号恢复路径。

Haruka 维护独立账号。参考 MyHome 的密码校验、会话、CSRF 与作用域查询机制，但不共享 MyHome 的账号表、Cookie、签名 Secret 或登录会话。首版不实现组织、共享资料库或单点登录。

## 2. 注册与会话流程

1. 注册校验当前开放/审批策略、输入和频率，事务创建账号、资料库与允许公开分配的默认角色；客户端不能指定管理角色/权限/状态，失败不能留下半成品。
2. 登录校验密码、账号状态及当前入口的 client.login/admin.login，创建带受众的独立会话；用户端已登录不自动取得管理会话。
3. 原生验证JWT算法/签名/issuer/audience/期限，Web验证opaque Cookie对应的服务端会话；两者均核对PG撤销/epoch、Redis存续和当前权限，不能信任旧Token角色。
4. Web有效会话只续idle、不在常规刷新中轮换Cookie；原生single-flight+CAS轮换刷新凭据，处理回执/重放/迟到代次；算法以本文会话机制为准。
5. 退出撤销当前设备会话；修改密码验证旧密码并撤销既有会话，要求重新登录。
6. 账号禁用后撤销两端会话，拒绝刷新和业务访问；撤销某端 login 权限则终止该端会话，功能撤权在下一受保护请求及后台阶段检查时生效。

PG AuthSession保存持久身份、受众、绝对期限、撤销状态和安全epoch；Redis保存Web会话摘要或原生刷新材料、idle TTL及限流。强退/禁用/改密与审计在PG事务提交即生效，新请求必须核对持久状态，Redis删除失败不延迟撤销。Redis或PG不可用均失败关闭；会话材料丢失最多重新登录，不丢学习数据。详情见 [数据与任务](data-jobs.md)。

权限关系和账号状态以 PostgreSQL 为准；首版每次受保护请求核对用户/全局授权 revision，再使用与版本匹配的缓存。管理变更事务性更新权限、revision、审计和 Outbox，不只等待 JWT 到期或异步失效通知。详情见 [RBAC 更新与失效](authorization.md)。

密码采用成熟库的 Argon2id 哈希，不能可逆加密或直接用通用摘要替代；工作参数结合服务容量验证，参考 [OWASP 密码存储建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。供应商 API Key 因调用需要可恢复明文，采用独立加密存储，不能与密码存储方式混用。

注册/登录按 IP 与账号维度限流，错误响应避免泄露密码或过多账号状态；不使用永久锁定造成简单的拒绝服务。具体规则随实际注册开放范围确定。

## 3. 三端凭据与账号切换

| 平台 | 会话传输与保存 | 约束 |
| --- | --- | --- |
| Web | HTTPS同源，高熵opaque session Cookie，Secure/HttpOnly/SameSite；不使用浏览器轮换refresh Cookie | 校验CSRF/Origin，续idle不延绝对期限；身份变更后重查当前会话，不把秘密放localStorage |
| Windows | HTTPS Bearer 访问令牌，刷新凭据保存在操作系统安全存储 | 短期令牌优先内存保存，不能写入普通配置文件或阅读缓存 |
| Android | HTTPS Bearer 访问令牌，刷新凭据使用平台安全存储 | 处理进程重建、会话过期与退出后的凭据清理 |

Cookie 名称和作用域与 MyHome 区分，优先主机限定 Cookie。Web 与原生传输适配可参考 MyHome，但不能把 Android/Windows 等客户端声明当作可信身份或授权依据；原生写请求必须携带有效 Bearer 凭据。会话保存和撤销设计参考 [OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

管理端推荐 Flutter Web 独立 /admin 入口，使用独立管理会话 Cookie/CSRF 与 admin 受众；client Token 不被管理接口接受。菜单、路由、按钮和管理字段使用当前受众的权限快照，快照不明或失效时不能先渲染受限内容。

退出/换账号必须停止播放器、下载、事件订阅和旧请求的结果应用，清除旧用户的内存状态、私有磁盘缓存、临时文件及凭据。本机缓存命名包含服务实例和 user_id；迟到响应通过账号代次检查丢弃。服务器已提交任务不因退出自动取消，私有结果仍只属于原用户；已发布的global_word目录音频独立保留，不转移任务或费用归属。

首次登录需要联网。离线只访问当前账号权限快照允许的章节、已保存词句解释和音频副本，并受有效离线租期限制（首版建议最多 24 小时，时长需配置验证）；解释同时要求实际来源read与ai.explain，音频要求实际来源read与speech.play，细则见 [学习结果缓存](learning-cache.md)。管理操作必须在线。联网先重查状态和权限，明确失效/撤权时清理对应缓存，不能当普通断网继续绕过。离线设备及已下载文件无法保证瞬时远程撤权。

## 4. 后端授权边界

身份从认证上下文获取；所有列表、详情、统计、写入和嵌套引用先验证当前动作权限，再验证归属/授权范围。不能仅凭猜不到的 UUID、角色名称或前端隐藏入口保护数据。

Haruka 使用独立数据库和数据库账号，P0 用户数据采用同库、同 schema 的共享表；每次私有数据访问必须携带由受信任身份构造的 `ScopeContext`。P0 不启用 PostgreSQL RLS，不按用户另建数据库/schema，也不声称数据库能自动阻止任意 SQL 的跨用户读写。管理服务使用明确授权的元数据范围，不能通过构造另一个 owner 的作用域取得私有内容。建表、查询与逻辑关联的完整规范见 [数据库规范](../engineering/database.md)。

| 对象/路径 | 必需约束 |
| --- | --- |
| 数据库查询 | 私有仓储强制接收ScopeContext，系统目录用限定资源/动作的CatalogScope；查询、更新、删除均附加当前授权范围，不存在或他人资源返回一致的不可访问结果 |
| 关联与批量写入 | 私有父记录/目标按ScopeContext逐一验证owner、library、版本与状态，同库子记录不能只校验首条；global_word引用另由目录服务验证受控词条/profile与状态，不能因此省略私有侧归属 |
| 注册初始化 | User 与 Library 关联唯一，失败回滚；客户端不能指定其他账号为所有者 |
| MinIO | Bucket不匿名开放；私有对象由后端分配用户路径，上传完成/下载签名验证所有者；global_word用独立实例前缀，下载/签名按[全局词音](learning-cache.md#51-收藏库标准单词发音的全局缓存)检查本人collection.read、speech.play及条目/读音/profile匹配，不要求贡献者owner |
| Redis | 配置、解释、私有音频索引、幂等键和通知按用户分区；仅global_word目录热副本/生成协调使用实例级键，不扩大个人请求/任务读取范围 |
| Kafka/Worker | 消息引用 Job；Worker 重查发起者/所有者、当前动作权限、对象、账号状态和 credential_id，不直接相信消息或旧权限快照 |
| 用户端 SSE/任务接口 | 按动作权限订阅、查询、重试和取消自己的任务；管理端仅经专用接口取得授权的元数据/运维能力，不全局广播私有结果 |
| Agent | Pydantic AI 运行依赖由后端注入身份；工具以调用者范围执行，模型不能通过生成 user_id/library_id 扩大权限 |
| CSV | 导出仅当前用户单词；导入 ID 和来源只是数据，不能决定归属或取得原文权限 |
| 试卷/考试 | 原卷、版本、题面、答案、草稿、场次、评分依据、成绩与批改任务均检查所有者；保存/交卷另验编辑代次、版本、状态和服务端时限 |
| 日志与埋点接收 | 已登录记录由服务端绑定用户；匿名入口仅接受受限事件且 user_id 为空；不能伪造来源或通过日志入口读取他人信息 |
| 管理 API | 验证 admin 受众与具体权限；仅允许管理服务的目标范围/DTO 字段，不能绕过普通用户接口的所有者限制 |
| 角色/权限变更 | 验证授予上限、有效继承权限、受保护目标与 revision，事务保存审计；不能自提权或移除最后一个可登录超级管理员 |

数据库不创建物理外键或组合外键，保留 PK、UNIQUE、NOT NULL 和行内 CHECK。跨表归属和引用有效性由实际服务执行；引用新增与父对象删除必须共用数据库规范中的父行锁/代次协议，防止“校验后被删除仍写入”。归属在创建后固定，删除/GC 先标记 tombstone 再按保留规则回收，不能靠修改 owner/library 转移数据。使用至少两个真实账号及真实 PostgreSQL 集成验证这些服务边界；未来若引入 RLS，需独立设计、评估和验收，不能替代已有 API/Worker 授权。

预签名下载地址是短期访问凭据，签发前必须鉴权。已经签发的地址通常在到期前仍可使用，不能承诺退出登录会立即撤销它；使用短有效期、禁止记录 URL，若需要即时撤销则走鉴权代理。

三端与管理 Web 日志队列按服务实例、账号与受众分区，退出时尽力发送后清除，不能在用户 B 登录后用 B 的会话补发 A 的记录。未登录事件保持匿名，不能补认成已认证历史。Loki/Grafana 仅供独立获授权的运维人员使用，应用管理角色和标签过滤不构成平台访问授权；具体入口、脱敏和补传规则见 [统一日志与前端埋点](../operations/observability.md)。

考试使用专用题面 DTO，答题期间不返回标准答案、隐藏解析或 rubric；答卷提交后锁定，结果按场次状态读取。用户切换清除旧账号本地答题草稿，不能用新会话补交；同账号另一端接管需验证编辑代次。原文件属于用户自己的材料，这些考试流程限制不构成监考保证，具体见 [试卷模式](../modules/exams.md)。

## 5. 个人 API Key 与费用归属

- ProviderCredential包含user_id、供应商、密文、credential_version（用户Key更换/撤销代次）、encryption_key_version（部署加密Keyring ID）、row revision和状态；读取仅返回掩码，不混用两种版本。
- 部署加密主密钥与认证签名密钥分离，不能复用 MyHome 的秘密。
- 当前用户/任务只能引用自己的凭据；任务消息不包含密钥明文。
- 管理员不能读取个人 Key 或借管理重试发起未经原用户当前权限/授权允许的付费调用；每个新付费阶段复核权限。
- Pydantic AI 模型客户端按本轮用户绑定，禁止通过全局环境变量或共享可变客户端切换 Key；运行依赖和凭据不进入对话/执行记录，见 [Agent 运行层](agent-runtime.md)。
- 用户缺少 Key、删除或撤销 Key 后，相关新调用失败或暂停；不回退到其他用户、服务器公共 Key 或 MyHome Key。
- 解释/私有TTS缓存及请求合并按用户隔离；[标准收藏词音](learning-cache.md#51-收藏库标准单词发音的全局缓存)以受控词条/读音/profile跨用户复用和合并。其Job、Key、费用和收藏关系仍属各自用户，不用共享音频权限读取贡献者内容或借用凭据。
- 单用户调用次数/并发/存储限制与全局上限共同生效。记录内部用户 ID、任务和用量，不记录密码、Token、Key 或材料全文。

## 6. 会话存储、刷新与撤销机制

### 数据职责

PostgreSQL AuthSession 保存 session_id、user_id、audience、transport、created_at、absolute_expires_at、revoked_at、创建时的用户/受众安全 epoch、近期重验时间和安全设备摘要；它是持久身份/撤销事实。User 保存 security_epoch 与各受众 epoch，区别于 RBAC authz_version。Redis 保存Web随机会话摘要/CSRF状态或原生刷新摘要/代次，以及idle TTL、短期重复请求回执和限流；Redis 丢失只能要求重新登录。

原生受保护访问验证JWT固定算法/issuer/audience/exp/sid；Web以Cookie摘要查服务端会话，不信任客户端自报sid。两者均读取PG用户、会话撤销/epoch/绝对期限、当前权限版本和Redis存续；transport与受众必须匹配，混合Cookie/Bearer身份拒绝。不能只依赖JWT、自报设备ID或异步缓存删除。会话元数据过期可按留存任务清理，账号管理页只返回必要设备摘要，不回传令牌。

推荐初值：原生用户访问JWT 15分钟；用户会话绝对7天、空闲24小时；管理Web会话绝对8小时、空闲30分钟，敏感操作要求5分钟内重验。Web续期/原生刷新均不延长绝对期限，客户端以服务器时间/响应期限判断，不能靠调整本地时间延寿。

### Web续期与原生并发刷新

Web正常业务访问或显式/auth/refresh只原子延长Redis idle TTL到不超过PG绝对期限，不轮换Cookie、不发送新的Set-Cookie。因此多标签常规续期无旧刷新Cookie迟到覆盖问题；失效会话必须重新登录。GET auth/csrf返回绑定当前会话的CSRF值，允许前端内存持有；Cookie写操作校验CSRF Header和Origin，登录/注册等尚无会话的写操作也要求可信Origin与JSON。带浏览器Origin的请求不能伪装native逃过来源验证。

Web登录/退出/换账号/近期重验属于身份变更，跨标签协调并广播“身份可能变化”，其他标签暂停私有写入，重新取当前Cookie的me/access最小身份后再绑定缓存；不广播秘密，不要求额外profile.read。重验成功创建新会话标识并撤销旧会话，不能把认证提升绑定到不变的旧标识。异常并发/迟到身份响应一律重新查询服务端当前身份；无法确认则清空私有UI并重新登录，不仅凭返回的邮箱切换缓存。改密/重置撤销全部会话。

原生ApiClient使用single-flight；刷新携带稳定refresh_request_id，同次网络重试不变，以会话/当前摘要/代次CAS原子轮换。成功后保留旧摘要和绑定原request_id的短期加密回执最多10秒，支持同次丢响应重试；只有最新代次可回放，不返回已被更后代次替换的凭据。窗口内不同request_id的旧摘要返回409 REFRESH_SUPERSEDED，不立即全家撤销；协调读取最新安全存储后最多再试一次。窗口外旧凭据重放撤销会话家族。

原生响应含session_generation，安全存储按会话/代次CAS更新，旧响应不得覆盖新值。窗口外无法恢复则重新登录，不永久保存旧凭据。仅ACCESS_EXPIRED触发一次原生刷新；权限不足、禁用、撤销或CSRF失败不循环刷新。自动重放业务请求受 [API幂等规则](../contracts/api.md) 限制。

### 退出、改密与强制下线

本人退出先在 PostgreSQL 标记当前会话撤销并记录安全事件/Outbox，再清 Redis 和客户端 Cookie/凭据；重复退出幂等。客户端网络失败也先本地清理并明确“本机已退出，远端撤销未确认”，不能宣称远端成功。失效凭据也允许本地清 Cookie，不得以失败阻止退出。

改密验证当前密码、活跃会话与 CSRF，事务更新哈希并增加 security_epoch，撤销两端既有会话；响应后重新登录。管理员撤销某会话以 PG revoked_at 为准，撤销所有/某端会话则增加对应 epoch；审计和撤销在同一 PG 事务生效，Redis 删除经 Outbox 重试。移除 login 权限会在授权事务推进受影响端 epoch，之后重新授予也不复活旧 Token。

普通退出/设备强制下线不自动取消已受理 Job；禁用、撤销动作权限或取消 Job 才停止其后续受限执行。相关语义见 [数据与任务](../architecture/data-jobs.md)。

## 7. 验收条件

- [ ] A/B 两用户通过替换材料、收藏、题目、对话、音频、任务及凭据 ID 均不能越权。
- [ ] 同库同 schema、无外键且未启用 RLS 的实际服务拒绝混合所有者/资料库/版本的关联和批量写入；新增引用与父删除/GC 竞争不产生新悬空引用，验证边界见数据库规范与 DAT-01/DAT-06。
- [ ] 列表、搜索、统计、CSV、流式事件和下载签名不返回另一用户内容。
- [ ] 注册并发、失败和重试不会重复创建或遗留孤立 Library。
- [ ] 登录/刷新/退出/改密在三端可用；失效会话和刷新重放不会继续访问业务。
- [ ] Cookie 请求验证 CSRF；伪造客户端类型不能绕过认证或写权限。
- [ ] 用户 A 退出后用户 B 登录，缓存、音频、迟到响应与通知均不串用。
- [ ] A 的 Key 缺失时不会调用 B 或 MyHome 的 Key，Worker 重试保持原用户范围。
- [ ] Redis 会话丢失时要求重新登录，业务数据保持完整。
