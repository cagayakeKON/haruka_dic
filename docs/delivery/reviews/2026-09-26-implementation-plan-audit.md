# 实施阶段合理性与功能覆盖审查

日期：2026-09-26。编号：PLAN-AUDIT1。审查基线：`5162695`。本轮检查六阶段计划、脚手架里程碑、功能覆盖与验收、产品总览、12个模块及相关架构/契约，并静态对照手机/电脑HTML原型。正文所列行号均指该基线；相对链接打开当前文件，后续修改可能使行号移动。

本轮只新增审查记录及索引，不修改实施方案、业务规格、原型或正式代码。审查期间工作区另有B0数据库就绪检查修订，未纳入本轮变更或审查结论。B0已验收、B1/B2未实现的状态保持。

## 1. 结论

**六阶段的大方向合理，但目前不能认定它是一份完整、无冲突、可直接逐项签收的实施计划。**

- 依赖主线成立：身份/授权/任务基础 → 材料与稳定出处 → 解释/收藏/音频 → 作答/评分/学习事实 → CSV → 发布运维。没有发现整个原型主模块或整个P0业务模块完全没有阶段归属。
- 确认6项计划/契约问题，均按问题严重程度记为P2：4项本轮发现，2项继承已有缺口。这里的P2是问题级别，不表示将相关产品功能降为产品P2。
- 完整性缺口主要是：听力试卷就绪条件跨阶段冲突、部分数据库首次落地晚于消费功能、站内消息缺少可执行契约与验收、生成错误题删除仍缺契约、章节下载优先级冲突，以及新增验收未完整并入阶段清单。
- 六阶段面向MVP/v0.1。产品文档中的P1/v0.2、P2/v0.3+增强功能有版本归属，但没有完整实施阶段。因此，如果“所有功能”包含这些后续版本，答案是**尚未全部纳入可执行阶段计划**；不能据此擅自把它们提前为P0。

本报告确认的是设计与计划覆盖，不是实现覆盖率。没有为“100%覆盖”提供可量化依据，也不把原型演示算作正式交付。

## 2. 已确认的问题

### PLAN-01：阶段2要求听力试卷ready，但必要音频在阶段3才交付

级别：P2。状态：待修订，本轮新发现。

- [路线图](../roadmap.md)第130、136、143行要求试卷冻结、校对后进入ready；第131行却明确“TTS生成在阶段3”，第151行才实现确认脚本后的私有音频。
- [考试](../../modules/exams.md)第55～60行规定必要媒体缺失阻止确认，冻结版本包含AudioBinding，只有具备可播放冻结音频的听力卷才能ready。[解析结构](../../contracts/material-structures.md)第157、179行同样要求验证必要音频后冻结。
- [数据库材料分册](../../architecture/database-materials.md)第260、268、277行只有ready前可编辑草稿、needs_audio问题及ready时冻结的定义，不能解释成“阶段2先冻结完整卷，阶段3再补写音频”。

影响：以带听力样本验收阶段2时，要么无法完成该阶段，要么为了通过清单错误放行缺音频的试卷。

建议修订：阶段2区分无听力卷与含听力卷；前者校验后可ready，后者完成脚本/题目候选及人工确认，停在待音频状态。阶段3验收音频、最终冻结与ready；阶段4再验收开考及播放账本。修复后应核对三个阶段的验收措辞与同一状态机一致。

### PLAN-03：站内消息已有原型与数据设计，但契约和验收未闭环

级别：P2。状态：待补齐，本轮新发现。

- [手机原型](../../../prototype/phone.js)第453～454行和[电脑原型](../../../prototype/desktop.js)第414～415行包含消息列表、未读及全部已读操作；[材料模块](../../modules/materials-reading.md)第142行明确用户离线后返回仍能查询站内完成提示。
- [通知表设计](../../architecture/database-learning.md#77-user_notifications--本人站内任务提示)已有持久通知、事件去重和read_at，[全表清单](../../architecture/database-convergence.md)第226行将其归入阶段2。因此这不是“完全没有设计或阶段”。
- 但数据分册第495行仍明确列表/已读API与权限映射须在功能切片补入；路线图和[覆盖索引](../coverage.md)只有消息入口与任务进度的间接说明，没有消息列表/已读的交付验收。[WSP-01～05](../../contracts/job-progress.md#4-验收)验证的是实时任务进度，不能证明持久消息和已读状态。

影响：材料进度WebSocket通过后，仍可能遗漏原型已有的消息入口实际功能，或由前后端各自定义列表、已读和权限行为。

建议修订：在阶段2明确站内通知切片，补列表/未读/已读契约及覆盖索引；验收离线后可查、重复事件不重复提示、已读跨端一致、全部已读的作用范围、账号隔离及来源失权后的安全跳转。仅限站内提示，不扩成邮件或系统推送。

### PLAN-04：生成错误题删除已保留为需求，尚不具备实施与签收条件

级别：P2。状态：已知缺口OPEN-10仍开放，本轮确认。

[产品总览](../../product/overview.md)第127行、[收藏与公共作答](../../modules/vocabulary-practice.md)第220行和[OPEN-10](../../decisions/pending.md)第22行都明确保留“用户删除AI生成错误题”，并承认操作语义、历史版本、权限/API/验收尚缺。数据库总册第164行已将OPEN-10关联阶段4，因此不能说该需求完全没有登记。

问题在于[阶段4](../roadmap.md#阶段-4ai习题错题库模拟考试与-agent)的实施和勾选项尚未形成这项用户操作的闭环。[AIX](../../modules/ai-exercises.md)与[VL](../../architecture/vocabulary-learning.md)中的“题目作废后重算”只规定下游行为，不能代替用户如何发起删除/隐藏/作废的契约。

影响：其余出题、错题和掌握验收通过，也不能说明这项明确保留的需求已经交付。

建议修订：按OPEN-10既定门禁，在相关练习契约冻结前明确用户操作语义，补权限、API、历史作答/冻结版本保留及学习证据处理，再把正式验收关联阶段4。本轮不替用户选择删除语义，也不把它降为P1。

### PLAN-05：所选章节提前下载仍被一处旧文案归为P1

级别：P2。状态：继承既有AUDIT1/DOC-01，仍待修订。

[设置](../../modules/settings.md)第5行已经承接所选章节提前缓存，第140行却仍写“P1才增加整章选择下载”；[路线图](../roadmap.md)第23行和[章节准备](../../contracts/novel-preparation.md)第54、67行已将所选章节的解析/音频下载纳入阶段3及NPREP验收。

影响：阅读/章节准备开发按P0实现，而设置/缓存开发可能把必要下载路径或状态推迟到P1。此问题已由[既有审查DOC-01](2026-09-26-business-design-audit.md)登记，[数据库修订](2026-09-26-database-audit-fixes.md)未关闭它，不重复算新发现。

建议修订：P0保留用户所选章节的解析/音频准备、完整下载校验及本机就绪；P1只保留下载中心、队列管理、固定保留等后续增强。同步检查设置、缓存、章节准备的范围措辞。

### PLAN-06：新增验收已写入附记，阶段主清单仍使用旧编号范围

## 4. 六阶段之外的功能与待决边界

[产品总览§6](../../product/overview.md#6-优先级与版本边界)明确区分P0/P1/P2。以下功能已有文档登记，但六阶段没有为它们安排完整开发和验收节点：

| 后续版本 | 已登记的主要范围 |
| --- | --- |
| P1材料/阅读 | 小说/课本PDF/OCR/TXT、普通块校正、分页/正文双语对照/阅读热力图、教材单元完成度与讲练分屏 |
| P1收藏/习题 | 智能筛选本、多图词表、匹配/排序/听写、易混词/语法变形、扩展写作/多句翻译、人工覆盖 |
