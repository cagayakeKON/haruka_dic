# 测试素材、场景工厂与运行数据

状态：设计基线 v0.1，2026-09-22，未实现、未执行。本文规定后续测试数据的来源、创建、隔离、使用和清理；不会创建素材、账号、测试接口或基础设施。用例层级与通过条件以 [测试规范](TESTING.md) 为准，平台驱动与 Test ID 见 [前端 E2E](FRONTEND_E2E.md)，B0/B1/B2 范围见 [脚手架验收](SCAFFOLD_ACCEPTANCE.md)。

## 1. 约束等级与三层数据

**必须**区分可提交到仓库的固定样本、声明式场景和每次执行产生的数据，避免共享可变账号或复制生产数据。**推荐**通过同一场景工厂供后端集成、Flutter 集成与平台 E2E 使用，测试驱动只负责平台操作。**例外**按 [交付验收](DELIVERY_ACCEPTANCE.md) 记录依据、范围、责任人和期限，不允许以方便复现为由连接或清理 MyHome 生产资源。

| 层 | 未来权威位置 | 内容与维护规则 |
| --- | --- | --- |
| 固定素材 | testdata/assets/，索引为 testdata/assets/manifest.json | 自建或许可明确的英/日文本、CSV、题图/试卷、音频与供应商响应样本；内容固定、版本化且可验证摘要 |
| 场景声明 | testdata/scenarios/，推荐 YAML | 素材引用、允许的准备配方、角色/状态、时钟与供应商模式、验收引用和预期别名；不存运行 ID、数据库地址或秘密 |
| 运行数据 | 本次隔离资源及不入库的运行目录 | 本次账号/资料库、业务对象、会话、任务、对象键、下载、日志与执行账本；按 run_id/case_id/分片/重试隔离，结束后受控清理 |

未来工厂实现位于 backend/tests/support；已规划的 backend/tests/fixtures 将引用工厂、素材 ID 或生成临时样本，不再复制第二份固定素材。Flutter 和浏览器测试也按清单引用同一来源，需要设备可读文件时复制到本次临时目录并核对摘要，不能另维护一份内容相同但独立修改的样本。

生产 Python wheel、运行镜像和 Flutter 发布资源不包含 tests/support、场景声明、测试账号或测试素材。测试 harness 与被测应用分进程、分职责：harness 可以从测试代码运行工厂并操作隔离依赖，生产应用不导入测试支持模块，也不因此获得通用测试管理接口。

## 2. 固定素材与场景声明

### 素材清单

manifest 至少记录 asset_id、版本、相对路径、SHA-256、媒体类型、字节数、语言、来源/许可和用途。文字相关素材另记录所用规范化/定位协议；音频记录实际容器/编码与采样信息；CSV 记录协议与预期逻辑记录数。预期结果注明人工确认依据或确定性规则，不能仅把当前实现输出保存为“正确答案”。

修改素材语义、题目依据或规范化方式时增加版本并复核依赖用例，不静默覆盖原版本。路径必须位于素材根目录，拒绝路径穿越、外部 URL 和未登记文件；大小/解析深度受限。缺文件、摘要不符、许可不明或版本不支持使准备失败，不下载任意外部文件补齐。

| 素材族 | 最小内容 | 不得误认为已验证 |
| --- | --- | --- |
| 文字/出处 | 英/日、假名/汉字、组合字符、emoji、注音、换行、跨块选区与多个内容版本 | 有样本不表示三端定位转换已通过 |
| 单词 CSV | 最小单列、Haruka 格式、多行/引号/标签、公式前缀、重复/冲突与失效 locator | 不包含真实词表；文件行数不能代替逻辑记录数 |
| 试卷 | 共享材料、题图、有/无标准答案、分值冲突、未支持题型和合法冻结版本 | 最终支持格式按产品决定；扫描/OCR 样本不能自动扩大 P0 |
| AI/TTS | 合法输出、结构错误、伪造来源、拒绝/限流/unknown 响应及合法音频字节 | Fake 内容不证明语言质量、真实供应商能力或用户实际听到了音频 |
| 隐私/异常 | 明显的假秘密哨兵、超长字段、非法编码/损坏数据等受控负例 | 负例不能被种成可用业务结果后宣称正常路径通过 |

### 声明式场景

场景只引用工厂登记的配方与模式。输入 schema 由工厂中的版本化模型维护，必要时导出供检查使用，不另手写一套不一致的验证规则。YAML 只承载数据，禁止任意对象构造、Python 表达式、shell/SQL、动态模块路径或可执行模板；未知字段和未知配方拒绝。

下面是未来声明的结构示意，引用值需在工程建立时登记，不是现有可执行场景：

~~~yaml
schema_version: 1
scenario_id: collection_owner_isolation
scenario_version: 1
acceptance_refs:
  - SCF-B1-03
  - COL-004
setup_recipe: owned_collection_sources
asset_refs:
  - english_unicode_excerpt_v1
  - japanese_unicode_excerpt_v1
actors_profile: collection_ab_minimal
recipe_params:
  source_assets:
    owner_a: english_unicode_excerpt_v1
    owner_b: japanese_unicode_excerpt_v1
clock_profile: real
provider_profile: blocked
expected_aliases:
  - users.owner_a
  - users.owner_b
  - sources.owner_a
  - sources.owner_b
~~~

acceptance_refs 关联产品/脚手架验收，不能代替真实 case_id 与执行结果。一个准备场景可以服务多个用例，但每个目标动作和参数仍在 required_cases 与相应用例中单独登记。场景更新必须说明会影响哪些用例；不因改了默认角色或素材而悄悄降低断言。

每个 setup_recipe 必须登记自身有类型的 recipe_params 和准备输出别名合同；多份素材与多个主体之间显式绑定，不能靠数组顺序猜测。参数引用的素材必须出现在 asset_refs，主体必须由 actors_profile 定义，expected_aliases 必须与该配方声明的准备输出一致。缺失、多余、重复或所有者不匹配的别名使准备失败。示例配方只准备 A/B 账号及各自来源，不生成目标收藏；后续真实创建产生的收藏属于运行结果。

## 3. 身份、命名空间与别名

四类标识各负其责：UI Test ID 稳定定位控件；case_id 稳定标识测试场景；run_id 标识一次测试运行；业务 ID 由应用/工厂按正常约束创建。任何一种都不是认证凭据，不能把 run_id/case_id 放进请求后就免除权限与所有者检查。

| 运行维度 | 规则 |
| --- | --- |
| run_id | 每次运行全局唯一，不复用历史运行的可变账号、缓存或任务 |
| case_id | 来自版本化用例清单；同一行为跨次运行稳定，不能根据成功结果动态生成 |
| shard_id / attempt | 区分并行执行器与本次重试；首次失败仍保留，重试使用新运行数据，不清掉失败证据 |
| variant | 记录平台、runner、测试层级、受众/传输和必要参数；同 case 的不同参数用规范化摘要区分，避免同分片内撞名或一种驱动结果覆盖另一种 |
| resource_namespace | 由上述执行身份生成；针对 PG/Redis/Kafka/MinIO/文件名长度与字符约束规范化，并保留摘要及原始映射，不能简单截断造成碰撞 |

随机种子可以固定生成的词句、顺序与预期值，但运行 ID、账号和资源名称仍独立。业务主键遵循应用的正式生成规则，不由固定种子强制复用；同一执行身份幂等 prepare 返回已创建并核实的相同引用，新 run/attempt 则创建独立数据。测试需重放并发或幂等时，在同一用例内明确复用其业务请求/幂等键；不能把所有重试、分片或用户共用一个固定 key 当作可重复性。

工厂返回本次准备阶段的 alias_map，例如 users.owner_a → 用户引用、sources.owner_a → 材料/版本/选区。测试驱动在真实目标操作成功后，可将返回的收藏 ID 登记为 collections.target 等运行结果别名，并在账本标明其来源步骤；这类结果不能提前成为准备输出。别名是测试代码的逻辑名称，不是 YAML 的对象引用语法；实际值只能来自本次受控创建或经过核验的不可变公共样本引用。A/B 映射包含独立所有者/资料库，跨次复制用户私有对象的裸 UUID 必须拒绝；固定 asset_id 不等于可复用的数据库业务主键。

测试通过 alias_map 找到对应对象和预期来源，不使用列表第几行、邮箱显示文案或固定数据库主键定位。UI 重复项的 Test ID 组合遵循前端 E2E 规范；不得把密码、Token、单词/题目正文编码进标识。别名/业务 ID 可辅助断言，服务端仍从真实会话取得当前用户。

## 4. 场景工厂与合法前置条件

### 输入、输出与秘密通道

| 接口部分 | 合同 |
| --- | --- |
| 输入 | scenario_id/版本、case_id、run_id、分片/attempt/variant、确定性随机种子、已允许的时钟/供应商模式；环境目标由受控 harness 配置选择，不接受场景自报任意连接串 |
| 准备前检查 | 明确 dev/test、允许的目标实例与数据库/存储指纹、迁移 revision、素材/场景摘要、资源归属、所需依赖与并发模式；不以名称带 test 作为充分依据 |
| 非秘密输出 | 场景/执行标识、素材与 schema 版本、alias_map、预期值、无认证信息的服务地址、资源账本引用、准备状态；不含密码、Cookie、Token、Key 或完整数据库连接串 |
| 秘密交付 | 合成账号的一次性登录秘密、harness 自身所需连接能力通过受控进程内存、管道或受限临时秘密文件另传，明确接收者与销毁时机；不进普通 JSON 输出、命令参数、截图或日志 |
| 重复/失败 | 同一执行身份的重复 prepare 要么返回已经核实的准备结果，要么明确状态冲突；不能覆盖正在测试的记录。部分准备失败保留账本并只回收本次资源，不能返回半成品 ready |

已规划的 check 入口将协调独立 fixture/测试 CLI，生产 haruka-manage 的受控初始化与测试 harness 保持边界。测试支持代码不打进生产包；不得新增公开 seed、debug/login、set-clock、任意 SQL 或强制成功 HTTP 入口。

UI 测试经正式登录控件使用合成账号登录，不把 SQL 账号、后台管理连接或会话 Token 注入 Flutter/浏览器以跳过登录。需要后端断言的 harness 使用自己受控且作用域明确的连接/正式 API 会话，不能把这种能力传给用户端；登录、会话恢复或权限本身为测试目标时必须完整走相应真实路径。纯 widget 测试的依赖覆盖须标明层级，不得冒充 E2E。

已认证context仅在同一run/case/shard/variant/attempt/actor/audience内复用。跨执行身份重新准备账号与会话并UI登录，不导入通用setup的storageState；同一用例中验证会话恢复可显式保存/恢复该用户状态，但仍先完成本次UI登录，状态文件按秘密管理。该边界与前端E2E专题一致。

### 准备配方与目标动作

场景工厂可通过正式服务或专用测试 fixture 创建合法前置状态，但必须遵守真实外键、归属、内容版本和状态不变量，记录跳过了哪些非目标流程。例如收藏用例可预置已解析材料；这不证明上传/解析通过。考试答题用例可预置合法 ready 版本；试卷导入/校对用例则必须从真实文件和目标操作开始，不能直接种好最终结果。

测试前准备应与目标动作有明确边界：不预先写入要验证的收藏，不直接把 Job 改成功，不在测试期间替 UI 保存答案。目标动作走真实 UI/正式 API/Worker，并检查服务端已提交结果。直接构造非法记录仅限明确的约束/拒绝测试，期待数据库或边界拒绝，不能将其复用为合法业务 fixture。

| 场景维度 | 必须可选择的前置条件 | 重点核验 |
| --- | --- | --- |
| A/B 与角色 | 独立 User/Library；最小允许、只读、login-only、显式 deny/继承与受保护目标；client/admin 受众；pending/disabled/locked | 默认不授予超级管理员；无动作权限与无来源权限分别测试 |
| 来源/收藏 | 本人有效版本/选区、B 的来源、旧版本、失效/删除来源、独立快照 | 真实 Unicode 偏移与归属；不得因知道 alias/ID 越权 |
| 试卷/答卷 | 本人/B 的冻结版本、合法计分依据、未开始/作答中/已提交、编辑代次与草稿 revision | 使用真实状态转换或经校验的前置配方；保存/交卷目标不由 fixture 代做 |
| 任务/模型 | 未配置/有效测试引用/已撤销凭据；正常/拒绝/无效输出/unknown 模式 | 当前权限/预算仍校验；模拟供应商不直接改业务表 |
| 会话/客户端 | A/B 独立会话、原生/浏览器传输、干净缓存及明确的旧状态 | 多标签场景共享同一个预定浏览器上下文；独立用户场景使用隔离上下文，设备仅清理本次测试应用 |
| 日志与文件 | 正常/错误事件、哨兵、下载/临时对象与中断传输 | 正常 info 与失败均可查，秘密和正文不进入报告；导出响应不等于系统保存成功 |

无需每个用例一次生成所有组合；按 [测试规范](TESTING.md) 选择有意义的正负例。注册/恢复模式、试卷格式尚未确定时保留明确决策门禁，合成 active 账号或 prepared 试卷不代表这些功能已经实现。

## 5. 时钟与供应商替身

可控的是应用显式注入的业务时钟。规则/状态机和适用的 API/Worker 测试可以冻结或推进同一场景时间，配合屏障控制截止、租约和迟到结果；记录起点、推进步骤与结果。共享进程中的并行用例不能修改一个全局 now 影响别人；需要虚拟时钟的 E2E 运行使用专属后端进程/实例或经过验证的场景隔离机制，控制面只在测试 harness。

| 时间/依赖 | 允许的验证方式 | 边界 |
| --- | --- | --- |
| 业务截止、学习窗口、重试状态机 | 注入时钟与确定性调度，API/Worker 使用同一场景时间 | 不靠等待几分钟验证纯规则，也不能只推进前端倒计时替代服务端判定 |
| Redis TTL、数据库自主时间、JWT 库内部时钟 | 使用其真实机制及受控短期限，或明确验证过的时钟适配 | 不假设它们会随业务 fake clock 改变；不能关闭到期校验来使测试通过 |
| 浏览器 Cookie/TLS、系统文件框、音频/后台生命周期 | 实际浏览器/OS 与有界等待 | 不调整宿主全局时间，不以虚拟时钟证明系统级行为 |
| 网络、Worker 竞争与超时 | 明确屏障、代理/进程故障、真实依赖和截止等待 | 记录操作顺序与超时；不使用固定 sleep 猜服务或任务已就绪 |

常规集成/E2E 的 Fake 仅替换模型或其他明确外部供应商边界，PG、Redis、Job、Outbox、Kafka、Worker、SSE 及权限/凭据校验保持真实。模式仅能由 dev/test 组装配置注入，staging/production 拒绝 Fake 和测试 seed；用户输入、Header 或管理目录不能启用。具体规则以 [脚手架 B2](SCAFFOLD_ACCEPTANCE.md) 为准。

独立 HTTP/TTS 出站也要被限制，不能只关闭文本模型 SDK 请求。Fake 音频可验证格式、传输、缓存和播放器状态；声音质量、真实供应商能力与实际设备听觉效果仍按独立授权的质量/平台验收处理。模拟用量、延迟和失败模式需明确标识，不当成真实费用或性能基线。

## 6. 并行运行与全局状态

优先每个运行/分片使用独立测试数据库或经过验证的隔离 schema，账号与业务对象进一步按执行身份分区；Redis key、Kafka topic/group、MinIO bucket/对象前缀、下载目录和客户端存储均登记真实目标。共享不可变素材可以只读复用，可变账号、会话、答卷或任务不跨用例复用。

修改注册策略、全局模型/配额目录、权限种子、迁移版本、共享时钟、全局/IP 限流或应用配置的场景使用独立实例；确需同实例时，在使用该实例的全部受影响用例之间串行并受独占锁保护，不能只让几个配置修改用例互斥而让其他测试继续受其影响。仅换 user_id 或 key 前缀不足以隔离全局策略。获取独占权失败不能继续执行；恢复失败后该环境不得供下一用例使用，不能用 try/finally 的“已尝试恢复”冒充恢复成功。

并发竞态用例内部可以有多个用户、API 实例或 Worker，共用的是该用例声明的隔离依赖与协调屏障。跨实例共享 PG 是测试目标时不得改成各自内存库；多设备一致性目标不得改成三个独立后端然后宣称同步通过。

同一原生设备/桌面用户配置中的用例串行执行；并行需要独立设备/模拟器或经过验证的应用身份与数据profile。设备重置只操作本次测试应用/凭据/缓存，不能清除用户正式安装的数据。同一多设备用例可以共享声明的actor验证同步；这不允许其他用例同时复用该账号。

## 7. 资源账本与清理

运行账本在 harness 侧维护，记录执行身份、创建意图/实际资源 ID、目标指纹、数据库对象/命名空间、对象键、进程 PID/启动时间、客户端测试身份、依赖关系和生命周期。秘密仅记录受控引用，不记录其值。创建前登记意图、成功后补实际引用；超时后状态未知须按本次已知引用核对，不能扩大查询/删除范围寻找可能的残留。

准备、运行、清理状态分别可追踪。清理顺序必须为：

1. 停止本次 UI/harness 发起新操作，关闭其 SSE、下载和轮询；记录当前 Job/Outbox/外部调用状态。
2. 通过既定任务协议明确取消或封存本次在途任务，推进/核对取消与代次 fence；等已领取执行到达安全边界。普通退出登录不能代替 Job 停止。
3. 验证旧 Worker/迟到结果与待投递 Outbox 不会重新提交已清理对象，再停止本次专属消费者/进程。使用共享测试 Worker 时只隔离本次任务，不能停止其他用例进程或删除其 Topic。
4. 在确认安静状态后，按账本及依赖顺序清理本次对象存储、消息资源、缓存、业务对象和测试账号，再释放本次基础设施；删除前重新验证目标指纹/归属，文件路径必须在本次允许根目录内。
5. 核对残留和清理结果并销毁短期秘密；成功不能仅依据发出了 DELETE 或进程退出。

上述 quiesce/fence 是“先停止或拒绝后续写入，再清理数据”，沿用 [数据与任务](../architecture/DATA_AND_JOBS.md) 的租约、代次、取消和延迟结果规则。若不能确认安全边界，在有期限的隔离环境中保留诊断与资源，记录环境/清理失败；不能继续广泛删库或依靠时间到了就强删活跃对象。清理失败不能伪装为整轮成功，也不覆盖原业务断言的结果。

运行器被强杀后，后续受控回收仅处理账本中可验证为本次创建且已无活跃租约/进程的资源，仍按以上顺序。过期回收不得只看名称前缀/TTL，不对共享实例执行清库、通配符批量删除或删除全部 Docker 卷。失败资源需要保留时登记到期时间和负责人，不无限保留会话、秘密或私人诊断附件。

## 8. 失败证据与验收

报告记录提交/制品、工具、scenario/素材版本与摘要、执行身份、别名映射的必要引用、时钟/Fake 模式、实际步骤、原始失败和清理结果。截图、录屏、网络 trace、请求附件和 DB 摘要同样按 [日志规范](OBSERVABILITY.md) 脱敏，默认不收集 Header/Cookie/Token/密码/Key/完整连接串或材料/答卷正文。需要对比合成样本内容时使用受控 fixture 引用与摘要，不把采集白名单扩大成任意内容转储。

登录秘密输入、凭据配置和测试控制通道不得被录制附件捕获；无法安全裁剪的附件不生成或拒绝上传，并留下缺附件原因。只使用合成数据仍需脱敏，因为合成账号的有效会话/密码也是访问凭据。失败记录保留第一次结果，重试另有 attempt，不覆盖原报告。

TDS 是测试数据能力的验收 ID，关联既有业务/SCF 用例，不新增产品功能或覆盖率门槛。按阶段交付相关能力，尚未使用的素材类型可标未进入范围，但已承诺的场景缺素材、准备失败、依赖不可用或清理失败均不能计为通过。

| ID | 必须证明 | 关键失败样本 |
| --- | --- | --- |
| TDS-01 | 固定素材只有一套权威索引，来源/版本/摘要可追溯 | 文件缺失、摘要变化、许可缺失、越根路径、另一份不同步副本被拒绝 |
| TDS-02 | 场景可声明、校验和追踪，工厂输出没有秘密 | 未知配方/字段、可执行 YAML、旧 schema、非法 alias、密码/Token 出现在普通输出时失败 |
| TDS-03 | run/case/shard/attempt/variant 不串用，幂等准备不覆盖运行状态 | 同 case 多参数/并行运行、截断碰撞、重试复用旧账号、部分创建超时有确定结果 |
| TDS-04 | 前置条件合法且目标动作未被 fixture 代做 | 伪造来源/归属被拒；注册/导入/交卷目标不能靠已完成种子冒充；应用发布包不含测试 support |
| TDS-05 | A/B、角色、会话、来源与试卷矩阵按需生成并验证 | 默认超级管理员、跨用户别名或 harness 将 Token/SQL 凭据注入 UI 使验收失败；业务端拒绝伪造来源或答卷 |
| TDS-06 | 时钟隔离且真实系统期限仍受测 | 只推进前端、并行全局 now 污染、Redis/Cookie 未过期却声称已过期、关闭 JWT 期限校验均被检出 |
| TDS-07 | Fake 仅限供应商与 dev/test，常规运行没有真实付费出站 | 正式环境启用、用户自报 Fake、独立 TTS 漏网、跳过 Key/权限检查时失败 |
| TDS-08 | 全局配置用例的独占与恢复有真实证据 | 两用例同时改注册/配额/限流、独占失败仍继续、恢复失败环境被复用时失败 |
| TDS-09 | 清理先停止/fence 再按账本回收，支持失败重入 | 迟到 Worker/Outbox、取消未确认、错误目标/账本、强杀后的活跃租约，不误删或复活数据 |
| TDS-10 | 失败附件脱敏，原始失败与清理结果不被重试覆盖 | 登录录屏/网络 trace 泄密、仅保留重试成功、残留资源却报全绿时失败 |

本次仅确立文档合同；所有工厂、素材目录、场景、CLI 适配和测试均待工程阶段实现，当前没有执行上述验收。
