# 代码与变更规范

状态：Draft v0.1，2026-09-22。本文是工程建立后的实施合同；当前仓库没有应用代码，不代表这些规则已由 CI 执行。

配套：[项目结构](../architecture/project-structure.md)、[API 契约](../contracts/api.md)、[数据与任务](../architecture/data-jobs.md)、[静态检查](lint.md)、[测试规范](testing/strategy.md)、[交付验收](../delivery/acceptance.md)、[认证与隔离](../architecture/authentication.md)、[统一日志](../operations/observability.md)。

## 1. 约束等级与适用范围

- **必须**：实施与交付门禁，代码审查和自动检查共同执行。权限、用户隔离、秘密保护、业务事务一致性不能以格式豁免方式跳过。
- **推荐**：首版默认实现，偏离时在变更说明记录原因、替代设计和验证。库版本、具体插件、平台限制需要实测后锁定。
- **例外**：仅对明确文件/规则/期限生效，记录跟踪项、负责人、影响和替代验证；不得全局静音检查。权限边界改变属于需求/架构变更，不是 lint 例外。

仅文档改动执行文档检查；应用工程建立后按真实配置运行。生成代码、迁移、脚本与测试也在仓库约束范围内，具体排除规则以静态检查规范为准。

## 2. 分层与依赖方向

目录的唯一详细定义见项目结构，以下约束跨目录有效：

| 层 | 允许承担的职责 | 不允许的捷径 |
| --- | --- | --- |
| Flutter 页面/组件 | 展示状态、收集交互、无障碍语义、调用控制器 | 直接解密 Key、拼 SQL、决定服务端角色继承或直接调用供应商 |
| Flutter 控制器/状态 | 业务流程、加载/错误/冲突状态、权限快照与账号代次 | 持有 BuildContext 作为长期状态；跨账号复用私有 Provider 缓存 |
| Flutter 数据与平台适配 | API DTO 转换、Drift 缓存、文件/播放器/凭据存储 | 把缓存当授权来源；在通用模块直接导入只能在一个平台运行的实现 |
| FastAPI 路由 | 请求校验、身份/权限声明、调用服务、响应映射 | 把完整业务事务、AI 调用循环或所有者判断散在路由函数中 |
| Python 服务/领域 | 状态机、授权范围、事务编排、业务校验 | 依赖 Flutter、HTTP Request 或模型自由文本决定身份/总分 |
| 仓储/模型 | 带范围的查询、约束与持久化 | 暗中 commit；提供没有明确调用范围的通用“读所有用户”入口 |
| AI/供应商/基础设施适配 | Pydantic AI、HTTP、音频格式、队列/对象存储协议 | 反向依赖路由；绕过统一费用预算、权限、日志或错误映射 |
| Worker | 领取任务、调用相同领域服务、阶段提交和恢复 | 复用已过期登录 Token、相信消息里的权限快照、直接拼业务写入 |

跨功能复用先抽稳定的数据契约/领域能力；仅一个调用方时不建立公共框架、万能 Repository 或额外微服务。domain 不反向导入 api、workers、adapters；外部资源经显式依赖注入。集成测试验证真实接线，代码审查检查跨层导入。

## 3. 命名、类型与边界模型

| 项目 | 规则 |
| --- | --- |
| Python | 模块/函数/变量用 snake_case，类用 PascalCase，常量用 UPPER_SNAKE_CASE；名称表达业务动作，如 submit_exam，不用 process_data |
| Dart | 文件用 snake_case.dart，类型用 UpperCamelCase，成员用 lowerCamelCase；组件/控制器/Repository 命名反映职责 |
| API/事件/数据库 | JSON 字段与数据库字段用 snake_case，Dart 显式序列化；既定权限码、事件码与 CSV 字段不随代码重命名暗改 |
| ID | 使用有明确语义的字段名，区分 actor_user_id、owner_user_id、session_id、revision；不将不同资源 UUID 相互代用 |
| 时间 | 持久时间为 UTC 的带时区时间，API 使用声明时区的 ISO 8601；时长用单调时钟，考试截止以服务端为准 |
| 金额/分数 | 按契约使用 Decimal/规定精度，数据库使用精确类型；不得用浮点误差决定得分边界或配额余额 |
| 文本 | UTF-8；来源偏移、规范化、语言标签必须遵循出处契约，不各端自行定义字符长度 |

Python 手写函数参数与返回值必须有类型，包括测试夹具和异步生成器；容器写明元素类型，边界先接收 unknown/object 再验证。不用 Any、cast 或 type ignore 掩盖未经验证的数据。第三方无类型接口封在小适配器中，必要时加最小准确 stub 与契约测试。

Dart 使用空安全；异步返回 Future<T>，集合带元素类型。JSON 的 dynamic 只停留在解码边界，经 DTO 校验后进入业务层；不把 Map<String, dynamic> 当长期领域模型。状态用不可变对象/明确枚举或 sealed 类型表达，不用几个可同时为真的布尔值隐含流程。

Pydantic 输入、持久化和返回 DTO 分开定义。注册/授权/Key 等敏感写入模型拒绝未知字段；公开兼容读取与供应商响应可由适配器按明确版本处理额外字段。不能原样返回 ORM 对象、供应商响应或包含答案的题目模型。Pydantic 校验之后仍需校验范围、归属、引用和业务状态；模型本身支持的数据校验见 [官方模型说明](https://pydantic.dev/docs/validation/latest/concepts/models/)。

## 4. Flutter 状态、交互与异步

1. 页面明确区分 initial/loading/empty/data/error，以及 submitting、conflict、permission_denied；无权限和无数据不能混成同一提示。
2. Riverpod 的账号、受众和账号代次是私有状态的作用域。退出/切换时释放播放器、订阅、下载及旧缓存；异步结果到达时核对代次与资源版本。
3. 页面守卫等待服务端 AccessSnapshot；菜单和按钮由有效权限推导。业务暂不可用显示原因，未授权不提前请求或渲染私有数据。
4. 不在 widget build 中请求网络、写库、发业务埋点或重复订阅；副作用进入控制器/生命周期。控制器不直接选择本机文件路径，由平台适配器返回受控结果。
5. 可等待的 Future 必须 await；明确后台执行才用 unawaited，并在被调用函数中处理错误、取消与归属。页面销毁后不更新 UI，跨 await 使用上下文前检查对应 mounted 状态。
6. 所有 Timer、StreamSubscription、播放器和控制器都有释放路径；刷新合并、重试和取消有上限。网络取消不等于服务端写入回滚，重连按请求/任务 ID 查结果。
7. 乐观更新只用于可恢复的低风险操作并有版本/回滚；注册、授权、考试保存/交卷和 CSV 确认成功必须等服务端提交确认。
8. 三端键盘/鼠标/触控及屏幕尺寸差异放平台/布局适配层。字符串进入本地化资源；错误文案不暴露原始异常或 SQL。
9. 关键控件/业务状态使用 [Test ID注册表](testing/frontend-e2e.md) 的生成常量或受限模板；Key用于Flutter定位，外部定位另验证Semantics。保留真实无障碍标签/角色，列表按稳定身份和作用域定位，不使用文案、索引或坐标作为主要契约。

异步和资源释放由 [Dart 异步文档](https://dart.dev/libraries/async/async-await)、analyzer 规则和组件/平台测试共同验证；静态规则不能证明账号切换或释放行为正确。

## 5. Python 异步、事务和任务

- 每次请求/独立任务拥有自己的 AsyncSession；不能在 gather 或多个并发任务中共享同一个会话。懒加载必须显式处理，返回 DTO 前完成所需读取。该限制来自 [SQLAlchemy AsyncSession 并发说明](https://docs.sqlalchemy.org/en/20/orm/extensions/asyncio.html#using-asyncsession-with-concurrent-tasks)。
- 服务定义事务边界，仓储只读写/flush，由上层统一 commit/rollback。注册初始化、交卷锁定与 Job/Outbox、权限变更与 revision/审计/Outbox分别保持各自原子事务。
- 不跨外部模型、TTS、网络上传或长解析持有数据库事务/行锁；先持久化请求与状态，再执行外部工作，最后短事务校验权限/版本并提交结果。
- 并发写入依赖数据库唯一约束、revision、行锁或明确隔离级别，不用“先查不存在”代替约束。锁顺序固定，死锁/序列化失败的重试只包可安全重做的事务，不重放整段付费调用。
- 阻塞 SDK/磁盘操作通过合适线程或 Worker 隔离；CPU 密集解析在 Worker/进程中处理。API 内不使用 time.sleep，取消不能被 except BaseException/裸捕获吞掉。
- 建立总超时与阶段预算，重试采用有界退避。TaskGroup 等结构化并发的取消语义按 [Python asyncio 文档](https://docs.python.org/3.13/library/asyncio-task.html) 验证；进程内后台协程不承载必须持久完成的业务。
- Worker 幂等键基于用户与稳定业务动作，领取、阶段更新和最终提交都验证预期状态/租约。Job 只保存资源与凭据引用，不序列化会话或解密 Key。
- Agent 工具调用相同的带授权领域服务；新的付费步骤重新校验当前权限，具体恢复与未知收费语义以 [运行层](../architecture/agent-runtime.md) 为准。

## 6. 错误与日志

业务错误使用稳定 code、安全 message、request_id 和必要的字段/冲突提示；HTTP 状态及客户端行为遵循 API 契约。异常只在能增加有意义上下文或转为领域错误的位置捕获，不 catch 后返回伪成功/空列表。

| 情况 | 必须处理 |
| --- | --- |
| 未认证/过期 | 仅原生 ACCESS_EXPIRED 按协议合并刷新一次；Web 按会话续期契约处理，撤销/失效等其他情况重新认证，不能无限循环 |
| 无权限/失权 | 刷新访问快照并退出失权操作，不靠刷新令牌反复重试 |
| 版本/状态冲突 | 展示最新状态与恢复操作，不覆盖新版本 |
| 限流/依赖中断 | 遵守可重试信息及总预算；保留已提交业务结果 |
| 外部调用结果未知 | 明确 unknown/interrupted 语义，先查本地记录，不自动当作从未发生 |
| 未预期异常 | 边界处理器返回安全错误与关联 ID，集中输出一次脱敏异常记录 |

Flutter 统一 Telemetry，Python 统一 logging/structlog；业务模块不直接 print/debugPrint，也不启用 HTTP 全量请求转储。事件字典、字段白名单、SQL/AI 内容禁入及客户端队列以 [日志规范](../operations/observability.md) 为唯一正文。测试使用明显假的秘密哨兵验证所有输出通道，不能用真实用户材料构造日志夹具。

## 7. 安全与数据变更

- 所有资源操作使用认证主体、受众、动作权限、归属和状态约束；角色名称只用于种子/展示，不用于业务分支授权。
- 数据库 query/update/delete 均受 scope 约束，嵌套与批量引用逐项校验。admin 元数据接口使用专门 DTO，不能复用“所有者可读全文”的接口绕过边界。
- 密码只存哈希，Key 使用独立版本化加密；生产凭据只从受控 Secret 注入。示例配置只放变量名与安全占位值，日志/异常/测试报告不回显连接串或秘密。
- 上传验证实际格式、大小与解压后限制；原始文件路径、压缩包条目、Markdown/EPUB 外部资源和链接均按导入契约处理，不相信扩展名。
- 所有 DDL 通过 Alembic，迁移文件带目的、锁/数据量影响和回滚/前滚策略。自动生成仅提供候选变更，必须人工检查；禁止发布后改写已应用迁移。
- API、事件、卡片、CSV 与持久化 SDK 消息有独立版本；兼容性变化同时更新消费者、样本和迁移方案，不以应用版本号代替协议版本。

## 8. 依赖、生成代码与评审

提交 Python pyproject.toml + uv.lock、Flutter pubspec.yaml + pubspec.lock；固定 Python、Flutter/Dart、uv、lint/test 工具及构建镜像版本。CI 不静默升级依赖；uv 的 --locked 会在锁与清单不一致时失败，见 [官方锁定语义](https://docs.astral.sh/uv/concepts/projects/sync/)。

添加依赖说明用途、许可证、维护状态、体积/平台支持和替代方案；只在需要的服务/平台引入。不并行加入第二套 Agent、状态管理或格式化框架。依赖升级单独审查锁文件差异、生成代码和平台回归。

生成文件带生成标识、来源与再生命令，由确定的工具版本产生；不手工修补生成结果。CI 重新生成并按统一格式化后比较，要求无未提交差异；实际采用何种代码生成器在初始化时确定。

每次变更说明需包含行为前后、影响权限/协议/事件、迁移或配置变更、运行的检查、未验证限制。评审重点是业务不变量和异常路径，不为 getter、简单映射或纯样式改动机械添加逐函数测试。独立评审发现的问题要记录修复与复核证据，交付流程见 [验收规范](../delivery/acceptance.md)。
