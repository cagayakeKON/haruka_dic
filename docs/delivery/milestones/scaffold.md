## 2. B0：可重复工程基础

### 干净检出与制品启动

从干净检出开始，只使用已提交的非秘密配置模板、工具清单和锁文件，按蓝图的 doctor、bootstrap、codegen、check、dev 职责执行。已实现命令见 [开发指南](../../engineering/development.md)，两系统实际记录由B0验收索引定位。测试使用新虚拟环境和独立资源，不能借作者已有全局包、相邻 MyHome 目录或未记录的本地文件成功。

doctor 必须能区分缺工具、版本不符、缺服务、端口冲突与配置缺项；输出可采取的修复步骤和失败状态，不打印连接串/秘密。bootstrap 可重复执行且不覆盖用户已有配置、不更新依赖锁、不默认启动供应商调用或初始化公开管理员。分别记录 Windows PowerShell 与选定 CI shell 的真实结果，不能用其中一个替代另一个。

构建依赖不能仅凭运行 uv.lock 或顶层 Hatchling 版本认定已锁定。按蓝图中 backend/pyproject.toml 的 tool.uv.build-constraint-dependencies 单一约定，核对实际 PEP 517 直接/传递构建依赖的精确版本与摘要。B0 用支持该配置的锁定 uv 和干净构建缓存验证本包 wheel/sdist/editable，以及本阶段批准的第三方源码构建；缺约束、缺 hash 或实际闭包漂移必须失败并保存报告。尚未批准的源码构建不能临时下载未约束构建器后继续，本文不新增另一套构建锁来源。

后端先构建候选 wheel，再在新的运行环境中按锁定运行依赖安装该 wheel；切换到仓库外目录，移除 checkout 挂载及指向它的 PYTHONPATH，核对模块实际来自安装位置。用正式 haruka-api、haruka-worker、haruka-outbox、haruka-manage 入口验证安装、配置校验与本阶段具备的启动能力，不能只有 help 能运行。尚无业务 handler 的Worker/Outbox在B0验证入口和生命周期；B1按所选账号模式验证必要通知领取/投递，B2验证模型生成任务。迁移、种子、Prompt/协议等运行资源按蓝图随包或同版本部署附件交付，路径显式解析，不依赖当前工作目录或未打包的源码文件。

包安装和 console scripts 是分发层能力，不能仅靠源码目录内 import 证明。依据：[uv 构建与包安装验证](https://docs.astral.sh/uv/guides/package/)、[PyPA 入口规范](https://packaging.python.org/en/latest/specifications/entry-points/)。本验收不要求把包发布到公共仓库。

### 迁移、种子、组装与生成

迁移和种子由受控管理入口执行，API/Worker 普通启动不自动修改 schema。B0 在隔离 PostgreSQL 执行空库到当前 revision、重复启动和种子幂等检查；后续增加迁移时，补前一已交付 revision 的升级路径。权限/菜单种子与合成测试数据分开：生产初始化不装载测试账号/材料，重复种子不覆盖人工授权，首管理员初始化遵守 [RBAC](../../architecture/authorization.md) 的受控方式。

迁移竞争采用蓝图的同一物理连接持锁并执行 Alembic 协议。必须用真实双迁移进程证明只有持锁者可执行 DDL，等待/超时者不并行升级；持锁/DDL 连接中断时原执行失败，不透明另开连接续跑。重试须重新取得锁并在锁内核对实际 revision/已提交 schema，再决定继续或要求修复；不能只把首次计划的 revision 当作数据库现状。故障注入覆盖取锁后、DDL 中以及部分步骤已提交后的中断，证据记录实际锁等待、连接/进程结果和最终 schema。

进程资源在统一组装入口创建和关闭。模块导入、读取命令帮助及 schema 导出不偷偷连接数据库或供应商；配置错误在接收业务前失败；中途初始化失败释放已取得资源。API lifespan 和独立 Worker/Outbox 停止都要有有界等待与实际关闭断言，不以进程被强杀掩盖连接泄漏。FastAPI 生命周期能力依据 [官方 lifespan 说明](https://fastapi.tiangolo.com/advanced/events/)。

codegen 按蓝图的权威来源生成 OpenAPI/Dart 契约和已采用的目录/常量，不建立互相反向生成的多份主表。干净检出生成后与提交的生成物一致，再次生成无差异；仅包含真实生成物的忽略目录按清单核对。用修改源字段、删除一个生成文件、生成器版本不符、写入未登记权限/事件等坏样本证明检查会失败。生成器尚处于原型评估时可按蓝图使用集中手写 DTO，但不能跳过 OpenAPI 样本解码与兼容差异检查，记录哪些输出尚非自动生成。

## 3. B1：账号闭环与收藏参考流程

B0已建基础表及公共Mixin/迁移必须提供 [数据库规范](../../engineering/database.md) 的必要结构、时间和字典证据；B1在下面身份/收藏范围补双账号查询、无外键关联写入与父删除竞争。DB验收只覆盖当期已交付表和直接影响，不提前创建或运行后续功能矩阵。

### 账号范围与前置决策

注册、邮箱验证激活、邮件找回/重置密码、本人改密与设备会话管理是B1必须交付的正式能力。[OPEN-02](../../decisions/pending.md)已由用户在2026-09-26确认：开放注册使用开关且默认关闭；开启后邮箱验证，恢复通过邮件。注册关闭不影响既有账号登录/验证/找回，审批、邀请及人工恢复分支不适用。用户进一步确认本阶段以本地隔离SMTP真实Worker投递闭环接受邮件通道，不执行外部SMTP实测；验收记录应标明这一接受范围，不将其写成外部邮件实际送达。

B1同时交付一次性挑战、通知持久受理/Outbox、投递Worker、失败重试和重发所需的最小任务基础，复用[数据与任务](../../architecture/data-jobs.md)的正式机制；不能等待B2或用进程内后台任务承诺可靠发送。B2随后扩充模型能力测试和任务恢复矩阵，L2补齐查询Agent/SSE，不另建第二套队列。常规测试用本地隔离SMTP验证真实持久链路；外部通道实际收取/链接不属于本轮实测要求，未来配置后可另行记录。实际发送须限定测试收件人及获准环境，受理不等于送达。配置缺失时不能开启注册或假受理邮件恢复；已经持久受理后发送失败保留账号并安全重试。

完整资料、头像和学习/显示设置仍属阶段1资料设置切片；B1先证明缺少这些可选字段不影响注册登录，且无资料权限仍可使用本人安全功能。完整引导/资料并发等剩余ACC-11/12和PROFILE验收不得随B1的最小账号证明一并勾选。

### 合成数据与正常路径

注册主路径的A/B账号必须从Web和Android正式注册入口创建，并经所选激活流程取得独立Library/UserExtension和允许的默认角色；工厂不能预建待验收账号或将其直接设为active。不执行Windows原生测试；特有实现仅由静态审查和低层逻辑测试核对。受控dev/test seed只准备注册策略/默认角色、必要管理者，以及独立登录故障/收藏用例的前置账号、login-only账号。使用一次性本地测试秘密，不提交可公开复用的密码；每份证据区分真实注册产物与仅用于其他测试的预置账号。

为 A/B 分别预置一份自建英/日短材料、不可变内容版本和有效选区，记录 fixture 版本和许可。B1 只需显示该合成片段，经真实选区查询已准备的完整结果，再创建收藏，不要求先实现完整上传、解析或阅读器；不得虚构 manual 来源类型、伪造稳定 ID，或为了演示新增生产调试 API。

1. 用户在Web和Android分别完成注册、所选激活与正式登录，取得对应会话，再取me/access绑定当前实例、账号、受众与会话；未满足激活条件只允许受限continuation，加载/失败/无权有明确界面。profile/settings无权不阻止login-only空状态及本人安全/退出入口。
2. A 打开获授权的合成来源片段，选中文字后点“查询”，由只读接口取得该来源/版本的已提交卡片，再通过真实 POST collections 保存一条单词收藏。测试工厂可准备合法的源解释/卡片作为前置对象，不能预建待验收收藏或用前端常量冒充服务端查询结果；B1无须提前接入真实模型生成。服务端核对来源、权限、所有者与幂等后提交，前端仅在确认提交后显示成功。
3. 经真实 GET collections 查询并渲染结果，重启/刷新客户端仍能读到同一 ID；同一账号另一平台可见服务器结果，B 的列表为空或仅含 B 自己的条目。
4. 注入超时和重复提交，同一幂等键只得到一条业务记录；伪造 owner/source/tag ID、撤销 create/read、旧会话或错误受众请求不能绕过对应约束。
5. A 退出切换 B，停止旧请求/订阅并清理 A 的私有状态；故意让 A 的响应和日志队列迟到，不能进入 B 的列表、缓存或已登录日志归属。
6. 管理 Web 用正式 admin 登录/access 获得最小受控页面；验证 client 会话不能进入管理接口，管理身份不能绕过收藏本人范围。此处不宣称完整管理后台已完成。
7. Web从登录页发起找回，完成本地隔离SMTP安全交付与密码重置后重新登录；旧密码及client/admin旧会话均不可继续使用。Android找回不重复测试，外部SMTP按用户确认不实测。过期、已消费、错误用途或错误账号的挑战由后端测试拒绝，禁用账号不因恢复而激活；重复/并发请求遵循账号契约。
8. 已登录用户完成本人改密、查看并撤销设备会话及全部退出；覆盖提交后响应丢失的结果未知，不自动重放改密。Web和Android保留必要失败/重试路径，管理Web共享同一账号的密码与跨受众撤销事实。

账号页面和服务均遵守[账号流程](../../modules/accounts.md)，会话算法直接遵守[认证设计](../../architecture/authentication.md)；预置active测试账号只证明其对应登录用例，不能替代正式注册、激活和找回证据。已确定纳入B1的流程不得因隐藏入口、尚未配置通道或使用测试种子而标记完成。

## 4. B2：配置、治理与模型任务

B2分B2a资料设置、B2b完整治理、B2c模型任务三个小阶段，各自按路线图验收/review/commit。下表细化B2c持久任务；B2a/b另须完成PROFILE/SET/ADM/PERM。B0/B1原有范围与SCF-B1-01～08保持。

FCACHE1的[前端缓存基础](../../architecture/frontend-cache.md)在B2a交付：三端产品能力适配、账号/存储代次、注册策略、资料设置写后刷新、跨标签/前台校验与清理升级；运行验收在Web/Android执行，Windows原生不执行；B2b/c接权限和任务失效。`validate`先有注册框架，实际阅读/解释/音频随M/L注册。FCACHE验收按专题分期，不追加SCF-B0/B1或要求B2提前实现学习缓存。

### 正式入口与替换边界

使用既有 `POST provider-credentials/{id}/test`，显式选择文本/视觉/TTS一种已启用能力、受控固定最小样本及调用上限。保存Key不触发测试。按[设置](../../modules/settings.md)和[API](../../contracts/api.md)以正式异步Job受理并返回job/run引用；不提前建习题，不创建fake-job/run-model调试路由，不接受任意Prompt。

复用B1账号通知的Outbox/Worker。B2c冻结凭据测试DTO/权限/错误/事件、受理与结果路由；学习文本/卡片SSE在L2随消费者交付，B2c使用jobs/events WebSocket与持久快照。结果读取需credential.read及本人归属，任务订阅还检查job.read和来源，不因知道run_id放行。

常规测试仅dev/test受控组装注入Pydantic AI确定性模型/供应商替身，PG/Redis/Kafka/Job/Outbox/Worker、授权/凭据检查保持真实。staging/production、用户Header/model ID/管理目录不能启用Fake，缺Key不得降级Fake。测试哨兵不能访问供应商，未声明出站须失败；模拟调用/用量与真实事实分开。

所选模型能力按获授权固定小样本取得实际协议证据，分别记录模型/能力。未实现能力不显示测试成功；M/L切片再补材料OCR质量、音频协议及实际消费平台证据，B2不宣称业务TTS已验收。

### 正常闭环

1. 本人保存Key后单独确认能力测试；API复核当前权限/凭据/配置/上限，事务创建Job/Stage/AiRun/Outbox与幂等事实，返回持久受理引用。
2. Outbox发布至隔离Kafka，Worker按当前权限/凭据代次领取，经相同ModelFactory/调用上限执行；每个供应商attempt先持久记录，不保存原始Prompt/Key。
3. 类型化校验安全结果，当前租约/代次提交；成功/失败/unknown分别呈现，不回传原始回复，不将网络失败永久标记Key无效。
4. 三端用有权WebSocket看进度；断连/窗口外查询Job/Run快照，不因刷新或重复点击重调供应商。
5. 核对PG/Job/Outbox/attempt和当前结果，沿operation/request/job/run到Loki/Grafana；配置/轮换/撤销及迟到结果不得串用户、能力或版本。
