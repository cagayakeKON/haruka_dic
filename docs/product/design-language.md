# 产品设计语言：晴空频率

状态：2026-09-24，用户认可整体风格并要求文档化，作为后续设计与实现基线。本文属于阶段1内的独立文档小阶段 DESIGN1；随后[手机/电脑 HTML 原型](../../prototype/README.md)按该语言重建，属于 DESIGN2；手机端在 DESIGN3 修订任务流，在 DESIGN4 进一步重构移动排版、底部动作与产品文案；电脑端在 DESIGN5 对齐手机视觉，并以移动优先方式重构宽屏排版、键盘与历史导航。Flutter 正式界面尚未迁移，B1/B2 或任何业务页面均未因原型而验收。

本篇是 Haruka 产品气质、视觉、组件表达、动效与文案的唯一设计语言正文。[产品总览](overview.md)维护信息架构与业务范围，各模块维护行为、权限和状态，[Flutter规范](../engineering/flutter.md)维护平台适配与工程方法；本篇不替代这些契约。

## 1. 方向与确认层级

设计名：**晴空频率 / Clear Signal**。产品气质是明亮、灵动、有探索欲；操作轻快，信息清晰，适合长时间学习。

| 层级 | 内容 | 当前状态 |
| --- | --- | --- |
| 整体方向 | 灵动青春、科技感；晴空蓝与少量芽黄绿；短声线与一角收紧的圆角形；材料鲜活、阅读安静、练习反馈轻快 | 用户认可，作为现行产品设计方向 |
| 基础视觉方案 | 本文的浅色主色板、角色分工、排版与反馈规则 | 本次方案基线，替代旧的泛化 Primary/杂志式描述 |
| 实现初值 | 深色派生色、字号/间距/圆角、动效时长、具体字体和图标资源 | 推荐初值，随对应切片验证后锁定；不能称为逐项用户确认或三端实测通过 |
| 工程交付 | 主题 token、正式组件、各业务页面、无障碍和目标平台验证 | HTML 交互原型已重建；Flutter/Python 正式实现与三端验收未完成，按路线图逐切片交付 |

产品表达围绕三个感受展开：青春感来自明亮对比和舒展文字；灵动感来自与操作相关的形变、位移和及时反馈；科技感来自选区与解释联动、来源可追溯、任务与保存状态准确。用同一套视觉语法表达不同业务，不给每个模块另造品牌。

识别组合为：**晴空蓝 + 芽黄绿点缀 + 短声线 + 随场景调整的视觉强度**。大面积霓虹、持续粒子、装饰性仪表盘、过度玻璃效果和循环漂浮不属于本方向；“青春”也不引入宠物、积分、打卡或每日任务等新产品范围。

## 2. 色彩与主题

### 2.1 浅色基线

以下是设计角色名，尚非代码中已存在的 token。组件按角色取值，后续集中映射到 Flutter 主题，避免页面各自硬编码。

| 角色 | 色值 | 用途与边界 |
| --- | --- | --- |
| 晴空蓝 / brand.primary | `#2457ED` | 主要动作、当前焦点和品牌重点；默认页面仅突出当前主任务 |
| 芽黄绿 / brand.signal | `#D8F36A` | 短声线、发现感、少量封面与装饰；不等同答对、已保存或已掌握 |
| 雾白 / surface.canvas | `#F4F7FB` | 应用底色，衬托正文与操作层 |
| 纸白 / surface.content | `#FFFFFF` | 阅读、表单、题面和解释内容层 |
| 深海墨 / text.primary | `#152B42` | 标题、正文和重要数据 |
| 次级文字 / text.secondary | `#58697B` | 辅助说明、出处和元数据；关键信息不继续降低透明度 |
| 浅蓝 / surface.selected | `#E8EFFF` | 当前导航、局部选择与选词背景，配深色或晴空蓝文字 |
| 分隔线 / border.subtle | `#DDE5EE` | 列表分隔、表单边界，避免所有容器都描边 |
| 主按钮文字 / text.on-primary | `#FFFFFF` | 晴空蓝填充上的文字与图标 |
| 点缀色文字 / text.on-signal | `#26370B` | 芽黄绿底上的可读内容，不在该底色上使用白色小字 |

中性色承载大多数内容，蓝色集中表达焦点，黄绿作为小面积节奏。比例按页面任务判断，不为了固定占比给正文添加装饰。材料类型始终带名称或图标，不能只靠封面颜色识别；封面色也不代表解析状态。

成功、警告、错误、等待使用独立语义角色，分别配明确文字或图标；不能从品牌蓝/黄绿推断业务结果。选中、键盘焦点、正确答案和用户已选答案也需独立表达。

### 2.2 深色、阅读主题与无障碍

深色版沿用相同结构和角色，以下为待实测的派生初值：画布 `#101925`、内容层 `#192535`、主文字 `#EDF3FF`、次级文字 `#A8B8CC`、强调文字 `#9AB6FF`、主要按钮填充 `#2954D3`、选中背景 `#273B60`。按钮填充与强调文字分别取值，不把浅色主题机械反相，也不让浅蓝底配白字。

应用主题、阅读浅/深/sepia、系统文字缩放、减少动态与高对比的保存/生效方式遵循[设置](../modules/settings.md)。阅读 sepia 只调整阅读内容层；原文、出处和已保存的解释保持一致。高对比模式可降低品牌装饰、强化边界与焦点。

实现时逐组合检查文字/背景和控件状态的对比度；本方案以普通文字至少 4.5:1、大号文字与关键非文本控件至少 3:1 为设计检查基线。示例色板不等于这些检查已完成。错误、选中和掌握等意义必须同时通过文字、形状或图标表达。

## 3. 字体、排版与空间

### 3.1 文字系统

中文界面使用舒展的现代黑体，拉丁字母与数字选择协调的无衬线字形。品牌字标可有几何特征，正文以清晰阅读为先。小说正文允许选择有书感的衬线体；日文标点、假名、汉字、ruby 与英日混排需用真实样本验证。具体字体文件、许可、离线打包和回退链在实现切片确定，不依赖远程字体才能显示。

| 文字角色 | 推荐初值 | 使用规则 |
| --- | --- | --- |
| 页面主标题 | 紧凑布局 28–32、宽屏 32–44；中等至较重字重 | 每页一个主层级，标题让位于内容；不把大标语重复放到每个学习页面 |
| 分区标题 | 18–22，中等字重 | 靠间距、位置和字重建立层级，不全部放进彩色卡片 |
| 界面正文 | 14–16，常规字重 | 按内容密度和缩放调整，长说明不使用全粗体 |
| 阅读正文 | 18–20，行高约 1.8–2.2 | 可由用户阅读偏好调整，随语种与真实材料验证 |
| 辅助信息 | 12–13 | 用于出处/类型/次要状态；重要操作与错误说明不能缩成脚注 |
| 对齐数字 | 与所在文字级别一致 | 时间、题号、表格数字使用等宽数字特性，状态变化不跳动 |

尺寸为默认缩放下的设计初值，正式客户端使用逻辑尺寸并遵守系统缩放。允许长标题、多行按钮/错误和文本重排；不能通过截断关键含义或禁用系统缩放维持视觉。

### 3.2 空间与形状

- 间距以 `4 / 8 / 12 / 16 / 24 / 32 / 48` 为初始刻度，按内容关联调整，避免逐页任意加值。
- 品牌面板采用一角收紧的圆角形；概念初值为其余角 22、右下角 8。只在封面重点、解释面板等少数位置出现，不把所有表格、输入框和弹窗都异形化。
- 常规按钮/输入框使用约 12–14 的规则圆角，内容面板约 20–24；胶囊形只用于确有需要的短标签/分组控件。
- 短声线是小面积、圆端且一端收紧的品牌笔触，可用于章节标记、AI 区域标识和状态过渡。装饰声线不冒充播放波形、进度或模型正在工作。
- 内容列表主要用对齐、留白和分隔线组织；内容层以底色区分，浮起的菜单/面板才使用必要的轻阴影。
- 图标统一视觉尺寸、线宽、端点与重量；操作需有可访问名称，关键操作可见文字。触控命中区、键盘焦点与弹层焦点管理遵循[Flutter规范](../engineering/flutter.md)。

## 4. 页面与组件的共同语法

### 4.1 场景强度

| 场景 | 表达与结构 | 必须保留的任务重点 |
| --- | --- | --- |
| 书库/材料 | 鲜活；明确标题、封面、稳定列表与类型筛选，少量品牌色块 | 本人材料与各自就绪状态；小说、课本、试卷进入专属页面 |
| 小说阅读 | 安静；正文占主导，目录和解释根据空间出现 | 原文、阅读位置、选区与出处；宽屏解释侧栏，紧凑布局使用底部面板或专用详情 |
| 课本学习 | 清楚、有层级；单元与正文/词表/语法/习题角色明确 | 保留教学次序与内容关系，不能把课本压成小说长文；讲练分屏仍按 P1 范围 |
| 收藏/单词本 | 进入即条目列表；类型、内容、释义、出处与归本有稳定层级；查看dialog、切换/管理词本dialog、每日单词独立入口 | 组织与显式 AI 习题选源；掌握只读，不能把品牌点缀当掌握证据 |
| AI 习题 | 集中；单题、选项、确认与反馈形成清晰顺序 | 保留选源/预览/确认生成流程；答案确认后按业务状态反馈 |
| 试卷 | 克制；题面、答题卡、计时和保存状态可辨 | 考试作答与交卷后复盘分开，不提前显示答案/解释，也不复用普通练习的即时判对动效 |
| 查询/Agent/解释 | 就近、可追溯；上下文与输出卡片关联 | 原句、来源、生成/复用/保存状态及下一步动作，长输出保持阅读宽度 |
| 登录/设置 | 轻盈、有秩序；短表单、分类与局部错误 | 表单与真实保存状态优先；品牌区域不能挤压输入区或遮挡软键盘 |
| 管理 Web | 高效、明确；延续相同字体、色彩角色和控件 | 降低装饰强度，突出权限、变更后果和审计；维持独立管理布局 |

宽屏和紧凑布局共享品牌及业务状态，但可拥有不同结构。具体断点、空间/输入/平台判断与状态保留由[Flutter规范](../engineering/flutter.md)唯一维护，不将会话概念稿的 CSS 阈值作为正式参数。跨布局不能丢失选区、输入、作答草稿或触发新的供应商调用。

手机端从拇指可及的当前任务出发组织信息，不把宽屏的横幅、常驻工具列、并排统计或完整工作台缩成单列。一级入口只放稳定的高频目的地；进入材料、每日单词、生成、设置详情后使用顶部返回与本页动作，不继续占用底部全局导航。需要跨步骤确认的操作逐步推进，保留已选条件；阅读正文占主导，选词解释用底部面板；教材按单元、内容、练习逐级进入；考试一次聚焦一题，答题卡与交卷作为明确的独立动作；对话输入保持在可触及的位置。触控路径和系统返回先处理当前面板、再处理页面，不能因为调整视觉层级丢失业务状态。当前[手机原型](../../prototype/README.md)展示这些原则，正式 Flutter 行为仍按适配规范验收。

电脑端沿用手机的浅色表面、蓝色主动作、书封色块、文字层级与五个核心目的地（材料、单词本、查询、练习、我的），先保证紧凑窗口内的单列任务完整，再按可用空间展开侧栏、目录、解释和设置分类。宽屏用于增加可扫描信息与并行上下文，不用于放大宣传横幅；阅读正文和表单仍限制行宽。鼠标悬停、可见键盘焦点、搜索定位、对话发送快捷键与弹窗焦点循环需要明确反馈。浏览器历史应保留所访问材料或词本的身份；已删除资源返回安全列表，跨尺寸重排保留输入与作答。当前电脑 HTML 原型演示这些交互，断点数值不替代正式 Flutter 适配规范。

### 4.2 控件与状态

手机五个主tab的header统一显示h图标、当前名称（材料库、单词本、查询、练习、我的）与当前动作，正文不再重复页标题。材料库和单词本默认只显示搜索按钮，点击后header切换为返回、输入框和清除；关闭搜索恢复标题并清除关键词，保留材料类型或当前单词本/收藏类型。单词本新增收藏放入header。搜索输入不因列表更新丢失焦点，浏览器返回先退出搜索，前进重新展开时恢复输入焦点。

手机材料导入作为右下角悬浮主操作，避开底部导航并留出列表末尾滚动空间；搜索展开期间收起悬浮操作。两端材料操作使用低权重的小型更多图标，保留至少44px命中区、可见键盘焦点和明确无障碍名称；点击先显示“查看详情 / 删除”，查看详情进入元数据dialog，删除另行确认。关闭面板恢复触发点，删除后焦点落到相邻材料，空列表回到搜索或标题。不为详情划分与材料主体竞争的大块区域。手机原型在宽窗口预览时仍保持手机内部的单列与紧凑控件，不直接套用外部窗口触发的电脑样式。

手机身份入口延续小品牌、短声线和蓝色主按钮，采用顶部展开的单列表单，避免大面积顶部留白及表单外再套重卡片。输入标签常驻，密码显隐就近，找回、注册、返回登录和服务地址按任务优先级排列；提交区不固定覆盖输入，短视口通过自然滚动完整操作。注册与找回的受理页复用相同结构，状态文案只表达已经发生的结果。具体行为与原型边界见[账号模块](../modules/accounts.md)。

| 对象 | 统一表达规则 |
| --- | --- |
| 按钮 | 实心蓝突出当前主动作；次级操作用中性底/边界或文字。hover、按下、焦点、禁用、等待分别可辨；等待文案说明正在做什么，防重复提交遵循实际业务状态 |
| 导航与筛选 | 全局导航放在应用壳，局部筛选靠近所控制内容；活动项保持稳定位置，并用文字/形状补充颜色 |
| 输入 | 标签常驻；错误靠近字段并说明可修正内容，保留允许保留的用户输入。不能只改变边框颜色 |
| 列表/面板 | 封面用于识别材料，类型、标题和就绪状态可扫描；点击范围与多选、行内操作分开，避免误触 |
| 选区/解释 | 原文选区与解释面板同步，保留原句和出处；切词保持上下文，关闭后返回原阅读位置与焦点 |
| 保存/收藏 | 显示未提交、处理中、已提交或失败的真实状态；“已保存”以服务端提交结果为准，成功动效不能代替持久化证据 |
| 作答反馈 | 用户选择、已提交、判对/判错、评分中、待复核分别表达；失败或未知不能画成答错。正确性标识不能与选中高亮混为一体 |
| 加载/空态/失败 | 加载保留已有上下文；无材料、无筛选结果、失权、离线和服务故障分别说明原因与允许动作，不全部显示通用空插画 |

状态语义以对应[模块](../README.md)为准，本表只规定表达方式。新解释和生成仍需对应显式动作与授权；查阅已保存结果不能被视觉联动改成后台重新调用模型。

## 5. 动效：跟随操作的轻快反馈

| 动效角色 | 推荐初值 | 使用位置 |
| --- | --- | --- |
| 按压/焦点反馈 | 约 160ms，小幅变化 | 按钮按压、选项选择；即时给出操作反馈 |
| 局部展开/切换 | 约 240ms，短位移与透明度过渡 | 解释面板、局部详情、作答反馈；位置变化有明确来源 |
| 收藏/提交完成 | 一次短确认，随结果出现 | 原位图标/文案变化，随后保持可读的稳定状态 |

动效不阻塞输入、不移动正在点击的目标，也不为等待动画延迟已经可用的内容。优先使用合成友好的透明度/位移变化，性能以目标平台实测为准；不声明固定帧率已达标。

减少动态开启时取消弹跳、缩放与大幅位移，使用直接状态切换或必要的短淡变。阅读过程中不持续漂浮装饰；考试计时、TTS 高亮和任务进度必须来自真实状态，不由动画时钟推算业务完成。动效状态不触发请求、保存或生成。

## 6. 产品文案与 AI 的呈现

语气亲切、具体、有依据。页面标题可以带少量情绪，操作名称优先表达动作及对象；错误先说明当前结果，再给出可执行的下一步。面向中文界面的关键导航、按钮和状态使用中文；概念稿中的英文眉题只是可选品牌装饰，不承担必要信息。

产品正文只保留帮助用户识别内容、做出选择、执行动作或理解结果的文字。删除“小说、课本和试卷，在这里各有自己的入口”这类复述界面的功能宣讲，不用技术契约、权限实现或开发进度填充空白。手机页已有明确导航标题时，表单不再重复大标题和口号；类型选项、出处、操作后果和可恢复错误仍需写清。原型说明集中放在独立入口；涉及未上传文件、模拟调用或虚构考试结果时，用简短就地提示明确真实效果。

| 场景 | 文案示例 | 使用条件 |
| --- | --- | --- |
| 首次材料引导 | “从喜欢的内容开始”“添加材料” | 适合空库或轻量引导，不在每页重复大标语 |
| 语境解释 | “放回这句话”“出处：第 3 章 · 第 1 段” | 展示真实原句与可解析来源；无法回跳时说明原因 |
| 有效答对 | “你抓住了‘不打扰’的语气。” | 有题目与可靠评分依据时使用，不据一次示例宣称已经掌握 |
| 保存失败 | “这次修改尚未保存，请重试。” | 仅用于已知未提交；结果未知时应说“暂时无法确认保存结果”，并按业务协议查询 |
| 缺少模型配置 | “配置个人模型后，可生成新的解释。” | 提供有权的设置入口，同时保留已有结果与基础阅读 |

AI 输出与原文、生成例与材料例句区分；已保存、正在生成、失败、待复核分别展示。收藏关系与解释持久保存分开，不暗示“收藏后才保存”。实际依据与行为分别见[AI与朗读](../modules/ai-speech.md)、[学习结果缓存](../architecture/learning-cache.md)和[AI习题](../modules/ai-exercises.md)。

## 7. 概念稿与现有原型的边界

本次会话概念稿用于感受色彩、形状、排版，以及材料、小说阅读、单题反馈三个场景之间的一致性。该稿是会话内示例，未纳入仓库制品或正式测试证据；本篇保存可复现的规则，不依赖某台机器的会话文件路径。

- 概念稿顶部“材料 / 阅读 / 练习”用于切换设计场景，不重新定义正式全局导航；正式入口以[产品总览](overview.md)为准。
- 大标题与小说章节重点面板展示视觉强度，不据此新增推荐材料、最近在读或“继续阅读”区域；书库仍以本人材料列表为默认任务。
- 示例解释、收藏和答题反馈均为演示，不证明模型调用、持久保存、学习证据或真实权限已经实现。
- 示例头像、字标和英文短句不等于最终品牌资产；具体字体/图标与标志成品仍需在实际设计切片中锁定。
- [现有 HTML 原型](../../prototype/README.md)已按本语言重建手机与电脑两套独立布局，覆盖主要页面与本地演示状态；它仍不能证明真实权限、模型调用、持久化或正式客户端适配。

“不设继续阅读/最近在读”、三类材料专属流程、显式生成、无词汇复习调度等现有边界继续有效。统一设计语言不增加第四类材料、共享万能业务页面或新的导航/设置功能。

## 8. 落地顺序与检查

DESIGN1 完成设计语言与文档同步，DESIGN2 重建独立 HTML 原型。后续正式实现按[路线图](../delivery/roadmap.md)在阶段1的 B1 及相关页面切片建立共享主题/基础控件，阶段2落到书库与三类材料页面，阶段3落实解释/收藏/朗读，阶段4落实习题/考试反馈；设置和管理布局随各自功能同步。不得回写 B0 历史验收为已通过新视觉。

以下为正式页面的设计检查项。HTML 原型提供局部视觉与交互检查依据，Flutter/Windows/Web/Android 的完整检查仍待对应实现；不新增全仓测试要求，也不表示仓库已有对应自动化用例：

| ID | 检查标准 |
| --- | --- |
| DESIGN-01 | 页面使用统一色彩角色、字级、空间与形状；主次动作明确，品牌点缀不冒充业务状态 |
| DESIGN-02 | 材料鲜活、阅读安静、练习反馈轻快；管理/考试保持清晰与克制，功能入口符合现有信息架构 |
| DESIGN-03 | 浅/深及阅读主题、文字缩放、高对比、减少动态下内容可读；真实颜色组合和焦点/触控目标有检查证据 |
| DESIGN-04 | 键盘、触控和鼠标均有完整路径；紧凑/宽屏、长标题、英日混排、错误及软键盘场景不遮挡必要内容 |
| DESIGN-05 | 动效与选区/解释/保存/作答真实状态一致；切布局/主题不重复调用，不把未知/待复核显示为成功或错误 |
| DESIGN-06 | 文案说明依据、来源、当前结果及下一步；概念示例、历史原型、真实服务状态和验证结论明确区分 |

检查方法与平台证据沿用[Flutter规范](../engineering/flutter.md)、[前端测试](../engineering/testing/frontend-e2e.md)及[交付验收](../delivery/acceptance.md)。每个实现切片只检查其直接影响，独立 review 与本地提交节奏按根 [AGENTS.md](../../AGENTS.md)。

DESIGN6交互补充：材料主区域直接进入阅读/学习/试卷准备，详情通过列表小型更多菜单中的“查看详情”打开；解析进度据WebSocket已确认状态显示。电脑站内消息只有header铃铛入口，任务进度只有右侧展开栏入口。收藏详情不占独立页面，关闭恢复列表位置/焦点；语法、句子与回答卡片保留各自类型。查询沿用聊天布局，回答以可收藏卡片呈现；手机输入区避开底部导航和键盘，电脑限制正文行宽。
