# 三类材料与处理边界

状态：2026-09-23，设计基线，未实现。用户已确认只适配小说、课本、试卷，分别处理和使用；本文约束类型选择、分派、版本和跨类型边界。解析对象与字段关系唯一详述于[三类解析数据结构](material-structures.md)；导入公共流程见 [材料与书库](../modules/materials-reading.md)，具体体验分别见 [小说](../modules/novels.md)、[课本](../modules/textbooks.md)、[试卷](../modules/exams.md)。文档中的“教材”与“课本”指同一类型。

DESIGN23确认扫描/图像型PDF及图片的视觉OCR、EPUB直接解析及原书ruby保留，混合文件按页/区域分派，细则见[提取契约](source-extraction.md)。这是处理方式的确认；开放格式组合和实施优先级仍沿下述能力目录及OPEN-01，不宣称所有PDF/图片导入已经实现。全应用基础NLP见[标注专题](../architecture/text-analysis.md)，不改变三类材料边界。

## 1. 类型与格式

`material_type` 是唯一业务类型字段，枚举为 `novel | textbook | exam`。上传意图、Material、解析 Job 的不可变输入均保存同一值；服务端选择对应处理器，Worker 提交时核对类型、版本和代次。替代旧设计中的 `import_mode/primary_type` 双字段，不维护两套可冲突的类型值。当前没有应用数据，因此这是设计修订，不是已执行数据库迁移。

- 用户先选“小说 / 课本 / 试卷”，再选文件；不提供“自动 / 其他 / 混合”作为第四条流程。AI 可以提示选择可能不符，不能改变用户类型或自动转入另一流程。
- 文件格式独立于业务类型：同一个 Markdown 文件可被用户按不同目的分别导入，但必须重新执行所选类型的校验；扩展名和 MIME 不决定业务类型。
- 实际可用组合由服务端能力目录按类型、格式和处理阶段发布，前端展示相同限制，后端重新验证。不支持的组合在受理前拒绝，不能退回通用阅读器假装成功。
- 当前格式优先级仍按 [产品总览](../product/overview.md)：MD/EPUB 为首版基础；小说/课本 PDF、TXT、OCR 仍为 P1，试卷首版 PDF/OCR 范围见 OPEN-01。确定三类不等于所有格式已获准或已经验证。
- OCR统一使用 [视觉模型](../architecture/vision-recognition.md)，三类各自提供识别配置和业务校验；可用文本层直接提取不属于OCR。模型转写候选由程序校验并标来源后发布，已发布原文仍不可被模型重写。

## 2. 独立处理与使用合同

| 类型 | 专用处理与产物 | 打开后的体验 | 可用条件 |
| --- | --- | --- | --- |
| novel | 章节顺序、段落/对话/注音/脚注；派生分句、分词、词形与朗读片段引用；NovelManifest | 连续阅读、目录、选词/扩选、选区查询后收藏、选区朗读、阅读进度 | 已发布且完整性通过的正文可读；语言标注失败只降级相关辅助能力 |
| textbook | Unit/Lesson、课文/对话/语法/词表/例句/练习的角色及关联；TextbookManifest | 单元学习页，从课程目录进入课文、词汇或练习；逐题提交反馈 | 单元中的可靠正文可学习；未识别块保留原文并标记，缺题干/选项/依据的练习按各自状态限制 |
| exam | 题组、共享材料、小题/空位、听力脚本/题目候选绑定、分值、答案出处与 rubric；ExamPaperVersion | 校对文字听力稿并生成TTS、考前说明、整卷答题、答题卡、交卷、成绩复盘 | 必须完成结构/听力/计分/完整性校对及版本冻结；解析出正文或模型自报听力匹配不等于 ready |

三类分别拥有服务、类型化输出、业务状态与页面 controller。`NovelManifest` 和 `TextbookManifest` 不是同一大 JSON 加一个 theme 字段；`ExamPaperVersion` 及题面 DTO 沿用考试契约，不包装成阅读章节。列表只返回共用元数据、类型和安全状态摘要，不把试卷答案、正文或评分依据塞进书库卡片。

共用范围仅为身份/权限、私有文件、格式提取适配器、不可变SourceUnit/ContentBlock、出处、Job/Outbox、语言标注基础能力、TTS、遥测与小型展示控件。共享来源层只表达可追溯事实，不要求三类都编排成同一个阅读块列表；小说/课本/试卷的完整对象关系、候选/发布和存储边界以[解析数据结构](material-structures.md)为准。禁止建立一个带大量 `is_exam/is_textbook` 分支的万能 Reader、controller 或评分状态机。

教材八类内容、试卷五类作答交互与题组的分类和映射统一见[解析展示契约](learning-presentation.md)。它规定各自结构关系、原文对照及降级，不新增业务材料类型或通用页面产物，也不改变本节的格式范围与就绪条件。

## 3. 类型修改与重新处理

首次完成受理前，用户可取消意图并重新选择类型；已有意图的类型不原地修改。材料建立后类型固定，`PATCH materials/{id}` 不接受 `material_type`。标题/标签可按现有 revision 规则修改。

“选错类型，重新处理”是显式创建另一份材料的操作：通过 `POST material-imports` 指定本人已有的源材料及目标类型，服务端复用已验证的不可变原文件，重新执行目标流程。它与上传新文件的输入互斥；不接受客户端提供任意对象 key/URL。需重新检查源 `client.material.read`、原文件可用、目标 `client.material.import`、配额与明确请求的阶段；目标为试卷另需 `client.exam.import`，AI 阶段另需 `client.material.analyze`、本人 Key 和上限。采用同一幂等/Job/Outbox机制，创建文件引用也遵守父行锁/删除代次协议。

使用完整原件另按源类型校验：小说/课本源适用 material.read；试卷源必须同时具有 `client.exam.read` 与 `client.exam.edit`，在本人试卷校对范围内才允许使用可能含答案的完整原件。仅有题面/场次/成绩读取权限不足；exam权限被撤销时，即使仍有material.read/import也拒绝复用。受理、Job阶段及提交重新检查这些源动作与目标动作，幂等命中也不能绕过；相同规则适用于完整原件读取/签名，通用文件接口不提供旁路。

源已删除、不可读、对象已回收或类型/格式组合不支持时拒绝；不能从仅保留的考试历史对象找回原文件。新材料独立分配 ID、版本、进度和任务；原材料保留，用户可另行删除。收藏、书签、作答、成绩不自动跨材料迁移；失败不会改变旧版或旧考试场次，界面提前说明会创建另一份材料。

## 4. 版本、出处与访问

三类的所有选区、词条、题干和关联媒体继续使用 [出处协议](content-locator.md)。领域节点可引用同一组源块，但引用必须验证同用户/资料库、材料与内容版本，不能以文本相同推断关系。

原文件不可变；修复阅读顺序、正文或规范文本时创建新 MaterialRevision。仅更新分词/分句等派生标注时建立新的分析版本，保留算法/词典/规则版本和原文范围，不更换已有内容 ID 或静默重新解释旧 sentence_id；旧标注引用仍须可解析或明确不可用。标注读取/缓存按内容版本和分析版本绑定，不能把新切句结果套在旧音频或旧选区上。

出处解析返回服务端验证的材料类型与目标节点，Flutter 交给对应小说/课本/考试入口；仍须验证目标业务动作。试卷原文、题面、答案/解析由考试接口按阶段和动作投影；通用材料接口、TTS/解释工具及缓存不能成为绕过考试 DTO 的内容出口。个人考试并非防作弊系统，用户本就拥有原文件，但应用不能误用普通阅读接口泄露受限字段。

## 5. 契约验收

- TYPE-01：导入、列表筛选、DTO、Worker 和路由分派只接受三类；未知值/不支持组合拒绝，AI 不覆盖所选类型。
- TYPE-02：同一合法文件分别选择三类，产生对应领域产物与入口；三类可用条件独立判定，试卷不能因正文已解析而开考。
- TYPE-03：类型不能通过 PATCH 改成另一类；显式重新处理幂等、重新授权、来源删除竞争安全，旧出处/进度/答卷不迁移或丢失；源试卷仅有题面权限、缺校对权限或任务中途撤权时拒绝完整源文件复用/发布。
- TYPE-04：把试卷 ID 传到小说/课本内容接口，或把另一用户/错误版本的节点传入任一接口均拒绝；来源回跳分派正确，试卷答案不通过共用接口/工具/缓存或完整原件签名返回给无相应权限者。
- TYPE-05：内容变化与派生标注升级分开版本；旧选区/句子/音频引用不被新分析静默改义。

以上是未来工程验收，测试覆盖与材料样本分别见 [追踪索引](../delivery/coverage.md) 和 [测试数据](../engineering/testing/data.md)。现有 HTML 原型尚未按三类独立流程迁移，其示例类型或菜单不能反向扩大本契约。
