# 任务进度 WebSocket 契约

状态：2026-09-24，P0 设计已确认，正式服务待实现。用于材料解析及本人任务的实时进度；HTML 原型有独立本地模拟服务，不能作为本契约的生产实现证据。配套：[API](api.md)、[认证](../architecture/authentication.md)、[RBAC](../architecture/authorization.md)、[任务事务](../architecture/data-jobs.md)。

## 1. 连接与授权

生产端点为同部署 `wss://<host>/api/v1/jobs/events`。Web 使用当前 client 受众 HttpOnly 会话 Cookie，握手严格验证允许的同源 Origin，不接受缺失/任意跨站 Origin 的浏览器握手；原生连接使用 Authorization Bearer 头并验证同一持久会话/epoch。不得把 Cookie、JWT、Key 放在 URL 或订阅载荷中。管理端不复用用户订阅接口。

握手、订阅、重连以及每次向连接交付事件前检查当前身份、登录资格、client.job.read、Job 所有者和所涉材料/结果的读取权限。心跳再次检查会话/权限，不仅依赖初始握手；PG/权限状态不可验证时关闭连接。无权订阅统一拒绝，不泄露目标任务是否存在、计数或内容。撤权后停止受限推送，退出/切账号主动关闭旧连接，客户端按账号代次丢弃迟到事件。

连接只订阅状态，不承担取消、重试、生成或更新业务数据；这些操作继续走有权限和幂等保护的 HTTP 接口。进度订阅不发起供应商调用。

## 2. 消息与进度

客户端发送版本化 `subscribe` 消息，包含受控长度的 `job_ids` 以及各 Job 的最后 `generation/sequence`；不接受 user_id。服务先整体校验权限，再确认订阅。显式 unsubscribe 移除选定订阅。首版建议每连接最多 100 个 Job，容量参数由运行配置发布，不使用无限订阅。

事件信封字段如下；实现时生成具体类型和版本化 schema，不把任意字典直接发送给前端。

| 字段 | 语义 |
| --- | --- |
| schema_version / event_id | 消息结构版本与稳定事件 ID |
| job_id / generation / sequence | 本人 Job、当前运行代次、代次内持久单调序号 |
| type | snapshot / progress / completed / failed / cancelled / resync_required |
| occurred_at | 服务端 UTC 带时区时间 |
| payload | 当前任务状态、stage、progress_percent、material_id、可用性状态、已发布内容版本及受控错误码 |

`progress_percent` 为 0–100 或 null；没有可测分母时为 null，界面显示“解析中”和当前阶段，不使用计时器推算百分比。进度与可阅读状态分开：可靠正文已经发布时允许进入小说/课本，即使可选分析仍在继续；试卷仍执行准备/校对/冻结门槛。

completed 只在对应业务阶段/结果及任务状态提交后发布，不能由“接收完消息”或百分比达到 100 推断。failed/cancelled 必须保留真实状态与可操作范围。载荷不含原文、文件路径、完整文件名、Prompt、答题答案或凭据；需要详情时按安全引用重新读取有权 HTTP 资源。

## 3. 断线与恢复

每次订阅先返回当前授权快照及服务端游标，避免订阅建立与状态提交之间漏更新。连接中断显示“连接中断，正在重连”，保留最后已确认进度，不显示失败或完成；采用有上限的退避和心跳，页面退出取消定时器。

重连后重新授权并请求快照/有界回放。同代次 `sequence` 不递增的事件丢弃；较旧 generation 丢弃，较新 generation 仅在服务确认当前 Job 代次后替换展示。缺口或回放窗口过期返回 resync_required，客户端 GET jobs/{id} 补读权威快照，再从对应游标订阅。重连不会重新上传、重启 Job、创建新的 run 或再次调用供应商。

任务事件与状态发布必须遵守 Job/Outbox 的提交边界，进度事件保留可以有界，但当前权威状态与最终结果必须可查询。WebSocket 不替代 Agent 文字/卡片流的 SSE；两种传输使用同一身份与业务事实，避免同一事件重复计数。
