# 单词掌握度与学习证据

状态：2026-09-23，VL2设计，未实现。掌握状态由有效习题结果自动计算，不能手动选择；用户端不提供词汇复习、每日队列、到期时间、间隔调度或 SRS。多本组织见[单词本](../modules/vocabulary-notebooks.md)，AI生成与错题见[AI习题](../modules/ai-exercises.md)，评分发布见[数据与任务](data-jobs.md)。

## 1. 学习目标与状态

P0以本人 `CollectionItem(kind=word) + learning_revision` 作为具体词形/义项/读音的学习目标。一词加入多本仍共用状态；不同义项、读音或未确认同义的条目不因拼写相同共享证据。

| 字段 | 权威含义 |
| --- | --- |
| mastery_state | 服务端计算 `new/learning/mastered/needs_practice`；UI/API/CSV/模型不能直接写 |
| exercise_control | 用户可设 `active/excluded`，只控制是否默认进入 AI 习题候选；不删除证据或改变掌握结论 |
| assessment_status | `ready/pending/rebuilding/needs_content` 等投影可用性；待评或缺题不显示为错误/已掌握 |
| learning_revision | 词形、语言、目标义项或读音实质变化时递增；笔记、标签和归本不递增 |
| evidence_revision / policy_version | 当前投影消费到的证据版本和判定策略，用于解释与重放 |

不存在 `due_at`、`ReviewSchedule`、每日新词限额或下次复习字段。首次收藏/导入为new；浏览、朗读、收藏次数、前端埋点和生成习题都不是掌握证据。excluded条目仍显示真实状态，可被用户显式选入一次AI习题，但不会出现在默认候选中。

## 2. 有效学习证据

题目发布时冻结 `question_assessment_targets`：本人条目/learning_revision、能力类别、评分项、答案/rubric版本及允许辅助。P0能力为词义识别和依据释义/有效语境主动回忆词形；没有实际测验的听力、发音或自由写作不显示已掌握。

| 结果/动作 | 证据处理 |
| --- | --- |
| 已提交且发布effective的可靠规则/合格AI评分 | 生成或替换Attempt/评分项/目标的唯一证据，保留来源和评分版本 |
| 无提示完整正确 | 成功候选；仍需不同习题集/根题的独立证据，不能重复提交刷次数 |
| 可靠错误、规则认定空答或明确“不会” | 失败证据，并进入错题账本；与技术失败/普通跳过分开 |
| 部分正确、提示后正确、揭答案后抄写 | 记录辅助/不完整结果，不作为无提示成功；可靠部分错误可进入错题账本 |
| pending/needs_review/failed/unknown或未发布整卷部分结果 | 不改变正式掌握；保留旧投影，显示待评/复核 |
| 跳过、退出、媒体/传输失败、仅看卡片/播放 | 不产生正负掌握证据，也不记错题 |

普通习题以对应Attempt的effective评分为边界，考试以整场有效成绩发布为边界。只有冻结到具体学习目标且分项评分明确的结果才能回流；作文/试卷总分或模型事后猜测不能摊成每个词的掌握。

辅助/揭答案由服务端同时绑定 `session_item`、稳定 `exercise_root_id + answer_lineage_id` 以及学习目标/learning_revision，并与提交按服务端接受顺序持久化。同一根题/答案谱系在A会话已接受曝光后，B设备或新会话随后提交仍标为有辅助；答案先被接受、迟到曝光才到达时不追溯污染该答案。真正独立的新根题不继承旧题曝光，避免一次看答案永久污染同一词。反馈后的同题订正标为training_only，不制造新的独立成功或错误；换设备/词本/session不能绕过已发生的曝光。响应速度只用于体验统计，不改变掌握。

## 3. 自动掌握策略 v2

首版采用可解释的结果窗口，不使用时间到期或记忆曲线：

- `new`：当前learning_revision没有有效测验证据。
- `learning`：已有有效证据，但在当前重放结果中尚未首次达到掌握窗口。
- `mastered`：当前重放中已经出现一段满足条件的窗口：连续3组独立合格证据均为无提示完整成功，其中至少2组是主动回忆，且来自至少2个不同习题集或根题；同一根题的重复提交/订正只贡献1组。达到后，后续可靠正向结果保持mastered，不能仅因滑动窗口换入识别题而降级。
- `needs_practice`：达到mastered后，出现更新的可靠错误、部分正确或辅助结果；之后从最近一次负面之后重新满足同一掌握窗口才回到mastered。

此窗口是待阶段4样本校准的推荐策略，不表示科学上的永久记忆。OPEN-11只锁定结果阈值、独立性与版本迁移，不再选择日额度、FSRS或间隔参数。新增正向证据按上述保持规则增量计算；有效评分被替换、题目正式作废、learning_revision变化或策略版本变化时，从有序有效证据完整重放，若原掌握窗口不再成立才可回到learning/new。时间经过本身不改变状态。

响应返回policy_version、evidence_revision、已满足/尚缺条件和受控原因摘要。明细需practice.read及实际来源读取权限；只有collection.read时不给出可探测的题目、Attempt、答案或分数。同拼写聚合按义项分别计算，不制造综合掌握百分比。

## 4. 去重、重评与重放

| 逻辑记录 | 用途 |
| --- | --- |
| EffectiveLearningEvidence | Attempt/评分项/目标、effective_grade版本、能力、结果/辅助、学习版本和accepted_at；业务唯一键防重 |
| VocabularyLearningState | 每词当前掌握、证据版本/原因和策略版本；可重算，不由客户端写 |
| LearnerContribution | 评分发布到学习投影的受控贡献，重评替换而非追加 |

有效评分发布事务写LearnerContribution与Outbox；消费者按稳定业务键upsert证据，在目标父行/投影锁下校验owner/library、learning_revision、未删除和有效版本，再重算状态。同一AI习题集中同一根题/考察点重复只按策略贡献一组；多本、两台设备或消息重投不能增加组数。

重评按新的effective版本替换旧证据，并以服务端accepted_at和稳定ID重放受影响窗口；不能按消息抵达时间追加。题目正式作废使对应证据无效并重算，历史Attempt仍保留。新重评失败保留旧effective证据；投影失败显示rebuilding，不把未知当new、错误或已掌握。

合并收藏仅在服务验证学习内容等价时合并证据并去重重算；解决义项/读音冲突属于新learning_revision，不继承较高状态。删词推进代次，迟到评分只存历史；删本不删词或证据。exercise_control只影响默认AI习题候选，已合法提交结果仍可发布。

## 5. API、CSV与日志边界

Collection写模型只允许内容、笔记/标签和exercise_control；mastery/evidence/policy字段只读。API提供本人状态摘要与必要的解释明细，不提供review-queue/review-plan、due或手动mastery写入。AI习题选择快照读取当时状态，但不能覆盖作答发布时的当前事实。

CSV v2可导出只读mastery快照和policy版本，导入只保存为非权威来源信息；新条目从new开始，既有条目不被CSV覆盖。CSV不备份错题、作答或证据，详见[CSV契约](../contracts/vocabulary-csv.md)。

投影更新事件只记录状态类别、策略/证据版本、数量和受控ID，不记录词、题目、答案或个人分数。管理员只能看授权的任务/失败元数据，不能直接编辑用户掌握结论或浏览证据正文。
