## 1. 概述

Haruka 是一款 **不限语种、以用户自有材料为教材** 的 AI 语言学习产品。

用户导入学习资料（小说、文章、教材、笔记、试卷），系统用 AI 解析并结构化入库。之后：

- 按材料类型呈现（小说用阅读器，教材按单元/习题渲染）
- 导入时选择试卷模式，整卷作答、交卷后 AI 批改，查看成绩并复盘
- 任意文本可朗读、可解释、可收藏，收藏永久带出处
- 用错题、收藏的词/句自动生成练习
- 所有作答由规则 + AI 评分，并回流到学习者模型
- 学习 Agent 分析薄弱点，并在对话中用「类型化卡片」解释词句

一句话定位：

> **把你正在读的东西，变成可朗读、可解释、可练习、可诊断的个人语言课。**

### 1.1 已确认的交付约束（2026-09-22）

- 前端使用 **Flutter**，目标平台为 **Windows、Web、Android**。
- 采用 **Python 后端 + Flutter 前端** 的前后端分离模式，复用 **MyHome** 项目的基础设施。
- 应用内学习 Agent 使用 **Pydantic AI**，卡片、题目和诊断结果使用 Pydantic 模型校验。
- 支持 **试卷模式导入、考试式答题、交卷后 AI 判断与评分**；文件格式的首版覆盖仍待明确。
- **全部日志与埋点接入 MyHome 的 Alloy / Loki / Grafana**，包括三端前端、业务埋点、后端、AI/TTS、数据库及基础设施日志。
- **支持多用户、账号注册和登录**；每位用户的资料、学习记录和模型配置独立，AI 使用各自填写的 API Key。
- 增加 **管理后台与完整 RBAC**，统一控制用户端/管理端登录资格、页面/菜单/按钮显示、接口操作及数据范围；管理端推荐 Flutter Web。
- 朗读使用 **Gemini TTS 或 OpenRouter 上的 TTS 模型**，不以系统 TTS 作为主方案。
- 备份与恢复范围仅为 **单词 CSV 导出和重新导入**；不提供整库 ZIP、原书/音频打包或数据库恢复界面。

服务器保存各用户的资料库，同一账号在三端访问自己的数据；本地存储用于按账号隔离的阅读和音频缓存。

以上按用户最新要求修订，替代此前的无登录、个人共用资料库和全量备份方案。推荐首版使用邮箱和密码注册登录，每个账号一个私有资料库；具体账号流程见第 8.8 节。

配套文档：[架构总览](../architecture/OVERVIEW.md)、[认证与隔离](../architecture/AUTH_AND_ISOLATION.md)、[管理后台与 RBAC](../architecture/ADMIN_AND_RBAC.md)、[MyHome 复用](../engineering/MYHOME_REUSE.md)、[统一日志与前端埋点](../engineering/OBSERVABILITY.md)、[单词 CSV](../features/VOCABULARY_CSV.md)、[试卷模式](../features/EXAM_MODE.md)、[实施计划](../planning/ROADMAP.md)。

逐功能操作、异常和可判定验收见 [功能覆盖索引](../planning/FEATURE_COVERAGE.md)；接口/权限/事务以中央专题为准，代码、测试、lint与发布约束见 [交付验收](../engineering/DELIVERY_ACCEPTANCE.md)。开放选项集中记录在 [决策清单](../planning/DECISIONS_AND_ASSUMPTIONS.md)，不把建议值变成已确认范围。

## 2. 要解决的问题

现有工具通常只覆盖学习链路的一段：

| 工具类型 | 擅长 | 缺口 |
| --- | --- | --- |
| 课程 App（Duolingo 类） | 固定路径、游戏化 | 无法用自己的小说/教材 |
| 阅读器（LingQ / Kindle） | 阅读 + 点词 | 教材习题无法原生作答；练习闭环弱 |
| 闪卡（Anki） | 记忆 | 制卡成本高，出处和语境容易丢 |
| 通用 ChatGPT | 解释力强 | 没有材料结构、没有错题本、没有持续学习者模型 |

用户真正需要的是一条闭环：

**材料 → 理解（读/听/问） → 记住（收藏） → 练（生成题） → 评（打分） → 诊断（Agent） → 再练/再读**

## 3. 产品原则

1. **材料即课程**：不强迫用户走官方大纲；用户导入什么，就学什么。
2. **类型决定界面**：小说进入阅读器，教材进入单元学习页，试卷进入整卷考试流程。
3. **任意文本都是可操作对象**：选中即出现朗读 / 解释 / 收藏，不限页面。
4. **出处不可丢**：收藏、错题、解释都必须能跳回原文上下文。
5. **练习来自你的缺口**：优先用错题、收藏、薄弱点出题，而不是随机题库。
6. **Agent 是教练，不是搜索框**：能总结问题、发起练习、打开材料，不只是聊天。
7. **语种中立**：界面语言、母语、目标语分离；日/中/英/韩/欧语等同一套能力。

## 4. 目标用户

### 4.1 主要用户

- 用小说、漫画文本、字幕、新闻做沉浸阅读的自学者
- 用学校/自学教材（含课后题）的学生
- 多语种学习者（同时学 1 门以上，或母语不是中文）

### 4.2 使用场景

- 晚上读日语轻小说，遇到词就查、收藏，第二天从收藏生成 10 题
- 导入英语教材 PDF/EPUB，按 Unit 学，选择题直接点选项，作文题 AI 打分
- 开口前问 Agent「这个句子为什么用了过去完成时」，弹出语法卡 + 立刻练 2 题
- 考前让 Agent 根据最近两周错题出一份薄弱点试卷
- 导入一套试卷并选择试卷模式，模拟答题，交卷后让 AI 批改并回看错题

### 4.3 非目标（本期不做）

- 替代学校完整 LMS（班级、作业下发、教师批改工作流）
- 社交社区 / 公开材料市场（可列为后期）
- 以视频课、真人外教为核心的产品
- 儿童专项（无家长监护体系）

## 5. 目标与成功标准

### 5.1 产品目标

| 目标 | 说明 |
| --- | --- |
| G1 | 任意常用学习文件能在数分钟内变成可学内容 |
| G2 | 阅读/教材界面可作为日常学习入口，试卷有完整的考试与交卷后复盘流程 |
| G3 | 收藏和错题能稳定变成练习，而不是沉睡笔记 |
| G4 | Agent 能说出「你弱在哪」并直接开练 |
| G5 | 不限语种：至少中/日/英在 MVP 体验完整，架构不绑死某一种语言 |

### 5.2 成功指标（上线后）

- 导入成功率 ≥ 90%（MD / EPUB）；PDF 以「可学文本提取率」单独统计
- 导入后 7 日内，产生至少 1 次朗读、1 次解释、1 次收藏的用户占比
- 收藏/错题转化为练习的周转化率 ≥ 40%
- 有练习行为的用户中，Agent 周活跃 ≥ 30%
- 从卡片/错题一键跳回原文的成功率 100%（数据层必须可追溯）

这些指标的事件、前后端统计口径和数据来源随功能维护。已提交学习事实以业务库为准，客户端埋点用于行为与体验分析；日志的有限留存及补传缺口不能导致重复计数或将缺失当作零。详见 [统一日志与前端埋点](../engineering/OBSERVABILITY.md)。

## 6. 信息架构

2026-09-22 最新视觉要求：年轻化、漂亮、现代美观。旧 HTML 原型已按用户要求删除，目前仅讨论方案，不创建文件；具体配色与布局尚未确认。这不减少下列 P0 功能范围，也不改变 Flutter/Python 技术选型。

**用户端默认以书库为首页，按权限显示。** 未登录进入登录/注册；登录成功且有书库权限时进入当前账号书库，否则进入第一个可访问页面或受控空状态。用户端不设独立「今日学习 / 仪表盘」页；管理端有独立 /admin 登录、运维概览与管理布局，见第 8.12 节。

```text
Haruka
├── 账号入口：登录 / 注册
├── 书库（默认入口 / 首页）
│   ├── 最近在读（有进度的材料，点进去接着读）
│   ├── 全部 / 小说 / 教材 / 试卷 / 其他
│   ├── 导入（学习材料 / 试卷模式）
│   └── 材料详情（目录、进度、语言）
├── 阅读 / 学习页（由材料类型决定皮肤）
│   ├── 小说阅读器
│   ├── 教材学习页（单元树 + 正文 + 内嵌习题）
│   └── 试卷（开考 / 继续 → 整卷答题 → 交卷 → AI 批改 / 成绩复盘）
├── 收藏
│   ├── 单词 / 短语 / 句子 / 摘录
│   ├── 按来源、标签、掌握度筛选
│   ├── 导出 CSV（全部单词收藏）
│   └── 导入：CSV / 拍照识词
├── 练习
│   ├── 智能练习（由缺口生成）
│   ├── 错题本 / 待复习
│   └── 练习历史与评分
├── Agent
│   ├── 对话
│   ├── 诊断报告
│   └── 建议动作（出题 / 复习 / 打开某章）
└── 设置
    ├── 账号资料、修改密码、退出登录
    ├── 服务地址与个人模型 API Key
    ├── 语言、阅读与朗读设置
    └── 单词数据：导出 CSV / 导入 CSV（与收藏页共用入口）
```

以下用户端功能树和全局工具均按当前权限/功能开关过滤，深链接与按钮操作也受控；隐藏页面不能替代服务端权限验证。

全局悬浮能力（有相应权限、选中文本后出现）：

- 朗读
- 解释
- 收藏
- 问 Agent（把选区带进对话）

试卷考试中的辅助工具按第 8.11 节限制：答题期间不提供解释、问 Agent 或答案提示；交卷后复盘恢复学习工具。

## 7. 核心用户旅程

### 7.1 第一次导入并开始学

1. 首次注册并登录，进入个人书库；空库时突出「导入」。AI 功能使用前配置个人 API Key，未配置时仍可进行基础导入和阅读
2. 用户选择“学习材料”并上传 EPUB/MD；试卷使用独立模式，格式范围见第 8.1.1、8.11 节
3. 普通材料保存原文件并解析目录/正文，先允许阅读；再异步执行 AI 分类（小说 / 教材 / 文章 / 混合）、补充结构和习题抽取，结果持久化
4. 书库出现材料卡片：类型、语言、章节数、习题数、预估阅读时长
5. 点开后进入对应皮肤开始学；之后该书出现在书库「最近在读」

### 7.2 阅读中的即时学习

1. 用户在小说里长按/划选一个词或一句
2. 弹出迷你工具条：朗读 / 解释 / 收藏
3. 解释以卡片出现，不打断阅读（侧栏或浮层）
4. 收藏时自动写入：词/句、上下文、材料、章节、偏移、时间

### 7.3 从收藏到会用

1. 用户（或 Agent）发起「根据收藏出题」
2. 生成选择题、完形、翻译、听写等
3. 作答后即时评分，错误进入错题本并标注错误类型
4. 错题可手动再次练习；自动间隔重复队列在 v0.2 引入

### 7.4 Agent 诊断

1. 用户问：「我日语弱在哪？」
2. Agent 基于近期阅读、收藏未掌握项、错题类型给出报告
3. 报告里的每一条都能点：生成 8 题 / 打开相关原文 / 加入复习

### 7.5 在对话里问词问句

1. 用户在 Agent 里输入或粘贴词/句，或从阅读页「问 Agent」
2. 系统识别意图（单词 / 短语 / 句子 / 语法 / 对比 / 发音）
3. 对话中插入对应卡片，而不是纯 Markdown 长文
4. 卡片上可直接朗读、收藏、生成例句练习

### 7.6 单词收藏导入导出

1. 登录后在收藏页点「导出全部单词」，得到当前账号的 UTF-8 CSV，用 Excel 或再导入均可打开
2. 或选择「导入」：上传 CSV，或拍照/选图
3. 预览识别/解析结果，确认后写入单词收藏；无原文锚点的条目来源为「CSV 导入」或「拍照导入」
4. 导入的词与划选收藏一样，可以出题、解释、朗读

### 7.7 注册、登录与切换账号

1. 用户通过注册入口创建账号，后端按注册/审批策略建立独立资料库、学习偏好与允许的默认角色；用户不能自选管理权限。
2. 账号激活且有用户端登录权限后进入允许的页面，配置自己的模型 Key；三端同账号共享个人数据与最新权限。
3. 退出登录后撤销当前设备会话，清除该设备的账号缓存、临时文件和待显示结果。
4. 另一用户登录时看不到上一用户的材料、收藏、对话、音频或 Key；服务器已提交任务仍属于原用户。

### 7.8 导入试卷并考试

1. 在导入页选择“试卷模式”，上传文件，后端识别大题、小题、选项、阅读材料、分值和可选答案区。
2. 预览并修正缺失/误识别项，确认题数、总分和可选时长，生成可开考的试卷版本。
3. 从书库打开试卷，开始或继续考试；用答题卡跳题和标记，答案自动保存，答题期间不揭示答案或评分。
4. 检查未答题后交卷，或限时到期自动提交服务器已保存的答案；答卷锁定。
5. 用户发起 AI 批改，后台逐题处理，完成后展示总分、各题得分、理由、参考答案和薄弱点；失败保留答卷待重试。

### 7.9 管理员配置访问权限

1. 具备管理端登录权限的账号进入 /admin，加载允许的管理菜单和操作。
2. 在授予范围内创建角色/配置权限、继承与拒绝规则，为目标用户分配角色；预览两端有效页面/操作及登录资格变化。
3. 提交权限变更后，服务端事务保存、更新权限版本并记录审计；两端重新取得权限快照，旧接口请求不能继续使用已撤销权限。
4. 管理员按独立权限审批/禁用用户、撤销会话、查看任务/诊断和审计，不因管理角色自动获得他人私有学习内容或 API Key。

## 8. 功能需求

优先级：`P0` 必须进 MVP，`P1` 首个正式版，`P2` 后续。

所有下述功能都以当前账号具备相应登录/动作权限及资源归属为前提。默认 learner 角色提供完整的普通学习体验，管理端可按 RBAC 调整；功能范围存在不表示所有账号都自动获得访问资格。

---

### 8.1 资料导入与 AI 结构化入库

**作为** 学习者，**我想** 把任何学习文件丢进去，**以便** 不用自己拆章节、抄习题、做闪卡。

#### 8.1.1 支持的输入

| 格式 | 优先级 | 说明 |
| --- | --- | --- |
| Markdown (`.md`) | P0 | 结构最清晰，作为解析金标准 |
| EPUB (`.epub`) | P0 | 小说/教材及有对应结构的试卷 |
| 文本型 PDF 试卷 (`.pdf`) | 推荐 P0，范围待确认 | 为试卷模式提前接入可用文本层、页码和题目图片，不代表通用 PDF 阅读器上线 |
| 其他 PDF / 扫描 PDF (`.pdf`) | 暂按 P1 | 普通资料阅读、OCR 和复杂排版；试卷首版是否包含扫描件待确认 |
| 多张试卷图片 | 暂按 P1 | 整卷页序、OCR/视觉识别与校对；与 P0 拍照识词分开，首版范围待确认 |
| 纯文本 (`.txt`) | P1 | 无结构时由 AI 切段 |
| 字幕 (`.srt/.vtt`) | P2 | 后续 |

单文件建议上限：MD/TXT 20MB，EPUB 50MB，PDF 80MB（1MB=1,000,000字节）；在对应格式上线时生效。试卷图片的页数/体积限制需随格式范围验证，不能把推荐的 PDF/OCR 优先级视为已确认交付。超出时明确报错，而不是静默截断。

#### 8.1.2 导入流水线

1. **选择导入模式**：学习材料 / 试卷；显式选择试卷时保存 import_mode=exam，AI 分类不能覆盖
2. **解析原始内容**
   - MD：保留标题层级、列表、代码块、表格
   - EPUB：保留 spine 顺序、chapter、基础样式提示（标题/段落）
   - PDF：文本型试卷优先文本层，保留页码与题目图片；扫描/OCR 按已确认的格式范围启用，不静默丢页
3. **语言识别**：文档主语言、是否双语对照
4. **类型分类**（可多标签，但必须有一个 `primary_type`）
   - `novel` 小说 / 故事
   - `article` 文章 / 新闻 / 随笔
   - `textbook` 教材
   - `workbook` 习题集
   - `notes` 笔记
   - `mixed` 混合（例如课文+课后题）
   - `exam` 试卷（由导入选择确认，走整卷考试流程）
5. **结构切分**
   - 卷 / 章 / 节 / 单元
   - 段落、句子（句子切分必须按语言，不能只按 `.!?`）
   - 教材额外：课文、语法说明、例文、词汇表、习题区
   - 试卷额外：大题/小题、共享阅读材料、题号、分值、时长、题面/答案区；保留跨页关系
6. **习题抽取**
   - 识别题型并转成结构化题目，而不是当普通段落存
   - 选项、空白、正确答案（若原文有）、解析（若原文有）都要入库
   - 试卷还需检查计分叶子题、题目与答案对应关系及参考答案来源；AI 生成答案必须标记来源
7. **质量报告**
   - 用户可见：识别类型、章节数、习题数、低置信度章节、失败页
   - P0 允许修改材料类型；普通材料的合并/拆分章节、习题/正文标注在 P1 提供；试卷必要的题干/选项/小题关系/分值校对属于 P0，详见试卷专题

导入和深度分析由后端执行。已有目录、原始文本和稳定 ID 由解析器/应用生成，模型负责补充分类和语义结构；材料导入后保留原始文件。任务可查询、重试、取消，并在 Worker 重启后恢复；不能依赖客户端持续在线。

试卷只有在必要校对、题目完整性和计分校验通过后才能开考。上传成功或抽取出部分文字不能直接视为整张试卷可用；普通材料“先读后分析”的规则不跳过试卷 ready 门槛。

#### 8.1.3 导入时的 AI 职责（必须落库，不只是聊天总结）

应用持久化的结构至少包括以下对象；原文、稳定ID、顺序与原格式定位由确定性解析和应用维护。AI只输出引用既有ID的分类/语义补充和习题候选，经schema、出处与业务校验后写入，不重写整本材料或替换原文ID：

- 材料元数据：标题、作者（若有）、语言、类型、难度估计；AI推断与原文元数据区分来源
- 应用解析的目录树；AI建议分组必须映射到已有内容范围
- 每个内容块：应用分配的`block_id`、原文、顺序、来源定位，AI可补充类型候选
- 每个习题：AI候选题型、题干范围、选项、答案/解析来源、所属单元；应用生成业务ID并验证原文映射
- 试卷额外：大题/小题关系、共享材料、原卷题号/定位、分值、答案与 rubric 来源、质量问题；版本与计分由应用校验
- 可选：章节摘要、关键词、预估 CEFR/JLPT 等难度（弱提示，允许不准）

**验收标准**

- 导入一本带目录的 EPUB 小说后，阅读器目录与原文顺序一致
- 导入一份含「Unit / Exercise / A. B. C. D.」的教材后，选择题以可点击选项出现，而不是一段纯文本
- 导入失败时给出原因（加密 PDF、空文本层、损坏 EPUB），允许重试
- 普通材料修改类型后切换对应界面；转为试卷需完成结构校验再开考，不必重新上传，已有场次不被改写
- 试卷模式支持有答案/无答案样本；不支持题型、缺选项或总分冲突可见，不静默删除题目

### 8.2 按类型显示：阅读器、教材与试卷

#### 8.2.1 小说 / 文章阅读器（`novel`, `article`）

P0 能力：

- 连续阅读 + 章节跳转
- 字体、字号、行距、主题（浅/深/sepia）
- 阅读进度（章节/内容锚点 + 百分比）保存到后端，连接同一资料库的三端共享；离线缓存与同步边界见第 8.8 节
- 划词/划句
- 当前朗读句高亮（跟读定位）
- 书签、阅读历史

P1：

- 左右分页模式
- 双语对照（若材料本身是对照，或用户开启「句级翻译层」）
- 阅读热力图（哪些段被查过/收藏过）

#### 8.2.2 教材学习页（`textbook`, `workbook`, `mixed`）

P0 能力：

- 左侧/顶部单元树：Unit → Lesson → 课文/语法/词汇/习题
- 正文区按块渲染：说明文字、例句、词汇表、习题
- 词汇表支持点读、收藏、加入复习
- 习题区用原生控件，不用「看起来像题的段落」

P1：

- 单元完成度（课文已读、习题已做、正确率）
- 教师式讲解块与练习块分屏

#### 8.2.3 习题原生渲染（所有材料类型都可能出现）

| 题型 | 界面 | 优先级 |
| --- | --- | --- |
| 单选 / 多选 | 选项按钮，选中态，提交后对错色 | P0 |
| 填空 / 完形 | 空位输入，可听提示 | P0 |
| 判断对错 | 对/错按钮 | P0 |
| 匹配（词-义、句-译） | 左右点选或拖拽 | P1 |
| 排序（组句） | 词块拖拽 | P1 |
| 翻译（句/段） | 多行输入 | P0 |
| 开放问答 / 作文 | 多行输入 + 字数 | 试卷基础文本作答/批改 P0；扩展写作训练 P1 |
| 听写 | 只播 TTS，不显示原文，用户输入 | P1 |
| 口语复述 | 录音（后置） | P2 |

原文没有标准答案的题，仍然渲染为可作答题，交由 AI 评估并标明参考答案来源。普通练习可以逐题反馈；试卷模式在整卷提交后才显示判定、解析和得分。

**验收标准**

- 同一材料若被标成小说，进入阅读器；标成教材，进入单元树。数据不丢
- 教材中的选择题提交前不揭示答案
- 阅读器里若夹了一道题（mixed），该块仍按习题控件渲染

#### 8.2.4 试卷考试页（`exam`）

打开试卷进入开考/继续入口，正式答题包含题目与共享材料、答题卡、已答/未答/标记状态、保存状态和可选计时；整卷提交后进入批改进度与成绩复盘。题面不返回隐藏答案或 rubric，交卷前无逐题反馈。详细要求见第 8.11 节。

### 8.3 通用文本交互：TTS、解释、收藏

阅读器、教材、卡片、Agent、错题解析与考试后的复盘都支持这些能力；试卷作答期间按第 8.11 节限制解释、问 Agent 和答案提示。

#### 8.3.1 选区模型

任意可见文本可形成 `Selection`：

- `token` 词（按语言分词，日语/中文不能按空格）
- `phrase` 短语
- `sentence` 句
- `excerpt` 多句摘录（有长度上限，建议 500 字或 5 句，先到为准）

工具条对以上四种全部可用。

#### 8.3.2 TTS 朗读

朗读供应明确为 **Gemini TTS 或 OpenRouter TTS 模型**。Python 后端负责调用、分段生成和音频保存；Flutter 负责播放、倍速、选句与高亮。文本解释模型和朗读模型分别配置。

P0：

- 词 / 句 / 段 / 当前章节朗读
- 语种自动匹配，用户可改声音
- 播放倍速 0.7x–1.5x；合成语速仅在对应模型支持时设置
- 播放、暂停、停止
- 朗读时高亮当前句
- 按句/短片段生成并预取后续片段，限制并发和预取量
- 生成的音频保存在服务端，三端复用；已下载音频在当前账号有效离线权限租期内允许播放
- 不假定模型提供词级时间戳；优先用句子 ID 与音频片段对应实现句级高亮

P1：

- 生词变慢或重复
- 听读模式（先听再显示）
- 按收藏列表朗读

**验收标准**

- 日语、英语、中文文本能正确选对应语音，不把日语当英语读
- 从阅读器、解释卡、Agent 卡三个入口都能朗读同一句
- 无声/失败时明确提示（Key 无效、额度不足、超时、模型/声音/语种不支持或音频格式错误）
- 同一文本和合成配置重复播放复用已有音频；仅调整播放器倍速不重新调用模型
- 分句拼接的停顿和声音一致性通过英/日/中真实材料验证

#### 8.3.3 AI 解释

解释必须 **结合当前材料上下文**，禁止只给脱离课文的词典第一义。

按对象输出不同结构（供卡片复用）：

| 对象 | 必须包含 | 可选 |
| --- | --- | --- |
| 词 | 拼写、读音（IPA/假名等）、词性、本义、**在本句中的意思**、1–3 个例句 | 搭配、近反义、词源、登记语体、常见错误 |
| 短语 | 整体意思、能否拆开、例句 | 同义表达 |
| 句子 | 整句翻译（用户母语）、逐块解释、语法要点 | 更自然的改写、语气 |
| 摘录 | 摘要、关键表达、为什么难 | 段落逻辑 |

解释语言默认 = 用户母语。可切换到目标语解释（高阶用户）。

P0 要快：词/句解释目标 3 秒内出首包（流式）。

**验收标准**

- 同一词在不同句中，卡片上的「本句义」可以不同
- 解释结果可收藏（连同当时的上下文）
- 用户能对解释点「有用 / 不准」，用于后续提示优化（不必立刻做模型微调）

#### 8.3.4 收藏（带出处）

可收藏对象：词、短语、句、摘录。

每条收藏 **必须** 保存：

- 收藏类型与原文
- 规范化形式（如动词原形、日语词典形）—— AI/形态分析生成，允许用户改
- 上下文（前后句）
- 来源：材料 ID、章节/单元 ID、块 ID、句 ID、字符偏移、PDF 页码（若有）
- 用户笔记、标签
- 时间、掌握状态（新 / 学习中 / 已掌握 / 暂停）
- 触发来源（阅读划选 / Agent 卡 / 习题解析 / CSV 导入 / 拍照导入）

能力：

- 列表筛选：语种、来源材料、类型、标签、掌握度
- **一键跳回原文并高亮**
- 取消收藏、合并重复项（同一 lemma + 同一材料可提示合并）
- 单词收藏导入 / 导出（见 8.3.5）

**验收标准**

- 从收藏点「来源」，必须打开原材料并定位到原句
- 材料被删除时，收藏仍保留文本和上下文，来源显示「原材料已删除」，不崩
- 同一词在不同小说里收藏，是两条来源记录，可按 lemma 聚合查看

#### 8.3.5 单词收藏：CSV 导出、CSV / 拍照导入

**作为** 学习者，**我想** 把全部单词收藏导出成 CSV，也想用表格或拍照把已有词表灌进来，**以便** 和 Anki、备考词表、纸质笔记互通，而不锁在 Haruka 里。

本期数据导入导出仅覆盖 **当前账号的单词收藏**（`kind = word`）。不导出短语、句子、摘录、原书、音频和练习记录；不提供整库恢复。

##### 导出 CSV（P0）

- 用户可导出 **当前账号下全部单词收藏**，不丢条，不受分页影响
- 同时支持按当前筛选结果导出（语种 / 标签 / 来源 / 掌握度）；入口文案区分「导出全部单词」和「导出当前列表」
- 编码 UTF-8（带 BOM，方便 Excel 直接打开中日文）
- 一份导出必须能被本产品再导入（往返）

字段包括单词、词典形、语言、读音、释义、上下文、笔记、标签、掌握状态、来源标题、可选定位与时间。字段协议、版本、转义和重复处理统一维护在 [单词 CSV 规范](../features/VOCABULARY_CSV.md)，此处不重复维护列定义。

CSV 不含账号密码、会话或模型 Key。定位只有在当前用户确有权访问对应材料时才可重新绑定，否则保留文本来源并显示「CSV 导入」，不能借导入访问其他用户的原文。

##### 导入 CSV（P0）

- 接受 Haruka 自己的导出格式，列自动对齐
- 接受最小表：至少一列单词；释义、读音、笔记为可选
- 表头对不上时，进入列映射（哪一列是词 / 释义 / 读音）
- 导入前预览：条数、语种推断、重复项
- 重复策略由用户选：跳过 / 合并（补空字段、保留已有出处）/ 仍创建新条
- 外来 CSV 没有原文锚点时：来源记为 `csv_import`，不假装能跳回某本书
- 大词表按批次处理，建议每批最多 10,000 条；全部单词 CSV 可自动分批导入，不要求用户手工拆分。超出配置的文件字节上限时明确报错
- 预览与确认仅写入当前账号；CSV 中的用户 ID、记录 ID 或来源信息不能改变归属或绕过权限

##### 拍照导入（P0）

用户拍或从相册选图片（单词本、教材词汇表、屏幕截图、手写词表）。

流水线：

1. OCR / 视觉模型抽出候选词行
2. AI 结构化为 `word / reading / meaning`（按用户当前目标语、母语）
3. 预览表，用户可改、删、补语种
4. 确认后写入单词收藏，来源记为 `photo_import`，并保留原图缩略（可选，便于核对）

约束：

- 一次可多图（P0：至少 1 张；P1：一次最多 10 张合并预览）
- 识别置信度低的行默认勾选但仍标记「待确认」，不静默丢弃
- 手写、歪斜、光线差时允许重拍，失败给原因
- 本节的拍照识词只进单词收藏，不创建材料；多页试卷图片属于独立的试卷导入流程及格式规划

**验收标准**

- 书库里收藏了 N 条单词，点「导出全部单词」得到 N 行数据行（不含表头）
- 该 CSV 再导入（选跳过重复）后，单词总数不增加
- 两列 CSV（word, meaning）导入后可在收藏列表出现，并能用来出题
- 拍一张印刷体英语或日语词表，预览里能看到词和释义，确认后进入收藏
- CSV 导出/导入不包含短语和句子；切换账号不会读取或修改另一用户的收藏

### 8.4 由错题、收藏生成习题

**作为** 学习者，**我想** 系统根据我不会的东西出题，**以便** 练习总是打在痛点上。

#### 8.4.1 出题来源（可多选）

- 收藏的词 / 短语 / 句
- 错题本（按错误类型、时间）
- 最近阅读过但反复查询的词
- Agent 标出的薄弱点
- 当前单元（教材内原题 + 变式题）

#### 8.4.2 生成策略

P0 题型：

- 词义选择题（目标语词 → 母语义 / 反方向）
- 语境填空（挖掉收藏词，保留原句）
- 句译（目标语 ↔ 母语）
- 原教材题重做

P1：

- 听写（TTS → 输入）
- 近义词/易混词对比题
- 语法变形（时态、活用、单复数）
- 组句

规则：

- **优先使用用户真实上下文造题**，不要凭空造完全无关的句子
- 一道题要记录：来源收藏/错题 ID、考察点、题型
- 一次练习默认 8–15 题，用户可改
- 避免连续两题考同一个 lemma，除非用户指定「专攻」
- 原教材题与 AI 变式题要标记来源，避免把教辅原题当原创

#### 8.4.3 练习会话

- 开始练习：来源、题量、题型过滤、语言
- 做题页：一题一屏，可听题干
- 提交后立即看到对错、解析、原句入口
- 会话结束：正确率、错误类型分布、可再练错题、可让 Agent 点评

本节为普通练习的即时反馈模式。试卷导入后的考试使用独立场次与整卷提交，反馈时机和答卷锁定以第 8.11 节为准。

**验收标准**

- 只收藏了 3 个词时，仍能出一轮题（允许重复语境或补充 AI 例句，但需标明「补充例句」）
- 错题再练时，题干可以变式，但考察点不变
- 生成的填空答案若是活用形式，评分必须接受该句需要的形式，而不是只接受词典形（见 8.5）

### 8.5 所有习题可 AI 打分

评分引擎分两层，对用户是一个分数，对系统要分开存。

#### 8.5.1 客观题（规则优先）

- 单选/多选/判断：精确匹配
- 填空：规范化后匹配（大小写、全半角、日语假名宽窄、可选拼写、标点）
- 可配置「接近答案」：漏冠词、词序轻微错误等给部分分

有可靠答案且规则能判定的，不调用模型，保证快和稳。缺少标准答案或需要语义评估时使用 AI 并标记依据；低置信度抽取的答案不能直接当权威规则答案。

#### 8.5.2 主观题（AI 评分）

适用于翻译、开放问答、作文、口语（后期）。

输出结构：

- 总分 0–100 或 0–分值
- 分项：意思是否完整、语法、词汇、流畅、拼写/书写
- 错误列表：每条含原文片段、问题类型、修改建议
- 参考答案（1–2 个自然版本）
- 置信度：低置信度时提示「建议人工再看」

P0：翻译句、填空模糊匹配、试卷中的文本简答/作文基础评分  
P1：扩展段落写作、多句翻译训练与更细的评分能力  
P2：口语发音/流利度

#### 8.5.3 回流学习者模型

每次作答写入：

- 题 ID、考察 lemma/语法点、对错、部分分、错误类型、用时
- 用于：错题本、SRS、Agent 诊断、下次出题权重

**验收标准**

- 选择题对错与原文标准答案一致
- 「I go to school yesterday.」这类翻译/改错能被标出时态问题，而不是只给一个「不对」
- 评分结果可被用户申诉：「我觉得我是对的」→ 标记待审，不影响继续学（P1 可做人工覆盖）
- 试卷总分由程序校验并累计；AI 返回无效分值、批改失败或待复核时不计作零分，未完成时只展示已评部分
- 试卷重评保留评分版本，学习记录按场次/题目去重更新，不能把重试当成新增作答

### 8.6 学习 Agent（薄弱点分析）

Agent 不是通用聊天机器人，它有工具，也有记忆。

#### 8.6.1 学习者模型（对用户可解释）

系统持续维护（按目标语分开）：

- 词汇：已见 / 已收藏 / 已掌握 / 易错
- 语法点：从错题和解释反馈中聚类（如「日语て形」「英语现在完成」）
- 技能：阅读理解、听辨（TTS 相关错题）、产出（翻译写作）
- 习惯：常读类型、平均会话时长、上次学习间隔

展示原则：用「证据」说话。例如：

> 过去 14 天，て形相关题 12 道，正确率 41%。相关收藏 9 条，有 6 条仍未掌握。建议先从《xxx》第 3 章的 4 个原句练起。

禁止空洞鼓励，如「继续加油哦」作为主结论。

#### 8.6.2 Agent 可执行动作

P0：

- 生成诊断报告（7 天 / 30 天 / 本教材）
- 根据薄弱点生成一轮练习
- 打开某条收藏 / 某章原文
- 解释用户问的词句（走卡片协议）

P1：

- 制定本周计划（每天 15 分钟：10 分钟读 + 5 分钟练）
- 「为什么这题错」：结合当时作答
- 对比两个易混词并出对比题

P2：

- 多教材之间的能力迁移判断
- 考试向（JLPT N2、CEFR B1）对照——仅估计，需免责声明

#### 8.6.3 诊断报告结构

- 总览：最近学习量、正确率趋势
- Top 薄弱点（3–7 条），每条含证据和动作按钮
- 已掌握亮点（避免只报忧）
- 下一步：读哪一章 / 练哪一组

**验收标准**

- 新用户没有任何数据时，Agent 说明「还没有足够的练习数据」，并引导导入或开始阅读，不编造薄弱点
- 报告中的「出 8 题」点下去，考察点必须与该薄弱点一致
- 用户切换目标语后，诊断与词库隔离

### 8.7 Agent Chat 与类型化卡片

对话是入口，卡片是结果。**不同类型的问题，弹出不同类型的卡片。**

#### 8.7.1 意图识别

用户输入或带入选区后，先判类型：

| 意图 | 触发例子 | 卡片 |
| --- | --- | --- |
| `word` | 「 tangents 是什么」「覚える」 | WordCard |
| `phrase` | 「take it for granted」 | PhraseCard |
| `sentence` | 粘贴一整句问意思 | SentenceCard |
| `grammar` | 「为什么用了被动态」 | GrammarCard |
| `contrast` | 「は 和 が 差在哪」 | ContrastCard |
| `pronunciation` | 「这个怎么读」 | PronunciationCard |
| `exercise_help` | 「这题我为什么错」 | ExerciseReviewCard |
| `diagnosis` | 「我弱在哪」 | DiagnosisCard |
| `chitchat` | 其他 | 普通回复，可引导回学习 |

识别不准时：先出最接近的卡片，并给「你是想问单词还是整句？」的轻量澄清。

#### 8.7.2 卡片通用能力

每张卡都有：

- 类型标签
- 朗读
- 收藏（自动带当前材料/对话来源）
- 「根据这个出题」
- 「在原文中看」（若有出处）
- 反馈：有用 / 不准

卡片是结构化组件，不是聊天气泡里的 Markdown 表格。

#### 8.7.3 各卡片内容

**WordCard**

- 词形、读音、词性
- 本语境义（若从材料进入）
- 其他常见义（折叠）
- 2 个短例句（优先来自用户材料）
- 变形/活用（日语动词、英语不规则变化等，按语种插件）

**PhraseCard**

- 整体含义、字面义
- 可否拆分、常用程度
- 例句

**SentenceCard**

- 原句
- 母语翻译
- 意群切分（chunk），点每个 chunk 可再展开
- 关键语法点（最多 3 个，点开变 GrammarCard）
- 更自然的复述（可选）

**GrammarCard**

- 规则名（用户母语 + 目标语术语）
- 用当前句当主例
- 2 个对比例（对/错或 A/B）
- 「立刻练 3 题」

**ContrastCard**

- 两个（或多个）形式并排
- 何时用 A / 何时用 B
- 易错点
- 对比练习按钮

**PronunciationCard**

- 读音符号
- TTS（慢速 / 常速）
- 近似发音提示（对用户母语）
- 后期：跟读打分

**ExerciseReviewCard**

- 用户答案 vs 参考
- 错因
- 相关规则/单词
- 再来一题

**DiagnosisCard**

- 见 8.6.3 的压缩版，可展开完整报告

#### 8.7.4 对话体验

- 支持把阅读页选区「发送到 Agent」，上下文（书名、章节、前后句）自动带上
- 多轮：用户说「那和 make 有什么区别？」应继承上一张 WordCard 的词
- 一次回复可以有多张卡（例如一句里两个生词 + 一张 SentenceCard），但默认不超过 3 张，避免刷屏
- 纯闲聊要短，并提供「解释刚才那句」「出题」等快捷芯片

**验收标准**

- 问单词出现 WordCard，问整句出现 SentenceCard，不以同一长文本框应付
- 从阅读器把句子丢进 Agent，卡片能显示出处并跳回
- 在卡片上收藏后，收藏列表里来源为该材料（而非「Agent 对话」丢失出处）；若确实是对话里手打的词，来源记为 Agent，并保存当时解释

P1：

- 完善下载管理和缓存管理

P2：离线写入与多设备冲突合并，具体范围另行确认。

### 8.9 单词备份与恢复的产品边界（P0）

「备份」就是导出当前账号的单词 CSV，「恢复」就是经过预览和重复处理后导入该 CSV。与第 8.3.5 节使用同一套功能，界面统一命名为「导出单词 CSV / 导入单词 CSV」。

- 导出不受列表分页影响，可下载全部单词；筛选导出另有明确入口。
- 导入仅新增或按用户选择补全当前账号的单词，不清空或替换现有资料库。
- 保留协议定义的单词字段；原材料未在本账号存在时，不承诺来源可点击回跳。
- 原书、附件、音频、其他类型收藏、作答、对话与设置均不在该功能范围。
- CSV 往返不调用模型，不创建账号，也不修改登录凭据或模型配置。

验收：原样导出的 CSV 在原账号按「跳过重复」导入不增加条目；在空账号导入恢复单词字段且不关联其他用户的材料；无效行、重复项和处理结果均可见。详见 [单词 CSV 规范](../features/VOCABULARY_CSV.md)。

### 8.10 统一日志与前端埋点（P0）

- 复用 MyHome 的 Alloy → Loki → Grafana，全部日志来源进入同一平台，按应用、服务、平台、版本和操作关联查询。
- 前端覆盖 Windows/Web/Android 的运行日志、正常/失败网络请求、页面访问、性能、Flutter/Dart 异常和可取得的原生诊断；正常日志和 info 埋点也要上传。
- 为注册登录、权限拒绝/变更、管理操作、材料导入、阅读、解释、朗读、收藏、练习、试卷考试/批改、Agent 和 CSV 建立事件字典；前端意图、服务端提交结果与客户端实际体验分别记录。
- 后端覆盖 API/访问/异常、业务服务、第三方库、Worker/Outbox、初始化与迁移；AI 覆盖 Agent、每次模型/工具调用、校验、用量、重试和 TTS。
- 数据库同时覆盖 SQLAlchemy 查询/事务/连接诊断与 PostgreSQL 引擎日志，网关、Redis、Kafka、MinIO 等运行日志一并接入。
- 统一日志字段和关联 ID；三端批量上报、有界离线补传、失败退避、重复识别、丢弃计数及账号隔离；未登录启动和登录失败有受限采集入口。
- 密码、Token、Key、原始材料/对话/答案、CSV 行和 SQL 参数不得进入日志；日志平台仅供获授权运维访问。
- 采集范围、级别、留存窗口、容量和告警在上线前实测；队列超限或平台中断不得无提示丢弃，也不能阻塞学习功能。

验收：三端关键流程的正常/失败事件及后端、AI、数据库日志可在同一个 Grafana 查到并关联；断网、关闭、补传、换账号和模拟秘密样本验证通过。具体协议、事件字典、原生崩溃边界与看板以 [统一日志与前端埋点](../engineering/OBSERVABILITY.md) 为准。

### 8.11 试卷导入、考试与 AI 批改（P0）

已确认：导入时可以选择试卷模式，打开试卷后像考试一样答题，完成后让 AI 判断与评分。以下为推荐的首版体验，详细协议以 [试卷模式](../features/EXAM_MODE.md) 为准。

- 导入区分“学习材料 / 试卷”，书库增加试卷筛选；用户选择优先于 AI 分类，打开试卷进入开考/继续/历史成绩入口。
- 结构化识别大题、小题、题型、选项、空位、阅读材料、题图、分值、时长与可选答案区；有答案和无答案试卷均支持。缺失/错配和不支持的题型必须呈现，不静默删题。
- 开考前预览并校对题目、分值/总分和必要材料，保存不可变试卷版本。试卷必要校对为 P0，普通材料的高级章节编辑仍按 P1。
- 三端提供题目控件、答题卡、跳题、标记、已答进度、自动保存和继续答题；限时为可选设置，开始后由服务端计时，退出/切后台不暂停。
- 作答期间不显示答案、解析、AI 提示或逐题得分；题面接口不返回隐藏答案。考试后复盘可使用原有解释、收藏、朗读和 Agent 能力。
- 交卷前提示未答题；服务端保存并锁定答卷，限时到期提交已收到的答案。重复提交、保存竞争和 Worker 重试不能重复写入或无限收费。
- 交卷后可发起 AI 批改。可靠客观答案用规则，主观/缺答案题由 AI 评估；明确评分依据，程序校验分值并汇总整卷分数。
- 成绩显示总分/满分、用时、逐题分项得分、理由、参考答案、错题和薄弱点；无标准答案标明 AI 评估，低置信度待复核，失败不计零分。
- 答卷与评分分开持久化；无 Key 或供应商故障保留已交卷答案，允许恢复未完成批改。重做创建新场次，重评创建新评分版本，旧成绩保留。
- 首版试卷格式待明确：沿用 MD/EPUB，推荐提前支持文本型 PDF；扫描 PDF/图片暂按后续规划，不能把拍照识词视为整卷 OCR 已具备。

验收：三端完成“选择试卷 → 校对 → 开考/保存/继续 → 交卷 → AI 批改 → 成绩/错题复盘”；验证题面答案隔离、服务端截止、多端草稿冲突、幂等提交、评分中断与部分失败、无答案标识、历史版本和双用户归属。日志记录过程与状态，不记录题目/答卷正文。

### 8.12 管理后台与完整 RBAC（P0）

已确认增加管理后台，RBAC 同时控制登录、用户端显示和管理端显示，并覆盖对应接口/业务操作，具体契约以 [管理后台与 RBAC](../architecture/ADMIN_AND_RBAC.md) 为准。

- 管理端推荐 Flutter Web 独立入口、登录与布局；模块包含运维概览、用户/会话、角色/权限、两端菜单、登录注册策略、配额/模型目录、资源/任务元数据及审计诊断。
- 用户可分配多个角色，角色可以受限继承；权限使用稳定代码，支持允许/拒绝，默认拒绝且显式拒绝优先。登录权限按 client/admin 区分，账号禁用优先阻断所有会话。
- 用户端各页面、全局工具、按钮、只读状态以及管理端菜单/字段/操作均依照同一有效权限快照显示；深链接、刷新、前进后退和直接调用 API 均不能绕过。
- 菜单显示开关和权限撤销分别配置；隐藏导航不等于禁用接口。页面/组件来自已发布清单，后台不能注入任意代码或伪造不存在的权限。
- 后端校验受众、账号/会话、操作权限、功能启用、数据范围与业务状态；本人数据仍按归属隔离，管理员只能使用已授权的管理字段/动作，不自动查看他人原文、答卷或个人 Key。
- 管理员授予角色/权限必须在可委派范围内；防止自提权、角色继承/修改默认注册角色间接提权，保护最后一个可登录的超级管理员。首管理员由受控部署初始化。
- 权限变更与版本/审计事务提交，下一次受保护请求以新版本校验；撤销登录资格可强制结束相应端会话，前端刷新可见界面，Worker/Agent 在后续操作/付费阶段重查权限。
- 管理变更审计持久化到业务数据库并经 Outbox 进入同一日志平台；保留有效权限差异和操作者，禁止秘密/私有正文入日志。普通管理账号不会因此自动获得共享 Grafana/Loki 权限。

验收：角色×账号状态×两端登录×页面/动作/接口/数据范围矩阵通过，包含只读、无权、继承冲突、直接接口调用、旧 Token/缓存、撤权、多实例、授予越界、最后管理员保护及审计。权限加载失败不先展示受限界面，后台基础与授权服务在阶段 1 建立。

```text
  profile_id, sentence_id, span, kind

CollectionItem
  id, profile_id, kind, text, lemma, lang
  context, locator, material_id, sentence_id
  status, tags, notes
  origin                 # selection | agent | exercise | csv_import | photo_import

Attempt
  id, profile_id, exercise_id, answer, score, rubric_json
  error_tags[], duration_ms

ExamPaper / ExamPaperVersion / ExamSection / ExamItem
  试卷、冻结题目结构/分值、共享材料及出处；从属于用户资料库

ExamGradingBasis / ExamSession / ExamResponse / ExamGradeRun / ExamItemGrade
  版本化答案/rubric、考试场次、草稿/锁定答卷、批改运行与逐题成绩
  详细状态、版本、幂等和字段职责见试卷模式专题

LearnerProfile
  profile_id, lang
  vocab_stats, grammar_stats, skill_stats, updated_at

AgentThread / AgentMessage
  结构化消息：text + cards[]

Card
  type, payload_json, source_locator

AudioAsset / AudioSegment
  text_hash, provider, model, voice, synthesis_config, object_key
  sentence_ids, segment_order, format, duration, status

ProviderCredential
  id, user_id, provider, encrypted_key, credential_version, encryption_key_version, revision, status

Job / CsvImportBatch
  user_id, library_id, kind, status, progress, result_ref, error, schema_version
```

关键约束：

- 以上为逻辑模型草案；用户、会话及资料归属为必需边界，首版不做组织/共享资料库
- 所有业务记录需直接携带 user_id/library_id 或通过强约束父级确定归属；跨表引用、唯一键、查询、文件下载和任务都必须验证同一所有者
- 示例省略的归属列不表示该对象可全局读取；CSV 中的 ID 不得决定新记录的所有者
- `CollectionItem`、`Attempt`、`Card` 都能指向 `locator`（CSV / 拍照导入的单词允许 locator 为空）
- 生成题必须能追溯到 `CollectionItem` 或 `Attempt` 或 `ContentBlock`
- 材料物理文件与结构化内容分离，允许重新解析而不丢收藏（按 locator 尽力重绑，失败则保留快照文本）
- 考试场次冻结试卷版本与时限，交卷后答案不可修改；评分依据和重评版本可追溯，学习统计不重复累计
- RBAC 授权在资源归属之外执行；管理数据范围不改变私有资料所有权，权限修改/版本/审计原子提交

## 10. AI 系统需求

### 10.1 能力清单

| 能力 | 用途 |
| --- | --- |
| 文档理解 | 分类、切章、抽题 |
| 试卷理解 | 题组/小题/题图/分值/答案区候选抽取，质量报告与可校对结构 |
| 词表视觉识别 | 拍照导入单词：OCR + 结构化为 word/reading/meaning |
| 分词/形态分析 | 划词、lemma、日语活用等（按语种插件，能规则就规则） |
| 语境解释 | 词句卡 |
| 出题 | 从收藏/错题生成 |
| 主观评分 | 翻译/写作与整卷逐题批改，按固定 rubric 返回可校验结果 |
| 云端 TTS | Gemini TTS / OpenRouter TTS，后端生成，客户端播放 |
| Agent 规划 | 诊断 + 调工具（出题、打开材料、查档案） |
| 嵌入检索 | 用用户材料做 RAG，避免胡编例句 |

### 10.2 设计约束

- **Agent 框架**：采用 Pydantic AI；工具、上下文、卡片、会话存储与执行恢复的职责见 [Agent 运行层](../architecture/AGENT_RUNTIME.md)
- **能确定的不用模型**：有可靠答案的客观题评分、整卷总分累计、目录已存在的 EPUB 切章
- **结构化输出**：解释、抽题、评分和卡片等结构化业务结果必须校验 JSON schema；TTS 返回音频并保存结构化元数据，不能强制套用 JSON 文本输出
- **引用用户材料**：解释和出题优先引用已入库句子
- **流式**：解释与 Agent 首包要快
- **失败可见**：超时、安全拒绝、低置信度都要有 UI
- **费用可控**：导入/整卷批改可异步；有可靠答案且规则可判定的题零模型；逐题结果可复用，Agent 有工具调用上限
- **执行位置**：AI 由 Python 后端统一调用；即时解释走流式响应，整章音频、整卷批改和批量分析走持久任务；所有调用使用当前任务所有者的配置与额度
- **日志观测**：Agent、模型、工具与 TTS 使用统一遥测，记录状态、耗时、用量和重试并关联用户操作；不记录原始 Prompt/回复或工具正文
- **供应可替换**：文本、视觉、TTS 按能力单独适配；具体模型 ID、声音、接口路由和流式能力在接入时验证

### 10.3 语种扩展

MVP 完整支持：**简体中文（界面/母语）、英语、日语**。

架构上语种是插件：

- 分词器
- 形态还原
- TTS voice 映射
- 读音表示（IPA / 拼音 / 假名）

韩语、西/法/德作为 P1/P2，不在 MVP 承诺「一样好」。

## 11. 体验与内容安全

- 导入的材料默认 **仅用户可见**（私人书库）
- Haruka 不将用户材料用于自身训练；发送给所选 AI 供应商的数据及其保留/训练政策应明确说明，不能代替供应商作未验证的保证
- 尊重版权：产品定位为个人学习工具，不做材料广场或公开整书分享；用户可导出自己的单词 CSV
- 解释中的例句若来自用户书，要能显示来源；AI 自造例句要标记「生成例」
- 儿童色情等违法内容按安全策略处理；用户上传试卷进行个人模拟答题、交卷后 AI 批改属于正常学习场景
- TTS 与 LLM 失败不阻断已授权的基础阅读：后端可达时可读已解析材料，离线时在有效权限租期内可读已缓存章节、播放已下载音频

## 12. 非功能需求

| 项目 | 要求 |
| --- | --- |
| 导入 | MD/EPUB 中位时长 < 30s（不含大模型深度抽题）；完整 AI 结构化可异步，完成后通知 |
| 阅读 | 已缓存章节打开目标 < 300ms；未缓存章节单独测量网络加载；滚动流畅 |
| 解释 | 首 token < 3s（正常网络） |
| 客观题评分 | 后端规则计算目标 < 100ms，不含网络往返 |
| 主观题评分 | 即时单题目标 < 8s；整卷批改异步显示逐题进度，不套用单题时延目标 |
| 考试可靠性 | 草稿状态可见、计时由服务端确定、交卷幂等并锁卷、评分失败保留答案、版本变更不改写旧场次 |
| 可用性 | AI 宕机时已授权的阅读和已有音频仍可用；后端不可达时限于有效离线租期内的本地缓存；任务支持重启恢复 |
| 身份与隔离 | 两端登录资格、会话撤销和账号切换可用；RBAC 与资源归属共同控制查询/写入/下载/任务，管理者不可越过授予边界 |
| 权限一致性 | 两端显示与 API 动作统一映射；下一受保护请求检查新权限，长连接/任务按约定边界复核；离线撤权限制明确 |
| 隐私 | 材料默认私有；API 使用 TLS；密码哈希保存，模型 Key 按用户加密；秘密不进入日志、队列或 CSV |
| 日志与埋点 | 三端、后端、AI、数据库与基础设施共用 MyHome 日志平台；正常事件可查，操作可关联，采集缺口与留存明确，上报不阻塞业务 |
| 单词数据 | 全量单词 CSV 导出及导入往返；不恢复原书、音频和学习记录；导入失败不破坏已有数据 |
| 可测试 | 认证隔离、导入、抽题、出处、CSV 往返、拍照识词、考试/评分、卡片、TTS 缓存和三端流程均需有效验证 |

## 15. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| PDF 排版/扫描质量差，抽题失败 | 试卷题目缺失或答案错配 | 文本型 PDF 试卷优先验证，提供质量报告/校对，阻止残缺版本直接开考；OCR 范围另行明确 |
| 小说与教材分类不准 | 皮肤用错 | 允许用户一键改类型；mixed 类型 |
| 日语分词/活用错误导致划词差 | 学日体验差 | 专用分词；允许用户扩展选区 |
| AI 出题脱离原文或太简单 | 用户不信任 | 强制带原句；记录来源；用户可删题 |
| 主观评分不稳定 | 成绩或反馈不可信 | 版本化 rubric + 低置信度待复核；规则可判定题不用模型，失败不计零分，总分由程序累计 |
| 考试保存/交卷竞争 | 答案丢失、重复交卷或历史成绩被覆盖 | revision/编辑代次、服务端截止、事务锁卷与 Outbox、冻结试卷和评分版本 |
| AI / TTS 费用 | 导入、整卷批改或朗读产生意外费用 | 分段生成、有限预取、已评分题复用、规则路径零模型；超时不能无限重试 |
| 用户数据串用 | 原文、音频或 Key 泄露给其他账号 | 服务端归属约束、任务与缓存分区、双账号越权测试 |
| 权限遗漏/旧策略/管理提权 | 隐藏页面仍可调用接口或获得越界角色 | 默认拒绝、完整接口映射、权限版本校验、授予上限与管理员保护、角色矩阵回归 |
| CSV 字段损失或重复 | 单词导入后缺字段或重复累积 | 版本化字段、可逆转义、预览与重复策略、往返测试 |
| 共用基础设施 | 解析/音频负载影响 MyHome | 独立凭据和命名、用户配额与全局并发上限，接入前检查容量 |
| 版权 | 合规 | 私人书库、仅单词 CSV 互操作、不公开分享整书 |

## 16. 已确认决策与待确认问题

### 16.1 已确认

1. Flutter 前端，Windows / Web / Android。
2. Python 前后端分离，基础设施复用 MyHome。
3. 多用户、注册和登录；资料隔离，用户自备各自的模型 API Key。
4. Gemini TTS 或 OpenRouter TTS。
5. 备份/恢复只保留单词 CSV 导出和导入，不做全量资料库备份功能。
6. 应用内学习 Agent 采用 Pydantic AI。
7. 前端全部日志与埋点、后端、AI/TTS、数据库及基础设施日志统一收集到 MyHome 日志平台。
8. 支持导入时选择试卷模式、考试式整卷答题、交卷后 AI 判断与评分。
9. 管理后台与完整 RBAC，控制两端登录、用户端/管理端显示及对应接口、操作和数据范围。

### 16.2 待确认

1. **注册方式细节**：推荐邮箱 + 密码；是否需要邀请注册、邮箱验证和邮件找回密码，需在公开上线前确定。
2. **账号关联**：当前采用 Haruka 独立账号，仅复用 MyHome 的认证机制；不默认共享 MyHome 用户或登录会话。
3. **阅读器要求**：横排学习阅读优先，还是 MVP 必须高度还原 EPUB 竖排/复杂注音？
4. **供应商配置**：默认采用 OpenRouter 统一入口，还是优先 Gemini 官方直连？具体模型和声音需实测。
5. **试卷文件格式**：推荐首版沿用 MD/EPUB 并提前支持文本型 PDF；扫描 PDF 与多张图片是否一起进入首版待明确。普通 PDF/OCR 与 SRS 的原后续安排不自动全部提前。
6. **目标语优先级和界面语言**：当前为中文界面、英/日学习；三语界面暂未纳入 MVP 承诺。
7. **教材缺答案处理**：普通教材是否在导入时生成 AI 参考答案仍待明确；试卷推荐开考前准备/冻结带来源标识的参考与 rubric，交卷后评估。
8. **部署条件**：共享基础设施的实际容量、网络、域名/TLS 和访问权限尚未在服务器验证。
