# 查询与习题任务流优化

日期：2026-09-25，阶段1内独立原型小阶段 DESIGN12，基线 aa208c8。用户要求从操作逻辑、显示排版、更好的显示/操作方式和界面方案四个角度重新体验。本次沿查询输入/示例/回答、练习选源/设置/确认、材料入口/导入及设置分类走查，集中修改查询与习题两条流程。范围为手机/电脑HTML原型及对应交互文档，不是全产品验收或B1/B2实现。

## 体验判断与方案取舍

| 用户关注点 | 实际问题及影响 | 本次方案 |
| --- | --- | --- |
| 操作是否合理 | “手选收藏”只有数量，没有逐条选择；词本/教材/错题控件集中放在来源列表底部，手机难以对应 | 选中某类来源后在该项下展开具体控件；手选收藏显示词句、释义及复选框，学习语言变化清理不可用选择 |
| 显示与排版是否合理 | 查询首页的大图标、标题和四个问题排在输入前，常用操作被示例挤到后面；确认范围只有数量 | 查询先输入/图片/发送，下方用两列紧凑示例；习题预览显示具体内容、释义/状态及来源，手机顺序排列，宽屏设置与范围并排 |
| 是否有更好的操作逻辑 | 原生成流程需要设置→点击预览→确认→弹窗再确认，却没有增加可判断信息；点击查询示例覆盖草稿 | 改为“选择来源→设置与确认”，一次明确确认前展示范围和演示效果；示例只追加草稿，超过上限保留原文并提示 |
| 是否有更好的界面方案 | 选源数量离操作按钮远；跨来源的同一收藏被重复计数，题量不足也可继续，容易误解配置 | 手机底部动作旁持续显示去重数量；同一收藏跨词本/手选只列一次并标出来源；不足时减少题量或显式允许同源多题，修改相关设置后清除旧授权 |

保留五个主入口、材料直达阅读/学习/试卷准备、详情另开面板、导入先明确三类材料、设置按任务分类。这些路径与当前产品边界一致，本次没有发现需要重排其信息架构的证据。没有新增总览页、继续阅读、复习队列，也不进行整套换肤。

选择两步而非把所有条件塞进一页，是为了在手机上先决定内容，再核对出题设置；宽屏第二步并排减少上下翻找。只读预览直接呈现，减少一次“展开预览”及一次重复确认；正式客户端仍需刷新服务端快照并验证版本、Key和权限，不因UI简化减少授权校验。

## 实现与边界

新增共享的 exercise-builder.js/css 负责本页选源、候选去重、设置和预览；两端保留各自导航/外壳。来源可用性按本页语言及材料状态计算，删除教材后不能继续选用；收藏按照实际内容ID去重。空范围禁用下一步，题量不足时禁用确认，允许改成1题。返回修改与浏览器历史保留本页选择。

最终按钮为“确认并体验示例”，就地说明仅打开1道内置语境填空题；控件演示配置，不按所选题型/数量调用模型或伪造生成。每次体验新题清空旧作答状态。原型没有正式selection快照、持久Job、模型用量或学习证据。

查询保留图片选择/粘贴/相册/拍照、预览/移除、快捷键及完整卡片收藏。首次输入与发送位于首屏，有消息后回到消息在上、输入在下的聊天布局；示例不能自动发送或清空已有草稿/图片。两端相关HTML资源参数更新，避免浏览器沿用旧脚本。

## Review与修订

发现1项P2：手机直接打开/刷新习题步骤2后，页头返回无条件调用浏览器后退，可离开原型到about:blank；同页修改来源则可回步骤1。另有1项建议：首次从练习进入选源页时焦点停在BODY，后续步骤才聚焦标题。

集中修订：手机页头返回与修改来源共用返回函数；存在本应用推入的来源步骤时返回历史，否则原位回到步骤1，避免退出原型或新增返回循环。保留历史标记以支持刷新后返回。首次进入选源页聚焦标题，随后正常键盘操作；新增定点回归。第2轮独立执行320/390px两组导航回归并核对文档，确认P2和焦点建议均已关闭，未发现返回循环或其余未关闭缺陷；不增加第3轮review。

作者回归时修复示例追加超长草稿的提示处理，保留原文并回焦输入，继续编辑清除过期提示；校正测试中日语收藏样本数量的假设。图片与其他错误的原处理保持有效。
