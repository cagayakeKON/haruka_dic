## 1. 框架与职责

应用内学习 Agent 使用 **Pydantic AI**。首版推荐以核心 Agent、类型化工具、依赖注入和 Pydantic 输出模型组成运行层，覆盖词句解释、语言查询、薄弱点诊断、出题、试卷结构化与主观评分。Agent是后端共享执行能力，不是用户端聊天功能；不建设独立Agent页面或“问学习Agent”入口。各业务服务提供具体动作与受限上下文，前端在对应功能内展示结果。

Pydantic AI 是模型/工具循环层；Haruka 负责权限、上下文组装、会话存储、业务校验、任务调度、调用上限及用量记录。框架提供的结构校验不能保证语言解释正确，也不能代替材料出处和数据归属校验。基础能力见 [Pydantic AI 官方文档](https://pydantic.dev/docs/ai/overview/)。

独立的 pydantic-ai-harness 扩展包、Pydantic Graph 和持久执行引擎均未作为本次选型的必选依赖。先验证核心 Agent 能力，出现具体需求再评估；Haruka 不同时建立 LangChain/LangGraph Agent 执行路径。

## 2. 调用链与组件

~~~mermaid
flowchart TD
    UI[Flutter] --> API[FastAPI 身份 / RBAC / 归属检查]
    API --> RUN[Haruka AgentService]
    RUN --> CTX[上下文与个人模型配置]
    RUN --> AI[Pydantic AI Agent]
    AI --> MODEL[OpenRouter / Gemini 文本或视觉模型]
    AI --> TOOL[类型化领域工具]
    TOOL --> SERVICE[带用户作用域的业务服务]
    RUN --> DB[PostgreSQL 对话 / AiRun / 业务阶段]
    SERVICE --> DB
    SERVICE --> JOB[Job / Outbox / Kafka / Worker]
    RUN --> STREAM[应用事件与结构化卡片]
    STREAM --> UI
~~~

| 组件 | Haruka 中的职责 |
| --- | --- |
| AgentService | 一轮请求的身份、上下文、模型选择、执行、结果校验和保存 |
| ModelFactory | 根据当前用户的 provider/model/credential 构建模型客户端，检查必要能力 |
| RunDependencies | 发起者/所有者、受众、资料库、目标语、请求 ID、授权/业务服务与上限；仅服务端注入，不把旧权限快照当授权凭证 |
| ContextBuilder | 当前选区、相邻原文、相关错题/收藏、有限历史和摘要 |
| Typed tools | 查询及业务操作，参数/结果具备类型，逐次检查当前动作权限和用户范围 |
| Output models | 文本、卡片、题目、诊断和出处引用的版本化 Pydantic 结构 |
| Run repository | 对话、执行状态、用量、阶段产物和幂等操作记录 |
| Event adapter | 将 SDK 事件转换为 Flutter 使用的稳定协议 |
| Telemetry adapter | 记录 Agent、模型、工具、校验、上限和重试事件，脱敏后统一输出到 MyHome 日志平台 |

这些是职责划分，模块名、类名及 API 在阶段 1 定案。

## 3. 模型、工具与卡片

OpenRouter 通过 Pydantic AI 的供应商适配接入，Gemini 文本/视觉调用使用对应模型适配。每次运行显式绑定当前用户凭据，不修改进程环境变量或共享客户端的 Key，避免并发请求串用。接入方式参考 [OpenRouter 官方适配文档](https://pydantic.dev/docs/ai/models/openrouter/)。

按任务检查工具调用、结构化输出、图像输入等能力；不能因为模型能聊天就认定所有能力可用。具体模型、版本与 SDK 依赖在工程初始化时验证并锁定。

首批领域工具建议为：

- 查询本人材料片段、收藏、全部/当前/已收藏错题的受控摘要和学习统计。
- 根据已授权材料取得出处及可导航目标。
- 调用AI习题业务服务提交用户已确认的生成任务，返回资源/任务ID；Agent本身不能跳过选择预览、Key/上限确认或自动后台出题。

当前用户与资料库从 RunDependencies 注入，不进入模型可指定的身份参数。模型只提供查询条件和业务输入；工具、Agent 工具结果及后续保存都受同一权限边界约束。学习材料按数据处理，其中的文字不能改变系统规则、工具权限或模型凭据。

client.agent.use只允许受理已授权的查询/Agent功能运行，不自动获得导入、收藏/错题收藏写入、生成AI习题、批改或TTS权限。按当前授权过滤可提供的工具，每次实际执行仍由AuthorizationService检查对应业务权限与所有权；模型提出未知/失权工具调用必须拒绝。学习Agent不暴露用户/角色/权限管理工具，管理角色也不能通过Agent读取其他用户内容或借用其Key。

WordCard、SentenceCard、GrammarCard、ExerciseCard 和题目输出使用 Pydantic 模型。完整通过结构、出处与业务校验后才能成为可收藏/作答的结果；流式中间数据不能提前触发保存或业务动作。首版采用单个学习 Agent 配合领域工具；固定抽取/评分步骤可以直接使用类型化模型调用，不强制增加规划循环。

TTS 继续使用独立的 Gemini/OpenRouter 音频适配器、音频任务及播放器。Pydantic AI 的文本模型接入不等于已经实现 TTS。

OCR/拍照识词统一通过 [视觉模型识别](vision-recognition.md) 的固定类型化调用，按小说/课本/试卷/词条采用各自识别配置；不增加规划循环或传统OCR后备。ModelFactory检查本人视觉能力和凭据，页面/区域任务、上限和结果提交由应用维护。视觉转写是待校验识别稿，可信内容ID及发布仍由程序生成，不允许模型重写既有正文。

### 试卷结构化与交卷后评分

试卷导入使用类型化输出表达题组、小题、选项、分值、共享材料和答案来源，经应用校对确认后形成版本。试卷批改使用固定的题目/答案/rubric 评估调用，整卷编排由 Job/Worker 负责；不让自由规划循环管理考试计时、交卷事务或决定满分。数据和状态契约见 [试卷模式](../modules/exams.md)。

评分仅处理已锁定答卷。运行依赖包含用户、场次、试卷/评分依据版本及上限；工具不能读他人答卷，题面与作答中的文字不能改变评分协议。可靠客观题由规则判断，主观/缺答案题由 AI 返回逐题得分、依据与复核信号；程序检查分值边界/映射并计算总分，无答案结果明确标注 AI 评估。

逐题/题组结果持久化，失败不计为答错，恢复只处理未完成项；显式重评另建评分版本，不静默覆盖或重复累计学习记录。考试期间的题面输出与交卷后的解析输出分离，学习 Agent 不通过考试流程提前发送答案提示。

## 4. 上下文、记忆与流式接口

DESIGN22手动查询遵循[ContextPlan/ContextSnapshot及默认10000预算](../contracts/query-context.md)，先按稳定计划resolve已有结果，只有显式新生成才执行对应模型窗口校验。完整成功卡片/解释统一进入[持久缓存](learning-cache.md)，应用命中不创建AiRun/供应商attempt；新的查询记录可以引用既有成品，但不能伪造新模型运行。TTS调用由[每模型适配注册](tts-adapters.md)负责，复用任务、凭据及用量入口，不复用文本Agent的响应解析。

- [独立查询](../modules/query.md)与材料解释、习题、诊断等功能共用运行层；AgentThread.mode区分语言查询query与业务功能上下文contextual；它是内部分类，不对应聊天页面。query只允许语言学习任务且无需材料来源，保存每轮解释语言和可选目标语，不默认获取全部私有材料或外部联网能力。查询入口不要求用户选择类型，由AI在运行内根据实际内容自动判断语言任务；确定性输入检查、模型任务推断及发布前的语言范围/图片用途/输出类型校验共同限制结果，超范围仅给提示，不用通用回答兜底；具体规则见查询模块。
- 查询图文轮次按[查询模块](../modules/query.md)装入当前用户/会话已发布的私有图片引用，发送前及每个新供应商调用阶段检查本人视觉能力、附件权限/状态和数量/像素/上下文上限。图片与OCR文字属于不可信输入，不改变系统指令或工具授权；缺视觉能力不静默忽略图片，不借其他账号Key，不允许模型抓取任意图片URL。
- AgentThread 和 AgentMessage 保存在 PostgreSQL，读取和后续功能调用前验证所有者；保存 SDK 消息时记录序列化格式/SDK 版本，不能把 Python 对象当长期存储格式。
- 学习掌握度、错题、收藏和诊断证据以业务表为准，对话摘要仅辅助上下文，不覆盖学习事实。
- 每轮只装入必要原文和相关记录，限定历史与工具结果大小；超限时裁剪/摘要并保留来源引用。
- 同一会话的并发请求采用执行占用或版本冲突处理，避免两轮各自覆盖历史；不同用户/会话独立执行。
- Flutter 接收应用定义的文字增量、工具进度、卡片就绪、运行完成/失败事件；不直接依赖 SDK 的内部消息类型。
- SSE 连接断开与任务失败分开处理：短即时运行可中断并保留已提交结果，后台 Job 在当前权限仍有效时独立继续；客户端经授权通过 run_id/job_id 查询已完成结果，不因重连自动重复调用模型。

账号会话、API Key、解密后的 Provider 对象和带凭据的依赖对象不得进入聊天记录、工具结果、运行快照或日志。

## 5. 持久化、重试与模型用量

首版推荐继续使用现有规划的 PostgreSQL + Job/Outbox + Kafka/Worker，在业务阶段边界保存和恢复；不额外引入 Temporal、DBOS 或其他持久执行服务。

**会话历史持久化不等于 Agent 循环可以从任意模型调用处自动续跑。** Pydantic AI 的跨进程持久执行需要配套后端，官方区分了对话存储与执行恢复，见 [Durable Execution](https://pydantic.dev/docs/ai/capabilities/durable_execution/overview/)。

Haruka 首版的执行规则：

1. 为请求创建 AiRun，记录所有者、输入引用、模型/提示/输出协议版本、状态和关联 Job。
2. 完成一个业务阶段后提交结果；Worker 重启从已提交阶段边界重新检查并继续。
3. 进程中断时，未提交的 Agent 轮次标记为中断。不能把只写入一半的工具调用历史当成已完成对话；按阶段策略重新执行或等待明确重试。
4. 写工具使用用户 + 稳定请求/业务动作的幂等键；不能只用可能随模型重跑而变化的 tool_call_id 去重。重试不得重复创建练习、收藏或任务。
5. 外部请求超时且完成情况未知时记录不确定结果并限制自动重试；无法保证供应商恰好只执行一次。
6. 同时限制模型请求次数、工具调用次数、输出/上下文上限、运行时长和用户并发。SDK、供应商客户端与 Job 重试共享总上限，不能层层叠加。
7. 领取任务、执行工具、开始新的供应商请求及提交业务结果前重新检查账号、受众、当前权限和归属。撤权/禁用后停止受限步骤；已保存结果不删除，已经发出的供应商请求可能仍会完成，只允许固定系统维护职责最小落盘/清理，不继续推理或以管理员身份重试供应商调用步骤。

每次真实供应商调用的 input、output、cache read、cache write 及可得的音频/图像/字符指标按 [模型用量统计契约](../contracts/model-usage.md) 持久化，AiRun 只保存派生汇总。需要长时间暂停后精确恢复到调用步骤时，再评估 Pydantic AI 支持的持久执行后端，先明确其与 Kafka/Job 的唯一调度责任。

### 统一 AI 日志

所有解释、视觉识词、出题、评分、Agent 和批处理统一经过遥测适配，记录 run、每次模型请求、工具结果状态、校验失败、重试、限额和中断；TTS 的独立适配器也进入同一平台。以 operation_id/request_id/job_id/ai_run_id 关联前端操作和后端执行，保留独立的模型调用 ID 与 attempt。

日志包含模型、耗时、首内容等待和供应商返回用量；缺失用量标记未知，汇总与逐次用量不能重复累计。数据库attempt记录是用量权威，日志只用于观测。原始消息、工具入参/结果、材料、Key 和带凭据的依赖不进入遥测。Pydantic AI 的 OTel instrumentation 如使用，关闭内容捕获并适配为允许字段的日志；当前基础设施不自动具备 trace 存储，也不默认接入另一个云平台。统一协议见 [日志与前端埋点](../operations/observability.md) 与 [模型用量统计](../contracts/model-usage.md)。

## 6. 验证与 MyHome 复用

复用 MyHome 的配置、错误、日志、任务和基础设施机制；文本模型调用改用 Pydantic AI，既有 ChatOpenAI 客户端及 LangGraph 图不直接作为 Haruka 运行层。细节见 [MyHome 复用](../operations/myhome-integration.md)。

最小验证包含：

- [ ] 从英/日选区返回有效卡片，保留出处，后续具体卡片动作绑定必要上下文，跨入口不串用记录。
- [ ] 查询本人有权的错题摘要→诊断→预览并确认AI习题的工具循环可完成；全部错题由有效评分事实自动记录，收藏与当前错误状态分离，统计由程序计算。
- [ ] A/B 并发使用不同 Key，消息、工具、结果和日志均不串用；伪造会话 ID 无法访问。
- [ ] 可调用 Agent 运行层但缺少业务动作权限时，相应工具不可用且直接伪造调用被拒绝；运行中撤权、后台重试和管理员调用均不能绕过当前权限/个人 Key 边界。
- [ ] 无效结构、错误出处、工具异常、限流和调用上限耗尽有确定结果，重试次数有界。
- [ ] 流式卡片完整校验前不可操作，断开后能查询结果，不自动重复生成。
- [ ] Worker 中断/重复投递后无重复业务写入，未知供应商请求不会无限重试。
- [ ] 同一 Grafana 可查询 Agent/模型/工具/TTS 的成功、失败、重试和用量，并关联三端请求；模拟秘密、Prompt/回复和工具正文不进入日志，统计不重复累加。
- [ ] 试卷结构/答案映射可校验；分值越界、无答案推断、逐题失败与重评均符合试卷协议，总分由程序计算，原始题面/答卷不进入日志。

当前仅确认选型并记录设计，以上验证均尚未执行。
