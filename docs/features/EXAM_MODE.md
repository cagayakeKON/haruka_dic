## 1. 功能与首版范围

导入入口新增“学习材料 / 试卷”模式选择。选择试卷后创建 primary_type=exam 的材料，进入题目结构化流程；书库增加试卷筛选和独立卡片，打开后显示开考/继续答题/批改状态/历史成绩，不进入普通阅读器。

试卷模式作为 P0 规划。以下交互与技术规则是推荐实现；文件格式覆盖仍待用户选择，不把推荐值写成已确认需求：

| 内容 | 当前计划 |
| --- | --- |
| MD/EPUB 试卷 | 复用首版已有格式解析能力，增加试卷结构抽取 |
| 文本型 PDF 试卷 | 推荐提前到 P0；优先有可用文本层的 PDF，保留原页图/题目图片及页码，需样本验证；格式范围待确认 |
| 扫描 PDF / 多张图片试卷 | 当前暂按 P1；需要整卷 OCR/视觉识别、页序管理与质量校正，不能用已有拍照识词冒充完整试卷导入 |
| 题型 | P0：单选、多选、判断、填空/完形、翻译、文本简答及作文的基础作答/批改；匹配/排序等专用交互仍按后续计划 |
| 作答 | 原生题目控件、共享阅读材料、答题卡、标记待检查、自动保存、整卷提交；可选择限时 |
| 批改 | 可靠客观答案由规则判定；主观题及缺答案题交给 Pydantic AI，整卷产生分数与逐题反馈 |
| 复盘 | 总分、分项/逐题得分、评分依据、解析、参考答案、错题和薄弱点；支持新建场次重做 |

普通材料的 PDF/OCR 全面支持仍按原计划推进；文本 PDF 试卷的提前接入不等于已经具备通用高保真 PDF 阅读器。Word 试卷、手写答卷识别、听力附件编排、录音作答、监考、班级考试与多人发布不属于本次已确认范围。

## 2. 导入与校对

推荐流程：选择试卷模式 → 上传 → 提取题目与可选答案区 → 质量预览 → 确认试卷 → 开考。

1. 用户显式选择 import_mode=exam，上传意图和 Job 都保存该值；AI 分类不能覆盖用户选择。普通材料改为试卷时启动结构化准备，不要求重新上传，但也不能未经校验就直接开考。
2. 保留原文件、原有页序、题号和定位；解析器提供内容与稳定 ID，Pydantic AI 返回类型化候选结构。正文、题目、答案页和解析区分开保存。
3. 识别试卷标题/语言、说明、时长、大题/小题、阅读材料、选项、空位、图片引用、每题分值、可选小题规则、标准答案与评分标准（原文存在时）。跨页题目和一段阅读材料对应多题必须保持关联。
4. 展示题数、题型、总分、建议时长及异常清单。缺页、OCR/文本质量差、选项残缺、题号重复、题目与答案错配、分值冲突、缺图或不支持题型不得静默忽略。
5. 试卷预览的必要校对属于 P0：修正题干/选项/题号、拆分或合并误识别的小题、绑定共享材料、确认分值及答案来源。已知试卷总分与小题合计不符时必须处理；没有原始分值时推荐默认每个可评分小题 1 分，由用户确认，不能标成原卷分值。
6. 不支持的专用题型、依赖丢失媒体或有“任选 N 题”等未实现计分规则时，阻止确认该版本并列出具体原因；允许明确转为可用文本作答并重新确认计分，不能静默删题或改变总分。
7. 校验通过后生成不可变 ExamPaperVersion。后续题目编辑/重新解析创建新版本，已开始的考试继续使用原版本。

带答案导入和不带答案导入都可用。来源答案保存出处，AI 生成的参考答案标记 ai_reference；低置信度抽取答案不直接成为权威规则答案。没有标准答案时，推荐开考前生成并冻结参考答案/评分 rubric，避免评分标准随本次作答漂移；该步骤使用本人 Key，结果仍标明 AI 推断。

用户可以只保存上传材料，在 Key 未配置或解析待修复时继续稍后准备；只有题目、分值和必要材料满足开考条件的版本才进入 ready。导入质量状态与普通“文件上传成功”分开显示。

## 3. 考试界面与操作

### 开始与继续

打开试卷后显示标题、题数、总分、题型、建议时长、是否包含标准答案及既有场次。用户点击“开始考试”才创建场次并启动计时；存在未完成场次时优先提供“继续答题”。历史答卷可查看，重新考试创建独立场次。

时长从原卷提取后由用户在开考前确认；没有明确时长时默认不限时，显示已用时间。限时场次由服务端保存 started_at/deadline_at，退出页面、切后台或刷新不会暂停/重置时钟；截止后自动交卷已被服务器接收的答案。这个行为在开考前说明。

### 答题页

- 桌面/Web 使用题目区与答题卡，Android 使用适合小屏的题目区和抽屉答题卡；阅读材料可与所属题组同时查看。
- 显示整卷进度、剩余/已用时间、当前题分值、已答/未答/标记状态；可前后跳题和修改答案。
- 单/多选及判断为选项控件，填空对应稳定空位 ID，翻译/简答/作文使用文本输入；题干图片与正文保持同题关联。
- 每次输入防抖保存，选项切换及时保存；显示“保存中 / 已保存 / 未同步”。不把本地状态直接显示为服务器已保存。
- 考试期间不显示正确答案、解析或逐题对错，也不触发逐题评分。考试视图暂不提供解释、问 Agent 和答案提示；题面朗读若支持，必须作为开考前固定的辅助设置，仅朗读允许的题面，不读答案/解析。
- 提交前展示未答题数量及题号，用户可以返回检查或确认交卷；提交成功后答案锁定。

上述限制服务于个人模拟考试体验。用户已持有原文件、可能在导入校对时看到答案，产品不承担监考或防止外部查阅的职责。答题 API 返回专用题面 DTO，不把答案/rubric/隐藏解析混在题面响应中再由 Flutter 隐藏。

### 保存、断网与多端

服务端是答卷与截止时间的权威来源。草稿接口带答案 revision 和幂等标识，过期响应不能覆盖新答案；同一场次首版推荐一个活动编辑端，另一个设备继续时显式接管并更新编辑代次，旧设备不能无提示覆盖。

短时断网保留账号内的未同步草稿并明确提示。恢复后，只有场次仍允许编辑且版本/时限校验通过才能补交；过期或已交卷的内容标明“未提交草稿”，不自动计分或覆盖已锁定答案。首版不承诺完整离线考试；限时截止以服务器收到的答案为准，不信任可修改的客户端时间。

刷新或进程重启后恢复服务器已保存的进度；退出登录清除私有本地草稿与答题状态，服务器场次仍归原用户，限时时钟继续。用户 B 登录不能看到或上送 A 的答案；应用不能用日志补传队列保存答题正文。

## 4. 交卷与批改

交卷采用“保存并锁定答卷”和“执行批改”两个持久步骤：

1. 服务端事务内检查所有者、编辑代次、状态、版本与截止时间，保存可接受的最终答案并锁定答卷；manual/timeout 分别记录提交原因。
2. 如果请求了批改，同一事务创建评分请求与 Outbox，再由 Kafka/Worker 批改；仅交卷则保留 not_requested，稍后可显式发起。重复点击、网络重试和截止自动交卷竞争只能产生同一份最终答卷，不得重复调度整卷付费评分。
3. 按题/题组持久化评分结果与失败原因；重启从已完成部分继续，未确认的供应商调用遵循 Agent 运行层的不确定结果与预算策略。
4. 用户可选“交卷并批改”；仅交卷、未配 Key、Key 失效或额度不足时显示“已交卷，待批改”，保留所有答案和可完成的规则结果，配置后由用户重试。
5. 关闭客户端不影响已提交批改。Worker 失败时只重试未完成项；主动重新批改创建新的评分版本，保留原始结果与所用模型/rubric，不能静默覆盖成绩。

推荐状态分别建模，避免把“卷已交”误解成“已有最终成绩”：

| 对象 | 状态示意 |
| --- | --- |
| 试卷版本 | preparing → needs_review / ready；结构修订生成新版本 |
| 考试场次 | in_progress → submitted；用户放弃另记 abandoned |
| 评分运行 | not_requested / queued / grading / blocked_missing_key / partial / needs_review / graded / failed |

到期判断在保存/提交接口强制检查，并由持久截止任务或定期扫描完成无人在线时的自动交卷；不能只依靠 Flutter 计时器。手动提交和截止扫描使用同一事务/幂等规则。用户提交后的无 Key、评分失败和待复核不会将场次退回可修改状态。

## 5. 评分契约与成绩报告

| 情况 | 评分方式 |
| --- | --- |
| 有已确认答案的单选/多选/判断 | 规则精确判断；多选部分分/错选扣分等以开考前确认的规则为准 |
| 有已确认答案的填空 | 按题目语言与允许形式规范化匹配；需要语义判断时调用 AI |
| 翻译、简答、作文 | AI 依据冻结题面、已提交答案、参考材料和 rubric 返回分项分数与反馈 |
| 没有标准答案 | AI 判断并提供评分依据，明确标识“AI 评估”；不能伪装为官方正确答案 |
| 空白作答 | 按既定规则计 0 分，不为判空调用模型 |
| 解析损坏、模型失败、结果越界、证据不足 | 标记失败或待复核，不按答错计 0 分，不伪造最终总分 |

Pydantic 输出模型推荐包含 exam_item_id、grading_method、answer_source、awarded_points、max_points、rubric_scores、verdict、feedback、reference_answer、source_refs、confidence_status、needs_review。原始评分事实保存在业务库，不写入遥测；confidence_status 是模型/应用的复核信号，不作为经过校准的正确率。

应用再次检查题目归属、分值上下限、必要字段、分项和总分一致性；使用固定精度分值和明确舍入规则，总分由程序累计，不能直接信任模型生成的整卷数字。每个可评分叶子题计入一次，共享题干/大题不能再次累加。同一评分依据版本不能因重试改变满分或标准；异常结果退回有界重试或待复核。

成绩页包括：

- 总分/满分、完成状态、实际用时、已答/未答、已批改/待批改/待复核题数。
- 各大题与逐题得分，用户答案、判定理由、参考答案、错误点和改进建议；注明规则/AI 和答案来源。
- 未全部完成时展示“已评部分 X / Y 分，另有 N 题待处理”，其中 Y 仅为已评题目的满分；整卷满分另外展示，不宣称这是最终总分或最终正确率。
- 基于已确认结果总结薄弱点，跳回对应题目/原材料；错题进入原有复习流程，可以让学习 Agent 生成针对性练习。

成绩回流采用 [数据与任务](../architecture/DATA_AND_JOBS.md) 的grade_generation/effective指针规则：同场次只有一个活动评分run，重试沿用run，重评新建代次；旧run迟到仅入历史，不能覆盖较新成绩。首版整次评分完成且无needs_review后CAS发布并按场次+题目替换学习贡献，partial/failed/needs_review不提前回流。重评期间保留旧有效成绩与统计，禁止重复累计错误。人工改分/申诉覆盖仍为P1。

## 6. 数据、接口与 AI 分工

推荐逻辑对象如下，具体字段在工程阶段固定，不在此给出数据库迁移代码：

| 对象 | 主要职责 |
| --- | --- |
| Material(import_mode/primary_type=exam) | 原文件、用户/资料库归属与导入任务 |
| ExamPaper / ExamPaperVersion | 试卷身份、冻结题面/题序/分值/辅助设置和来源版本；准备、校对与 ready 状态 |
| ExamSection / ExamItem | 大题/共享材料、可评分叶子题、题型/空位/选项、题目图片、出处和满分；复用 Exercise 渲染契约 |
| ExamGradingBasis | 答案与 rubric 的版本、来源/确认状态；存于服务端；未含于题面 DTO |
| ExamSession | 一次考试的所有者、试卷版本、状态、开始/截止/交卷、编辑代次和提交原因 |
| ExamResponse | 按场次 + 小题唯一的草稿 revision 及交卷时锁定的答案快照 |
| ExamGradeRun / ExamItemGrade | 评分依据/模型版本、Job/AiRun、逐题状态/结果、汇总和有效评分版本 |

场次冻结题目版本、分值、计时/辅助规则及当时的评分依据版本，首次评分使用该绑定。若尚无标准答案且需稍后生成参考依据，只能基于冻结题面独立准备，不把本次考生答案当作生成标准的依据，再绑定版本后批改。来源题面修改只影响新场次；纠正答案/rubric 必须形成新依据版本并显式重评，保留旧成绩，不能后台静默改变已交卷结论。

建议接口资源为 exams、exam-versions、exam-sessions 及其 responses、submit、grading-runs、results。开始/保存/交卷/重评分别定义幂等与版本冲突；批改进度复用 Job/SSE。按 RBAC 专题分别检查 client.exam、client.exam_session、client.exam_grade 下的具体动作权限，Flutter 入口/按钮同步受控。题面、答卷、答案、成绩 DTO 分离；各查询都校验当前权限、所有者与允许状态。

考试进行中禁用账号或撤销作答权限时，停止新的受限保存/提交，保留已保存答卷，不把权限拒绝当作答错。服务端仍可按固定系统职责截止锁卷，但不能借此新增已失权用户的付费批改。批改领取、付费步骤与提交检查当前权限，失权后保留已完成分题结果并暂停后续步骤；恢复权限后按状态和幂等协议继续。后台运维权限只提供规定的元数据/操作，不开放他人试题正文、答卷或 Key。

Pydantic AI 负责试卷结构候选、参考答案/rubric 候选及逐题/题组主观评估。题面/答案属于待处理数据，不能改变工具权限、满分和评分协议；评分通常使用固定的类型化调用，不必让学习 Agent 自由调用工具决定事务或总分。Haruka 程序负责身份、题序/版本、计时、保存/交卷、幂等、规则题与总分计算。

题库与答题组件可以复用普通练习，考试场次及交卷状态独立建模。原有普通练习保留逐题即时反馈；试卷只在整卷提交后出批改结果。技术仍为 Flutter + FastAPI + Pydantic AI + PostgreSQL/Job/Outbox/Kafka，不新增考试服务或另一套 AI 框架。

试卷、答卷和成绩属于当前用户业务数据；用户侧导出恢复仍仅为单词 CSV，不自动增加试卷/答卷 PDF 或整库导出功能。

## 7. 日志、埋点与验收

所有事件接入现有规划的 MyHome Alloy/Loki/Grafana。增加 exam.import.reviewed、exam.session.started、exam.response.saved、exam.session.submitted、exam.grading.started/completed/failed、exam.result.viewed；提交事件用 submit_reason 区分 manual/timeout，失败细分导入、保存、批改阶段。

记录 exam_session_id、exam_paper_version_id、grading_run_id、job_id、ai_run_id、操作/请求 ID、题数/已答数/待评数、耗时、状态、尝试次数及用量。这些 ID 属于 JSON/structured metadata；题干、作答、答案、rubric、个人成绩明细与原卷载荷不进入日志。前端保存事件以服务器确认版本为准，UI 点击交卷不算交卷成功，超时关闭客户端后仍有服务端提交事件。

首版验收：

- [ ] 导入时可主动选择试卷；同一文件的普通材料与试卷路径清晰，打开试卷进入考试入口。
- [ ] 有答案/无答案、跨页题目、共享阅读材料、多空填空和题干图片样本能校对后形成 ready 版本；不支持题型/计分规则明确阻止确认，不静默删题。
- [ ] 分值缺失或不一致必须确认，题目总分可程序复算；答案区不出现在考试题面接口及考试 UI。
- [ ] 三端可跳题、标记、保存、继续、提交和复盘；普通练习仍逐题反馈，考试中不泄露评分结果。
- [ ] 刷新/切后台/多端接管不重置计时或覆盖新答案；断网未同步与服务器已保存状态可区分。
- [ ] 手动/超时交卷并发、保存/交卷竞争、重复点击及 Worker 重启不重复锁卷、写业务结果或无限调用模型。
