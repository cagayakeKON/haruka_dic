# 实施计划与验收

状态：Draft v0.8，2026-09-22，旧 HTML 原型已删除，新视觉方案讨论中，Flutter/Python 正式实现尚未开始。范围以 [PRD](../product/PRD.md) 为准；逐功能流程见 [覆盖索引](FEATURE_COVERAGE.md)，技术见 [总览](../architecture/OVERVIEW.md)、[RBAC](../architecture/ADMIN_AND_RBAC.md)、[运行层](../architecture/AGENT_RUNTIME.md)、[试卷](../features/EXAM_MODE.md) 和 [日志](../engineering/OBSERVABILITY.md)。

## 1. 当前范围与前置验证

Flutter 覆盖 Windows、Web、Android；Python 后端复用 MyHome 基础设施，学习 Agent 已确定使用 Pydantic AI。v0.1 包含多用户注册登录、管理后台与完整 RBAC、个人资料与 Key 隔离、语言学习闭环、试卷导入/考试/AI 批改、Gemini/OpenRouter TTS、单词 CSV 导出/导入，以及全部日志和前端埋点统一接入 MyHome 的 Alloy/Loki/Grafana。

当前仅讨论年轻化、漂亮、现代美观的视觉方案，不创建原型文件。旧 HTML 原型已删除，具体风格与后续原型范围待确认。所有下方正式应用验收项仍未完成；不修改 MyHome、不连接生产服务。

多用户和账号功能已确定。推荐每账号一个私有资料库、邮箱密码登录和 Haruka 独立会话。注册开放策略、邮箱验证/找回方式、阅读器要求与默认供应商见 [PRD 待确认问题](../product/PRD.md)。

试卷模式已确认；文件格式还待明确，当前推荐 MD/EPUB + 文本型 PDF 优先，扫描 PDF/多图 OCR 暂按后续。文本型 PDF 的首版接入为推荐计划，确认后再锁定解析库、样本范围与工期。

管理端推荐 Flutter Web，授权服务推荐 PyCasbin；先验证关系策略表到引擎的唯一版本投影，再锁定依赖。每个业务阶段必须同步登记权限点、两端显示规则、接口/工具校验与审计，不能最后补 RBAC。

先完成八个最小验证，再扩展页面：

| 验证 | 样本/操作 | 通过标准 |
| --- | --- | --- |
| 双账号隔离 | A/B 分别建材料、单词、Key 与任务，交换资源 ID | API、文件签名、缓存、Worker 和 CSV 均不串用 |
| 管理后台与 RBAC | 用户/管理两端登录，多角色、继承、deny、深链直达、直接 API、运行中撤权和越权授予 | UI 与接口一致，管理会话隔离，多实例旧缓存不放行，管理员仍受私有数据边界约束 |
| Pydantic AI 运行层 | 类型化工具、卡片输出、两用户并发、多轮历史和中断重试 | 结构与出处可校验、Key 不串用、预算有界、业务不重复写入 |
| 统一日志链路 | 三端正常/错误/埋点 → API → AI/工具 → ORM，另核对 PostgreSQL 引擎日志 | 同一 Grafana 可查且可关联，info 不遗漏，秘密脱敏，账号不误归属 |
| EPUB 出处 | 含日文、注音和图片的 EPUB，加一份 MD | 三端选区、保存及回跳一致，Unicode 偏移正确 |
| 云端 TTS | 数句英/日文本，选定 Gemini/OpenRouter 路径 | 三端播放、暂停、续播、倍速和句级高亮可用 |
| CSV 往返 | 多行笔记、标签、重复词与公式前缀 | 原账号跳过重复，空账号恢复字段，不能绑定他人来源 |
| 试卷闭环 | 有/无答案试卷，含共享题干、跨页小题、分值和题图；模拟保存/交卷/批改失败 | 校对后可开考，题面无答案，草稿/截止/交卷一致，评分可恢复且总分校验有效 |

核对 MyHome 实际运行版本、网络、域名/TLS、权限和容量；当前证据仅来自本地源码。用 EPUB 小说、MD 笔记、带题教材及有/无答案试卷建立人工确认的样本；格式确认后补充对应实际文件。常规测试用可控供应商响应，实际 AI/TTS 验证限制输入规模和重试费用。

## 2. 六个实施阶段

各阶段共同遵守 [项目结构](../architecture/PROJECT_STRUCTURE.md)、[代码](../engineering/CODE_STANDARDS.md)、[Lint](../engineering/LINT_RULES.md)、[测试](../engineering/TESTING.md) 与 [交付验收](../engineering/DELIVERY_ACCEPTANCE.md)。先完成 [开发/配置合同](../engineering/DEVELOPMENT.md) 的实际初始化，再运行其中标注的未来命令。文档审查不勾选下列应用验收，当前review闭环单独见 [记录](DOCUMENT_REVIEW.md)。

### 阶段 1：工程基础、两端登录、管理后台与 RBAC

先按 [脚手架蓝图](../engineering/SCAFFOLD_BLUEPRINT.md) 和 [脚手架验收](../engineering/SCAFFOLD_ACCEPTANCE.md) 取得以下子里程碑证据。它们不另开产品阶段，也不替代本阶段下方的完整验收：

- [ ] B0：锁定工具/构建依赖、统一命令、可安装包与仓库外启动、三端壳、受控迁移/种子、代码生成和质量门禁通过。
- [ ] B1：三端正式登录/access、合法选区收藏新增/列表、最小管理受众边界和日志查询通过；最终注册恢复策略另行落实。
- [ ] B2：从收藏经正式Job/Outbox/Kafka/Worker/SSE生成一个练习，dev/test Fake、撤权/故障/重复与模拟日志口径通过；真实AI验证仍待执行。

参考收藏与出题只提前实现最小业务链路，阶段3/4仍负责其完整功能与最终验收；不能因参考流程通过就勾选整项功能。

- 建立 Flutter 三端、Python 工程、登录/注册/设置页面及 CI 检查入口。
- 按 [前端E2E](../engineering/FRONTEND_E2E.md) 建立Test ID单源生成、Key/Web语义定位原型及平台runner分工；按 [测试数据](../engineering/TEST_DATA.md) 建立共享样本、声明式场景、工厂秘密通道与资源账本，映射UIE/TDS验收。
- 按 [MyHome 复用](../engineering/MYHOME_REUSE.md) 接入独立数据库、凭据、Bucket、队列、网络和日志，不共用 MyHome 账号数据。
- 实现注册事务、密码哈希、设备会话、刷新/撤销、改密、Web Cookie/CSRF 和原生安全存储。
- 按 [账号操作合同](../features/ACCOUNT_FLOWS.md) 实现PG持久撤销/epoch、Web opaque Cookie与原生轮换；覆盖激活条件、login-only空状态、Redis故障与并发刷新。
- 建立管理 Web 布局、用户管理、角色/权限、两端菜单及注册策略；任务、配额、审计和运行概览随对应模块接入。
- 实现权限目录、角色继承/显式拒绝、授予边界、AuthorizationService、数据库授权版本与只读策略投影、两端访问快照和路由/操作守卫。
- 实现受控首管理员初始化、禁用/强制下线、最后管理员保护，以及管理变更与审计/Outbox 同事务提交；测试并发撤权和自我/间接提权。
- 建立用户/资料库作用域、跨表归属约束、个人 Key 加密、用户配额、Job/Outbox/Worker。
- 建立 Pydantic AI ModelFactory、运行依赖、基础领域工具、Pydantic 输出模型、AgentThread/AiRun 和应用流式事件；验证阶段边界重试，不默认增加持久执行引擎。
- 建立 Flutter Telemetry、批量/匿名接收入口、账号隔离队列、Python 统一日志与关联上下文；接入 AI/工具、SQL 访问与 PostgreSQL 引擎日志，验证三端错误捕获和原生诊断边界。
- 扩展 Alloy 采集清单，在现有 Grafana 建立 Haruka 基础看板；核对 MyHome 的只上报 warn/error、旧 Docker 日志过滤及 7 天留存等适配差异。
- 固定 API、任务、出处、卡片/题目、考试版本/草稿/交卷/评分、CSV v1 和日志/埋点契约，执行最小验证并锁定兼容依赖。
- 将已细化的API/权限/数据契约落为OpenAPI、策略目录与迁移，建立必需用例结果检查和完整覆盖率分母检查；先用失败样本验证门禁能阻断。

验收：

- [ ] 三端可注册、登录、续期、退出、改密；失败注册不留下半成品 Library。
- [ ] A/B 的 API、文件、会话、模型配置和任务不能越权，MyHome Token 不被接受。
- [ ] 客户端和管理端登录分别受控；client 会话不能调用 admin API，权限未加载/不足时不显示受限页面、菜单、按钮或字段。
- [ ] 多角色合并、继承环/深度限制、deny 优先、默认拒绝、两端直达路由和直接 API 调用通过权限矩阵。
- [ ] 授权变更后新请求读取最新版本；缓存失联/消息丢失不继续放行，运行中任务和流按边界撤权，离线租约限制明确。
- [ ] 安全默认注册角色、授权边界、首管理员和最后管理员的并发保护通过；管理操作审计可追溯，Loki 中断不丢数据库审计。
- [ ] 退出/换账号后旧缓存、播放器、订阅及迟到请求不会进入新账号。
- [ ] 无 Key 不影响登录和基础数据操作，付费调用不会借用其他用户凭据。
- [ ] Worker 重启和重复投递不重复写入，认证依赖失败时不放行。
- [ ] Pydantic AI 核心流程及 OpenRouter/Gemini 选定模型的必要能力通过验证，版本锁定，模拟响应与真实调用的检查结果分别记录。
- [ ] 三端的正常日志、info 埋点与异常，以及后端、AI、SQL 和数据库引擎样本进入同一 Grafana；可按操作/请求关联，模拟秘密不泄露。
- [ ] 未登录受限上报、断网补传、重复批次、429/5xx、队列上限及 A/B 切换验证通过；日志失败不阻塞业务且不递归上报。

### 阶段 2：材料/试卷导入与阅读

- 校验上传并保留原文件，先做确定性目录/正文解析，再异步 AI 分类和抽题。
- 实现小说阅读器、教材单元页、基础改类型、书签、阅读进度和账号缓存。
- 确定内容版本、Unicode 选区协议、重新解析后的出处重绑及日语断句/选区。
- 同步导入阶段、阅读/回跳事件与章节加载耗时，区分前端体验和后端提交结果。
- 新增“学习材料 / 试卷”导入选择与书库入口；提取试卷题组、共享材料、小题、分值和答案来源，实现必要校对/总分检查与冻结版本。
- 试卷模式先复用 MD/EPUB 解析，按最终格式范围接入文本 PDF 或 OCR；不把拍照识词当作整卷识别实现。

验收：

- [ ] 三份真实样本可读，AI 失败仍能访问已解析原文。
- [ ] 同账号三端可续读，其他账号持有材料 ID 也无法读取或修改。
- [ ] 日文、组合字符和 emoji 回跳正确；删除/重解析后保留引用上下文。
- [ ] 离线只在有效权限租约内显示当前账号已有缓存，重联重新鉴权；不承诺完整离线写入。
- [ ] 导入/阅读/回跳日志及埋点可关联到 API/Worker，页面重建不重复记录业务事件。
- [ ] 有/无答案试卷可预览校对后进入 ready；残缺选项、题号错配、未知题型/计分规则、总分冲突不被静默忽略。
- [ ] 显式试卷选择不被 AI 分类覆盖，题目/分值更改生成新版本，题面/答案/评分依据分离。

### 阶段 3：解释、收藏与 TTS

- 实现选区工具条、Pydantic AI 流式解释、带出处的收藏/笔记及 Pydantic 结构和业务校验；Flutter 接收应用事件协议。
- 接入选定 Gemini/OpenRouter TTS 路径，处理实际音频格式、句子映射与有限预取。
- 实现用户音频缓存、请求合并、三端播放、倍速、续播与过期媒体地址刷新。
- 补齐解释、收藏、TTS 合成/缓存及播放器事件，区分服务端生成与客户端实际播放等待。

验收：

- [ ] 收藏可回跳本人材料，单句和连续朗读在三端实际可用。
- [ ] 再次朗读/改变播放倍速复用音频，A/B 相同文本不混用私有结果或 Key。
- [ ] 限流、超时、取消及不支持的声音有明确状态，不无限重试或静默改用系统 TTS。
- [ ] 记录首音频等待、句间停顿、请求数量与用量，确定实际发布目标。
- [ ] Grafana 可从前端朗读/解释操作定位模型/TTS/Worker 故障；缓存命中不算模型调用，原词句/Prompt/音频 URL 不进入日志。

### 阶段 4：练习、模拟考试与 Agent

- 实现图片识词、预览确认、选择/填空/判断题展示，从收藏和错题生成选择、填空、句译。
- 实现规则评分、句译及必要的填空模糊匹配 AI 评分、反馈、作答和错题记录。
- 按当前用户真实学习记录生成诊断与练习，提供 WordCard、SentenceCard、GrammarCard。
- 使用 Pydantic AI 工具与运行依赖固定用户范围，支持多轮上下文及业务阶段保存；模型不能自报身份扩大权限。
- 同步练习、作答、评分与 Agent 卡片操作埋点，以及每次模型/工具/重试的遥测；业务统计以实际记录为准。
- 按 [试卷模式](../features/EXAM_MODE.md) 实现开考/继续、答题卡、跳题/标记、revision 草稿保存、编辑端接管、可选服务端计时和截止自动交卷。
- 实现事务锁卷与评分 Outbox、逐题/题组批改、失败恢复/待复核、程序累计总分、成绩复盘和评分版本；试卷文本简答/作文基础评分纳入本阶段。
- 保持普通练习逐题反馈，考试整卷交卷后反馈；题面 DTO 不返回答案/解析，学习统计按场次/题目去重更新。

验收：

- [ ] 英/日样本可完成材料 → 收藏 → 练习 → 评分 → 错题 → 再练习。
- [ ] 有确定答案且规则可判定的题不调用模型；失败不丢已提交答案，无标准答案的 AI 评估明确标记依据。
- [ ] 生成题和诊断有实际来源；非法卡片不能写入，他人内容不能进入工具结果。
- [ ] 对话重载、流式断开、预算耗尽、工具失败和 Worker 重试均符合 [运行层验收](../architecture/AGENT_RUNTIME.md)，不会重复创建练习或无限发起付费调用。
- [ ] Android 可拍照，Windows/Web 至少能选择图片；确认前不写入单词。
- [ ] 模型/工具失败和预算可追踪；前后端结果、run 汇总与单次模型用量不会在看板重复累计。
- [ ] 三端完成试卷导入 → 校对 → 考试 → 交卷 → AI 批改 → 成绩/错题复盘；未答题提示和答题期间无即时提示验证通过。
- [ ] 保存/交卷竞争、多端接管、刷新、断网、手动/截止提交并发和 Worker 重启不丢服务器已保存答案、不重复提交或重置时限。
- [ ] 分值越界/总分校验、失败与待复核、缺 Key/限流重试、重做/重评、版本冻结和双账号隔离通过试卷专题验收。
- [ ] 开考/保存/交卷/批改可在 Grafana 关联，题目、答案、rubric 和成绩明细不进入日志。
- [ ] 答题或批改期间禁用/撤权后停止新的受限操作，保留已保存答卷；系统截止锁卷不借此继续付费 AI，管理端仅访问授权的运行元数据。

### 阶段 5：单词 CSV 导出与导入

- 按 [CSV 规范](../features/VOCABULARY_CSV.md) 实现全部/筛选导出、三端保存、最小词表和原生格式导入。
- 实现列映射、可逆转义、预览、重复策略、账号归属、幂等提交与结果统计。
- 设置页与收藏页共用功能，不实现 ZIP、整库切换或全资料备份任务。
- 记录 CSV 预览/提交/导出传输/本地保存的结果、行数与耗时，不采集行内容或文件私人路径。

验收：

- [ ] 导出当前用户全部单词，不受分页影响，不夹带其他用户数据。
- [ ] 原样往返保留协议字段，跳过重复不增加条目；空账号不关联他人原文。
- [ ] 多行文本、公式前缀、日文、标签、错误行和重复确认验证通过。
- [ ] 无 Key 也可操作，不调用模型，不覆盖原书或学习记录。
- [ ] 三端实际保存、选择及导入流程通过。
- [ ] CSV 成功/失败事件进入统一平台，导出传输与本地保存分别统计，无单词/笔记正文泄露。

### 阶段 6：三端交付与运维验证

- 完成 Windows 安装升级、Android 签名包、Web HTTPS 和媒体/流式代理配置。
- CI 执行相关 Python 检查、Flutter 分析和测试、三端构建；Windows 使用对应运行环境。
- 验证注册/登录限流、会话失效、用户配额、共享服务负载与日志脱敏；明确注册开放及账号恢复策略。
- 完成管理 Web 的用户/角色/权限/菜单/策略/任务/审计闭环，执行 [RBAC 验收](../architecture/ADMIN_AND_RBAC.md)；普通应用角色不自动获得 Grafana/Loki 的全局访问权。
- 完成全部日志来源、三端 release 堆栈、平台崩溃诊断、补传与采集故障恢复验收，验证看板、告警、端到端探针及留存容量。
- 验证迁移、运维数据保护和回滚步骤；运维灾难恢复不变成用户侧全库备份需求。

验收：

## 3. 三端验收矩阵

| 场景 | Windows | Web | Android |
| --- | --- | --- | --- |
| 账号 | 原生安全存储、刷新、换账号 | Cookie、CSRF、多窗口刷新 | 安全存储、进程重建、退出 |
| RBAC | 菜单/路由/按钮、撤权、离线租约 | 用户/管理 audience、深链、字段裁剪、两端撤权 | 路由/返回栈、恢复后重新鉴权、离线租约 |
| 阅读 | 鼠标/键盘、日文选区 | 浏览器选区、缩放 | 长按选区、触控与返回 |
| TTS | 音频后端、队列、拖动 | 自动播放限制、媒体可达 | 音频中断、后台状态 |
| 缓存 | 退出清理、账号隔离 | WASM、存储清理与隔离 | 容量、清理、账号隔离 |
| CSV | 文件保存与选择 | 下载/上传及失败状态 | 系统保存/分享、文件选择 |
| 考试 | 键盘/答题卡、关闭恢复、编辑接管 | 刷新/多标签、未保存状态、截止提交 | 小屏题组、软键盘、切后台/进程恢复 |
| 日志/埋点 | Dart/宿主错误、退出补传、版本堆栈 | Flutter/异步/JS 错误、pagehide、Cookie/CSRF | Dart/插件/宿主诊断、后台与重启补传 |
| 同账号数据 | 三端进度、收藏、作答一致 | 同左 | 同左 |

Android 后台连续朗读的支持范围需实际验证；浏览器清理缓存不影响服务器资料。
