## 原型画面对照与还原

依据根[AGENTS.md](../../AGENTS.md#前端原型还原必须)，当前及后续前端交付的整体视觉和交互还原目标为80%～90%，关键操作不能因这个比例被删减或更换流程。采用真实后端、Flutter控件或分阶段实现，不是自行设计另一套页面的理由；只对当前切片已实施的页面和状态验收，不假装后续业务已经交付。

1. 编码前打开当前原型对应路由，直接看渲染画面并操作本次涉及的按钮、导航、弹层、选中/禁用/错误等状态；手机与电脑布局分别查看。阅读源码用于确定样式参数，不能替代直接看画面。
2. 记录所参照的原型页面/状态、逻辑视口和对应实现页面。按原型落实布局比例、字体层级、颜色、留白、图标、卡片、按钮层级及位置、dialog/panel形态、动效和反馈；不能用默认表单或通用列表代替原型已有设计。手机与电脑在信息层级、导航或任务步骤不同时，分别实现页面布局和展示组件，必要时完全重写移动端组件；共享业务状态与数据契约，不强迫共用一份充满平台分支的展示组件。
3. 真实权限、加载/失败、平台能力造成的必要差异，记录原因和对应效果。原型缺失状态沿用已确认设计语言与相邻组件，必要时补充原型；演示提示/虚构数据不照搬为正式成功提示，不为视觉还原改变安全与业务约束。
4. 实现后打开实际应用，以相近逻辑视口和同一业务状态直接比较原型与实现的画面，并实际走过相关交互。只收集安全截图和必要的交互记录，列明偏差及修正；不能凭编译/接口/控件测试通过，或未经观察的主观百分比，认定已达目标。明显偏离布局或核心交互时本切片不能标完成。

原型页面打开不了时，先恢复本机预览；不能查看的事实及仍未验证的状态必须如实记录，不以源码推断冒充视觉验收。检查范围、review轮数和是否需要应用测试仍遵循AGENTS的小阶段规则，不为此机械重跑无关平台或全仓测试。

## 1. 共享与独立实现的边界

保留一个Flutter工程和统一业务协议，允许同一功能拥有不同页面结构和交互实现；不以代码复用比例作为交付指标，也不拆出互相复制业务的Android/Web/Windows应用。

| 层/内容 | 共享范围 | 允许独立的部分 |
| --- | --- | --- |
| application/domain | 业务状态、用例、权限判断入口、幂等/版本处理、当前材料/题目/任务身份 | 有真实平台语义时通过明确能力接口协调，不复制评分、身份或任务规则 |
| data/core | DTO、统一API错误、缓存分区和日志协议 | Web Cookie与原生凭据传输、缓存存储引擎、媒体/文件适配 |
| 基础组件 | 设计token、文字样式、状态提示、卡片内容和可复用输入控件 | 触控尺寸、焦点/hover、组合与摆放方式；不强制所有页面共享一个万能组件 |
| presentation | 相同业务状态及动作接口 | 紧凑/宽屏页面、导航、目录、工具栏、弹窗/侧面板、局部交互 |
| 平台宿主 | 公共能力接口与安全/错误语义 | Android、Windows、Web的插件实现及必要宿主代码 |

拆分规则：仅间距、列数、最大宽度变化时，在小组件内响应式布局；导航/信息层级/任务步骤或焦点交互不同，拆成独立layout及必要的独立展示组件，移动端组件可以完全重写；文件、音频、权限等系统行为不同，进入platform adapter。简单表单只有在两端实际画面和操作一致时才共享展示组件；阅读/考试等复杂页面不强行塞进一个充满平台条件的build方法。业务控制器、DTO和权限状态仍按共用契约维护，避免两端各自定义业务规则。

业务页面调用Riverpod应用控制器/用例，再经repository访问服务。控制器不持有BuildContext、Widget、FocusNode或ScrollController；布局不自行实现认证刷新、拼请求JSON、选择他人Key、判断角色名或直接调用供应商。目录与依赖方向只在项目结构维护。

## 2. 空间、输入、能力三条判断轴

| 判断轴 | 输入 | 决策边界 |
| --- | --- | --- |
| 可用空间 | 当前窗口/页面容器约束、有效高度、安全区域 | 单/双栏、底部导航/侧栏、面板容纳方式；不能由操作系统名称或物理屏幕尺寸推断 |
| 输入方式 | 当前触控/鼠标/键盘事件与可用输入能力 | 长按/划选、hover、右键、Tab和快捷键；设备可同时有多种输入，不能用互斥isMobile禁用其中一种 |
| 平台能力 | 构建目标、平台适配器报告的支持状态、运行时权限/条件 | 文件选取/保存、音频播放、系统返回、安全存储；支持能力不等于当前用户拥有业务权限 |

窗口级使用MediaQuery.sizeOf，局部容器使用LayoutBuilder；按实际约束选择视图。布局判断作为无副作用的策略集中在core/layout，不在各feature重复定义isMobile。Web手机可用紧凑UI，Android大窗口可用宽屏UI，Windows窄窗口也必须可用。[Flutter适配方法](https://docs.flutter.dev/ui/adaptive-responsive/general)

以下是B0开始验证的项目布局基线，单位为逻辑像素；不是Flutter强制标准。唯一阈值实现在未来core/layout/adaptive_policy.dart，调整需同步受影响布局样例和边界测试。

| 空间级别 | 容器宽度 | 默认处理 |
| --- | --- | --- |
| compact | 小于600 | 单列内容、紧凑导航、抽屉/底部面板；阅读/考试按沉浸流程决定是否隐藏全局导航 |
| medium | 600至小于1024 | 应用壳可用导航轨；业务页默认沿用紧凑结构，只有模块明确验证足够容纳时才分栏 |
| expanded | 至少1024 | 可用侧栏/并列详情；正文/表单保持最大阅读宽度，内容容纳不足时仍降为单栏 |

页面依据扣除导航后的本地内容约束决定是否分栏，壳与子容器不能各自叠加一套全局导航。模块在开发切片中登记双栏最小宽度/最大正文宽度等实际参数，不以全屏宽度保证每一列都放得下。高度不足或键盘弹出时优先让内容/面板可滚动或改为全屏，不让键盘高度直接切换整套应用壳。

不锁死方向来规避适配；横屏、分屏和窗口缩放保留已有操作。折叠/遮挡信息存在时避开不可用区域；这不增加新的目标平台。[HTML原型](../../prototype/README.md)的CSS布局阈值属于独立视觉验证，不能直接当Flutter已验证参数。[适配实践](https://docs.flutter.dev/ui/adaptive-responsive/best-practices)

## 3. 状态归属与布局切换

| 状态 | 所有者/生命周期 | 切换与恢复规则 |
| --- | --- | --- |
| 身份/权限、账号代次、API/缓存 | app/core的受众与AccountScope | 实例/账号/受众切换释放旧私有状态；权限未就绪或已撤销不展示旧内容 |
| 当前材料/版本、考试场次、筛选、任务/run、编辑值与保存状态 | feature应用控制器，按账号、资源和业务版本作用域建立 | 在layout分支以上保持；缩放/横竖屏不创建新业务会话、不重新调用供应商、不将未保存标成已保存 |
| 滚动、焦点、动画、菜单展开、输入法组合态 | 当前presentation及必要的页面级视图状态协调器 | Widget局部资源有明确释放者；需要跨layout保留的最小视图快照在分支外协调，不放进业务domain |
| 服务端已提交数据 | API/持久业务库 | 刷新或进程重启后先验证身份/权限，再查询服务器；本地恢复对象不是授权或提交证据 |

feature作用域不能因layout变化被销毁重建：Provider的身份包含账号/资源/版本等业务键，不包含compact/expanded；同时不能无限keepAlive使退出后仍保留私有状态。路由拥有应用状态，layout消费同一份状态和动作。框架重建、语言/主题切换、键盘开合都不得触发新增任务/重复订阅。

切换步骤：记录允许保留的视图位置与编辑状态 → 渲染目标layout → 必要尺寸完成后按稳定身份恢复位置/焦点 → 释放旧视图资源。默认只挂载一个活动layout；确需过渡动画时，旧树不再接收输入/语义焦点或触发副作用，不重复挂载全局播放器、SSE和日志订阅。

阅读定位使用内容ID/版本与 [source_locator](../contracts/content-locator.md)；字号/宽度改变后重新布局定位，不能只恢复旧ScrollController像素值。原型的段落比例只属于示例，不能代替正式出处协议。触控与鼠标选区都要转换为同一协议偏移并处理字素/UTF-16差异，不能因换layout改变原文引用。

输入值、选中题目和未同步状态跨layout保留；TextEditingController/FocusNode归presentation，不将它们放入domain或从服务端响应每帧覆盖。正在进行中文/日文输入法组合时，不强制重建该编辑器或提交半成品文本；必要时延迟结构切换，验证组合结束后的光标和选择范围。

临时失联按模块处理：考试已有短时未同步草稿规则继续适用，补交必须重查编辑代次、revision、截止与锁卷状态；不新增完整离线考试或通用离线写队列。进程重启只承诺恢复服务器已保存进度，不宣称所有未提交输入能跨进程保留。密码、Key、Token和私有正文不进入通用Restoration、路由URL或日志；需要本地持久化的内容必须有既定缓存/草稿范围与账号隔离。退出清除私有本地状态，已提交任务是否继续按业务规范处理。

## 4. 页面适配合同

下面是各模块的实现基线；业务功能、动作权限和状态沿用模块规格。平台差异改变布局/交互，不擅自删掉三端已承诺功能。

| 模块 | 紧凑/触控优先视图 | 宽屏/鼠标键盘增强 | 共用状态与约束 |
| --- | --- | --- | --- |
| 登录/注册 | 可滚动单列表单、键盘避让、提交和错误可见 | 限制表单最大宽度、Tab/Enter与焦点顺序 | 同一校验/认证状态，重排不清空输入或重复登录；密码不恢复到其他账号 |
| 书库 | 纵向材料列表、底部导航、筛选面板 | 侧栏、封面/列表、常驻或弹出筛选 | 同一筛选和分页；视觉按产品设计语言，不添加“继续阅读/最近在读”区 |
| 小说阅读 | 通栏正文、目录抽屉、底部选区/解释工具 | 目录/正文/解释面板按空间组合，鼠标划选与快捷操作 | 小说专用controller内共享版本/出处/播放状态；关闭解释恢复位置与焦点 |
| 课本学习 | 单元逐级导航，课文/词表/练习分区 | 课程目录与当前单元内容；P1再启用讲练分屏 | 课本专用controller；位置与Attempt分开，切区/布局不重复作答，不复用小说页面 |
| 收藏/CSV | 卡片/单列、分步预览确认、系统文件入口 | 可扫描列表、并排来源与批量操作 | 同一预览/确认/去重和权限；区分生成完成、已交给浏览器/系统保存、已确认落盘，不超出平台可证明的结果 |
| 练习/考试 | 单列题目、可收起共享材料、抽屉答题卡、底部操作区避让键盘 | 题目与答题卡并排、键盘跳题、材料可并看 | 场次/答案/计时/编辑代次共用；考试中全部layout与快捷键均禁止解释/答案提示等受限辅助 |
| 查询与AI功能 | 查询统一输入，其他功能在当前面板/卡片/题目内操作；不设Agent聊天页 | 查询结果限制行宽，阅读解释可并列原文，诊断使用独立报告 | 保留对应资源上下文、run与已完成结果；布局切换不重新调用Agent、不跳入聊天 |
| 设置 | 分类入口进入单列表单 | 分类导航与详情并排 | 同一偏好revision和能力目录；未保存变化有明确提示，改layout不保存或触发模型调用任务 |
| 管理Web | 窄浏览器下表单/列表可操作，复杂表格可明确横向滚动 | 管理导航与元数据列表/详情 | 仅Web注册admin路由、独立受众且在线；窄Web不是Android原生管理端 |

移动端的bottom sheet、独立详情页、触控工具条属于正式允许的专用UI代码。只有确实依赖Android系统语义的实现才使用android命名；compact布局可以同时用于手机Web和Windows窄窗口。触控路径始终可完成目标动作，hover/右键/快捷键作为增强入口，不能成为唯一入口。

教材八类内容与考试五类作答交互/题组按[解析展示契约](../contracts/learning-presentation.md)编排：分领域注册renderer，复用纯展示控件，各自controller负责提交/权限/反馈。小屏图表保留对应关系，题组共享材料打开返回不丢作答/焦点；原文对照遵守考试投影权限，未知必需结构不得被隐藏为“无内容”。这些规则不将教材讲练分屏从P1提前。

## 5. 平台能力与系统交互

平台能力由core/platform接口、构建条件和bootstrap选择具体实现；feature只消费类型化结果。能力不可用、用户取消、权限拒绝和实际失败分别表达，不能默默返回成功或用另一供应商顶替TTS。

| 能力 | Android | Windows | Web |
| --- | --- | --- | --- |
| 文件输入/输出 | 系统文档选择/保存与URI，不能假定真实磁盘路径或要求宽泛存储权限 | 系统文件对话框，处理占用/无写权限/用户取消 | 浏览器文件对象/下载；不能把触发下载当作已确认落盘，实际可证明范围按CSV契约 |
| 身份与安全存储 | 既定安全存储适配，处理进程重建 | 既定系统凭据适配 | HttpOnly Cookie与CSRF；Flutter不能读取Cookie令牌来模拟原生Token接口 |
| 播放 | 音频焦点、耳机拔出、来电/后台中断 | 插件播放后端、设备变化与窗口生命周期 | 用户手势/自动播放限制、媒体可达性 |
| 返回/导航 | 系统返回/手势、键盘与弹层优先级 | Esc关闭当前弹层、键盘焦点、窗口关闭 | 浏览器历史、刷新/深链；不能假设卸载回调一定执行完 |
| 生命周期 | 前后台、进程可能被回收；恢复先确认权限/任务状态 | 窗口隐藏/恢复、进程关闭 | pagehide/可见性、标签被丢弃、网络恢复 |

1. 系统返回与应用返回进入同一页面决策：有键盘/弹层时按平台实际行为处理，关闭当前面板，再处理页面离开。存在未保存输入时提示状态与允许选择；离开考试不自动交卷、不暂停服务器计时。使用锁定SDK对应的PopScope等机制验证Android预测性返回；不要等路由已退出后才补保存确认。[PopScope](https://api.flutter.dev/flutter/widgets/PopScope-class.html)
2. SafeArea负责必要安全区域；键盘viewInsets、底部面板和Scaffold的避让由同一布局层协调，防止重复加高度、遮挡输入/提交按钮。安全区不代替键盘处理。[SafeArea与MediaQuery](https://docs.flutter.dev/ui/adaptive-responsive/safearea-mediaquery)
3. 不依赖退出/切后台时“最后一次请求必达”；平时按业务协议保存，恢复查询持久结果。播放器/订阅重连只恢复已有任务，不能因恢复生命周期自动重新生成。Android锁屏常驻播放仍为待验证范围，遵循 [AI与朗读](../modules/ai-speech.md)。
4. 平台不支持的库通过条件导入/独立适配文件隔离；仅在运行时写if(kIsWeb)不能让已导入的原生库自动兼容Web。业务Widget禁止直接import dart:io或调用MethodChannel；确有插件缺口时才在适配边界补宿主代码，不提前建三套桥接框架。[Dart条件导入](https://dart.dev/tools/pub/create-packages#conditionally-importing-and-exporting-library-files)
5. 上传、下载、播放结果带所属实例/账号/受众和本地代次，迟到结果在应用前校验；适配器返回受控文件句柄/字节流或安全失败类型，不把本机路径、签名URL、私有正文自由写入日志。

## 6. 操作可用性、移动端性能与日志

触控可操作区域以至少48逻辑像素为项目初始基线，小图标可扩大命中区，但不能覆盖相邻控件；模块调整需要实际可用性依据。按钮的文字、图标、禁用状态与错误反馈在画面上清晰可见；复杂选区工具提供明确的触控和键鼠操作。弹层关闭后恢复触发页面的业务状态。

本地化文本进入ARB，默认界面仍zh-Hans，错误按统一返回契约翻译；不得为了排版截掉关键错误/按钮意义。验证长标题、多行错误、英日混排/输入法和已提供的减少动画显示选项，允许滚动或重排。不同layout同一业务动作优先使用相同Test ID，当前活动视图内必须唯一，具体规则见前端测试。

- 长列表/长文档按需构建、分页/分块加载；以稳定业务ID维护条目身份。阅读分块必须保留出处与选区连续性，不因虚拟化将跨块选区截断为错误文本；所选阅读引擎须以样本证明。
- 图片/题图按显示需求解码并限制缓存；预取与音频缓冲有容量、取消和账号隔离规则。不能靠无限keepAlive或把全书Widget永久挂载解决滚动恢复。
- 播放进度、倒计时、流式文本等高频变化只更新必要子树，按需要合并UI刷新；不丢业务事件、保存结果或评分状态。静态组件优先const，订阅选择实际使用的状态字段。
- 大文件解析/AI等既有后端职责留在后端；必要的本地重计算先测瓶颈，再按平台选分块/后台计算方式，不能假设原生isolate方案在Web自动同效。
- Android性能用目标真机profile模式记录帧耗时/卡顿、峰值内存、打开大材料和连续阅读/输入表现；Web用实际浏览器性能工具补证。当前不执行Windows原生性能测试；debug或浏览器窄屏截图不作为Android性能证据。[Flutter性能分析](https://docs.flutter.dev/perf/ui-performance)

性能门槛按 [交付验收](../delivery/acceptance.md) 在阶段1/对应功能原型登记设备、构建、刷新率、样本规模、测量窗口和目标，候选发布前锁定。没有数据时记录待测，不承诺已达固定帧率；界面动画优化不能跳过功能/权限正确性。

全部layout和平台adapter使用同一Telemetry，保留operation/request/job关联。重排不重复记screen.viewed、重复上传日志或把既有任务当新操作；必要布局/性能诊断只登记粗粒度layout/输入类型及耗时等白名单字段。高基数字段、正文/选区/输入值和凭据的日志限制仍以 [观测](../operations/observability.md) 为准。

## 7. 一个功能切片的开发步骤

1. 从功能模块和API契约确定共同业务状态、权限、动作和必要三端行为；页面适配不新增后端字段或降低已承诺能力。
2. 依据[产品设计语言](../product/design-language.md)落实共享主题/文字/控件与真实状态反馈，再列紧凑/宽屏结构与触控完整操作路径；判断使用单组件参数、独立layout还是平台adapter，登记功能切片所需边界样例。设计初值随本切片验证，不能把概念稿参数当成已验收组件。
3. 先落实共享应用状态/数据访问，再编写独立视图；接口尚在并行开发时使用契约样本进行组件开发，不能将其冒充联调/E2E通过。
4. 明确状态所有者、订阅释放、重排恢复与账号代次；为编辑器、选区、播放器等复杂能力验证切换行为。
5. 选择必要最低层测试：状态规则用unit、两种布局/边界用widget；受影响真实流程用integration_test及平台补充。改一页不默认运行所有业务/所有平台E2E。
6. 在目标平台验证此次涉及的原生交互/性能，更新Test ID、事件目录、模块差异和实际限制，按AGENTS完成局部review及本阶段commit。

前端与后端按既有契约并行，前端内部可按feature/layout分工；共享controller/API/设计token的修改指定负责人。设计/原型改变先确认是否涉及行为契约，不能两个layout各自实现不兼容的保存与错误处理。

## 查询图片的平台适配补充

按[查询模块](../modules/query.md)实现图片输入：共享层只处理图文草稿、附件状态、预览/移除和发送；系统相册/相机、Web粘贴及本机临时文件生命周期放平台适配层，不能仅凭窗口宽度判定相机能力。Android点击拍照直接启动系统拍摄流程，确认后追加草稿；取消/拒绝/不可用时保留原草稿并允许相册，权限仅在动作发生且平台需要时申请。恢复携带账号/会话/选择请求代次，进程重建后重新鉴权，不把旧账号返回的URI或相机结果接入新草稿。

Web仅响应输入区的用户粘贴事件，不持续读取系统剪贴板；读取图片数据项、保留同时粘贴的文字，不抓取HTML/URL图片。能力不支持时保留文件选择。HTML原型通过[ClipboardEvent.clipboardData](https://developer.mozilla.org/en-US/docs/Web/API/ClipboardEvent/clipboardData)示意粘贴，通过[capture=environment](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture)请求拍照；后者取决于浏览器/设备，桌面可能仍打开文件选择，不能代替Flutter Android原生相机、权限和恢复验收。

缩略图按显示尺寸解码，格式/字节/像素/张数先预检，服务端仍独立校验和去元数据；释放被移除的临时资源，退出/换账号关闭预览、清理缩略图/文件并取消接收旧回调。软键盘、相机返回和横竖屏变化后不丢文字，不遮挡发送/移除按钮；TalkBack/键盘能定位有序图片、放大与移除。QRY-06～09的Web事件和Android真实系统流程分别举证。
