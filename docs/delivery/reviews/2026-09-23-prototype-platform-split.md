# HTML 原型 v0.6 手机端与电脑端分离

日期：2026-09-23。范围：[HTML原型](../../../prototype/README.md)的页面入口、应用壳与样式拆分小阶段；不计入 Flutter/Python 或 B1/B2 业务实现。

## 用户反馈与变化

用户要求手机端、电脑端分为独立原型，不再由一个文件兼任两端。原`phone.html`只是在`iframe`里打开`index.html`，实际页面依靠浏览器宽度决定布局。

现在[phone.html](../../../prototype/phone.html)是真实手机页，含手机主导航、手机专用阅读视图及底部面板；[desktop.html](../../../prototype/desktop.html)是真实电脑页，含侧栏、顶栏和宽屏阅读/词本布局。[index.html](../../../prototype/index.html)只提供两个直接入口。手机页不含桌面侧栏/顶栏，不加载电脑专属样式；电脑页不含手机主导航，不加载手机专属视图脚本。两页共享示例数据、词本操作规则及基础样式；分别维护内存状态，互不自动同步。

平台由页面入口明确给出，不再从窗口宽度推断。手机页在宽浏览器中固定为390px画布，导航、阅读工具栏、底部面板均对齐画布；电脑页保持宽屏结构，窗口窄于980px时可以横向查看。此行为只描述HTML原型，不改变Flutter跨布局共享状态的正式设计。

## 局部检查

- Edge无头浏览器直接打开手机端的320、390、1440px视口：无iframe/桌面侧栏，手机导航显示；首页→词本→详情→编辑并保存成功，编辑弹窗保持底部面板。1440px下手机画布及导航均为390px并居中。
- 直接打开电脑端的390、1024、1440px视口：无手机导航，侧栏与电脑视图保持；书库→单词本→详情→编辑可用，1440px阅读解释面板可用。
- 两端JavaScript无页面错误；入口页的两个链接指向各自页面。实际查看了手机390px、宽窗口手机页及电脑1440px截图。初次宽窗口手机截图发现底部导航左右内边距按整个视口计算，导致铺满页面；已将导航宽度与内边距固定到手机画布，并重新实测、查看截图。初次窄窗口电脑端的本内词条被挤到不可点，已给电脑画布设置980px最小宽度，390/1024/1440px定点复测可完成详情和编辑。

手机与电脑端分别通过本地`file://`直接打开并进入预期页面；改变浏览器宽度不会切换另一个入口。3个受影响JavaScript文件语法检查、3个HTML入口的21处本地资源引用、2份说明文档的35处本地链接及代码围栏检查通过。

## 独立审查

作者：root；非作者：prototype_review。第一轮只查本次拆分及直接影响，发现1项P2：原共用的弹窗背景滚动锁随手机样式移走，电脑端弹窗打开时背景仍可滚动。已把`body.dialog-open`规则放回共用样式；作者用Edge定点验证电脑阅读页、手机书库页打开设置后滚轮不移动背景，关闭后滚动样式恢复。审查建议手机提示条也应限制在手机画布内，已将其最大宽度限制为354px并允许长文换行；1440px窗口下长提示的左右边界实测均在390px手机画布内。

第二轮非作者定点复核独立用Edge验证电脑1440px与手机390px的弹窗滚动锁：打开后滚轮不移动背景，关闭后恢复滚动。宽窗口手机长提示限制在390px画布内；两条路径无页面错误，无剩余P1/P2。
