# 注册、登录与账号操作

PLAN2实施分界：本页closed/open、邮箱验证/邮件找回及“不启用审批/人工恢复”的约束保持为B1已选基线。当前版本在B2b另外交付原型可配置的审批注册与人工恢复，见[路线图](../delivery/roadmap.md)；B1不增加这些分支，也不改变默认关闭注册。B2b必须交付待审批/拒绝/激活进度，以及人工恢复申请/受理、受控身份核验、一次性挑战安全交付、消费/到期/重复/并发拒绝和全部旧会话撤销；不得以可选个人资料作为核验证据，不允许管理员查看/设置永久明文密码或代登录。策略快照与既有账号状态不得因切换自动重写；邀请仍不进入当前范围。B2b开发前同步正式API/权限/挑战通知和ACC/ADM用例，不能只做开关或“联系管理员”文案。

状态：设计基线 v0.2，2026-09-23，未实现。身份边界以 [认证与隔离](../architecture/authentication.md)、授权以 [RBAC](../architecture/authorization.md) 为准。本篇负责用户操作、页面状态与可验收结果；公共会话算法由认证设计维护，个人资料与学习偏好字段以[设置模块](settings.md)为准。

2026-09-26明确交付归属：正式注册、邮箱验证激活、登录、邮件找回/重置、本人改密及会话管理全部纳入[B1账号闭环](../delivery/milestones/scaffold.md#3-b1账号闭环与收藏参考流程)。同日用户确认OPEN-02：开放注册使用受控开关，默认关闭；启用后必须邮箱验证，找回通过邮件完成。本地隔离SMTP真实投递与Web找回闭环已获用户接受为B1邮件验收范围；外部发信配置尚未准备且不实测，不能称为外部邮箱送达。完整首次引导、资料/头像/学习设置在阶段1对应设置切片交付，不因B1验证了“可选资料不阻止注册”就视为完成。

## 1. 范围、入口与权限

P0 覆盖注册、激活条件、两端登录、会话恢复、本人改密/会话管理与退出，以及登录后的可跳过资料/学习档案引导；这些能力不需要模型 Key。用户端支持 Windows/Web/Android，管理入口推荐 Flutter Web；首版采用邮箱加密码、邮箱验证与邮件找回，不启用邀请、人工审批或人工恢复路径。

用户端 `/login`、`/register`、`/account/profile`、`/account/security` 和 `/settings`；管理 Web `/admin/login`、`/admin/account/security`。两端属于同一 User，分别建立 client/admin 会话，首版切换入口重新登录，不默认静默交换。登录表单只有邮箱、密码、显示密码开关和提交；支持系统密码管理器、粘贴、键盘提交和明确焦点/错误标签。头像、出生年份、性别、母语和学习语言不进入注册凭据表单，也不能成为管理员审批之外的隐藏登录条件。

所有业务页面须经过当前受众的登录和访问快照；只有 login 权限时也可进入受控空状态及本人安全/退出。账号基础操作使用中央身份规则，不能因为学习菜单被撤销而无法改密或退出；操作他人账号/会话属于管理权限。

## 2. 流程、状态与异常

### 2.1 注册与激活

注册模式为 `closed/open`，部署初始值为 `closed`；具备专门策略权限的管理者才能按revision修改，并记录审计。关闭时前端明确显示暂未开放，后端拒绝新注册；关闭不影响既有账号登录、继续验证或邮件找回。启用前验证通知配置可用，缺失不能假成功；SMTP受理后的发送失败由持久任务重试并提供受限重发。公开能力与实际依赖一致，不展示未启用的审批、邀请或人工恢复入口。

1. 页面读取公开 /auth/policy，仅返回 registration_enabled、approval_required、email_verification_required、recovery_mode 和输入约束，不公开角色 ID、密钥、名单。
2. 输入邮箱、密码和确认密码；确认只在前端比对，不是后端安全依据。注册不要求邀请码、显示名、头像、年龄/出生年份、性别、母语、学习语言或模型 Key，避免把可选资料变成账号创建门槛。
3. POST /auth/register 检查策略、限流、输入、公开允许的默认角色。额外 role/status/permissions/owner 字段拒绝，而非绑定到 ORM。
4. 单个数据库事务创建User、Library、一个空的UserExtension、默认角色绑定和必要的通知Outbox；唯一邮箱约束处理并发。失败全部回滚。账号注册成功不要求模型Key。
5. 邮箱验证要求按本次注册的策略快照保存，审批为不要求。验证成功且账号仍满足激活条件才从 pending 转为 active；不能启用disabled账号。后续关闭注册不改变既有账号的验证要求，也不自动激活pending账号。
6. 返回统一受理说明与后续可用入口；已有邮箱不创建第二个账号，也不公开其状态。若启用邮件，按相同响应处理，重发受限。页面不根据该响应宣称已经能登录。
7. 激活完成后回登录页；首版不在注册成功时自动创建登录会话。默认角色必须仍有效，若配置失效则注册事务失败并向管理员报告配置问题。

账号字段区分 status=pending/active/disabled、email_verified_at、approval_status、locked_until。首版approval_status为not_required；邮箱检查是激活前置条件，locked_until 是限时安全阻断，不覆盖管理员 disabled。已有受阻状态不能被验证或恢复流程绕过。

### 2.2 登录与失败反馈

1. 用户Web端 POST /auth/login；Windows/Android POST /auth/native/login；管理Web端 POST /admin/auth/login。固定路由决定audience与凭据传输，platform只描述原生设备，不能获得更多权限；原生入口拒绝浏览器Origin/Fetch Metadata及混合Cookie/Bearer。
2. 解析输入，检查来源/CSRF（Web）、账号/IP/全局频率，取得 User；不存在的账号也执行受控等价哈希验证，避免明显时序差。
3. 验证密码后检查 status、锁定/激活条件、当前 client.login/admin.login、功能安全策略。一般错误统一为 AUTH_LOGIN_FAILED，不通过文案/状态码泄露账号是否存在。
4. 正确密码但仍待邮箱/审批时可返回短期、仅能查询本人激活进度的 continuation challenge；不签发业务会话，不返回角色列表/其他个人数据。安全锁定/禁用等敏感失败仍按统一文案处理。
5. PostgreSQL 创建会话元数据并绑定当前安全 epoch；Redis 初始化会话摘要/刷新材料与 TTL。只有两步均成功才返回凭据；失败返回 503 并撤销/清理半成品，永不返回没有有效服务端会话的成功结果。
6. Web 使用高熵 opaque session Cookie，按受众分别命名、HttpOnly/Secure/SameSite，JSON 不含令牌；原生端收到短期 JWT Bearer 与轮换刷新凭据，刷新凭据进入系统安全存储。Web 不把原生令牌响应模式作为默认会话实现。
7. 读取access中的最小本人身份（user_id/instance_id/audience/session_ref）、权限/导航，再进入首个有权限页面。profile/settings仅在具备对应权限时可选加载，无权不阻塞启动；access失败停留可重试加载页。只有login权限的账号也能显示受控空状态、本人安全和退出入口。
8. 成功登录清理旧账号/受众内存与队列，再启动当前账号缓存/播放器/订阅。迟到响应携带账号代次校验，不准改变新会话。

推荐限流起点：IP 20 次/分钟、账号 10 次失败/15 分钟，逐步退避，临时锁定不超过 15 分钟；注册/重置更低的单独限额。账号限流键用服务器摘要，不记录邮箱；这些是待压测初值，不是抗攻击保证。密码哈希计算有并发上限，Redis/身份依赖不可用时失败关闭，返回可重试的服务错误。

### 2.3 恢复密码与继续激活

页面只显示当前部署已启用的恢复方式。邮件模式提交后统一显示受理结果，可在冷却期后重发；打开有效链接后填写新密码并确认，成功后重新登录。链接失效/已用则提示重新申请，不自动登录或激活禁用账号。邮件发送失败保留原账号，给出可重发状态；页面不能凭受理响应宣称邮件已经送达。

首版不开放人工恢复入口。账号激活进度仅通过正确凭据取得的受限 continuation 查询；它不允许访问书库、角色或其他私人数据。

### 2.4 会话恢复、本人安全与退出

打开应用先恢复当前受众身份，再加载最小 access 身份和有权页面；会话过期、撤销或无法确认身份时清理私有界面并重新登录。权限不足、CSRF 失败、账号禁用不会触发无限刷新。Web 标签收到身份可能变化时暂停私有写入，重新确认当前 Cookie 的身份后再展示；原生刷新期间合并同会话请求，异常由统一认证客户端处理。

本人可查看设备会话摘要、撤销其他会话或退出全部设备；不依赖学习菜单权限。当前退出成功清除本机凭据、私有缓存、草稿、下载、播放器和订阅。网络失败仍本地退出并显示“本机已退出，远端撤销未确认”，失效凭据也不能阻止本地清理；重复点击不会恢复旧会话。

改密页显示当前密码、新密码、确认新密码和保存动作。服务端重新验证当前密码与有效身份，拒绝与当前密码相同、常见泄漏/弱口令及不满足当前策略的新密码；确认字段不发送或存储为安全依据。密码验证和新Argon2id哈希计算在短事务外基于同一快照完成；提交事务锁定User和当前AuthSession，再核对快照的password_version/security_epoch、当前会话仍有效且绑定同一epoch，任一已变化就拒绝本次提交。成功事务替换哈希并增加password_version/security_epoch，撤销client/admin全部既有会话并写审计/Outbox，当前端立即清除凭据并回登录页；两个并发改密或改密与恢复竞争只能有基于原版本的一次提交成功。

只有确定在提交前被拒绝或数据库回滚的请求才能保证密码和会话未变化，此时保留用户正在修正的新密码字段。提交确认断连、超时或响应丢失属于结果未知：客户端不得自动重放、不得宣称密码未改，也不继续保存当前/新密码；应清理秘密和本机会话，提示用新密码重新登录，无法登录时进入当前部署已启用的恢复路径。PG已经提交后，即使Redis清理或响应失败也不能翻译成“改密回滚”；服务端Outbox继续完成缓存清理。

密码修改不会改邮箱、资料、角色、Key或学习数据。忘记旧密码走已启用的恢复流程，不能借资料页、管理员可见字段或API Key证明身份。被管理员强退/禁用或撤销对应端登录资格后，下一授权边界退出该端；后来恢复权限不复活旧凭据。普通退出/设备强退不自动取消已受理 Job，任务继续属于原账号；禁用、撤销动作权限或显式取消才停止后续受限步骤。

### 2.5 首次登录与基础资料引导

激活后首次成功登录可进入可跳过的引导：确认显示名/头像（均可空）→选择一个或多个母语/常用解释语言→选择一个或多个已支持学习语言及当前语言→确认时区→按需配置模型Key。注册事务已经创建一个空UserExtension，引导只是普通、有revision的本人资料更新，不创建第二个User/Library，也不自动取得新权限。

未完成引导不阻止登录、本人安全、设置或读取已有有权数据；需要学习语言的AI习题、诊断、默认筛选等功能在调用前返回“请先选择学习语言”，不能从设备locale或导入材料悄悄持久化替用户决定。模型Key步骤始终可跳过；无Key仍可使用不需要新模型调用的功能。引导进度按已提交字段派生，不以客户端“完成”埋点为真相，多端同时修改使用资料revision冲突协议。

显示名、头像、出生年份/年龄展示、性别、语言档案、主题与显示偏好由[设置模块](settings.md)维护；管理员创建/审批账号与角色分配见管理模块。首版没有公开个人主页、用户名/昵称唯一性或用户间搜索，个人资料不能被其他普通用户读取。用户 API Key 不参与登录校验，也不是密码恢复证据。

## 3. 前端职责

表单状态 idle → validating → submitting → authenticated / action_required / error。提交中防重复；网络失败保留邮箱，密码只短暂在内存，不写缓存、日志、埋点或状态恢复。输入修改清理对应字段错误，服务端错误通过稳定 code 映射中文文案，不直接显示堆栈。

| 平台/场景 | 前端职责 |
| --- | --- |
| Windows/Android | 会话材料进入经过验证的系统安全存储；应用重启、存储失败、迟到刷新与换账号必须保持同一 AccountScope |
| Web | 使用同源 Cookie/CSRF 协议，不把长期令牌写 localStorage；身份变更跨标签协调后重新取得最小身份 |
| 两个受众 | client/admin 页面、缓存、队列和入口分别绑定；默认切换端重新登录，不因另一端已经登录而放行业务 |
| 权限加载/空页面 | access 未就绪不先渲染受限页面；无 profile/settings 权限不阻塞最小身份初始化；无可用业务页仍有安全/退出 |

登录成功、失败与限流采用稳定安全文案；密码/挑战 Token/Key 不进入页面埋点、崩溃上下文或状态恢复。密码管理器、粘贴、键盘提交及可见错误提示在Web和Android验证；Windows原生不执行。

手机登录、注册和找回页采用顶部小品牌区与单列短表单，不将整页垂直居中。标签常驻，密码显隐按钮独立且至少 44px；主操作紧随表单。登录页的找回入口靠近密码，创建账号与服务地址作为下方次级操作；注册和找回提供明确的返回登录。内容按正常文档流滚动，短屏或键盘出现时仍能到达确认字段和提交，不通过固定高度裁切表单。切换显隐或调整可用空间不丢失输入；离开凭据页后不通过页面历史恢复密码。

格式错误贴近对应字段，提交失败聚焦首个错误，修改输入清理相应错误。注册受理与找回受理使用独立结果页，保留返回登录和适用的重填入口；路由切换提供新标题焦点与页面标题，受理不等于账号已激活或邮件已送达。当前 HTML 手机原型展示上述布局与本地校验，注册长度仅采用第4节的推荐值演示；正式页面仍从公开策略读取约束与已启用恢复方式。原型不创建账号、不发送邮件、不改密，不作为 ACC 验收证据。

## 4. 后端职责

邮箱去首尾空白、校验格式/长度后生成大小写不敏感的 email_normalized 唯一值，原显示邮箱另存；不删除加号别名或点。密码不 trim/截断/改变 Unicode，首版建议 15–128 Unicode 码点，最大 UTF-8 1024 字节，允许空格/粘贴；常见密码离线阻止清单版本化。哈希使用 pwdlib/Argon2id，参数经容量基准验证并允许登录时升级哈希。输入建议和安全原因参考 [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)。

### 4.1 邮箱验证与恢复的服务端职责

挑战使用高熵随机一次性 Token，数据库只用摘要验证，绑定 user/purpose/expiry/security_epoch；验证建议 24 小时、重置建议 30 分钟、重发至少 60 秒，均为可调初始值。通知 Worker 只从受控短期加密载荷取收件地址/链接，Kafka/普通 Outbox 消息只放引用，链接、Token、邮箱不入日志。通知依赖未配置时不能受理；受理后发送失败可重试，不回滚已创建账号，页面显示可重发路径。

重置请求对存在/不存在账号返回同一受理结果；完成重置在事务中消费挑战、更新密码哈希、推进两端会话 epoch 并审计，再提示重新登录，不自动登录、不启用 disabled 账号。邮件跳转域名由部署白名单固定，不能使用不可信 Host/return_to 生成。链接使用URL fragment承载Token，页面读取后立即从地址栏移除，不放query或路径以免进入访问日志；GET打开不自动消费，用户明确确认后POST。挑战页面禁止采集Token，过期/已用提示重新申请。Windows/Android可在Web完成后回应用登录，也可显式粘贴同一受信任域名与用途的邮件链接在原生完成；不自动读取剪贴板、不假定已配置系统深链。参考 [OWASP Forgot Password](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)。

首版没有人工恢复或管理员代登录路径；管理者不能查看或设置用户的永久明文密码。

注册事务、当前策略/默认角色检查、受众隔离、账号状态/锁定、并发唯一邮箱、速率和哈希并发限制由后端执行。会话的 PostgreSQL/Redis 职责、期限、Web 续期与原生轮换/CAS/回执不在本模块复制；严格执行认证设计并在失败时拒绝建立半成品会话。

## 5. 公共契约与依赖

会话期限、PG/Redis职责、Web续期/CSRF和原生single-flight/CAS/回执算法由 [认证设计](../architecture/authentication.md) 维护。客户端按该协议恢复身份、处理过期与账号切换；退出、改密、强退后的页面行为和ACC验收保留在本模块。

[API 契约](../contracts/api.md) 维护 auth、admin/auth、本人 access 与安全操作的公开/受保护边界；[权限目录](../contracts/permissions.md) 和 [授权设计](../architecture/authorization.md) 定义 client/admin.login、账号状态与专用本人安全操作。个人设置见 [设置模块](settings.md)，管理者流程见 [管理模块](admin.md)。

注册、激活、登录拒绝、会话恢复/撤销、改密与恢复使用 [统一观测](../operations/observability.md) 的安全事件，关联操作与请求 ID；日志不含邮箱全文、密码、Cookie、刷新材料或挑战链接。认证成功、权限业务事务与遥测上报分别完成，遥测不能作为身份或授权事实。

## 6. 验收

| ID | 操作与期望 |
| --- | --- |
| ACC-01 | 并发注册同邮箱仅产生一个User/Library及一份UserExtension（资料/学习/设置分组版本）；角色越权字段拒绝，失败事务无孤立记录 |
| ACC-02 | 正确密码但无对应 login 权限无法建立该端业务会话；用户端 Token 不进管理 API |
| ACC-03 | 注册默认关闭且前后端均拒绝新注册；管理员有权开启后，pending邮箱未验证不能激活；关闭不阻断既有验证/找回，策略变更不静默激活旧账号 |
| ACC-04 | 两端三平台登录恢复、到期/空闲、退出/换账号和迟到响应正确，密码/Key/Token 无持久日志 |
| ACC-05 | Web多标签续期不轮换Cookie，身份变更后按当前Cookie重新绑定；原生丢响应/迟到代次/窗口内外重放有确定结果，无刷新风暴 |
| ACC-06 | 禁用/指定会话撤销/撤销端登录权限提交后，新请求被拒；Redis 删除失败仍不能通过；重新授权不复活旧会话 |
| ACC-07 | 改密重验当前密码并拒绝相同/弱密码；提交锁内核对password_version/security_epoch/会话，同一旧版本的并发改密或恢复仅一次成功；成功原子更新版本/epoch并撤销client/admin全部会话，确定拒绝/回滚不撤销；提交后丢响应按结果未知处理且不自动重放；重置挑战单次消费且不激活失效/禁用账号 |
| ACC-08 | 无 Key 可完成已授权的注册登录和基础操作；密码管理器、键盘输入与界面可见的错误提示可用 |
| ACC-09 | 邮件验证/恢复测配置缺失、发送失败/重试/重发/过期/重复及进程重启；B1以本地隔离SMTP真实投递闭环验收，外部邮箱实际投递不实测并明确记为用户接受范围，不把受理当送达 |
| ACC-10 | client.login-only/admin.login-only账号登录与刷新恢复仅依赖access最小身份；无profile/settings权限仍能显示空状态和本人安全/退出 |
| ACC-11 | 注册只需当前策略要求的身份字段，不因头像、出生年份、性别、语言或Key缺失失败；首次引导可跳过，需语言的功能单独提示补全且不自动持久化设备推断 |
| ACC-12 | 多端首次引导/资料更新按revision处理，重复或迟到提交不创建第二份Profile/Library、不覆盖较新资料或改变角色/账号状态 |

## 7. 待决与后续

[待决清单](../decisions/pending.md) 维护尚未锁定的邀请与公开上线条件。B1邮箱验证、邮件找回已选定，审批注册与人工恢复归B2b扩展；未启用的能力不展示空链接，不把“联系管理员”写成已经可用的恢复流程。

首版不提供随意修改登录邮箱或自助销号界面；后续需要新邮箱验证、会话撤销、数据留存与删除完整设计。出生年份/性别等可选资料不能充当找回账号问题。管理员建号使用受控邀请/一次性设置，不产生可公开复制的永久默认密码。

原生安全存储插件、跨标签协调与刷新回执实现需工程验证后锁定版本；本篇是明确的待实现协议。
